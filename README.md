# 老胡 AI 视觉作品生产系统

这是一个给 AI Agent 使用的视觉作品创作项目。你可以从一句灵感开始，和 AI 一起完成故事、剧本、视觉资产、分镜、视频提示词、封面和复盘。

仓库里不只有提示词模板，还保存了作品目录、创作规则、质量检查、失败案例和项目专属 Skill。它们共同解决一个问题：怎样把“模型能生成画面”，继续推进到“创作者能稳定做完一部作品”。

整个系统由 Markdown 文件和本地目录驱动，不需要部署前端或后端。在支持项目上下文和文件读写的 AI Agent 中打开仓库，就可以直接开始创作。

## 它会帮你推进流程，但不会替你决定审美

项目已经搭好了创作流程、目录结构和质量检查，也整理了不少可以复用的方法。但题材怎么选、人物怎么看世界、镜头应该留下什么感受，最终仍然需要创作者自己判断。

这不是一个把所有作品都做成同一种样子的模板。你可以沿用它的工作方法，再把自己的审美、题材、失败经验和发布反馈逐步补进去。用得越久，它才会越像你的创作系统。

## 这个项目能做什么

### 1. 从灵感确定故事内容

你可以只给一句灵感、一段口述、一个画面或一个题材。系统不会马上套结构，而是先把几件事想清楚：

- 你真正想让观众看到什么、感受到什么。
- 哪些人物、事件、台词或结果不能改。
- 它更适合 15-60 秒短视频、1-3 分钟概念片、3-10 分钟短片，还是系列短剧。
- 观众为什么愿意继续看，作品最后要留下什么。
- 当前最需要解决的是故事、生成稳定、剪辑衔接，还是发布传播。

仓库里的 Reference 只有在真正适合当前作品时才会调用。如果现有方法只能解决一小部分问题，系统会直接说明缺口，而不是为了利用旧模板把新作品改成另一种东西。

### 2. 写剧本和单场次剧本

即使你最终只想拿到文生视频提示词，系统也会先把故事、人物和镜头任务说明白：

- 故事确认。
- 世界观和人物关系。
- 正式剧本。
- 单场次剧本。
- 需要继续拆成分镜的镜头任务。

短剧 / 短片编号使用 `E1-S1-C1` 规则，插入镜头用 `E1-S1-C5A` 这类字母后缀，不重排后续编号。

写对话和情绪短剧时，系统会继续检查人物为什么说这句话、他想从对方那里得到什么、情绪从哪里发生变化，以及说完以后有什么反应。动作、道具和人物位置也会记录前后状态，避免上一个镜头已经扔掉的东西，下一个镜头又回到手里。

### 3. 判断视觉资产

项目会先区分哪些内容需要做成长期资产，哪些只在当前镜头出现一次。

资产不是画面里出现过的一切。只有跨镜头、跨场次、跨集或跨作品复用，或者需要锁定外观、空间、材质、比例、色彩和风格连续性的内容，才进入资产表。

视觉资产分两类：

- 图片资产：固定角色脸、服装、场景空间、关键道具、第一帧等具体形象。
- 文本资产 / 提示词资产：固定氛围、妆造、服饰体系、建筑语法、色彩材质、声音气质和世界观视觉规则。

一次性角色、一次性奇观和单镜头场景，通常只作为当前画面元素或临时参考图，不会为了显得完整而全部建档。

需要生成多项资产时，系统会先排好顺序。后续会被引用的风格、道具或人物先生成，再做组合人物、场景和故事板。暂时没有参考图的部分，也会在提示词里锁定服装、材质、空间和色彩，不把连续性完全交给模型碰运气。

### 4. 生成分镜表和视频提示词

剧本确认以后，系统会继续拆分镜，再把每个镜头写成可以独立提交给模型的视频提示词。

正式视频提示词必须使用三段结构：

```text
【基础设定】
【氛围与画质】
【画面内容】
```

每条提示词都按一次独立生成来写，不能依赖“沿用上文”或“参考前一个镜头”这类模型看不到的信息。

视频镜头总时长必须是确定值，例如 `9 秒`、`12 秒`、`15 秒`，不写 `10-12 秒` 这种模糊范围。

如果同一个未资产化人物连续出现在同一场景里，且总时长不超过 15 秒，优先合并成一条视频提示词，避免独立生成时人物变脸。

画面内容用 `[景别][运镜 / 转场]` 区分镜头，动作、表演、环境和声音都写进实际发生的镜头。需要跨视频衔接时，系统会继续锁定人物动作、道具状态、运动方向和声音，让上一条的结尾确实能接到下一条开头，而不是只写一句“无缝转场”。

项目内置了按需调用的创作 Reference，覆盖文戏对白、动作打斗、产品广告、MV / 概念 PV、MG 动态图形、纸艺拼贴科普、视觉奇观、POV 纪实、提示词压缩和速度节奏。它们提供的是创作方法和失败修复，不会替当前作品决定题材和内容。

### 5. 控制表演、动作、速度和声音

遇到复杂表演，系统不会停在“悲伤地说”或“愤怒地大喊”，而是从人物此刻想争取什么开始，继续明确：

- 哪句台词、哪个重词、动作或声音触发表情变化。
- 眼神、眉眼、嘴唇、下巴、呼吸、手指、重心和关系距离如何变化。
- 哪些反应不能提前出现，台词结束后留下什么静止状态。
- 必要时用少量 FACS / AU 辅助校准，但不把动作单元当作情绪公式。

动作和动态图形则控制蓄势、启动、加速、接触、余波与停点，并区分人物速度、摄影机速度、切镜速度、信息速度和声音速度。存在音乐时，动作完成点、转场、图形变化和镜头段落会与强拍、乐句边界、长音或休止建立关系，避免画面与音乐各走各的。

### 6. 为成片设计封面

封面属于作品完成后的发布流程，不是开拍前随手套一个模板。系统会读取最终视频提示词、成片截图和已确认资产，为当次内容重新设计一条可适配常用画幅的封面提示词：

- 标题原文使用中文双引号逐字锁定，默认直接生成文字。
- 人物、环境、光色、手势和装饰共同把第一视觉焦点送向标题。
- 参考图按人物身份、成片事实、构图或风格分别限定职责，避免一张图把无关背景和版式也锁死。
- 封面承诺必须能在正片中兑现，不能只追求点击而误导观众。

### 7. 复盘生成结果和发布反馈

系统会把真实结果回流成长期经验：

- 角色是否变脸。
- 动作是否乱。
- 表情是否失控。
- 风格是否跑偏。
- 镜头是否能剪。
- 提示词是否独立完整。
- 封面、标题、开头、完播和评论反馈是否达标。
- 成功或失败是否需要沉淀到共享资产或 Skill。

失败结果也会被保留下来。它能帮助系统判断问题究竟出在故事、资产、分镜、提示词，还是模型本身的能力边界。

## 核心流程

默认采用分阶段生产和内部质量门：

```text
灵感输入
→ 故事确认
→ 剧本
→ 视觉资产与图片提示词
→ 分镜表
→ 首个分镜提示词试跑
→ 完整视频提示词
→ 老胡生成素材并完成剪辑
→ 封面与发布内容
→ 归档复盘
→ 经验沉淀
```

每个阶段都会留下文件并经过内部检查。已经确定的内容不会在后面被随意改掉；普通的创作细节由对应模块主动补全。只有遇到互相冲突的核心方向、高成本生成、真实发布或法律安全风险时，系统才会停下来请你决定。

这样既不会在故事还没想清楚时就急着写提示词，也不会每碰到一个小细节都反复提问。剧本、资产、分镜、视频提示词、剪辑和封面之间会形成一条可以检查的完整链路。

### 作品隐私

公开仓库只保留 `01_作品项目/进行中/`、`已完成/`、`已发布/` 三个空目录骨架。通过脚本创建的具体作品、原始需求、剧本、图片资产提示词、分镜、视频提示词、生成结果、封面和复盘都只保存在本地，并由 `.gitignore` 自动排除；更新 GitHub 时不会上传个人作品内容。

从作品中验证出的通用方法，可以在去除作品名、人物名、台词组合和私有素材后，沉淀进 `02_共享资产库/` 或 `skills/`。这样 GitHub 公开的是可复用的创作系统，而不是老胡本人的作品库。

## 把你的经验继续补进系统

这个项目不会在第一次使用时就完全适合所有人。真正有价值的是，你可以把自己的作品结果和判断继续补进来。

你可以把这些材料丢进项目：

- 自己认可的剧本、分镜、提示词和视频结果。
- 你喜欢的电影、短剧、广告、MV 或账号案例。
- 优秀 AI 视频提示词拆解。
- 某次 AI 图片或视频生成失败的截图、视频和原因。
- 发布标题、封面、评论、收藏、转发和完播反馈。
- 你对某个镜头、某条提示词、某个资产判断的肯定或否定。
- 你自己的口头创作经验。

AI Agent 会按下面的顺序处理这些材料：

```text
原始材料归档
→ 判断材料类型
→ 提炼它对剧本、视觉资产、分镜、视频提示词、生成复盘哪一环有用
→ 判断是当前作品经验还是跨作品规则
→ 更新作品复盘或共享资产
→ 必要时更新对应 `laohu_` Skill
→ 在输入输出索引记录
```

你可以这样对 Agent 说：

```text
这是我认可的一段视频提示词。先不要照抄，请分析它具体解决了什么问题，哪些方法可以迁移到其他作品。
如果确实是长期有效的方法，再更新对应的共享资产或 Skill。
```

也可以这样说：

```text
这是一次生成失败的结果。请先判断问题出在故事、资产一致性、分镜、提示词，还是模型能力。
如果同类问题以后还会出现，再把修复方法写回项目。
```

## 快速开始

### 1. 获取项目

你可以只安装 Agent Skills，也可以把完整项目拉到本地使用。

方式 A：只安装 Skills。

```bash
npx skills add LaohuAD/laohu-ai-visual
```

只想安装某一个 Skill：

```bash
npx skills add LaohuAD/laohu-ai-visual --skill laohu_ai_visual
```

这会把 `skills/*/SKILL.md` 安装到当前 Agent 的 Skills 目录。适合已经有自己项目，只想复用部分视觉创作能力的人。

`npx skills add` 主要安装 Skill 本体，不会带走完整的作品目录、共享资产库、模板和检查脚本。想使用整套系统，请选择下面的方式 B 或 C。

方式 B：克隆完整项目。

```bash
git clone https://github.com/LaohuAD/laohu-ai-visual.git
cd laohu-ai-visual
```

方式 C：用 `npx degit` 拉一份干净模板。

```bash
npx degit LaohuAD/laohu-ai-visual my-ai-visual-system
cd my-ai-visual-system
```

如果你想保留 `00_输入原料/`、`01_作品项目/`、`02_共享资产库/`、`skills/` 这整套目录结构，推荐用方式 B 或 C。

### 2. 检查项目结构

```bash
bash skills/laohu_ai_visual/scripts/check_laohu_skills.sh
```

如果输出：

```text
Contract check passed.
```

说明核心目录、规则文件和脚本都在。

```bash
bash skills/laohu_ai_visual/scripts/create_work_project.sh "我的视觉作品"
```

也可以指定日期：

### 4. 和 AI Agent 对话创作

在支持项目上下文和本地文件读写的 AI Agent 里打开本项目，然后直接输入你的灵感。

例如：

```text
我想做一条横屏仙界短片。开场是一位年轻仙人面对镜头说：“大人，请登仙界！”
后面切成第一人称视角，带观众穿过仙门，看到云海、神兽和不同层次的仙界奇观。场面要大，但也要有能看清人物和细节的近景。
```

系统会先判断这条短片需要补故事、人物、资产还是镜头设计，再进入视频提示词，不会一上来就堆一长串画面形容词。

## 推荐使用方式

### 新作品创作

```text
我想做一个 AI 视觉短片，灵感是：……
```

系统应该先进入故事确认或剧本阶段。

### 已有剧本转视频

```text
这是我已经写好的剧本。请先判断哪些人物、场景和道具需要做成视觉资产，再拆成分镜。
每个阶段都保存结果，遇到会改变故事或增加生成成本的选择时再问我。
```

### 生成结果复盘

```text
这是我生成的视频，我不满意的地方是：……
请先判断问题出在剧本、资产、分镜、提示词还是模型本身，再给我修改方案。确定会反复出现的问题，再沉淀回项目。
```

### 吸收创作经验

```text
下面是我认可的一些创作经验。请先理解它们分别解决了什么问题，不要直接照搬原句。
能跨作品复用的部分，再整理到对应的规则或 Reference 里。
```
