# 老胡 AI 视觉

用 AI 做短片、广告或 MV，生成画面只是其中一步。故事怎么讲、人物和场景怎样保持一致、镜头之间如何接起来，都需要有人把事情想清楚。

老胡 AI 视觉是一套给 Agent 使用的视觉创作规则和工作方法。你可以带着一句想法、一个故事，或一首已经完成的歌进来，逐步整理出剧本、角色与场景设定、分镜、声音方案和视频提示词，再交给生成工具与剪辑软件制作。

项目当前主要交付文本方案，不直接调用外部生成 API。它的作用是帮你在生成之前想清楚要做什么，并在看到结果之后判断哪里需要修改。更完整的能力和使用方式见下文。

[快速开始](#快速开始) · [项目能力](#它能帮你做什么) · [创作流程](#一部作品怎样完成) · [项目结构](#项目结构) · [授权](#授权)

> 想看看 AI 影视、音乐和工具怎样用在实际作品里？[来老胡的个人主页](https://lao-hu.com)，看教程、找工具，也可以了解[老胡画梦枋](https://lao-hu.com/#community)。

## 适合谁

- 想用 AI 做短片、短剧、概念片、MV 画面、封面或视觉演示的人。
- 不想每次从零开始写提示词，希望把人物、场景和画面方法留下来复用的人。
- 需要把故事、剧本、视觉资产、分镜、视频提示词和成片放在一条链上检查的人。
- 愿意根据生成结果复盘，而不是把所有问题都归咎于模型的人。

如果你只想临时生成一张图片，这个项目可能显得太重。它的价值在于一部作品要反复修改、跨镜头保持一致，或者以后还要继续做同类作品。

## 它能帮你做什么

### 先把用户想做的，变成观众真正会经历的

面向公开观众或跨多个专业节点的作品，先由总导演分清请求者、导演、演员与最终观众，确定全片只争什么、靠什么推进、观看过程为什么有趣，以及各部门谁承重、谁托住、谁退让。总导演只形成一份导演阐述，不另写一份导演版剧本。

编剧仍是编导型编剧：它听得懂导演对观众、表演、镜头和节奏的要求，再把这些要求变成人物选择、场面、台词、空间和镜头化正式剧本。其他节点也能按需咨询相邻专业，但调用不会转移主责。

### 从灵感找到可拍、可生成的故事

输入可以很简单：一句灵感、一段口述、一个人物关系，甚至只是一个画面。

系统会先判断这条想法真正要让观众看到什么，哪些人物关系和事实不能改，适合做成短视频、短片还是系列内容，以及当前最需要解决的是故事、资产连续性、镜头衔接还是发布入口。现有方法不适合某个作品时，会指出能力缺口，不会为了套用旧模板把作品改成另一种东西。

### 记录生活素材，并在写剧本时调用

当你明确说“记录灵感、保存素材”时，系统会完整保留原话，再把其中彼此独立的人性机制、行为细节、冲突用途和适用边界拆成故事原子。普通分享和讨论不会被擅自长期保存，私有原话也不会进入公开仓库。

正式写剧本时先读素材库概况，再搜索压缩索引，只对真正入围的候选读取原话和详细边界。匹配不足时先逐次放宽表面条件，再寻找跨领域但机制相同的类比；所有候选都不如原创方案时允许零采用。只有内部材料确实不足才形成网络候选报告，未经创作者确认，外部案例不能进入剧本或长期素材库。

### 写故事、剧本和单场次

项目可以继续完成世界观、人物关系、正式剧本、单场次剧本和镜头任务。

写对白时，重点不是把人物说的话变得“像台词”，而是检查每句话背后的目的：人物想得到什么，害怕失去什么，这句话说完以后关系发生了什么变化。动作、道具和人物位置也会记录前后状态，减少镜头之间的断裂。

### 把一首歌发展成可制作的 MV

输入可以是最终音频、锁定歌词、人工 LRC / SRT / DAW 标记、ASR 对齐候选、歌曲创作背景和音乐风格说明。系统先区分哪些是事实、哪些只是创作参考，再从叙事、表演、概念和氛围四类视觉引擎里选择一个主引擎，建立导演命题、情绪运动和声画关系。

最终音频负责真实总时长、段落边界、能量变化和同步事件；歌词负责锁定文字；ASR 只提供对齐候选。没有最终音频时仍可做概念方案，但不会伪造精确时间码。歌曲的创作段落与后续生成单元分开：前者决定意义和情绪，后者才按当次模型能力拆分。每个单元再按需要选择单帧、首尾帧或多关键状态的图片任务，并输出图片提示词任务和视频导演卡；项目当前只交付文本，不调用外部生成 API。

### 规划视觉资产

不是画面里出现过的所有东西都值得建档。需要跨镜头、跨场次保持一致的角色、场景、道具、材质、色彩或风格，才会进入资产表；只出现一次的元素留在当前镜头里，避免把项目变成一堆没人会维护的资料。

资产可以是具体图片，也可以是人物设定、服装体系、建筑语法、色彩材质和世界观规则等文字资产。后续提示词会引用这些资产，减少人物变脸、空间漂移和风格跑偏。

### 拆分镜并写视频提示词

剧本确认以后，系统会把镜头任务拆出来，再为每个镜头写一条可以独立提交给模型的视频提示词。正式提示词使用：

```text
【基础设定】
【氛围与画质】
【画面内容】
```

每条提示词都写清楚人物、动作、环境、声音、镜头和时长，不依赖模型看不到的“沿用上文”。跨镜头需要衔接时，还会检查人物动作、道具状态、运动方向和声音是否真的接得上。

项目里的参考资料覆盖对白、动作、产品广告、MV、动态图形、纸艺科普、视觉奇观、POV 纪实、速度节奏和提示词修复。它们提供解决问题的方法，不替作品决定题材和审美。

### 处理表演、动作和声音

复杂表演不会只写“悲伤地说”或“愤怒地大喊”，而是从人物的目的出发，说明哪句台词或哪个动作触发表情变化，眼神、呼吸、手指、重心和距离怎样变化，以及台词结束后留下什么状态。

动作和动态图形会区分蓄势、启动、接触、余波和停点，并检查人物速度、摄影机速度、剪辑速度、信息速度和声音速度是不是在服务同一件事。

声音现在有独立的设计入口。它可以把“一位中年教师，声音低沉、有磁性”这类想法，展开成一段连贯、可直接给语音模型使用的自然语言音色描述。给了情绪就写它如何改变重音、语速、呼吸和停顿；没给情绪就保持人物的中性常态，不擅自加戏。它也能建立旁白、对白、环境声、动作声和音乐生成任务，并为不同模型保留可追溯的适配与听试状态。

### 做封面和复盘

封面放在作品完成后的发布阶段处理。它要服务作品真正的记忆点，标题、人物、手势、光色和留白共同把视线送到入口，不靠一个漂亮但和正片无关的模板骗点击。

生成以后，可以把截图、视频、失败结果、剪辑问题、封面数据和观众反馈放回项目。系统会继续判断问题来自故事、资产、分镜、提示词还是模型边界，只有能跨作品复用的经验才进入共享规则。

## 一部作品怎样完成

```text
灵感、故事或歌曲材料
→ 公开作品由总导演确认观众经历、主胜负手与部门取舍
→ 叙事作品由编导型编剧确认故事与剧本；歌曲型作品确认 MV 导演命题与歌曲—视觉结构
→ 需要时先完成作品级美术风格设计
→ 再完成人物、服装、场景与布景设计
→ 视觉资产、音频与音色设计
→ 图片提示词与可生成音频任务
→ 影视分镜表或 MV 制作时间线与动态分镜任务
→ 首个镜头试跑
→ 完整视频提示词
→ 生成素材与剪辑
→ 封面和发布内容
→ 复盘与经验沉淀
```

每个阶段都有自己的产物和检查。项目采用“顺序生产、网状会商、按根因返工”：已经确认的内容不会在后面被随意改掉；当前负责人可以按需咨询相邻能力，但不会因此把责任变成共同负责。只有会改变作品方向、明显增加生成成本、涉及真实发布或存在法律风险的选择，才会停下来交给创作者决定。

## 快速开始

### 获取完整项目

```bash
git clone https://github.com/LaohuAD/laohu-ai-visual.git
cd laohu-ai-visual
```

也可以只安装 Skill：

```bash
npx skills add LaohuAD/laohu-ai-visual
```

只想安装项目入口：

```bash
npx skills add LaohuAD/laohu-ai-visual --skill laohu-ai-visual
```

完整项目适合想使用目录、共享资产和检查脚本的人；只装 Skill 适合已经有自己工作区，只想借用某项能力的人。

### 检查项目

```bash
bash skills/laohu-ai-visual/scripts/check_laohu_skills.sh
```

### 创建作品目录

```bash
bash skills/laohu-ai-visual/scripts/create_work_project.sh "我的视觉作品"
```

然后在能读取项目文件的 AI Agent 中打开仓库，直接输入灵感即可：

```text
我想做一条视觉短片，灵感是：……
先帮我判断故事和人物关系，再决定要不要进入剧本和分镜。
```

已有剧本或生成结果，也可以直接交给系统：

```text
这是我的剧本。请先判断哪些人物、场景和道具需要做成资产，再拆分镜。
```

```text
这是生成的视频，我不满意的是：……
请先判断问题出在故事、资产、分镜、提示词还是模型本身。
```

## 这些项目怎样配合

我做自媒体时，要找选题、写文章、做图片、剪视频，有时还要写歌、做 MV。下面这些项目分别帮我处理其中的一部分，也都在跟着我的实际创作继续修改。

| 项目 | 可以用它做什么 | 在我的创作里负责什么 |
| --- | --- | --- |
| [老胡的审美起源](https://github.com/LaohuAD/laohu-taste-genesis) | 把自己判断作品好坏的方法、修改意见和经验整理成 Agent 能调用的规则与 Skill | 给其他创作项目建立和改进专业能力，让反馈不只停在一次聊天里 |
| [老胡 AI 视觉](https://github.com/LaohuAD/laohu-ai-visual) | 推敲故事、写剧本、设计角色与场景，再拆分镜、写视频提示词 | 处理影视短片、MV 和其他视觉内容的创作方案；当前主要交付文本，不直接替你生成整部影片 |
| [老胡音乐 V4](https://github.com/LaohuAD/laohu-music) | 从歌曲想法开始，讨论歌词、曲式、演唱与声音方案，再做歌名、封面和发布准备 | 处理歌曲创作，也给 MV 提供歌词、音乐方向和创作背景 |
| [老胡无限画布](https://github.com/LaohuAD/laohu-Infinite-Canvas) | 在本地画布中连接素材、模型调用和生成结果，保存参数与工作流 | 承接图片、视频、音乐等生成任务；基于 Infinite-Canvas 继续开发 |
| [CapMotion](https://github.com/LaohuAD/laohu-CapMotion) | 在 Cap 产品基础上继续开发录屏、口播剪辑、字幕和讲解动画工作流 | 把教学录屏和讲解素材整理成视频；涉及桌面编译和环境配置，先看本项目的开发说明 |

比如做一支歌曲 MV，可以先在音乐项目里打磨歌词和声音方向，再用 AI 视觉整理故事与镜头，最后在无限画布里调用模型、保存素材。做软件教程时，CapMotion 则更相关。它们之间可以传递方案和素材，但还不是安装一次就能全自动跑完的产品。

你只需要挑眼下能帮上忙的项目，不必一次把它们全部装好。

## 我是老胡，喜欢玩 AI，也喜欢讲故事

我是**老胡用AI画梦**。看到有意思的 AI 工具，我总想上手玩一下：写文章、做图、写歌、做视频，都想试试。玩得挺杂，但现在花时间最多的，还是 AI 影视创作、讲故事，以及一个人怎么把自媒体做起来。

我自己就要经历找选题、写稿、做素材、剪辑和发布这些事。哪些环节可以让 AI 帮忙，哪些地方还得自己想、自己改，我会边做边琢磨。这些开源项目和教程，就是在这个过程中一点点做出来的。如果你也在独立做内容，希望里面有些东西能帮你省下重复劳动，多留点时间给真正想做的作品。

### 经常跑模型，想把试错成本降下来？

做图、做视频时，往往要试好几轮才有满意的结果。我自己也在用和维护[老胡的模型小屋](https://api.lao-hu.com)，希望把模型调用的成本降下来，让同一份创作预算能多试几种想法。

如果你正在找价格更合适的模型接口，可以先看看站内的模型和当前价格，再用一个小任务比较效果、速度和费用，合适再继续用。模型调用按站内说明收费，开源项目本身和接口消费是两回事。

**[查看模型与价格 →](https://api.lao-hu.com)**

### 加入老胡画梦枋，成为造梦师

一个人做内容，有时最难的不是再找一个工具，而是不知道自己卡在哪：想法该怎么往下做，画面哪里不对，流程为什么接不上。

**老胡画梦枋**是我组织的付费 AI 创作交流社群，在这里，我们把一起玩 AI、做作品的伙伴叫作“造梦师”。我会在里面分享创作案例、值得关注的新东西和自己的尝试，也会亲自参与答疑。你可以带着作品、尝试过程和具体问题来，和一群同样在玩 AI 的人一起讨论。

如果你想持续做作品，希望有个地方交流、提问、看看别人在怎么做，欢迎先来[主页了解老胡画梦枋](https://lao-hu.com/#community)。入群方式和当前费用在主页了解，不用急着决定，先看公开内容是否对你有帮助。

我也希望通过内容、合作和社群获得收入，支持自己继续研究 AI。能一边做喜欢的事，一边和志同道合的人互相帮助，是我想把这件事长期做下去的方式。

**[了解老胡画梦枋，找老胡聊聊 →](https://lao-hu.com/#community)**
