# 音频提示词编译：专业方法与案例

## 当前专业决策

文本规整将数字/缩写转为可读形式；发音词典约束名字/多音字；适配层把抽象声音控制映射为当次接口。若把标签写进不识别标签的引擎，可能被读出或忽略。

保留锁定原文→生成有映射的规整文本→发音词典→合并身份与当场演法→核验接口支持→记录不支持项/降级→输出文本任务或实物状态。适合TTS、音效、音乐生成任务；反例是为适应时长删台词、跨模型照搬标签、未听试标记已通过。

### 同一材料候选比较

候选A：同一“2026年”及人名：跨模型照贴不支持的phoneme标签。

候选B：保留原文映射，年份规整为二〇二六年；核验引擎词典，不支持时使用已验证备用读法。

取舍：后者区分词义与接口，不让标签被读出或将未支持控制伪报为精确。

适用与反例：不为时长删词；没有真实文件/听试只标文本合同通过，不报已生成。

### 编译或返修结果示例

“锁定原文含‘2026年’，规整文本标为‘二〇二六年’，保留对应关系；指定人名目标读音。平台若不支持phoneme，则采用其已验证词典或人可读替代，不自称已精确控制。”

### 返回合同

返回锁定/规整映射、词典、抽象控制、接口证据、降级与生成记录；指出本次改变哪个决定、原有哪项事实不能动、从哪个状态开始以及下一负责人如何验收。输入缺口影响因果时停止专业深化，带证据返回；不把下游修词当作上游事实已存在。

## 完整专业方法

### 抽象合同到提供商的无损映射

每条生成请求保持四份对应：锁定原文、规整朗读文本、抽象表演/声场意图、当次接口内容。原文不能被标签和发音替代写法覆盖；规整只解决读法，若改变意思就不是规整。人名、多音字、单位、年份、缩写分别明确目标读法，记录只影响哪种语言或哪一角色。

逐项核验接口是否支持：声音身份参考、表演指令、停顿、发音词典、时长、循环、声道、输出格式及异步方式；只有需要项才查，不因官方API有一个字段就塞满。平台不支持词级停顿时，不能把毫秒标签当已锁定；可返回范围型表演要求、分句生成或待人工编辑方案，但任何分句必须保意群与冻结文本。

声音合成输出不等于音频资产已验收。先核对文本/发音，再听身份与表演，再确认文件异常及可编辑性。模型随机性与版本变化意味着相同参数不保证完全复现，记录条件是追溯，不是承诺。音效、音乐的结构控制若接口只支持整体提示，则标方向性引导，不把文本计划冒充可精确执行的多段时间轴。


## 4. 比较候选，再编译模型任务

语音在生成前完成`语音文本规整`、`发音字典`、多音字 / 名字 / 数字 / 缩写校正、重音与停顿标记。先保留人可读的原文与抽象控制，再根据当次接口映射为指令、SSML、音频参考或原生参数；平台不支持的字段要明确降级，不伪装成已精确控制。


## 六、生成与验收

先建立平台无关合同，再选当次提供商。需求是“文本生音效”时，接口至少要核实提示词、时长、循环、输出格式和异步任务方式；需求是音乐时，还要核实段落结构、时长、器乐 / 人声、参考音频、版权、输出及局部重生成能力。

听试不只问“好不好听”：

- 声源和画面动作是否同因。
- 方向、距离、遮挡和空间尺度是否一致。
- 关键信息是否在可读窗口到达，没有被对白、音乐或其他声音遮蔽。
- 起声、峰值、余震和衰减是否符合事件相位。
- 循环点、入出点、动态余量和文件规格是否能进入真实剪辑。


## 四、语音文本规整与发音字典

保留三份内容：

1. `锁定原文`：与剧本或歌词权威一致。
2. `可读规整文本`：数字、缩写、符号、单位和异形词改为当次模型能稳定读对的形式，但不改语义。
3. `发音字典`：人名、地名、品牌、方言词、多音字和术语的目标读法、人可读备用形式与适用语言。

抽象控制优先使用“在这个词前留出辨认窗口”、“本句只在尾部加速”等相对关系。只有对齐、时长或口型确实承重时才加数字窗口。SSML 可表达停顿、重音、韵律、发音和文本解释，但不同引擎实现子集不同；先保留抽象意图，再生成当次平台的标记。


## 研究依据与验证边界

W3C SSML定义文本解释、发音、停顿、重音和韵律等标记；具体引擎只支持其子集。[SSML 1.1](https://www.w3.org/TR/speech-synthesis/)。标准不是每个生成模型的共同接口。

本页的项目编译链与原创例子是本地方法设计；专业资料不证明生成模型一定遵从，也不证明观众效果已经发生。平台控制每次实际执行前重新核验。
