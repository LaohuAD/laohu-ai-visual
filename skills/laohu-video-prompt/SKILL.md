# 视频提示词核心

## 能力定位

把单场次剧本、分镜、故事板和已确认资产编译成完整可复制的视频提示词。这个 Skill 不替代编剧、分镜或视觉资产阶段，也不是把形容词拼成长文；它负责把已经成立的镜头构思压缩成模型可执行的时间因果、摄影机路径、屏幕变化、声音变化和结束状态。

视频美学的根本不是单帧漂亮，而是关系在时间里有秩序地变化。每条提示词先建立时间关系链：`起点状态 → 触发事件 → 动作路径 → 表演变化 → 镜头路径 → 光影变化 → 声音进入和退出 → 峰值停点 → 尾帧接续`。任何句子都要改变其中至少一项，否则删除。

用于模型测评、教程和公开发布时默认使用原创虚构内容。品牌只继承 `老胡 / laohu / 老胡用AI赚钱` 及其授权行业变体；需要固定 Logo 时调用 `【Logo参考@老胡Logo】`，不重画、不改字形、不改比例。

## 输入权威与按需资料

启动时先读取当前作品的项目总览、已确认剧本、分镜、资产总表、已有生成结果和相邻单元交接合同。项目顶层规则由运行环境继承，不为显得完整而重复加载全部长文档。

只有出现对应判断缺口时才读取项目级资料：阶段职责或规则冲突读取 `02_共享资产库/00_核心规则手册.md`；导演链路和文戏、武戏、画面、剪辑之间的责任不清时读取 `02_共享资产库/05_工具流程/导演级影视创作总控流程.md`；需要核对正式三段字段时读取 `02_共享资产库/01_模板库/视频模板/模板_视频提示词_基础设定氛围画面内容.md`；需要追溯研究依据或提出新能力时读取 `02_共享资产库/02_视觉语言资产/高质量创作特征资产库/高质量AI视频提示词开发计划.md`。当用户明确指出参考视频 / 关键帧未经后期调色却已经成立，或要求原生直出、直出质感、生成阶段完成光色时，必须读取该计划的 `6.5 原生直出影像链`，并在三段式中落实光源、曝光、材质反射、背景分离和运动连续性。

具体题材继续只按下方 Reference 路由读取，不把全部专业文件同时加载。

## 能力加厚纪律

### 先有镜头，再写提示词

视频提示词不能承担第一次发明镜头的职责。若上游只有“人物悲伤”“女侠御敌”“展示产品高级感”等概念，没有决定性瞬间、动作几何、摄影机观看位置、可见证据和结束状态，退回分镜层生成 3-5 个镜头构思候选。只有胜出镜头进入编译。

综合测试题、固定台词清单、故事梗概都不是剧本。叙事内容没有最小单场次剧本、明确说话权、动作状态和情绪节拍时，先交给 `laohu-script-writer`；不得直接用提示词补剧情。

### 从观众结果反推信息密度

内部先写本镜五个判断：

1. 主注意力目标：观众第一眼看哪里。
2. 主观看任务：观众等待什么变化或结果。
3. 主情绪目标：观众经历什么，不只是认出什么。
4. 决定性证据：哪一个动作、接触、反应、声音或环境结果证明本镜成立。
5. 停点：素材在哪一帧最值得保留或剪切。

观众看懂情绪不等于观众经历情绪。代入还需要目标与代价、危险方向、关系距离、受力触感、呼吸节奏和声场变化。构图、光影、时间、姿态、场景都只服务主情绪：加强则保留，削弱则删除。

观众认知状态只做内部分析，只编译成可见、可听、可定位的证据。正式正文不得写“观众暂时相信”“观众正在问”“观众预测”。

### 视频画面内容四核

每个镜头先完成 `视频画面内容四核`：

- 观看意图：摄影机此刻替观众盯住什么。
- 摄影机物理路径：机身或镜头真实怎样移动。
- 屏幕变化：主体尺寸、角度、遮挡、焦点、方向和相对位置怎样变化。
- 情绪倾向与停点：为什么这样运动，最后停在哪里。

专业运镜术语必须先区分物理机制：`Dolly / Track` 是机身整体移动，`Pan / Tilt` 是机位原地转动；希区柯克变焦是机身向前推进同时光学变焦拉远，或反向执行。不能只堆术语，不写屏幕结果。

摄影路径与正式画面分层处理：内部可以写“机身沿右前方弧线靠近”，正文还要写主体从侧轮廓转成近正面、背景视差向左滑开、手中物进入前景等屏幕可观察性检查结果。

### 承重字段选择

摄影、构图、光影、色彩、景深、材质和环境是开放控制杆，不要求每镜全部出现：

- 构图承担主情绪或信息引导时才展开；不要求每镜点名专业术语，失衡可以为压迫服务。
- 光影承担主情绪、主体塑形或动作可读性时才展开；不强制主光、辅光、轮廓光全部出现，单一硬光也可以成立。
- 色彩承担主情绪、身份识别或连续性时才展开；不是每镜都需要完整色彩体系，单色、近无色或自然综合色都可成立。
- 景深与空间层次承担主情绪、空间因果或注意力控制时才展开；深景深、平面化和无前景也可以是有意选择，不强制前中后景齐全。
- 氛围环境元素只有在加强主情绪、空间真实或动作反馈时才写；雾、尘、雨、粒子不是质量标配，没有来源或不承担情绪就删除。
- 主体细节承担身份、状态、动作因果或主情绪时，从颜色、材质、纹理、反光、破损、湿度、瑕疵和边缘状态中选择必要证据，不要求组成完整细节束。
- 使用动态光源时必须写出来源、运动原因和它扫过哪个对象；焦段、景深只在承重时展开，不固定为某组参数。

- 当光源本身是镜头事件，或光的传播路径决定画面质感时，读取 `02_共享资产库/02_视觉语言资产/画面风格库/画面氛围与画质规范.md` 的“光照事件链与传播路径”。正式正文按 `光源 → 路径 / 介质 → 光的变化 → 落点材质 → 镜头结果` 线性描述；动态光再写进入、移动、峰值、离开和恢复基线。审稿时反向检查结果是否可见，不能只写“光线很美”、只罗列光源，或让标签层单独承担关键光影结果。

承担视觉记忆的镜头需要审美停点 / 情绪停点；功能型插入镜头不强制壁纸帧。只选择能承重的要素，避免每镜都成为姿态海报。

四类控制杆是构图与空间、光影与色彩、时间与运动、主体与环境反应；不把它们当四项必填。通用 AI 视频分层只作为开放问题库，不逐层检查齐全。

透视和视觉重心承重时，明确灭点在画内还是画外、导引线把视线送到哪里；用色彩透视让远处降低饱和与对比，用影调透视让前后层次分离。若平面化更符合设计目标，可以主动取消纵深，而不是机械补前中后景。

高张力短视频优先判断是否使用特写进：`局部证据特写 → 反应 / 决定性动作 → 空间揭示`。特写进不是固定模板；只有局部证据能制造问题、全景会提前泄底时才使用。

已有色卡时在基础设定调用 `【@C1 色卡名】`。场景段写主色彩锚定，连续画面段落逐镜写颜色映射：整体光线、主角服装、肤色、发色、场景结构、关键道具、氛围与过渡分别使用什么颜色；切换到新空间时重新校准，不只写“调用色卡”。

电影镜头判断合同在三段正文之外完成：先由关系压力决定观看位置，再设计视线流量；每镜通常只保留一个主要构图决定、一个主故事线索和按需一个辅助线索。多镜头正文定稿后执行顺序打乱测试，若打乱后意义不变，说明镜头没有持续更新观众状态。

### 场景关系与物理因果

复杂画面先在内部建立场景关系图：出场人物、出场物品、人物和物品、物品和物品、人物和人物之间是什么关系。交互必须写清交互方式、接触点、作用力大小轻重、受力方向和可见结果；光线必须写清光源位置、光线方向和照射对象。

动作链必须闭合为 `准备 → 发力 → 接触 → 冲击结果 → 连锁反应 → 回收 / 永久终态`。歧义动作必须写清工具、接触方式和顺序；“加一点、取一点、放进去、抹上去”必须落到具体器具、材料和接触部位。

工具劳动动作明确 `工作面 → 工具 → 材料 → 受力 → 收尾位置`。例如劈柴要写木料立在木墩、斧刃进入木纹、木块分裂或斧刃卡住，不能只写“用力劈柴”。

### 画面内容的镜头化叙事门

`【画面内容】` 不是作者对镜头的说明，也不是小说式名词堆叠，而是按观众接收顺序组织的可见事件链。每个镜头块必须先写画面中看见谁、什么物体、位于哪里、处于什么状态，再按媒介选择实体摄影机、虚拟摄影机、二维视窗、版式焦点或固定构图；主体变化必须符合当前主导机制并写出屏幕结果；VFX 与声音必须由画内事件产生；最后写停点或下一镜继承状态。动作片需要接触、方向和受力，文戏需要触发、反应和关系变化，广告需要产品参与和卖点证据，MG 需要映射规则与信息结论，不能强制共用动作句法。

景别或信息尺度是证据边界：真人和三维空间中，特写负责局部，近景 / 中近景负责表情和上半身关系，中景负责身体动作和移动证据，较宽画面负责空间关系；二维动画、MG、UI 和字幕动效中，总览负责整体结构，分组焦点负责比较或顺序，单点细节负责数字、标签和局部变化。一个尺度不能凭空承担另一尺度才能看见的信息；跨尺度必须写清切近、拉远、视窗缩放、图层前后移、遮罩展开、版式重排或焦点迁移。人物移动必须有地面、背景反向位移、视差、衣料 / 尘土反馈或其他空间证据。观察路径不得只写术语，至少说明起点、路径、方向、速度变化、屏幕变化和停点。

高风险解释句（例如“第一帧已经发生动作”“让观众理解”“这里揭示身份”“不出现第二次拔刀”）不得进入模型正文。它们要么删掉，要么改成目标画面或动作完成后的正面状态。读者可以从画面因果中理解“完成亮相”，模型不需要作者解释。

首次产出就必须通过这道门，不能把景别混用、镜头跳接、动作断因和特效无来源留给 `laohu-vibe-creating-prompt` 第二轮补救。需要详细理论、失败案例和跨题材迁移时读取 `references/10_画面内容镜头叙事语法.md`；正文只保留真正改变像素、运动、声音、情绪或剪辑接口的句子。

### 正文主轨与声画补充轨

`【画面内容】`中的正文是事件主轨，`【VFX】`、`【环境音】`、`【动作音】`和`【音乐 / 节拍】`是紧跟镜头的补充轨。正文必须先写清事件何时发生、由什么触发、画面或声音发生什么变化；补充轨再写该事件的材质、方向、声场、强弱、相位、衰减和节拍细节。标签不能成为关键动作、特效或声音的唯一来源。

正式编译优先给承重事件建立 ID，例如 `【VFX-A1】`、`【动作音-A1】`、`【环境音-B1】`、`【音乐-B1】`，并把同一 ID 放进正文触发句和后面的补充标签。每个标签必须通过 `存在性绑定 / 时序绑定 / 属性绑定`：正文存在同名触发；标签不把结果提前或改成另一个事件；标签补充的参数不改变主体、位置、运动方向、颜色母题和结束状态。没有正文触发点的孤儿标签删除；正文里出现但没有必要补充的事件不机械加标签。

这套分层是为了让作者和剪辑者容易阅读、修改和逐项回查，不是为了假设视频模型一定理解标签层级。模型正文仍要保留关键的画面因果和音乐同步关系；删除标签后，事件仍应能被模型大致生成，删除正文触发句后，标签不能独立救回该事件。正文负责“发生什么”，标签负责“如何校准”。

复杂镜头先在正文外建立最小声画事件账本：事件 ID、画面触发、可见结果、声音结果、音乐关系和下一状态。正文内还要检查声源视角是否匹配摄影机距离、接触音是否落在真实接触点、预置声和声音桥是否有来源、静音抽掉了什么并在何处恢复，以及对白 / 决定性接触音 / 环境警报 / 音乐谁拥有本镜最高声音优先级。一个镜头通常只保留一至两个主声画事件。

### 资产与独立生成

每条正式视频提示词必须按独立生成请求处理，不能写“沿用全片设定”。`【基础设定】` 只调用老胡实际上传或绑定的资产，例如 `【@A1 人物】`、`【@S1 场景】`、`【@C1 色卡名】`。图片资产引用是模型召回指令，不是给作者看的备注；本镜未实际使用的资产不得引用。

资产行还必须经过本镜实际使用检查。固定身份不等于服装也必须继承：变身前丝袜不能泄漏到变身后铠甲；人物资产里的场景配件不能被机械继承，某镜不背书包就不能因形象图有书包而继续出现。图片参考与当前状态冲突时，当前剧情状态优先，并明确只锁脸、体型或结构。

图生视频与文生视频使用不同描述预算：图生视频不重复资产已锁定的静态外观，把篇幅留给变化、交互和镜头；文生视频必须补齐未资产化元素。提示词资产主要进入 `【基础设定】` 和 `【场景状态与氛围画质】`；图片资产 / 固定资产在 `【画面内容】` 只写本镜状态与交互；未资产化元素才详细描述。

严格占位格式使用 `【@资产名】`、`【素体参考@B01 人物素体形象资产】`、`【服装参考@W01 人物服装资产】`、`【妆造参考@M01 人物妆造设计资产】`、`【音色参考@xx】`、`【视频参考@VID-A尾部连续性片段】`。三类人物参考要分别说明职责，不在每条视频提示词里重复长篇身份、服装和妆造描写。

### 连续性与剪辑接口

所有相邻镜头、相邻 `VID` 和上下集执行相邻单元交接合同：`A 结束状态 = B 开始状态`。状态至少覆盖人物姿态与屏幕侧、物品位置与持有者、服装妆发、光源方向、背景锚点、声音余韵和动作相位。B 只能从 A 的下一相位开始，不能重演 A 已完成动作。

若 A 尾与 B 头依靠同一物体、图形、遮挡面、光斑、文字、服装局部、声音或动作形状转场，先建立 `交接载体视觉指纹`：规范名称、几何轮廓与内部结构、画面位置与占比、颜色层级、材质与表面纹理、受光与反射、运动方向 / 速度 / 相位、VFX 阶段、遮挡边界、同步声音和稳定把手。A 最后一段与 B 第一段必须分别完整复述同一份指纹，不能用 `保持上一段、同一个、继续该图形` 代替，也不能只详写一侧。B 从共同状态之后只新增第一项明确变化。双端镜像详述属于跨独立生成的必要重复，不在零废话压缩中删除。

生成 A 后执行二次绑定：读取 A 真实尾部，决定继续使用图片参考、`【首帧参考@VID-A尾帧】`，还是实际生成后再选 `【视频参考@VID-A尾部连续性片段】`。同一景别、构图、光源方向、人物姿态、表情余韵和背景锚点需要继承时用自然镜头语言写清，不写“第0秒”。状态等式检查失败时禁止生成 B；不能假定提示词里的计划尾帧就是实际尾帧。

跨 `VID` 连续性参考只继承世界状态和必要运动趋势，不把 A 的完整剧情动作再次播放。世界状态默认硬继承，镜头语言和节奏可按 B 的任务变化。

首尾帧双端锚定模式先写：必须保持什么、必须改变什么、共同桥梁是什么、最大断裂点在哪里。变化过程按起点脱离、主变化、接近终点、尾帧召回与减速收束编译，不能只描述首尾两张图。

剪辑接口编译在提示词外建立素材剪辑接口卡：入口锚点、出口锚点、主要匹配属性、声音桥、可裁切区和不建议裁切区。转场写法用画面行为表达：遮挡转场、明暗转场、运动转场、匹配转场都要写前一动作怎样铺满画面、下一状态怎样从同一锚点接出。

### 声音与表演来源

声音内容不自动等于音频参考资产。普通 BGM、环境音、动作音和随机声场直接写正文；只有固定歌曲、指定声纹、现成对白口型或必须准确复现的节奏才调用音频参考。

台词、旁白、画外音和脑内 VO 按承重程度选择声音参数：音高 / 音区、响度 / 音量、语速 / 节奏、停顿 / 气口、重音位置、气息状态、咬字 / 吐字、距离感、混响和衰减。关键发声镜头即使有音色资产，也要重申本镜声线例外；例如短视频开场钩子可写冷感磁性女中音、近麦干声，不甜、不夹、不软。

视频提示词不得擅自改剧本台词。台词原文、旁白原文、VO 原文、字幕原文一经确认，不能改句子、删关键词或加新句。剧本中的语气 / 神态必须编译为眼神、眉头、嘴角、呼吸、姿态和表情占用时长；表情来源记录为 `laohu-video-prompt / 画面内容短句 / 无`。

### 命名与正向收束

命名检查先区分具体人物、群体类别和物种：`大人` 不能在一处指主角、另一处泛指成人；`群仙` 是群体画面元素；`神兽` 必须确定为白鹿、云龙或青鸾等可见物种。一个对象全片使用一个确定称呼。

正式视频提示词代码块里禁止写作者意图，例如“让观众懂”“表现孩子不冷漠”“避免误读”“模型不知道上下文”。全部改成屏幕证据。正向收束优先写目标画面；排除句只用于文字水印、比例畸形、动作僵硬等抽象质量边界，具体风险放代码块外。

### 首稿零废话编译门

`laohu-video-prompt` 的第一次正式产出必须已经是可直接生成的高质量稿，不是交给 VC 收拾的粗稿。镜头格式、模型路由、字符上限、资产引用、镜头边界、逐镜声画归属、首尾状态和相邻交接全部在首稿交给 `laohu-vibe-creating-prompt` 之前完成；任何一项不合格都留在本 Skill 内重写，不能把基本错误转嫁给第二轮。

首稿采用“先建结果骨架，再生成句子”的顺序：

```text
观众承诺与唯一主情绪
→ 决定性画面 / 声音结果
→ 为产生该结果必需的起点、触发、动作、摄影机、VFX、声音和停点
→ 三段式与逐镜编译
→ 最低充分信息审稿
→ 字符、连续性和格式机械校验
→ 才交给 VC 做效果增益
```

每个准备写入正文的短语必须先回答它改变什么：`身份稳定 / 屏幕对象 / 动作相位 / 摄影机观看 / 光色材质 / VFX物理结果 / 声音时点 / 情绪证据 / 转场接口 / 结束状态`。没有明确归属的短语不生成。已经由全局段、资产或本镜上一句完整表达的事实不换词重复；一个事实只放在一个最能发挥作用的位置。

首稿逐句执行反事实删除测试：删除这句话后，模型生成的像素、声音、节奏、身份、物理、情绪或剪辑接口是否会发生可感知变化？不会变化就删除；只是在解释为什么这样写、概括已经出现的效果、重复情绪结论或证明字段完整，也删除。详细不等于平均填满字段；只有本镜真实承重的 VFX、环境音、动作音、音乐 / 节拍和台词才出现。

首稿字符上限是设计输入，不是写完后的补救。模型未明确时从第一句就按 `≤4000` 分配信息；Seedance 2.5 明确时按 `≤5000`。正文接近上限时优先保住决定性瞬间、动作与镜头因果、情绪证据、声音推动和转场接口，删除同义形容词、重复外观、字段解释和不改变结果的装饰。不能先写超限长稿，再把压缩动作伪装成第二次质量提升。

## 能力边界

- 剧本、对白和因果未确认：交给 `laohu-script-writer`。
- 人物、场景、道具或色卡需要先稳定：交给 `laohu-visual-assets`。
- 首稿通过零废话编译门后必须调用 `laohu-vibe-creating-prompt` 做效果增益；VC 重点提升首秒冲击、作品身份、角色魅力、情绪峰值、决定性画面、声音推动和转场惊喜，不承担首稿格式、限字和明显重复清理。优化后重新落回 `【基础设定】【场景状态与氛围画质】【画面内容】` 三块。
- 生成结果验收、模型失败归因和二次绑定：交给 `laohu-generation-review`。
- 不直接生成图片、视频或音频，除非老胡明确要求调用生成工具。

## 输入判断

最低输入包括：已确认剧本或非叙事镜头任务、确定模型与时长、实际目标画幅、生成方式、实际可绑定资产、上一单元结束状态、下一单元剪辑需求。实际目标画幅用于内部构图和平台参数，默认按 `16:9`；可复制模型正文只写主体占比、留白、裁切、运动路径和文字安全区等可见结果，不写比例数字、横屏、竖屏、横版或竖版。用户指定其他比例时重新设计构图，不能只替换数字；只有用户明确要求正文写比例或平台没有独立比例设置时例外。信息缺失但可由专业判断补齐时直接补齐；会改变剧情、版权、成本或发布风险时再确认。

默认路线单条 `4-15 秒`。Seedance 2.5 明确支持时可做 30 秒长时路线，但先检查后半段指令遗忘、身份漂移和动作稀释；不能把 30 秒长时能力错误继承给其他模型。

生成前明确检查：默认路线是否在 4-15 秒内；只有明确选择 Seedance 2.5 时才启用 30 秒；发现长时能力错误继承立即退回模型路由重算。

不预设镜头数量。15 秒使用少量镜头或约 10 个镜头都可能正确；连续跟拍 / 少量长镜头、高强度多切或混合结构由结果决定。高频动作覆盖不是快闪蒙太奇，每个切换必须带来新的攻击几何、证据、关系或尺度。

## 分镜宏观表

正式提示词前可在文件中保留提示词外的宏观表：`VID / 对应剧本 / 确定时长 / 主任务 / 主情绪 / 资产 / 入口状态 / 出口状态 / 剪辑接口`。每个完整动作单元可以由一个镜头完成，也可以由多个镜头完成；不得为了填镜头数拆碎动作。

镜头预演板与视频提示词同源但服务对象不同：预演板给图片模型和人工确认，视频提示词给视频模型。不强制生成预演板；简单连续镜头可只用干净首帧 / 构图图。一个 `VID` 若使用整张故事板，只生成一张故事板图片，并写 `【故事板参考@SB01 故事板图片】`；不能把板内每格改写成独立 `SB01-01` 图片引用。

## 输出结构

正式视频提示词必须严格按照 `模板_视频提示词_基础设定氛围画面内容.md`。代码块正文只允许 `【基础设定】`、`【场景状态与氛围画质】`、`【画面内容】` 三个一级区块；镜头编号、景别、机位、运镜 / 转场和逐镜声画字段属于 `【画面内容】` 的必要内部结构，不算新增一级区块。解释、验收和剪辑表仍放在代码块外：

```text
【基础设定】
总时长：15秒。生成方式：图生视频。实际绑定资产：【@A1 人物】【@S1 场景】。声音策略：只生成对白、同期动作音效和环境声，不生成 BGM。

【场景状态与氛围画质】
用 1-3 句写跨本条全部镜头成立的场景初始状态、主风格、摄影介质、宏观色彩、整体光源和空气状态。局部光影、特效、声音和材质变化放回对应镜头；删除某句后如果只影响一个镜头，它就不属于本段。

【画面内容】
【镜头01｜景别｜机位 / 视角｜运镜 / 转场】
镜头固定在或移动到具体空间位置，写主体动作、环境变化、镜头路径、屏幕结果和停点。画面内容必须达到执行稿详细度，不用概要替代动作因果。
【VFX】仅本镜实际发生的特效及其物理结果。
【环境音】声源、方向、距离与变化。
【动作音】接触、材料与余响。
【音乐 / 节拍】只有音乐承重时才写本镜进入、重拍或退出关系。
【台词】角色名（表演）：“已确认原文”。
```

每个新镜头必须以独立的中文方头 `【镜头01｜景别｜机位 / 视角｜运镜 / 转场】` 开始，并按实际顺序连续编号；编号用于让模型和剪辑者识别镜头边界，不等于逐秒时间码。总时长仍属于平台参数，正文默认不把每个普通镜头锁死到秒数。镜头边界必须同时由动作、遮挡、视线、焦点、声音、光色峰值或运动方向中的至少一项建立，不能只靠编号强行切开。

时间只能作为镜头详细内容中的按需相对约束。先用自然语言写清起点、路径、接触、受力、结果、摄影机和声音；当高速连锁、亚秒接触、延迟结果、极短反应窗口或停点可读时间无法靠“瞬间、紧接着、随后”稳定控制时，再加入少量 `顶镡到刃光切屏控制在0.2秒内`、`刀刃接触后0.1秒内出现裂缝`、`标题形成后稳定保持至少0.8秒`。每个复杂镜头通常只留 `1-3` 个决定结果的相对约束，超过后优先拆镜、删动作或加时长。默认禁止 `【本镜0.0-0.2秒】`、`【片内14.2-15.0秒】` 等绝对起止区间，使同一提示词能随总时长伸缩；只有绑定锁定音频、真实时间码或固定播出点时例外。不得用秒数替代动作因果，也不得把生成前时长约束当作真实剪辑时间码；真实入点、出点和把手由复盘模块逐帧回填。

VFX、环境音、动作音、音乐 / 节拍和台词必须逐镜归属，紧跟在产生它们的镜头描述之后；本镜没有的字段直接省略。禁止把所有特效和声音汇总到全段末尾，也禁止把镜头头部埋进连续散文，让模型猜测何时换景别、换机位或发生转场。

只要正文生成或调用音乐，先建 `音乐段落 → 主视觉事件 → 拍前蓄势 → 同步完成点 → 拍后余波 → 不同步边界` 合同，再写逐镜 `【音乐 / 节拍】`。每个主要视觉短语至少说明一次音乐怎样驱动动作接触、切镜、转场完成、VFX 峰值、构图锁定、标题形成、光色反转或摄影机冲量；不能只有开头和结尾卡点，中段画面自行漂移。强拍 / 乐句边界承载大变化，弱拍 / 细分拍承载连续小运动，长音承载持续变形，休止承载蓄力与停点。卡点以视觉事件完成态为准，不机械每拍切镜；抢拍、拖拍和切分必须写清重新合拍点。固定歌曲或精确节奏必须调用音频参考，纯文生音乐只锁结构与关系。没有音乐时不强制卡拍，动作音与环境音以材质、接触、空间、传播和衰减为先，可在不破坏真实的前提下形成强弱与疏密节奏。

速度承重时先做内部 `速度意图 → 主速度承载者与参照物 → 起点状态 → 蓄势 / 启动 / 加速 / 峰值 / 接触 / 余波 / 停点 → 摄影机与切镜响应 → 声音完成点` 编译，再把决定结果的部分写入对应镜头。速度不是一个“快 / 慢”形容词；人物、摄影机、切镜、VFX 和声音不能默认同时加速。先保住动作方向、接触和结果，再用快慢对比制造力度；具体规则按需读取 `09_速度节奏与时间动力设计.md`。

每个镜头头部只承担一个唯一主要情绪功能。运镜不套固定情绪词典，先回答摄影机站在谁的感知位置、靠近或远离改变了什么权力和身体感。

正式提示词本体单独放进 `text` 代码块，代码块里只放可直接投喂视频模型的正文；代码块外放镜头编号、资产说明、表演来源、剪辑接口、字符数和验收条件。视频提示词交付必须方便老胡直接复制。

长度硬上限：Seedance 2.0 单条不超过 `4000` 字符；Seedance 2.5 单条不超过 `5000` 字符；模型未明确或跨模型共用按 `4000` 字符。上限不是目标，简单镜头不凑字。

字符数是机械事实，不得目测、估算或沿用改稿前数字。每次首次产出、任何正文修改和 VC 优化后，都必须实际运行 `bash skills/laohu-video-prompt/scripts/count_video_prompt_chars.sh "提示词文件.md" --limit 4000`；Seedance 2.5 改为 `--limit 5000`，老胡指定 `7000` 或其他上限时传入对应数字。同一文件有多条正式提示词时，脚本逐条报告；需要核对指定条目时使用 `--block N`。只允许把脚本输出写成代码块外的 `字符实测：N / 上限（block=N，PASS / FAIL）`。脚本未运行、运行失败或正文在统计后又被修改时，只能标记 `字符数未验证`，禁止报告推测数字。

## 文件输出位置

正式创作按阶段维护：分镜表格输出文件、第一个分镜的视频提示词展示文件、所有分镜视频提示词结果输出文件。对话里不要贴长篇正文，只给阶段结论和具体结果文件链接。默认在同一个阶段文件上迭代更新，不自动新建 `v1/v2/v3`。

## 自检

初稿完成后先执行所选题材 Reference，再执行本节最低质量门；只有发现压缩、污染、重复、超限、字段错位或连续性账本失败时，才读取 `08_提示词压缩质检与失败修复.md` 修复后重新检查。

若已触发 `10_画面内容镜头叙事语法.md`，它必须在最低质量门之前执行；审稿不能只检查格式和废话，还要逐镜检查画面是否从可见事实开始、景别是否匹配证据、运镜是否造成屏幕变化、动作是否闭合因果、特效和声音是否有画内来源、转场是否有共同载体。

- 剧本、台词、核心词、道具状态和空间调度是否原样继承。
- 起点、触发、路径、接触、结果、停点和下一状态是否闭合。
- 每镜是否只有一个主观看任务和一个主情绪目标。
- 摄影机物理路径是否能产生正文所写的屏幕变化。
- 资产是否真实绑定，引用职责是否清楚，本镜未用资产是否删除。
- A 尾部与 B 开头是否通过状态等式检查；生成后是否完成二次绑定。
- 是否提供可裁切入口、出口、声音桥和不建议裁切区。
- 是否存在口水话、同义风格词、作者解释、重复外貌和泛化弱词。
- 当用户指出参考视频 / 关键帧未经后期调色却已经成立时，是否读取并执行 `6.5 原生直出影像链`：光源、曝光、肤质反射、背景分离和景深是否在首帧就成立，人物运动与摄影机运动中光色是否连续；是否没有把 `清透、治愈、电影感、直出` 当作完成条件。
- 口播 / 旁白任务是否按语义变化而非标点或固定秒数拆节拍；每段 B-roll 是否有唯一视觉职能、明确证据等级、完成点和退出接口，而不是关键词空镜或漂亮填充。
- 直接证据、可标注示意、代表性插图和纯氛围是否被正确区分；AI 生成实验室、股票界面、新闻画面、专家人物或虚构数据是否被误当成真实记录、研究结果或事实证明。
- A-roll 是否保住讲解者的立场、限定、反例、情绪与结论回收；B-roll、字幕、音乐和动作音是否服从口播可懂度，并通过声音连续或清洁落版进入下一节拍。
- 每个镜头是否直接从可见画面开始；是否存在景别职责混用、镜头路径与屏幕变化脱节、人物移动缺少空间参照、VFX / 声音无来源或用否定句召回具体对象。
- VFX、环境音、动作音和音乐 / 节拍是否在正文中都有触发事件；补充标签是否有对应 ID，是否存在孤儿标签、标签新增事件、标签改变时序或标签与正文重复到可以互相替换。
- 声源视角是否与摄影机距离一致；接触音、预置声、声音桥、静音和音乐完成点是否落在正确动作相位；是否有过多同权重声音争抢决定性事件。
- 有音乐时是否已建立全段音乐-画面节拍合同；每个主要视觉短语是否至少有一项动作、转场、图形、光色、文字或摄影机事件与音乐结构发生明确关系，而非只有局部碰巧卡点。
- 速度承重时是否读取 `09_速度节奏与时间动力设计.md`；是否区分动作、摄影机、切镜、信息和声音速度，并写清参照物、速度曲线、承重相位、结果与停点，而非全程只写快速、激烈或慢动作。
- 相对时长约束是否只出现在真正需要精密计时的复杂镜头；是否约束动作速度、触发后延迟或结果保持，而非把事件锁进绝对起止区间；删除秒数后是否仍保留完整动作因果。
- 是否在最终一次改稿后运行字符统计脚本，并以脚本实测结果确认符合当前 4000 / 5000 / 自定义字符硬上限；是否没有沿用旧数字或人工估算。

单点反馈必须触发全局扫描同类问题。老胡指出某一个镜头、台词、动作或资产错误时，默认把它视为通用失败模式，抽取剧本全部对白和全分镜视频提示词做同类扫描，不只修当前一句。
