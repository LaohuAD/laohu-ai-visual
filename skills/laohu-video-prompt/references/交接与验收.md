# 视频提示词：交接与验收合同

本文件只承接父级任务、权威边界、协作路由和最终验收。按具体缺口调用子能力，专业方法不在此重新展开。


## 导演协作接口

公开作品先继承`导演阐述`中的主观看任务、观众经历、视听主次、表演尺度和生成前复验项，再读取正式剧本与资产。本 Skill 可 `CONSULT` 总导演、编剧、资产、声音和目标模型 Reference，解决执行与可生成性；调用不转移主责。它不得补编上游没有确定的戏，也不得把本节点的“导演判断”扩张成重新决定全片目的。导演取舍缺失返回 `laohu-director`，剧情事实缺失返回编剧，摄影事实由视频专业形成，资产和声音缺失返回各自负责人。



## 输入与责任

本 Skill 在写正式模型正文时`CONSULT laohu-language-mode`进入`VIDEO_PROMPT`：把已成立镜头写成模型可执行的时间因果，不把导演解释、人物不可见心理、资产说明或作者辩解混进正文。调用不转移主责；时长、入口、批次、镜头语法、三段式、资产绑定与模型限制仍由本 Skill 裁决。语言层发现剧情、空间、动作资格、镜尾事实或锁定台词不足时，必须返回原负责人，不能自行补编。

启动时只读取当前作品真正相关的：项目总览、已确认剧本、`MV导演交接包`、分镜或镜头任务、资产总表、相邻单元交接合同、已有生成结果和目标模型。

最低输入：

```text
镜头为什么存在：主观看任务与主情绪。
分段继承合同：源E-S-P、剧本指纹与原文范围、冻结台词、讲戏节奏、估时范围、世界位置、起止状态、下段第一项变化、资产与音色引用、状态参考需求。
本段唯一主要兑现：最后哪个可见 / 可听结果必须成立。
可选次要兑现：最多一项，它怎样服务而不竞争主要兑现。
起点状态：开拍前人物、道具、空间、声音已经怎样。
触发事件：什么让状态开始改变。
确定时长与目标模型：
目标入口能力合同：具体平台 / 入口 / 版本 / 模式，以及已验证的时长、输入、长度和参数边界。
生成方式：文生 / 图生 / 首尾帧 / 视频参考。
实际可绑定资产：
真实参考图调用合同：每张实际图片的绝对路径、正式像素验收状态、入口模式、可见对象、固定与可动边界、禁止新生对象、首个变化和最终结果。
GEO 运行时切片：当前镜头真正需要的空间锚点、站位、轴线、路径、遮挡和可变状态。
激活参考职责：本次实际绑定的每份输入分别只负责什么，不负责什么。
作品结果图成像合同及本段阶段变体：
上一个单元的真实结束状态：
本单元结束后要交给谁：
```

剧情因果、说话权、人物选择、世界空间或行动结果不足RETURN编剧；P边界、时间和接续不足RETURN分段；基础身份/结构不足RETURN相关设计。摄影机、画框出入、构图与镜头切换属于本Skill，不退回编剧补摄影。

## 先接P，再编段内C

一P是一条生成请求；C是请求内部的摄影镜头。新提示词标题使用E01-S02-P03，正文从C01重新编号。批次E-S-P与VID仅用于历史读取，不默认合并P。先核对同一场次、原文顺序、时长含余量及入口限制，再检查同时维持的人物、空间、动作、特效和声音负荷；不适配则携原因RETURN分段，不删台词或强改演法。

摄影边界按连续观看确定：实际剪切建立新C，连续运镜、拉焦或揭示不机械拆镜。文戏与武戏均由注意、行动相位和表演决定镜数，不规定每秒切镜。每C写景别、机位/视轴、构图、运镜及可见行动；必要的VFX、台词和声音嵌在对应镜头，不设空栏目。详细方法见[镜头空间与连续性](镜头空间与连续性.md)。

段落可结束在明确的运动相位，不要求静止或完成小故事。正片不重演上段动作；为剪辑保留的重叠另标素材余量并计入生成时长。跨段台词指定完整音频归属与承接画面，不能重复合成同一句或让声音突断。跨场仍由两段各写一端，不将旧场空间带入新场。

## 状态参考与生成前提醒

逐卡检查结束状态是否被后续P使用，先选文字/成片取帧/预制状态图路径，再交付视频正文；判断依据为状态复杂度、复用范围、运动接续和实际入口，不是“发生变化就补图”。日常湿污、损坏、拆装先用基础资产＋状态差异；新基础结构缺失才返回设计。

- **文字即可**：在正文明确开始状态、变化和结束状态，引用基础资产，不要求额外图片。
- **成片取帧**：本段提示词上方先提醒“生成后保留接续参考”，说明对象、需要清楚的状态/姿态及后续使用P；本段生成后复盘验收，再登记真实帧/片段。不能生成前要求已有抽帧。
- **预制状态图**：本段提示词上方列“生成前准备状态参考”、基础资产、目标差异、用途、后续使用P、可单独用于图像制作的描述与待制作状态；由用户按需制作，未绑定不宣称就绪。

物品状态图只负责对象的确认状态；接续关键帧还负责人物持物、场景、姿势与动作相位。真实像素错误、遮挡或变形不得继承。预制图只是目标，成片必须达到可接续状态；不一致先修本段、重新选择合格参考或修订后段的合法入口，不硬接、不反改剧情。见[资产状态帧规则](../../laohu-visual-assets/references/状态帧与下游运动.md)。

提示词上方提醒固定写：生成前/生成后 → 对象与基础引用 → 目标状态 → 用途与使用P → 当前真实状态 → 用户需要做的一步。无额外素材需求就省略提醒；不让用户重复阅读长篇规则。操作提醒、来源、余量和后续关系留代码块外，模型正文仍自足地写当前状态及真实绑定，不写“同上一段”。

## Reference 路由

正式提示词必须留下内部 `Reference 调用回执`：本轮读取的文件、提取的机制、被它改变的导演 / 镜头决定、变化进入哪段提示词，以及为什么到这里可以停止。只写“已阅读”或摘抄摘要不算调用；无法定位到实际改变时，先修路由和中间结果，不能直接进入 VC。

先读取 `skills/laohu-video-prompt/references/交接与验收.md`，按观众承诺、主导机制、空间语法、时间语法、证据方式和媒介物理，判定 `完全适配 / 组合适配 / 能力缺口`。

- 完全适配：一个主要题材 Reference。
- 组合适配：一个主要题材 Reference，最多一个辅助 Reference。
- 能力缺口：建立当前作品机制卡，不为有文件可用而强套。

动态内容默认读取 `skills/laohu-video-prompt/skills/laohu-video-compilation/references/专业方法与案例.md` 完成跨媒介镜头编译。其余按主导机制选择：

任何将被交给模型产生视频结果的提示词都必须读取`02_共享资产库/05_工具流程/视觉生成模型注意力与提示词编译参考.md`，完整执行注意力合同、镜头可执行语言与时序分支。多主体、多参考、图生视频、复杂属性绑定、专有概念视觉翻译或空间与时间竞争只会增加需要绑定和仲裁的对象，不改变这项基础完成条件。图生视频由输入图负责主体、构图、色彩、光线和风格，正文优先写动作、环境运动、摄影机、方向、速度、触发和停点；只有引入新元素或改动起始图时才重述对应静态外观。

同一作品、同一连续阶段必须继承`laohu-art-direction`交付的`结果图成像合同`。视频Skill不凭“电影感、古偶唯美、港风”等短标签重新猜风格，也不临时改选导演、作品、介质或调色；它只把合同中当前镜头真正可见的成像基底、色彩肤色、主光影调、空间构图和表面光学编译进`【场景状态与氛围画质】`。剧情阶段、记录媒介、观看者或世界规则改变时，使用美术交接包已经定义的阶段变体和返回条件。

若美术交接还包含叙事灯光合同，静态部分只继承当前可见受光关系；动态部分必须进入`灯光变化事件`的起始光态、触发、传播过程和结束光态。参考帧只负责已确认的光影关系，不负责虚构实际灯位；同一光型随人物、空间、材料和摄影条件变化时，不沿用固定情绪结论。

`02_共享资产库/02_视觉语言资产/画面风格库/画面氛围与画质规范.md`由`laohu-art-direction`负责消化成作品合同，视频Skill不绕过合同重新组合风格母版。合同缺失、只剩短标签或当前阶段没有合法变体时，退回美术方向补齐；不能为了赶写视频直接从共享风格库另选一套画质。

凡人物表演承重，同时读取`02_共享资产库/02_视觉语言资产/人物表演库/人物表演提示词规范.md`；需要寻找可见的脸、目光、呼吸、身体、关系距离或声音候选时，按需读取同目录`人物表情与肢体动作词典.md`。八维在内部完整判断，把剧本已经锁定的情绪因果编译为`多通道异步变化`；正式正文只保留人物目的、精确触发、足以辨认本次变化的承重通道（单一通道可以成立）、禁止提前反应和结束状态。不得把词典整行投喂或让所有身体通道同时表演；上游情绪因果缺失时返回编剧，不在本层重写人物。

对白、同期声、动作接触声、空间声场、声音桥、画外触发或原生音频承担因果时，读取`02_共享资产库/02_视觉语言资产/声音与同期声库/声音提示词规范.md`。它只负责声源、方向、距离、材质、声画相位、混响、遮挡和衰减；不能用声音标签新增正文没有发生的事件，也不能让配乐、对白、环境声和动作声同时成为主注意力。

正式成稿使用`02_共享资产库/01_模板库/视频模板/模板_视频提示词_基础设定氛围画面内容.md`作为版式与交付表面，不把模板中的全部候选字段机械填满；本Skill与当前题材Reference决定内容，模板只承接三段、逐镜方头、补充声画轨和代码块外接口。镜头方案已经成立但缺少准确摄影词汇时，可以按需查询`02_共享资产库/02_视觉语言资产/镜头语言库/镜头语言词典.md`，只选择能改变观看位置、空间关系、注意力轨迹或停点的一项词汇，并把术语翻译成摄影机路径与屏幕结果。

共享库中的开发计划、历史编号规范、导演总控流程和生成后评分表不进入每条提示词的默认运行上下文：计划文件只保存建设历史；编号与状态规则由当前Skill和核心合约承接；导演总控由`laohu-ai-visual`路由；真实结果评分由`laohu-generation-review`负责。文件存在不等于全部读取，只有能改变本次决定且职责不冲突的知识才进入调用回执。

Reference 提供机制、不变量、可变槽、失败修复和迁移测试，不提供可复制的外部案例表面。人物、品牌、台词、镜头顺序和标志性特效必须重新设计。


## 三段式成稿

正式投喂代码块只有三个一级区块：

```text
【基础设定】
只写总时长、生成方式、实际绑定资产的职责和一句全条声音策略。未真实绑定的资产不能写成已存在；逐镜动作、剧情解释、场景光色和作者验收不进入本段。

【场景状态与氛围画质】
只写开拍前已经成立、且跨本条全部镜头有效的空间边界、人物与道具初始状态、主成像基底、宏观光色和空气关系。开拍后才发生的入场、落泪、破坏、天气变化和局部灯光变化进入对应镜头，不能提前写成初始状态。

【画面内容】
每个批次先写一至三句时间因果主线，只包含动机或初始压力、不可交换的触发和变化顺序、主要兑现、即时影响与余韵。简单事件可压缩成一句，但不得省略；它只写画内可见 / 可听事实，不写主题和作者解释。
【C01｜景别或景别演变｜机位 / 视角｜固定机位、连续摄影机路径或转场｜复杂镜头按需续写构图与节奏栏】
从可见画面开始，依次写触发、主体与环境变化、摄影机路径、屏幕结果、声画事件、停点和结束状态。
按需紧跟【VFX】【环境音】【动作音】【音乐 / 节拍】；台词直接嵌入当前镜头正文，并与说话者表演、听者反应和摄影机变化连续书写。
```

每个新镜头使用连续编号的中文方头。镜头边界由动作、遮挡、视线、焦点、声音、光色峰值或运动方向建立，不能只靠编号切开。

代码块外保留：

```text
观众问题—声画兑现：悬念、寻找、误判、揭示、倒计时或知识问题承重时填写；不承重时省略。
分段ID、剧本原文来源映射与段内C镜头任务：
实际绑定资产：
相邻批次交接：
素材剪辑接口卡：推荐入点 / 内部节点 / 出点 / 匹配属性 / 干净把手 / 不建议裁切点。
字符实测：
生成风险与回传字段：
```


## 硬规格

- 单条时长由剧情、表演、动作、对白、摄影机和停点反推；目标入口已经核验的可用时长仍是硬边界。启用长时路线时单独验收后半段遗忘与漂移。
- 正式编译前读取`02_共享资产库/03_模型适配/通用规范/多模型AI视频提示词通用规范.md`中的`目标入口能力合同`。平台名称、模型名称、网页 / 移动 / API、T2V / I2V / 首尾帧 / 多参考等模式不能互相代替证据。
- 只有官方文档、真实入口报错或可复现实测才能建立字符硬上限。未获得证据时标记`入口长度兼容性未验证`，字符脚本只报告实测长度，不按跨模型 4000 或默认 10000 裁切。
- 不设置机械最低字数，但必须通过“最低充分控制密度”语义门。字符数由有效控制信息自然产生，上限不是扩写目标；也不能把“不凑上限”偷换成提前停止，导致对白表演、空间调度、动作因果、声画来源或结束接口缺失。禁止为了接近上限增加同义反复、作者解释和低权重装饰。
- 画幅用于内部构图和平台参数；模型正文默认写主体占比、裁切、留白和运动路径，不机械重复比例数字。
- 台词、旁白、字幕和固定音乐原文一经确认，不擅改。

任何正文改动后重新实测字符。未知上限只统计：


## 底线门：首稿可执行

- 上游镜头是否已经成立，提示词没有承担第一次发明故事。
- 每镜是否只有一个主观看任务和一个主情绪。
- 期待承重时，是否继承观众问题—答案交接并完成声画兑现表；每次快慢、切角、遮挡和停点是否改变信息、风险、关系或判断，且内部作者解释没有进入模型代码块。
- 起点状态、触发、路径、屏幕变化、结果和结束状态是否闭合。
- 人物动机、台词、动作与道具选择是否共享同一条因果；表面矛盾是否有意且有可见证据，否则是否退回上游。
- 承重道具是否通过状态账本锁定起点、接触、承重、路径、落点、支撑和下一镜状态，没有悬空、瞬移、易手或数量漂移。
- 每个切点是否有剪辑承接合同；省略是否通过省略成立门，而不是靠“自然衔接”或观众替作者补因果。
- 两镜以上共同完成同一动作时，连续动作主线是否已经进入正式`【画面内容】`，并与逐镜状态逐项一致。
- 摄影机物理路径是否真的产生正文所写屏幕变化。
- 动作、表演、VFX 和声音是否有画内来源与正确时点。
- 冻结台词是否嵌入镜头正文，并同时写清开口前动作、说话对象、重音 / 气口 / 口型、说话中的身体变化、听者准确反应与说完后的停点；是否完全没有独立 `【台词】` 轨。
- 是否逐镜通过镜头原子检查：一镜一事、一个主要画面内容、一项主变化和一条连续摄影机路径；真实切镜是否已经新开编号；连续拉焦、揭示和反应是否仍保留连续镜头身份。
- 直接对镜时是否写清`镜头关系对象合同`；人物的称呼、礼貌程度、攻击性、眼线、距离和动作强度是否服从戏内对象，而非笼统服从公开观众；无害边界是否落在道具、接触、停手和结果上，而没有削弱冻结台词。
- 复杂单元是否通过最低充分控制密度检查；是否仍有承重人物、空间、表演、摄影机、环境或后半段状态需要模型猜测。
- 首稿无论采用完整母稿法还是关键场面→专业补全法，是否都完成同一导演母稿合同；是否因为“已经有镜头编号 / 台词 / 音效”而在强度仅1—2级时提前停止。
- 每个承重节拍的主要兑现、决定性视觉落点和结果停点是否达到3级主导；构图、焦点、光色、动作、声音或VFX是否以足够可辨认的证据证明主结果，单一机制可以成立，竞争信息是否退让。
- 所谓重点是否通过当前观众问题与信息增量证明；是否既没有在证据可读前抢答，也没有在预期和反应完成后继续拖成等待过期。
- 实际绑定资产是否真实存在，本镜未用资产是否删除。
- 图生、首尾帧和多参考任务是否已打开真实图片并完成真实参考图调用合同；路径、入口模式、真实可见对象、固定对象、可动对象、禁止新生对象、首个变化与最终结果是否齐全。
- 参考图是否通过语义一致性门；文件名与真实像素不一致、草图未验收或内部编号 / 临时占位泄漏时，是否已经拒绝绑定并返回视觉资产。
- A 与 B 状态是否相等，B 是否从下一相位开始。
- 代码块是否只有模型需要的内容，没有作者意图和后期解释。
- 承重句是否具备实际基准、变化维度、方向 / 幅度 / 路径和可见 / 可听终态；不可变项是否吞掉了可变项。
- 具体排除是否已经改写为正向唯一结果；真实时间状态是否被正确保留。
- 字符、格式、时长和命名是否通过机械检查。

首稿未通过，留在本 Skill 修复，不能交给 VC 收拾基础错误。


## VC 交接

VC 指外部 Skill `vibe-creating-prompt`，本项目只通过本地适配入口 `laohu-vibe-creating-prompt` 调用它，不直接调用外部原文。首稿合格后交给该适配入口：

```text
不可删不变量：
允许重排 / 压缩：
最值得增强的观众效果：
资产和相邻状态合同：
字符预算：
```

所有通过首稿门的视频提示词都必须交给 VC；不能因题材偏功能、原稿已经成熟、预计改动很小或时间紧而跳过。VC 可以在实际读取和判断后零改动放行，但必须留下调用记录与比较结论。

VC 完成后重新回到本 Skill，检查三段式、镜头编号、状态、接口和字符实测，再写入当前作品 `05_视频/文本/` 的阶段主文件。外部原文、便携副本或二者一致性失效时，保留已经通过首稿门的版本作为排障与恢复材料，同时标记“VC 链路失败”；未实际完成 VC 的稿件不得进入正式写入和付费生成。


## 巅峰门：正式提示词值得生成

底线门与 VC 都完成后，视频 Skill 仍对最终作品效果负责，不能只复查格式。正式写入前检查：

```text
主胜负手：本段最不可替代的情绪、关系、视觉、声音或卖点结果是什么。
候选比较：决定性瞬间、观看位置、构图、运镜、表演、声画和停点中，哪些方向被比较并淘汰。
序列推进：每个镜头 / 批次新增什么，换序或删除后是否明显失去力量。
导演连续性：人物目的怎样穿过镜头，道具状态怎样交接，省略怎样被观众无负担地重建；是否仍有逐镜成立、合看断裂之处。
峰值兑现：前面的蓄压是否在可见 / 可听结果中真正到顶，而不是靠形容词宣布高潮。
专业协同：构图、运镜、表演、动作、VFX、光色、音乐和环境声是否共同托住主胜负手；不承重的维度是否主动退让。
质量强度：主胜负手是否达到3级主导；不是统计规则有没有，而是判断它是否足够强、有效信息占比是否足够高、删掉任何承重句是否会明显削弱结果。
Reference 生效：调用回执能否指出机制改变了哪个决定并落到哪处成品。
VC 生效：有改动时为什么更强；零改动时为什么原稿已经优于可行改法。
已知上限：是否仍存在一个具体、可实施且预计明显更强的方案没有处理。
```

最后一项为是，返回对应的导演选择、镜头编译或 VC 环节继续改；不能以字符已满、三段齐全或时间已花费为理由停止。极致不要求每个维度最大：承重的是静止、留白、沉默或固定机位时，强行增加运动和特效反而判为降级。

同样是广告，可能靠产品证明、人物关系、速度对比或图形解释成立；同样是国风，可能是文戏、动作、奇观、文化事实或纯视觉节拍。Reference 按“作品为什么会有效”选择，不按名词和风格标签配对。

## 语义单元归并门

发现两个文件讲同一话题时，先比较的不是句子像不像，而是它们是否拥有同一个`触发条件 → 判断 → 行为 → 失败表现`。四项相同，视为重复语义单元并执行无损归并：

1. 选出与职责最接近、内容最完整且运行时可达的唯一负责人。
2. 逐条提取非负责人文件中的独有条件、反例、专业例外和下游字段，迁入负责人或保留为本地例外。
3. 非负责人文件删去重复解释，只留下何时调用、调用什么、返回什么以及指向负责人的路径。
4. 模板保留版式和插槽，词典保留候选词，案例保留证据；三者都不能反向升级为规则权威。
5. 删除前用行为场景证明：原本能触发的决定仍能触发，原本的失败分支仍能被拦住，下游仍知道读取谁。

以下情况不能合并：同一词在图片和视频中承担不同时间职责；共享基线与题材例外的触发条件不同；生成前规则与真实结果诊断使用不同证据；模板字段虽然同名但输出接口不同。简洁的目标是减少重复决策，不是减少有效信息。

## 内容指纹

路由前先生成六轴内容指纹：`观众承诺 / 主导机制 / 空间语法 / 时间语法 / 证据方式 / 媒介物理`。

- 观众承诺：观众看完必须相信、感到或记住什么。
- 主导机制：效果由表演触发、力量接触、产品证明、节拍同步、图形推导、世界变化还是摄影机在场产生。
- 空间语法：真实三维空间、扁平二维版面、浅层 2.5D、分层舞台、严格 POV 或不断重组的图形空间。
- 时间语法：连续动作、触发后渐变、节拍事件、停格组装、状态机、拆解重组或快速标题序列。
- 证据方式：人物反应、接触结果、产品输出、数据关系、环境尺度、图形形变、文字 / UI 或声音连续。
- 媒介物理：真人摄影、赛璐璐、纸片、三维材质、动态图形、界面元素或多媒介混合怎样限制运动。

`skills/laohu-video-prompt/skills/laohu-video-compilation/references/专业方法与案例.md` 是跨媒介的通用编译层。凡是需要镜头运动、主体动作、画面转化、VFX、声音、音乐卡点、卖点证明、表演转折或跨镜衔接的动态内容，默认使用它；静态单对象展示可以省略。它不决定主导机制，只负责把主导机制翻译成 `当前画面 → 摄影机路径 → 触发变化 → 可见 / 可听证据 → 停点 / 下一状态`。

选择主导机制时执行跨媒介适配：文戏优先检查人物目的、触发台词、反应和关系状态；动作优先检查蓄势、位移、接触和受力结果；广告优先检查用户问题、产品参与、卖点证据和利益兑现；动画 / PV / MV 优先检查轮廓、色彩、运动向量、视觉母题和音乐完成点；MG / 科普优先检查数据或对象的图形映射、变形规则和结论停点；特效奇观优先检查来源、传播、尺度、材质反馈和残局；POV / 纪实优先检查视点、路线、声源和现场反馈。这个适配层不创建新的题材分类，也不要求把所有专业词汇写进正文。


## 三类判定

1. `完全适配`：一个现有 reference 的机制与不变量覆盖主导机制，风格差异只需写进可变槽。
2. `组合适配`：一个主要 reference 覆盖主导机制，最多一个辅助 reference 只补声音、字效、局部特效、表演、速度节奏或剪辑接口。
3. `能力缺口`：现有 reference 只能覆盖局部，或套用后会把作品改成另一种空间、时间、证据或媒介逻辑。

禁止把局部覆盖提升为主要 reference，也禁止用两个辅助 reference 拼出虚假的主路由。没有匹配时不读取题材 reference，先写当前作品一次性机制卡。


## 缺口提案

能力缺口提案固定说明：内容主机制；最接近的现有 reference 能覆盖什么、缺什么；不新增时如何用一次性机制卡完成当前作品；建议的新 reference 名称、适用范围、核心不变量、与旧分类的边界、预计复用场景和维护成本。建议的新 reference 永久创建前必须得到老胡确认。

仅视觉风格变化不创建新分类；只有机制、空间语法、时间语法、证据方式或媒介物理形成可复用的新规律，才提出升格。

新分类名称必须使用稳定的观众任务和主导机制，不能使用单个案例的角色、颜色、题材、道具、软件或特效皮肤命名。提案先通过跨样本抽象测试：把人物换成物件或符号、把色板换掉、把游戏换成 MV / 文化 / 时尚主题后，核心状态机是否仍成立；再通过邻近边界测试：知识解释、产品证明、连续叙事或真实动作为什么不能被这个新分类误吸收。若第二、第三个同类案例暴露更高层共性，优先升级已有 reference 的内部机制分支，不为每种视觉锚点另建小类。


## 当前能力导航

先问“这一段最需要观众相信什么”，再检查是否存在主要 reference：

1. 相信人物此刻真的被某句话击中：`laohu-performance`。
2. 相信力量、速度、接触和结果真的发生：`laohu-action-design`。
3. 相信产品解决问题并值得行动：`laohu-video-compilation`。
4. 相信音乐 / 声音、表演、视觉母题、文字和版面重排共同建立作品身份：`laohu-motion-design`。
5. 相信抽象知识由可见图形机制推导出来：`laohu-motion-design`。
6. 相信抽象知识由纸片物件、层级和组装顺序变成可触摸模型：`laohu-motion-design`。
7. 相信知识口播中的事实、机制、反差和结论被恰当的辅助画面证明，而且讲解者没有被辅助画面抢走：`laohu-audiovisual`。
8. 相信不可能变化有阶段、有尺度、有不可逆结果：`laohu-vfx`。
9. 相信摄影机真实在场、路线连续、互动未摆拍：`laohu-camera-movement`。

`laohu-audiovisual` 解决的是口播语义与证据编排，不负责固定画风。先把口播拆成命题、对象、机制、证据、反差和结论，再为每个节拍确定 `视觉职能 → 证据等级 → 进入 / 完成 / 退出 → A-roll / 声音接口`；随后只按主要证据职能选择最多一个实现层：数据与机制用 `laohu-motion-design`，纸质隐喻与组装用 `laohu-motion-design`，真实现场与人物操作用 `laohu-camera-movement`，标题 / 音乐排版用 `laohu-motion-design`。不能把所有 B-roll 都路由成 MG、多图蒙太奇或纸艺，也不能用两个局部视觉模块拼成虚假的完整适配。

速度与节奏执行横向判定：如果作品成败取决于谁在快、如何加减速、哪里蓄势与制动、动作和摄影机怎样错速、快切如何保持可读、跨镜运动怎样接相位，或文戏反应窗口怎样变化，主 reference 仍按上面八类选择，并把 `skills/laohu-video-prompt/skills/laohu-video-compilation/references/专业方法与案例.md` 作为唯一辅助 reference。普通走路、单一推镜和不承重的背景运动不读取 `laohu-video-compilation`；不能因为题材是动作片或音乐存在就自动加载。

画面文字组织执行另一条独立的编译判定：如果正文出现作者解释、景别混用、镜头路径与屏幕变化脱节、人物移动缺少空间参照、VFX 没有来源、转场没有共同载体或句子像名词清单，读取 `skills/laohu-video-prompt/skills/laohu-video-compilation/references/专业方法与案例.md`。它是跨题材的表达与镜头叙事层，不是新的题材主类，也不替代主要 reference；它不占用题材辅助名额。触发后必须先修复“可见画面 → 镜头路径 → 动作因果 → 屏幕结果 → 声音 / VFX 来源 → 停点 / 交接”，再进行压缩、风格增强或速度优化。

当用户要求电影感、电影正片感、导演 / 摄影参考、宽银幕叙事，或结果像海报、CG、游戏截图、滤镜套图时，在上述编译层中启用 `skills/laohu-video-prompt/skills/laohu-video-compilation/references/专业方法与案例.md` 的“电影视觉母体转译”分支。它负责提取观众承诺、摄影机权限、空间压力、视线流量、光色来源、成像基底和时间证据的不变量，再把人物、地点、色板、媒介和动作作为可变槽；它不是独立题材 Reference，不强制 21:9、三联拼接、胶片颗粒或某位导演风格。删除“电影感”一词后，如果提示词仍保留机位、空间、事件、光色来源、成像限制和停点，才算完成转译。

混合任务按节拍拆，不按题材标签全加载。例如女武神“变身后战斗”：变身段主用 `laohu-vfx`，交手段主用 `laohu-action-design`；产品 PV 含三维机械剖面：全片主用 `laohu-video-compilation`，机制解释节拍辅用 `laohu-motion-design`；知识博主讲财经趋势：全片先用 `laohu-audiovisual` 确定哪些话需要事实图表、哪些只需情境插图，再按主要证据职能辅用 `laohu-motion-design`，不能因为画面里有人和图表就同时加载 `07 / 05 / 04`。
