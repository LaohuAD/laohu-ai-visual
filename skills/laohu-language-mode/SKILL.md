# 老胡语言模式与身份切换

> 话有对象，文有身份。身份一换，写法就得换。

本 Skill 是跨专业共享的语言路由。领域 Skill 先决定事实、剧情、设计与执行要求，本 Skill 再决定当前文本块用什么语言把它交给眼前的接收者。它不拥有内容权，不新增生产阶段，也不作为文字总监监督或代写其他专业。

## 什么时候调用

出现以下任一情况时调用：

- 专业角色正在与老胡讨论、解释、建议、汇报或交接。
- 同一份剧本包含镜头方头、`△` 动作、表演括号、人物台词或剧本说明。
- 同一事实需要分别进入资产规格、图片提示词、视频提示词或声音提示词。
- 文本虽然信息正确，却出现教材腔、作者腹语、模型说明口吻或体裁串门。
- 文本看似完整，却出现长短失衡、同义堆叠、知识尾巴、无后果台词或无法改变声画结果的控制项。
- 返工一个文本块时，需要保护已确认台词、镜号、事实与专业约束。

纯路径、编号、格式转换和脚本检查等机械输出不需要为展示本能力而扩写。

## 权力边界

- 总导演拥有作品意图与跨部门取舍。
- 编剧拥有人物、因果、镜头事件、动作与台词内容。
- 资产、图片、视频和声音 Skill 拥有各自的设计与模型执行规则。
- 本 Skill 只拥有模式判定、文本块分权、共享中文法度和模式污染修复。

语言模式可以改变语序、详略、句法、标注与对接方式，不能改变事实、故事、人物关系、镜号、锁定台词、资产锚点和模型硬约束。不因顺口改动锁定台词。内容不足时停止润色，返回内容负责人。

## 运行链

```text
领域负责人先确定内容事实与保护项
→ 判定角色、阶段、文本块、发声者、接收者和任务
→ 选定唯一主语言模式
→ 只读取该模式所需 Reference 与专业桥接
→ 领域负责人完成该文本块
→ 先过必要信息保护门，再过边际作用门
→ 逐分句执行 KEEP / MERGE / MOVE / DELETE / RETURN
→ 文本块改变时重新判定
→ 内容缺失或冲突时返回内容负责人
```

模式不接管主责。当前编剧调用 `CHARACTER_DIALOGUE` 后仍由编剧写台词；视频负责人调用 `VIDEO_PROMPT` 后仍由视频 Skill 编译时序。

## 模式与声音不能混为一谈

语言模式决定文本体裁怎样工作；人物声音与场景状态决定这个人此刻怎样说。最终表达由下面五项共同形成：

```text
专业内容 × 语言模式 × 发声身份 × 当前场景状态 × 接收对象合同
```

Luna 装淑女、压着火或彻底释放小恶魔本性，仍属于 `CHARACTER_DIALOGUE`；变化的是人物声音和情绪状态，不是语言模式。知识教学、爱情、治愈与惊悚也不自动产生新模式，题材只改变材料、尺度与节奏。

## 处理模式污染

1. 标出当前块真正的接收者和任务。
2. 把动作、心理、声音、台词、说明或模型指令拆回各自文本块。
3. 只重写被污染的块，其他已确认内容保持原样。
4. 内容事实不够时写明缺口并返回原负责人；不能自行补技能、补剧情或补设计。
5. 重写后检查同一事实是否保真，以及下一位接收者是否可以直接使用。

## 整稿覆盖门

用户指向“整份”“各个位置”“类似问题”或同一种污染已经跨块出现时，不得只修改最显眼的一类。先列出文件中已出现的每种文本块，再逐类判定是`KEEP / MERGE / MOVE / DELETE / RETURN`。剧本整稿返工至少覆盖实际存在的镜头方头、动作、表演括注、人物台词、剧本注释和生产说明。

不能只改台词，就默认动作、括注和说明已经通过；也不能因某类文本应原样保留，就略过判定。完成时留下简短的块级处理回执：哪些类别改了、哪些类别保留、保留的理由是什么。回执用于防止漏审，不进入正文。

## 完成门

一次语言模式调用只有同时满足以下条件才完成：

- 当前块只有一个主要接收者和一个主要任务。
- 写法与接收者一致，事实和专业权力没有漂移。
- 作者解释、人物原话、制作说明与模型指令没有互相冒名。
- 文本块改变时已经重新判定，没有沿用上一块的语气惯性。
- 必要信息保护门已经确认知识、因果、空间、身份、锁定内容与执行约束没有因压缩而丢失。
- 边际作用门已经确认每个保留分句都会新增事实、关系、行动、理解、感受或可执行控制；零边际内容已经合并、迁移、删除或返回原负责人。
- 整稿任务已通过整稿覆盖门，已出现的每种文本块都有块级处理回执。
- 使用 Reference 后，内部能指出它确认或改变了哪一个具体表达决定；只记录“已读取”不算激活。

结构或格式可以机械验证；自然、像人、像角色和模型是否更好执行仍需行为样例与真实结果验证。
