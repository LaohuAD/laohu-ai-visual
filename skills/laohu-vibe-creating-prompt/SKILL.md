# 老胡视频提示词提纯

## 提纯箴言

提纯不是添光，是让最该发亮的地方亮起来。

VC 不是首稿清洁器，也不是把语言改得更顺。每一条已经可直接生成的提示词都必须经过它：能增强就增强，原稿已经最好就零改动返回。可以不改字，不能不调用。

## 身份与来源

本 Skill 是外部 Skill `vibe-creating-prompt` 进入老胡 AI 视觉后的本地适配层，不是该外部能力的原创原文，也不是可以脱离来源自行改写的方法替身。VC 是 Vibe Creating 的项目简称。

| 角色 | 路径 | 职责 |
|---|---|---|
| 仓库内外部原文 | `02_共享资产库/05_工具流程/外部优化Skill/vibe-creating-prompt/SKILL.md` | 保留外部方法原貌，不参与本地规则改写 |
| 独立 Skill 便携副本 | `references/01_外部Vibe_Creating原文.md` | 供本 Skill 单独安装时读取，必须与仓库内外部原文逐字一致 |
| 本地适配层 | 当前 `SKILL.md` | 决定何时调用、何时拒收、哪些硬接口不能改变以及怎样回填 |
| 最终返回负责人 | `laohu-video-prompt` | 复验三段式、镜头、状态、接口和字符，决定结果能否进入正式作品 |

外部原作者和公开来源地址没有保存在当前仓库历史中，暂记来源信息缺失，不得猜测或补写。完整依赖身份与更新方式见 `../../02_共享资产库/05_工具流程/外部能力依赖清单.md`。

调用方只调用本地适配层，不直接调用外部原文。仓库内外部原文、便携副本或二者一致性失效时，停止 VC，保留已经通过基线的原稿作为排障与恢复材料并交回 `laohu-video-prompt`，明确标记“VC 链路失败”；不得凭印象模拟外部能力，也不得把基线稿冒充已经完成 VC 的正式稿。

## 输入基线

只接收已经通过 `laohu-video-prompt` 首稿门的三段式正文。开始前检查：

```text
三个一级区块完整。
镜头中文方头连续编号。
景别、机位、转场和逐镜声画归属清楚。
起点、屏幕变化、结束状态与相邻单元可接。
资产引用真实且职责明确。
字符实测已经通过当前模型上限。
没有明显作者解释、字段污染和同义重复。
```

任一项失败，退回 `laohu-video-prompt`。VC 不用“提纯”掩盖剧本、资产、分镜、格式和生成基线问题。

## 增益边界

### 不能改变

- 确定总时长、模型路由与字符上限。
- `【基础设定】【场景状态与氛围画质】【画面内容】` 三段结构。
- 已确认台词、旁白、字幕、音乐和关键声音原文。
- 人物关系、剧情结果、资产身份、空间事实和相邻状态。
- 摄影机物理路径、屏幕变化、动作相位、接触、受力、声音时点和结束状态。
- 镜头编号、逐镜 VFX / 环境音 / 动作音 / 音乐 / 台词归属。
- 素材剪辑接口卡的入点、节点、出点、匹配属性、干净把手和禁切区。

合同本身矛盾时回到最早上游，不能靠润色把冲突藏起来。

### 可以增强

每次只选择最有价值的一到两个维度：

```text
第一秒更快建立问题、危险、欲望或视觉冲击。
角色第一眼更有身份、魅力或威胁。
决定性瞬间更清楚、更意外、更有尺度。
情绪触发与保护层破裂更可感。
镜头速度和停顿形成起伏，不再全程同速。
VFX 更服从动作来源、传播和环境结果。
声音更早预示、更准完成或更有余波。
相邻镜头的动作、形状、视点、遮挡、光色或声音连接更有记忆。
尾帧从“任务结束”变成可记住的作品画面。
```

新增一句必须能指出新增了什么观众可感知的屏幕或声音结果。只能说“更顺、更高级、更有电影感”，不算增益。

### 保留作品身份

主视觉、核心意象、开场、情绪主句和声音状态先做反平均检查。准确的关系压力、动作停点、光影来源和留白不能被改成“电影质感、情绪饱满、氛围浓厚”。

提纯可以减少无贡献的形容词，不能把具体设计磨回公共模板。原稿已经比改稿更有作品身份时，保留原稿。

## Reference 路由

每次进入本 Skill 都读取 `references/01_外部Vibe_Creating原文.md` 并执行其判断。该文件是外部 Skill `vibe-creating-prompt` 的便携原文副本，不改写、不删减；其仓库内权威原文位于 `02_共享资产库/05_工具流程/外部优化Skill/vibe-creating-prompt/SKILL.md`。本 Skill 只负责把外部判断嵌入本项目硬接口，并保留实际调用证据。

零改动放行不是跳过 Reference，而是读取、比较以后确认没有稳定增益。退回上游也必须说明是在 VC 基线检查或执行判断的哪一步发现断点。

增益涉及追逐、力量、快慢变化、反应窗口或运动转场时，再按需读取 `../laohu-video-prompt/references/09_速度节奏与时间动力设计.md`。先区分人物、摄影机、切镜、信息和声音速度，只增强主速度承载者、对比、可读性、惯性与完成点。

## 提纯动作

先选择一种动作：

| 动作 | 适用情况 | 结果 |
|---|---|---|
| 零改动放行 | 原稿已经达到观众效果目标 | 正文不改，但记录已读取 VC、比较了什么以及为什么不改 |
| 轻度提纯 | 一个决定性画面、声音或连接仍可增强 | 局部替换或重排，篇幅基本不扩张 |
| 直接改写 | 基线合格，但主视觉普通、峰值弱或节奏平 | 围绕最弱观众效果重做相关镜头 |
| 退回上游 | 缺故事、资产、镜头、格式或字符基线 | 指明最早负责人和缺口 |

### 每次都要寻找更强版本

必经不等于每次都要强改，必经意味着每次都要真正寻找。VC 先围绕本段主胜负手提出至少两个局部增益方向，例如更早的异常、更准确的观看位置、更有压强的构图、更清楚的触发、更大的尺度证明、更有余韵的声音或更难忘的停点；只换形容词、滤镜、粒子和镜头术语不算方向。

用同一组硬约束比较原稿与候选：观众效果是否更强，作品身份是否更清楚，因果是否更顺，主次是否更集中，生成负担是否可控，状态和剪辑接口是否无损。只有候选不能稳定赢过原稿时才零改动放行。零改动结论必须写明比较过什么、为什么不改；“原稿已合格”不是理由。

改写顺序：

```text
确定唯一增益目标
→ 找决定性瞬间及其前后因果
→ 保留所有硬接口
→ 增强可见 / 可听证据
→ 删除同等权重以下的旧句，避免信息稀释
→ 对比原稿与改稿
→ 无明确增益则撤销
```

音乐存在时做全段声画审计，不只给几个重拍加“卡点”。速度存在时先保住方向、接触和结果，再增强快慢对比；不能让人物、摄影机、VFX、背景和切镜同时加速。

商业内容把购买矛盾、核心承诺、卖点场景、产品介入、可见证据、品牌归属和行动出口视为骨架。画面没有证明卖点时退回上游，不能用更像广告的空口号覆盖。

## 回填与验收

### 输出

```text
【VC 优化记录】
调用状态：已读取并执行 / 链路失败。
执行动作：
唯一增益目标：
保留硬约束：
实际改变的屏幕 / 声音结果：
为什么优于原稿，或为什么保留原稿：

【素材剪辑接口卡】
原样继承；正文变化影响接口时同步校准，不得删除。

【优化后三段提示词】
只保留三个正式一级区块。

【字符实测】
脚本命令、block、结果与 PASS / FAIL。
```

### 验收

- 首稿基线是否真实通过，而不是由 VC 代修。
- 有改动时，至少一个观众可感知维度是否明确增强；零改动时，是否有实际比较依据。
- 改稿是否仍然属于这个作品，而不是更漂亮的平均答案。
- 人物、资产、动作、声音、状态和剪辑接口是否没有被磨平。
- A 的结束与 B 的起点是否仍相等，B 是否仍从下一相位开始。
- 正式代码块是否仍只有三个一级区块。
- 改动后是否重新运行字符脚本，字符实测是否符合模型上限。
- 对比无法证明更好时，是否零改动保留原稿，而不是为显得做过工作强改；同时是否留下 VC 已执行的证据。
- 是否真的提出并比较过至少两个局部增益方向，而不是从“已经能用”直接跳到零改动放行。
- 采用的结果是否让主胜负手更强，同时让不承重的效果退让；是否没有把极致误解成堆满。

完成后交回 `laohu-video-prompt`。由它进行最终三段式、接口、状态和字符复验，并写入作品主文件。
