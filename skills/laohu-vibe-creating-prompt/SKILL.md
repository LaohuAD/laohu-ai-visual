# 视频提示词 Vibe Creating 优化

## 能力定位

把已经生成好的正式视频提示词初稿，进行一次 Vibe Creating 提纯，再交还给 `laohu-video-prompt` 输出给老胡。

本 skill 不是替代 `laohu-video-prompt` 写提示词，也不是首稿清洁器。它只接收已经通过格式、限字、连续性和最低充分信息门的可直接生成稿，在这个合格基线上进一步增强首秒冲击、作品身份、角色魅力、情绪峰值、决定性画面、声音推动、节奏起伏和转场惊喜。修复缺字段、超字数、明显重复和作者解释不算 VC 增益，发现这些问题必须退回 `laohu-video-prompt`。

最终交付给视频模型的正文仍只能是：

```text
【基础设定】
【场景状态与氛围画质】
【画面内容】
```

## Reference 路由

本 Skill 启动时不预读全部 Reference。先用本地主体完成首稿拒收门与输入判断，再按执行动作决定是否读取：

| 执行动作 | 是否读取 | 读取内容 |
|---|---|---|
| 直接放行 | 不读取 | 原稿已达到 VC 目标，不为证明工作量而加载方法或强行改写 |
| 原样保留 | 不读取 | 当前任务属于低适配场景，或老胡明确禁止 VC 优化 |
| 退回上游补齐 | 不读取 | 问题属于剧本、资产、分镜、格式或生成基线缺口，不由 VC 掩盖 |
| 轻度提纯 | 读取 | `references/01_外部Vibe_Creating原文.md`，只使用与当前增益目标有关的判断和方法 |
| 直接改写 | 读取 | `references/01_外部Vibe_Creating原文.md`，完成场景适配、约束优先级和改写模式判断 |
| 提供可选 VC 版 | 读取 | `references/01_外部Vibe_Creating原文.md`，同时保留原版，不能把可选优化变成强制替换 |

`references/01_外部Vibe_Creating原文.md` 是外部 Skill 的本地原文副本，内容不得改写、删减或重新概括后冒充原文。本地主体只负责规定它在老胡 AI 视觉流程中的调用时机、输入基线、不可破坏项、交互规则、三段式回填和下游交接。

当增益目标明确涉及速度、追逐、力量释放、快慢变化、慢动作或转场运动时，再按需读取 `../laohu-video-prompt/references/09_速度节奏与时间动力设计.md`；不涉及速度时不读取。

## 能力加厚纪律

执行顺序固定：

```text
laohu-video-prompt 生成并完成首稿零废话编译门
→ laohu-vibe-creating-prompt 读取初稿
→ 先验收首稿是否达到可直接生成基线，不合格则退回
→ 按 vibe-creating-prompt 判断最有价值的效果增益点
→ 优化首秒、决定性画面、情绪、角色魅力、声音、节奏和转场
→ 把优化结果重新落回三段模板
→ 交还 laohu-video-prompt 写入展示文件或全分镜结果文件
```

VC 优化必须遵守本项目硬约束：

```text
不能改变三段模板。
不能改变确定总时长。
不能删除或改写用户明确指定的台词、旁白、音乐、音效。
不能破坏已确认的分镜编号、镜头任务和资产一致性。
不能把摄影机物理路径、屏幕变化、焦点转移、动作受力、声音空间、切换触发和停点误判成低价值技术噪声。
不能压缩或改乱多主体运动账本中的世界 / 屏幕方向、朝向、共同惯性、速度变化原因、相对顺序、出画顺序和摄影机速度 / 轴线；也不能删除事件传播账本中的命中点、传播方向、材料失效、碎片落点、声场和永久终态。
不能把人体姿势变换账本里的约束解除、支撑点转换、肩胸骨盆与关节链、重心 / 旋转轴、四肢净空、首次接触和卸力顺序压缩回 `翻身、跳下、旋转、摔倒` 等概括动词。
不能删改角色动作语法中的能力等级、距离偏好、起势、攻击几何、防守 / 借位、场景利用和回收节奏；不能把不同人物磨成同一套通用连招。连续动作中，上一招形成的遮挡、失衡、空位、掉落物、反作用力和下一招入口必须保留。
不能把攻击来路、逼近速度、提前占位、接触瞬间短暂清晰、结果高速余势和决定性瞬间误判为重复动作描述。VC 可以减少无贡献的特效形容词，但必须保证主体轮廓、攻击线、接触点和人物能力证据比光效更清楚。
不能删除、合并或改乱 `【镜头01｜景别｜机位 / 视角｜运镜 / 转场】` 连续编号头部，也不能把镜头切成互不承接的段落。动作、遮挡、视线、焦点、声音、光色峰值和运动方向承担切换桥梁时必须保留；新镜头的姿势、道具状态、余势、空间方向和声场继承不能被优化掉。
不能把 `【VFX】`、`【环境音】`、`【动作音】`、`【音乐 / 节拍】` 和 `【台词】` 移出所属镜头或汇总到全段末尾。本镜没有的字段可以省略；有承重作用的逐镜字段不能为了文字顺滑被删掉。
不能把 `【场景状态与氛围画质】` 重新压缩成只有风格词。开拍前已经成立的空间、人物、道具、天气、人群和现有破坏必须保留；开场后才发生的变化仍留在对应镜头块。
不能把情绪承重台词的表演压缩成泛化情绪词。功能台词可以保持简短；承担主情绪的台词必须保留眼神、面部、呼吸、视线、姿态、距离和声线中的关键证据。
首尾帧双端锚定模式中，不能删除或弱化首帧 / 尾帧引用、不变量、变化量、共同桥梁、中间状态链、尾帧召回、减速收束和落帧校正；模型正文超限时只能先重写重复措辞，必要信息仍装不下则拆分任务。
跨 `VID` 连续模式中，不能把 `【视频参考@上游VID尾部连续性片段】` 改成泛化风格参考，也不能删除它的继承职责。交接卡里的连续性类型、实际截取、世界状态、屏幕投影、必须继承、允许重置和第一可见动作属于硬接口；VC 只优化 B 条新动作的表达，不把 A 已完成动作重新写进 B，也不把直接连续、同场重建和关系重置混成同一种接法。
同一条视频内部切镜、跨场或上下集同样受 `相邻单元交接合同` 约束。VC 在重排句序、合并镜头块、强化转场或增加感官连接前，必须比较改写前后的 A 结果、B 起点和第一项新变化；只要改写造成道具跳位、人物换手 / 换向、服装伤势复原、动作重演、情绪无触发降温、环境永久结果消失或声音桥断裂，就不是优化，必须撤销。合同本身有矛盾时退回最早上游修正，VC 不靠润色掩盖。
不能违背上游已经明确的人物关系、剧情反转、场景设定、动作结果和资产状态。上游未写明且属于体验连续性、感官连接、动作过渡、声音空间、光影呼应和情绪节奏的创意留白，可以主动增强，并在优化记录中标明新增决定。
优化后必须服从模型路由上限：Seedance 2.0 `≤4000` 字符，Seedance 2.5 `≤5000` 字符，模型未明确或跨版本共用按 `≤4000`。超限先删重复和作者解释，再合并无新增证据的句子；不能删掉空间坐标、人物站位、运动路径、避让方向、接触点、受力结果、镜头承接和情绪表演，仍装不下则拆分 `VID`。
VC 只要改动正式 `text` 代码块，改稿前字符数立即失效；交付前必须重新运行 `skills/laohu-video-prompt/scripts/count_video_prompt_chars.sh` 并传入当前上限。没有脚本实测结果时不得声称“字符数合规”，也不得用大概、约、目测或旧报告替代。
不能把判断、执行动作、补充说明写进正式投喂代码块。
不能把“前一个镜头”“下一个镜头”“后期备注”等场外说明写进提示词正文。
不能删除或改乱代码块外的 `素材剪辑接口卡`。推荐入点、内部节点、推荐出点、主要 / 辅助匹配属性、干净把手、不建议裁切点和后期依赖属于下游剪辑接口；VC 可以提纯模型正文中的可见 / 可听实现，但不能把接口目标当成冗余说明删掉。
不能为了语言更顺，把动作中切需要的动作相位、视线 / 焦点落点、遮挡满屏、光色峰值、声音瞬态、台词停顿和结果停点抹平；也不能把短暂稳定把手优化成连续不停的新动作。若接口只存在于卡片、正文没有对应可见 / 可听证据，应退回 `laohu-video-prompt` 补编译，不由 VC 在卡片里假装已经实现。
```

如果外部 `vibe-creating-prompt` 原文要求输出“判断 / 执行动作 / 输出结果 / 补充说明”，这些只用于内部优化记录或提示词外说明。正式投喂给视频模型的内容，只保留“输出结果”里优化后的三段提示词。

VC 优化不能把有身份的表达磨成平均值。遇到主视觉概念、风格核心、开场钩子、转场机制、结尾封面帧、人物情绪主句和声音状态主句时，先做反众数审美否决：检查它是否只是泛电影感、泛写实、泛治愈、泛国风、泛高级或普通情绪标签。如果原文已经有准确的关系压力、具体光影、可见留白、动作停点和作品身份，优化只能增强这些锚点，不能为了顺口把它改回 `高级电影感、情绪饱满、氛围浓厚` 这类公共模板。

VC 提纯的正确方向是“更具体、更可见、更有作品归属”，不是“更顺、更泛、更像漂亮说明文”。例如 `黑衣女侠在庭院舞剑，国风高级` 需要被提纯成月洞门、冷月侧逆光、墨黑衣料、剑脊高光、湿石板暗面、竹影留白和动作停点；不能只改成 `古风氛围更加浓烈，画面更有电影质感`。

VC 优化也必须独立提升观众代入，不能只压缩文字。检查观众是否知道人物为什么在乎、何时和人物获得信息、危险或快乐从哪里进入、身体和声场怎样响应、镜头是否给足等待与余波；在不破坏硬约束和总时长的前提下，可以重排感官证据、强化声音桥、动作触发、焦点迁移和尾帧余韵。全程贴脸、手持和刺激不是代入，体验连续性与呼吸同样重要。

### VC 前置拒收门与增益合同

VC 开始前必须确认首稿已经满足：三段完整；逐镜中文方头连续编号；景别、机位和转场清楚；声画字段逐镜归属；字符数合规；没有明显作者解释、同义重复和资产外观复述；首尾与相邻状态可接。任一项失败，返回 `laohu-video-prompt` 修复后重新送审，VC 不代修。

VC 每次改写至少要明确提升一个观众可感知维度：

```text
第一秒更快建立等待问题或视觉冲击；
角色第一眼更有身份、魅力或危险；
决定性瞬间更清楚、更意外、更有尺度；
情绪触发、保护层破裂或高潮释放更可感；
镜头速度和停顿形成更强起伏，而不是全程同速；
VFX 更服从动作来源、传播和环境结果；
声音更早预示、更准卡点或更有余波；
相邻镜头 / VID 的动作、形状、视点、遮挡、光色或声音连接更惊艳；
尾帧更像可记住的作品画面，而不是完成任务的结束。
```

若改写只让语言更顺、形容词更多、格式更整齐或字符更少，却没有增强上述任一结果，应判定为无效 VC 并保留原稿。VC 新增一句时必须指出它新增了什么屏幕 / 声音结果；无法指出则不加。VC 不默认扩字，新增承重效果时应同步删除同等权重以下的旧句，避免注意力稀释。

原稿只要存在音乐，VC 必须把“更准卡点”扩展为全段声画审计：检查音乐段落是否对应宏观视觉阶段，每个主要视觉短语是否至少有一个动作接触、转场完成、VFX 峰值、光色反转、构图锁定、标题形成或摄影机冲量与音乐事件建立关系；检查拍前蓄势、同步完成点和拍后余波是否完整。不能只增强几个重拍镜头，让中段继续脱离音乐；也不能为了整齐把所有切镜机械吸到每一拍。抢拍、拖拍、切分和留白若承担情绪，保留并写清重新合拍点。

当 VC 的增益目标包含速度起伏、力量释放、慢动作、快切、追逐压迫、反应窗口或转场运动时，读取 `skills/laohu-video-prompt/references/09_速度节奏与时间动力设计.md`。先区分动作、摄影机、切镜、信息和声音速度，找出唯一主速度承载者，再检查蓄势、启动、加速、峰值、接触、余波和停点中哪些相位真正缺失。VC 只能增强对比、可读性、物理惯性和决定性完成点，不能让人物、摄影机、VFX、背景与切镜同时加速，也不能把 `慢动作 + 拖影 + 快切` 当作通用高级感。

遇到动作段，VC 先找本段唯一的主决定性瞬间，再检查前面的危险与速度是否把力量送到这里、后面的受力与环境余势是否把结果带出去。所谓提纯，是让观众更快看见这一瞬为什么厉害，不是把整段改成慢动作、命中定格、炫光堆叠或人物站桩。压迫、关系和崩溃段同样要有决定性瞬间，但它可以是最小动作、关系证据或控制破裂，不强制动作 Pose。

### 商业骨架保全

优化电商、TVC、品牌或获客提示词时，把 `购买矛盾、核心承诺、卖点场景、产品介入机制、可见证据、文案命名、品牌归属和行动出口` 视为商业骨架。提纯可以删同义风格词、重复外观和不参与证明的技术噪声，不得为了简短、顺口或高级感把商业骨架压成无证据的产品蒙太奇。

如果原稿文案声称某卖点，画面却没有对应处境、结构介入和结果，这不是表达冗余，而是上游商业逻辑缺口；VC 应标记并回退 `laohu-script-writer / laohu-visual-assets / laohu-video-prompt` 补证据，不得自己编一句更像广告的空口号覆盖问题。

## 能力边界

可以优化：

- 过于机械、执行单味太重的画面描述。
- 低价值技术参数和不会提升生成效果的拍摄术语。
- 情绪方向不够清楚的画面内容。
- 视觉中心不够明确的描述。
- 多镜头之间共同体验不够统一的表达。
- 画面内容太散、太像说明书、不像可生成画面的句子。

不能优化：

- 剧本结构、分镜编号和镜头总时长。
- 已确认资产外观。
- 用户明确指定的台词、旁白、音乐和音效措辞。
- 严格功能演示、UI 教程、参数保留型执行稿。
- 需要精确对白同步的长篇剧情片段。
- 决定模型执行的运镜物理路径、主体 / 背景可见变化、焦点迁移、速度层、画外声源和时长预算；默认完整保留，不能删除因果。
- 老胡明确要求“不要做 VC 优化”的提示词。

## 输入判断

收到视频提示词初稿后，先判断：

```text
是否已有三段模板：
是否有明确视觉锚点：
是否有明确主体动作或状态：
是否有局部调性：
是否有视频主题和画面风格：
是否包含用户硬约束：
是否包含低价值技术噪声：
是否适合 VC 优化：
执行动作：直接放行 / 轻度提纯 / 直接改写 / 原样保留 / 先补问
```

注意：老胡项目里的视频提示词通常已经经过剧本、分镜和资产阶段，因此优先选择“直接放行 / 轻度提纯 / 直接改写”，不要为了 VC 分类反复追问。只有视觉锚点、主体动作、风格方向严重缺失，且会影响生成落地时，才回退给 `laohu-video-prompt` 补问或重写初稿。

## 优化方式

### 1. 直接放行

适用：

```text
三段模板完整。
主体、动作、情绪、风格都清楚。
没有明显低价值技术噪声。
语言已经适合生成。
```

处理：不改正文，只在提示词外记录“已通过 VC 检查”。

### 2. 轻度提纯

适用：

```text
原提示词已经通过首稿拒收门，但决定性画面、情绪触发、声音推动或转场力度仍可提高。
```

处理：强化一个最有价值的观众效果，必要时重排或替换同等篇幅；不得把清理首稿废话冒充优化，不得新增剧情。

### 3. 直接改写

适用：

```text
原提示词结构和基本信息合格，但主视觉普通、角色无独特魅力、情绪峰值不足、节奏平直或关键奇观没有形成决定性画面。
```

处理：保留三段模板和硬约束，围绕最弱的观众效果重做对应镜头；不是全文换同义词，也不是补泛化电影感。

### 4. 原样保留

适用：

```text
功能演示、UI 教程、参数必须保留、对白同步严格、老胡明确不希望 VC 化。
```

处理：不做 VC 改写，只可做错别字或格式级检查。

### 5. 先补齐

适用：

```text
缺视觉锚点。
缺主体动作或状态。
缺风格方向。
缺视频主题。
```

处理：优先在 VC 职责内补足体验连续性、感官连接和表达缺口；超出职责的故事或镜头缺口返回 `laohu-video-prompt` 主动补齐，不向老胡输出长问题。只有外部成本、法律安全或互斥核心定位才进入人工确认。

## 自检

- 当前执行动作是否真的需要读取 `references/01_外部Vibe_Creating原文.md`；直接放行、原样保留和退回上游时是否没有多余加载。
- 需要读取时，是否使用了本地原文副本，并且没有改写、删减或污染其内容。
- 是否只在 `laohu-video-prompt` 初稿之后执行。
- 是否保留了三段模板。
- 是否保留了场景初始状态，没有只剩宏观风格词。
- 是否保留了确定总时长。
- 是否保留了台词、旁白、音乐、音效原文。
- 有音乐时是否完成全段音乐-画面节拍审计；VC 是否提升了段落融合与主要视觉事件卡点，而非只增加局部鼓点词或机械每拍切镜。
- 速度承重时是否读取 `09_速度节奏与时间动力设计.md`；是否让主速度承载者、参照物、相位、加减速、接触、余波和停点更清楚，而非只增加高速、慢动作、快切和拖影词。
- 是否保留了资产一致性和已确认分镜编号。
- 是否没有违背上游明确剧情、人物关系或结果；新增体验、感官、连接与节奏创意是否已记录并继续交接。
- 是否真正提升观众代入，而不只是把句子压短或改顺；目标代价、信息、空间、身体、时间和选择中本段承重项是否更清楚。
- 是否没有把 VC 判断标签写进正式投喂代码块。
- 是否没有把具体、有作品身份的表达磨成泛电影感、泛写实、泛治愈、泛国风或漂亮说明文。
- 首尾帧双端锚定提示词是否保留不变量和变化量、主变换机制、摄影机路径、尾帧召回与收束，没有为了流畅删掉落帧因果。
- 跨 `VID` 连续提示词是否保留实际参考类型与职责、世界状态 / 屏幕投影分层和 B 第一项新变化，没有复演 A 或把同场重建误写成直接连续。
- 内部切镜、跨场和上下集是否也保持相邻单元状态；VC 的压缩、重排和转场增强是否没有改变 A 的结果、B 的起点或阶段性资产状态。
- 高价值视觉表达是否已经通过反众数审美否决，保留了具体场景、光影、构图、动作、声音、留白和作品关系。
- 是否保留了空间、动作、表演、声音和前后因果的生成必要信息，没有为了文字更短破坏可执行性。
- 是否保留并校准代码块外的素材剪辑接口卡；是否让每个接口继续对应正文中的可见 / 可听证据，没有把计划接口、干净把手或可读停点优化掉。
- 是否保留每个 `【镜头01｜景别｜机位 / 视角｜运镜 / 转场】` 编号头部及所属 `【VFX】`、`【环境音】`、`【动作音】`、`【音乐 / 节拍】`、`【台词】`，没有把逐镜控制重新合并成全段列表。
- 是否保留多主体世界运动与屏幕相对运动的区别、共同惯性、相对顺序和摄影机轴线；复杂破坏的事件传播链是否仍完整可执行。
- 复杂人体动作的关键姿势相位是否完整保留，支撑点、重心、旋转轴、四肢路径和落地卸力是否仍能被模型看见。
- 是否交还给 `laohu-video-prompt` 写入第一个分镜展示文件或全部分镜提示词结果文件。
