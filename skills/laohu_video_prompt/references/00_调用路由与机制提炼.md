# 调用路由与机制提炼

## 用途

本文件负责两件事：把用户需求路由到最少的专业 reference；把外部案例或成功提示词拆成可迁移机制，而不是复制其表面形式。

## 对标审计边界

本轮完整审计 `T8mars/minimax-h3-prompt-skill-T8` 的 `skills/` 与 `docs/`，固定到提交 `833540be0a75f7dc83ebd952ac4e2a7cf1731dd8`，共检查 74 个 Skill。外部仓库的价值主要在知识组织和机制抽取，不在某个模型专属字段，也不证明所有案例都经过同等强度的生成验证。

随后完整审计 MiniMax 官方 `MiniMax-AI/MiniMax-H3` 的 `skills/`，固定到提交 `6da473b48daf91e5aebfb56451f8a0b116348df5`，共 9 个生产型 Skill：3D 动画、品牌宣传、双人游戏开场、H3 提示词写作、手绘真人融合、极简产品广告、音乐字幕 MV、编辑纸拼贴讲解、纸艺定格科普。官方仓库本轮未发现根目录许可证文件，只吸收独立改写的流程机制和质量判断，不复制长文本、固定模板和案例提示词。

### 直接吸收

- `mechanism`：先写效果成立的因果，不先堆关键词。
- `invariants`：明确不可删除、不可换序的承重点。
- `variable slots`：允许人物、地点、物件、材质、节奏、镜头和声音原创替换。
- `failure modes / quality repairs`：把常见失败直接映射到修复动作。
- `transfer tests`：换题材、换人物、换媒介后，机制仍应成立。
- `anti-copy boundary`：禁止继承案例表面的独特表达。

### 改造后吸收

- 外部按 MiniMax / Seedance 区分的格式只吸收任务逻辑，正式输出仍使用本项目三段式。
- 外部逐镜任务卡只作为内部规划，不进入模型正文。
- 外部精确秒点只在音乐同步或模型确实需要时使用；本项目正式正文默认不用逐镜时间码。
- 外部强案例骨架只能当候选机制，必须经过剧本、资产、连续性和可剪辑门。
- 官方纸拼贴的“最终静帧作为完成构图”改造为结果帧先行：先验证知识关系，再倒推组装，不固定为图生视频或 4 秒片段。
- 官方 3D 动画的逐秒镜头表只吸收空间锚点、退场状态和交接意识；正式三段式正文仍不用逐镜时间码。
- 官方品牌 / 产品 Skill 的事实表、来源清单和真实产品动作驱动转场，分别并入商业证据与资产真实性规则，不继承 Apple 风等固定审美。
- 官方 MV 的音频连续和自然拼接并入声音桥与剪辑接口，不继承其特定音乐风格预设。

### 明确拒绝

- 不复制人物、地点、品牌、台词、镜头顺序、精确时长和标志性表面特效。
- 不因为案例有电影术语就堆满镜头参数。
- 不把“复杂”误解成镜头越多、形容词越多、粒子越多。
- 不把 74 个外部 Skill 一比一迁入本项目，避免入口爆炸和题材重复。
- 不把模型名称当成创作机制；模型适配只负责长度、输入能力和已知限制。
- 不继承官方生产流程里的固定 16:9、4 秒、15 秒、逐秒指令、默认模型、固定色彩语义和阶段选项卡；这些是产品工作流默认值，不是视频创作底层规律。

## 路由算法

### 内容指纹

路由前先生成六轴内容指纹：`观众承诺 / 主导机制 / 空间语法 / 时间语法 / 证据方式 / 媒介物理`。

- 观众承诺：观众看完必须相信、感到或记住什么。
- 主导机制：效果由表演触发、力量接触、产品证明、节拍同步、图形推导、世界变化还是摄影机在场产生。
- 空间语法：真实三维空间、扁平二维版面、浅层 2.5D、分层舞台、严格 POV 或不断重组的图形空间。
- 时间语法：连续动作、触发后渐变、节拍事件、停格组装、状态机、拆解重组或快速标题序列。
- 证据方式：人物反应、接触结果、产品输出、数据关系、环境尺度、图形形变、文字 / UI 或声音连续。
- 媒介物理：真人摄影、赛璐璐、纸片、三维材质、动态图形、界面元素或多媒介混合怎样限制运动。

### 三类判定

1. `完全适配`：一个现有 reference 的机制与不变量覆盖主导机制，风格差异只需写进可变槽。
2. `组合适配`：一个主要 reference 覆盖主导机制，最多一个辅助 reference 只补声音、字效、局部特效、表演、速度节奏或剪辑接口。
3. `能力缺口`：现有 reference 只能覆盖局部，或套用后会把作品改成另一种空间、时间、证据或媒介逻辑。

禁止把局部覆盖提升为主要 reference，也禁止用两个辅助 reference 拼出虚假的主路由。没有匹配时不读取题材 reference，先写当前作品一次性机制卡。

### 缺口提案

能力缺口提案固定说明：内容主机制；最接近的现有 reference 能覆盖什么、缺什么；不新增时如何用一次性机制卡完成当前作品；建议的新 reference 名称、适用范围、核心不变量、与旧分类的边界、预计复用场景和维护成本。建议的新 reference 永久创建前必须得到老胡确认。

仅视觉风格变化不创建新分类；只有机制、空间语法、时间语法、证据方式或媒介物理形成可复用的新规律，才提出升格。

新分类名称必须使用稳定的观众任务和主导机制，不能使用单个案例的角色、颜色、题材、道具、软件或特效皮肤命名。提案先通过跨样本抽象测试：把人物换成物件或符号、把色板换掉、把游戏换成 MV / 文化 / 时尚主题后，核心状态机是否仍成立；再通过邻近边界测试：知识解释、产品证明、连续叙事或真实动作为什么不能被这个新分类误吸收。若第二、第三个同类案例暴露更高层共性，优先升级已有 reference 的内部机制分支，不为每种视觉锚点另建小类。

### 当前能力导航

先问“这一段最需要观众相信什么”，再检查是否存在主要 reference：

1. 相信人物此刻真的被某句话击中：`01`。
2. 相信力量、速度、接触和结果真的发生：`02`。
3. 相信产品解决问题并值得行动：`03`。
4. 相信音乐 / 声音、表演、视觉母题、文字和版面重排共同建立作品身份：`04`。
5. 相信抽象知识由可见图形机制推导出来：`05`。
6. 相信抽象知识由纸片物件、层级和组装顺序变成可触摸模型：`05A`。
7. 相信不可能变化有阶段、有尺度、有不可逆结果：`06`。
8. 相信摄影机真实在场、路线连续、互动未摆拍：`07`。

速度与节奏执行横向判定：如果作品成败取决于谁在快、如何加减速、哪里蓄势与制动、动作和摄影机怎样错速、快切如何保持可读、跨镜运动怎样接相位，或文戏反应窗口怎样变化，主 reference 仍按上面八类选择，并把 `09_速度节奏与时间动力设计.md` 作为唯一辅助 reference。普通走路、单一推镜和不承重的背景运动不读取 `09`；不能因为题材是动作片或音乐存在就自动加载。

混合任务按节拍拆，不按题材标签全加载。例如女武神“变身后战斗”：变身段主用 `06`，交手段主用 `02`；产品 PV 含三维机械剖面：全片主用 `03`，机制解释节拍辅用 `05`。

## 机制卡写法

每次吸收新案例，内部建立一张机制卡：

```text
机制：观众体验由哪条因果链产生。
不变量：删除、换序或模糊后会失败的 3-7 个锚点。
可变槽：允许原创替换的主体、空间、材质、动作、摄影、声音。
三段式编译：哪些进入基础设定，哪些进入全局氛围，哪些逐镜变化。
失败修复：失败现象 → 根因 → 最小修复。
迁移测试：至少换两个题材，机制能否继续工作。
反复制边界：哪些独特表达绝不继承。
```

## 重点密度判断

提示词重点不是“重要词多写几遍”，而是形成少数高权重因果：

- 每条只设一个观众承诺。
- 每个镜头只完成一个新的状态变化或证据。
- 每个奇观只有一个主物理机制，辅效只证明它。
- 每个动作写到结果，不在接触前结束。
- 每个镜头给出可保存停点，不让模型平均分配注意力。
- 全局不变量上移，逐镜只写变化量。

凡是删掉后不改变身份、空间、运动、情绪、声音、光影、结果或剪辑的句子，都是口水话候选。

## 迁移测试

机制入库前至少通过：

1. 换人物和地点仍成立。
2. 换视觉材质仍成立。
3. 换 9:16 与 16:9 后主因果仍可读。
4. 换图生视频与文生视频后只改变描述预算，不改变事件逻辑。
5. 删除外部案例专有名词后，仍能独立指导创作。

若只能在原案例的镜头顺序、材质和文案中成立，它不是机制，只是案例复述。
