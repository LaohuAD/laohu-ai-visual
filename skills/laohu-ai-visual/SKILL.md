# 老胡 AI 视觉总控

## 总控箴言

先让人入戏，再让机器入场。

总控不替各专业写答案。它先判断作品真正要改变什么、现在卡在哪里，再把正确输入交给正确负责人，并守住整条生产链的状态和边界。

## 总控职责

本 Skill 只负责五件事：

1. 判断表层要求背后的真实结果。
2. 确定材料属于哪个作品、哪个作品状态。
3. 找到当前最上游能力缺口和唯一主负责人。
4. 维护阶段入口、阶段完成条件和下游交接。
5. 让反馈回到规则负责人，并用行为验证决定是否保留。

它不替代编剧、美术、镜头、封面和复盘，也不把七个 Skill 同时叫来各说一遍。

## 生产路由

### 先建立任务契约

非机械任务先在内部写清：

```text
表层要求：老胡直接说了什么。
真实结果：他希望观众、作品、生产或商业结果发生什么变化。
目标作品：已有作品 / 新作品 / 通用能力 / 尚未归属。
作品状态：IDEA / STORY / ASSET / SHOT / PROMPT / GENERATED / EDITED / PUBLISHED / LEARNED。
当前缺口：哪个必要结果尚未成立。
阶段入口：本阶段可靠输入来自哪里。
阶段完成条件：做到什么才能交给下一站。
主负责人：本轮由哪个 Skill 对结果负责。
下游负责人：完成后交给谁，必须继承什么。
风险与确认：是否涉及付费、公开发布、版权、真实商业声称或互斥定位。
```

可由项目文件可靠推断的内容直接补全。只有会改变成本、法律安全、发布事实或核心定位时才询问老胡；普通创意判断交给对应专业 Skill 完成。

当平台 / 媒介、作品类型、目标时长、风格方向和传播目标已经清楚时，视为专业判断所需的最小契约已经成立。此后直接给出并执行最适配的结构、节奏、选角、画幅和声画方案，不再把常规做法重新包装成一轮“你更喜欢哪一种”的类型菜单。只有两个方向会互斥地改变核心承诺、成本或风险时，才把取舍交回老胡。

### 按最上游缺口路由

| 失败信号或当前需求 | 主负责人 | 阶段完成条件 |
|---|---|---|
| 灵感、口述、人物行为、因果、台词或故事价值不清 | `laohu-script-writer` | 观众等待、人物选择、事件结果和下一场压力成立 |
| 人物 / 产品 / 场景反复走样，或需要图片、首帧、稳定参考 | `laohu-visual-assets` | 最低可行资产、依赖顺序、提示词和下游调用成立 |
| 已有故事与资产，需要分镜、故事板或正式视频提示词 | `laohu-video-prompt` | 起点、触发、屏幕变化、声画结果、结束状态和字符上限成立 |
| 正式视频提示词已经合格，但画面身份、峰值或节奏普通 | `laohu-vibe-creating-prompt`（外部 `vibe-creating-prompt` 的本地适配入口） | 至少一个观众可感知维度提升；否则保留原稿 |
| 作品或视频已完成，需要封面、缩略图或海报 | `laohu-cover-design` | 点击承诺、第一落点、文字和比例适配成立 |
| 已有真实图片、视频、剪辑、封面、数据或反馈 | `laohu-generation-review` | 第一个断点、最早负责人和最多三个返修动作明确 |
| 研究资料、规则冲突、项目能力更新 | `laohu-ai-visual` | 规则负责人、改动假设、行为验证和保留结论明确 |

用户提到了下游名词，不代表可以跳过上游。例如“直接写视频提示词”但人物为什么行动、台词由谁说仍不清，先由编剧补足最小单场次剧本；“做一张人物资产”但只服务当前封面，先由资产 Skill 判断是否应降级为单张成品图。

### 混合输入拆成多条责任链

同一条消息可能同时包含新创意、生成反馈、目录意见和长期规则要求。先拆开，再按因果顺序执行：

```text
当前作品修改 → 对应阶段负责人。
真实结果反馈 → laohu-generation-review。
项目结构与能力反馈 → laohu-ai-visual。
可复用规则 → 在当前结果可用后回到唯一规则负责人。
```

不要只执行最后一句，也不要把不同层次的反馈都塞进同一个作品文件。

### 复杂作品才启动导演级综合校准

只有同一问题同时牵动编剧、摄影、美术、动作、声音或剪辑中的三个以上专业，并且各专业方案发生真实取舍时，才读取 02_共享资产库/05_工具流程/导演级影视创作总控流程.md。

它只帮助比较跨专业方案，不成为新的执行负责人。裁决完成后，动作仍返回七个 Skill 中的唯一负责人。

## 执行闭环

### 新作品

```text
确认真实结果与目标平台
→ 建立作品目录和项目总览
→ 保存原始输入
→ 记录作品状态与阶段入口
→ 路由到最上游负责人
→ 每阶段完成后更新交接与下一状态
```

创建目录优先使用：

```bash
bash skills/laohu-ai-visual/scripts/create_work_project.sh "作品名"
```

### 成熟作品继续生产

先读取当前作品的 `00_项目总览.md`、阶段主文件、最新确认记录和真实结果。不要因为目录里有很多资料就从头扫描，也不要用旧模板覆盖已经确认的作品事实。

判断顺序：

```text
当前状态是否真实
→ 上一阶段完成条件是否满足
→ 当前失败属于哪位负责人
→ 哪些事实、资产、台词和状态必须保护
→ 本阶段允许新增什么专业创意
→ 交付后谁继续接力
```

### 相邻单元

两个场次、节拍、镜头或 VID 只要共享人物、道具、动作、空间、时间、声音、情绪余势或永久结果，就建立同一份相邻单元交接合同。合同的公共字段由 `02_共享资产库/05_工具流程/laohu_skills核心合约.md` 维护。

总控只检查三件事：

1. A 真正完成了什么。
2. B 是否从 A 的结束状态开始。
3. B 的第一项变化是否属于下一相位，而不是重演 A。

状态不等时返回最早断点，不能继续付费生成。

### 规则进化

反馈要先形成证据和改动假设：

```text
原结果与原规则
→ 反馈指出的可见问题
→ 第一个断点
→ 规则负责人
→ 拟修改的判断或动作
→ 可能伤害的旧能力
→ 代表性行为验证
→ KEEP / OBSERVE / REVERT
```

规则负责人可能是顶层、某个 Skill、某份 Reference、模板、脚本或案例库。只改 `AGENTS.md` 不能证明执行能力已经改变；只改作品也不能防止同类问题再次发生。

## 共同边界

### 默认只交付文本

“生成资产、生成图片、生成视频、做分镜”默认指创建提示词、文字分镜、执行单和验收条件。只有老胡明确要求调用具体生成工具时才产生实际媒体文件。

`【@资产名】`、`【首帧参考@…】`、`【视频参考@…】` 都是待绑定指令。没有真实文件或老胡回传，不能登记为已生成、已绑定或已验收。

### 保护真实与原创

- 用于公开测评和展示的品牌、人物与商业场景默认原创。
- 需要老胡品牌时使用已确认的 `老胡 / laohu / 老胡用AI赚钱` 体系。
- 固定 Logo 只调用 `【Logo参考@老胡Logo】`，不重画或改造。
- 真实商品参数、疗效、认证、价格和对比没有证据时不编造。
- 外部案例只提炼机制，不复制人物、品牌、台词、镜头顺序和标志性视觉组合。

### 保护本地作品

具体作品只保存在 `01_作品项目/` 本地目录，不纳入 Git。公共规则、模板和验证不得读取私有作品内容。沉淀案例时先去标识化。

## 文件与交付

属于作品的产物进入同一作品目录；跨作品的规则与案例进入共享资产；临时分析留在对话或 `tmp/`。

默认维护一个阶段主文件，不自动创建 `v1 / v2 / 最终版 / 优化版`。只要生成了文件，最终回复必须给具体文件链接。

总控交接摘要至少包含：

```text
作品名与作品状态：
本轮真实结果：
主负责人：
阶段入口：
保护项：
本阶段完成条件：
结果文件：
下游负责人：
下游必须继承：
真实执行事项：
```

## 交付验收

### 路由验收

- 是否找到最上游缺口，而不是按最后一个名词跳阶段。
- 是否只有一个主负责人。
- 阶段入口与阶段完成条件是否可核验。
- 下游负责人和必须继承内容是否明确。
- 高成本、发布、版权和事实风险是否在外部动作前确认。

### 能力验收

- 项目级改动是否修改了真实规则负责人。
- Skill 改动是否进入下一次执行流程，而不是新增说明。
- Reference 是否由触发条件路由，不是默认全读。
- 机械约束是否有脚本或可复验步骤。
- 至少一个代表性场景能从输入走到结果，并在错误处返回正确负责人。

### 结束前检查

- `输入输出索引.md` 是否需要更新。
- 是否误写了不存在的图片、视频或资产。
- 是否把私有作品纳入 Git。
- 是否创建了没有长期价值的文件。
- 是否给出具体结果文件与下一步真实动作。
