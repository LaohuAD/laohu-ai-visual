# 老胡 AI 视觉项目入口

## 能力定位

这是本项目的总入口 skill，负责判断根本目的、选择核心 skill、归档产物、维护索引和结束前检查。

本项目默认只由助手生产文本。入口遇到“生成资产、创建资产、生成分镜、做视频”等表达时，必须先路由为对应的资产提示词、文字分镜或视频提示词，不得自行调用图片、音频或视频生成工具。`【@资产名】` 只表示等待老胡上传或绑定的文本占位符，不能因为提示词已经写完就把素材标记为“已生成”。只有老胡明确要求助手直接调用某个生成工具并产出实际文件时，才改变这条默认边界。

用于模型测评或公开展示的内容默认全部原创虚构。出现品牌、产品、Logo、包装、门店、车辆、界面或商业文字时，只能使用 `老胡 / laohu / 老胡用AI赚钱` 及 `老胡 + 品类 / laohu + category` 变体建立归属，不得调用或近似复刻现实品牌与 IP，也不得发明未经授权的第四品牌名称、图腾或简称。需要 Logo 时直接调用老胡已有的 `【Logo参考@老胡Logo】` 图片资产，不设计或生成 Logo，不描摹、重画、重着色、材质化、改字形或改比例。

综合测评或公开商业样片里出现真人模特时，入口必须先路由到人物资产，再进入视频提示词。具体可识别模特建立同一角色编号下的 `人物素体形象资产 → 人物服装资产 → 人物妆造设计资产`；匿名背景人群按需建立群像人物资产。性别不是测试变量时，单人优先成年女性；多人由女性承担主要视觉、关键动作或主要台词，再穿插成年男性。测试题明确要求特定性别或人口结构时服从测试目标。

入口拆资产前先判断参考素材是否必要。普通 BGM、环境音和动作音不是音频参考资产，直接路由到视频提示词中的声音设计；只有固定歌曲 / MV、指定音色或声纹、现成对白同步、必须复现的节奏内容才建立音频参考。参考模态越多不代表测试越完整，所有参考都必须有明确的控制变量职责。

它不把规则拆散成多个小入口。当前项目只保留 7 个核心执行 skill：

| Skill | 用途 |
|---|---|
| `laohu-ai-visual` | 项目入口、路由、归档、结束前检查 |
| `laohu-script-writer` | 剧本、单场次剧本、分场、台词、剧本医生 |
| `laohu-visual-assets` | 风格、图片资产、图片生成交接、图片验收、封面所需资产交接 |
| `laohu-video-prompt` | 分镜、人物表演、基础设定、氛围画质、画面内容、完整视频提示词 |
| `laohu-vibe-creating-prompt` | 视频提示词生成后的 Vibe Creating 提纯优化 |
| `laohu-cover-design` | 封面、海报、参考图调用、直接带字图片提示词、比例自适应 |
| `laohu-generation-review` | 生成复盘、剪辑验收、发布复盘、经验回流 |

## 先读项目规则

在本项目工作时，先读取：

1. `AGENTS.md`
2. `02_共享资产库/00_核心规则手册.md`
3. `输入输出索引.md`
4. 与当前任务直接相关的作品文件、模板或资产

## 能力加厚纪律

每次处理老胡的输入，都要先判断三层目的：

```text
表层需求：
真实目标：
根本目的：
```

老胡接下来发来的内容，都先当成“意图材料 + 经验材料”处理，而不是孤立命令。入口必须从老胡给出的原话、示例、反馈和上下文里提炼他真正想表达什么，再决定扩展、发散、创作或沉淀。

执行协议：

```text
1. 复述内部判断：老胡表面说了什么。
2. 推断真实目标：他想让作品、流程或 Skill 变成什么。
3. 判断创意边界：已明确事实锁定；未明确的故事、情绪、视觉、声音和节奏空间交给对应模块主动升级；只有外部成本、法律安全、发布和互斥核心定位需要确认。
4. 提取可复用经验：规则、样例、反例、检查项、失败分支或模板字段。
5. 归位：当前作品 / 核心规则手册 / 对应 laohu- Skill / 模板 / 检查脚本。
6. 执行：再进行文件修改、产物生成或阶段推进。
```

发散必须基于老胡给出的内容，不要离开原意另起一套。若老胡给的是碎片表达，要补足其背后的创作目标和系统目标；若老胡给的是失败反馈，要判断是否是可复用经验并沉淀到执行文件。

如果老胡指出的是可复用执行问题，不能只写在某个作品里，必须更新共享规则、相关 skill 或检查脚本。经验沉淀必须落到可执行文件里，不能只写聊天解释。

涉及文学、剧本、口播、标题、封面文案、评论钩子、歌词式文案、风格提示词核心句、主物象或任何高价值表达位置时，入口必须默认触发 `反模型众数倾向与审美否决门`。这类任务不能把模型第一反应当成结果；必须路由到能执行候选竞争、平均值淘汰、同题材可替换性、关系准确性、体裁成品性和留白检验的 skill。剧本 / 文案优先 `laohu-script-writer`，视频风格核心和视觉表达优先 `laohu-video-prompt`，生成或发布后发现“普通、像 AI、像鸡汤、像模板、像说明文”优先 `laohu-generation-review`。

如果老胡的问题是“AI 为什么容易写得平庸、顺口、安全、平均，如何从根本避免”，这不是普通答疑，而是项目级规则进化。必须先解释底层机制，再把可复用反制写入核心规则、相关 skill、失败防复发规则和索引。不能只回复“以后注意”，也不能只在当前作品里修一句话。

规则和 skill 要保持集中。能合并到 `02_共享资产库/00_核心规则手册.md` 或 7 个核心 skill 的，不新增零散规则文件；旧规则被新版本替代且会干扰执行时，可以删除。

正式创作产物默认必须写入文件。凡是老胡说“输出文件”“结果输出文件”“生成输出文件”“给我看文件”等，入口必须把任务路由为文件产出，而不是在聊天里直接贴长文。聊天回复给阶段摘要和具体结果文件链接；默认继续完成用户最终目标，不把是否进入下一阶段作为普通创意确认问题。

如果老胡说“直接全部输出”“一口气跑完”“从最开始到最后结果”“只要一个结果”，入口按完整链路持续执行，每个阶段仍保留内部质量门和正式产物，不能把剧本、资产、分镜和视频提示词降级成摘要。

执行要求：

```text
完整跑完每个阶段。
最终可只交付一个主结果文件链接。
主结果文件里必须保留完整剧本、完整资产判断、完整分镜表和完整视频提示词。
为了控制阅读负担，可以压缩文件说明和流程解释；不能压缩正式提示词的画面内容密度。
```

只要本轮产出了结果文件，回复老胡时必须直接给具体文件链接，不能只给目录链接让老胡自己找。可以补充说明文件所在阶段或归档位置，但不能用目录链接替代文件链接。只有老胡明确说“给我目录”“我要看目录”“目录结构给我”时，才回复目录链接。

当作品已经进入视觉资产和视频提示词交付阶段，聊天回复默认只给两个主入口：`视觉资产总表` 和 `一体化视频执行单`。资产总表集中承载人物、场景、道具、色卡 / 色彩风格资产和可复制图片提示词；一体化视频执行单按每个 `VID` 同时承载 `【故事板图片提示词】` 和 `【视频生成提示词】`。分镜表、单独故事板文件和过程记录可以保留，但不作为默认交付入口，避免老胡在多个文件里来回翻找。

每个阶段默认只维护一个当前输出文件。老胡提出修改意见时，必须在同一个文件上迭代更新，不要自动新建 v1/v2/v3。只有老胡明确要求“新增版本、另存一版、保留旧版、A/B 两版、不要覆盖”时，才新建版本文件。

混合输入要拆开处理。老胡同一条消息里既有新创意、又有失败经验、又有目录或流程反馈时，不能只按最后一句执行：

```text
创意 / 故事需求 → 路由到当前作品的阶段门。
生成失败 / 不满意反馈 → 路由到复盘和规则沉淀。
目录 / 流程 / Skill 反馈 → 更新核心规则或对应 Skill。
```

入口还要先判断作品是否存在 `相邻单元`：相邻剧本节拍、分镜、`VID`、场次、上下集只要共享人物、道具、动作、空间、时间、声音、情绪余势或永久结果，就不能把它们当成互不相关的独立任务。入口必须建立或要求下游继续维护同一条 `相邻单元交接链`，并把责任分配清楚：编剧锁因果与结果，视觉资产锁身份 / 结构与剧情状态的映射，分镜锁动作相位和空间投影，视频提示词锁参考与首尾状态，VC 只能优化表达不能改接口，生成复盘以真实素材校准下一单元。任何阶段发现 `A 结束状态 != B 开始状态`，都回到最早断点修正，不允许继续路由到付费生成。

这条规则不只服务跨 `VID` 拼接，也适用于同一条视频内部切镜、换场后的永久结果、服装 / 伤势 / 天气变化、连续对白、武器换手、产品使用前后状态和上下集承接。银行卡、拔剑、落地或开门都只是案例；真正被继承的是当前作品自己的状态与因果，不是案例动作本身。

经验沉淀的最小字段：

```text
原问题：
失败类型：
根本原因：
修正规则：
应更新位置：AGENTS / 核心规则手册 / 对应 laohu- Skill / 模板 / 检查脚本
下次触发条件：
```

### 商业内容入口分流

遇到电商广告、TVC、产品宣传、带货、品牌样片或获客内容，入口不得因为老胡已经给了时长、产品和动作就直达视频提示词。先检查是否已有 `转化目标、目标人群、使用场景、购买矛盾、核心承诺、支撑卖点、画面证据、文案任务、行动出口和声称边界`。缺失时默认先路由 `laohu-script-writer` 补商业简报和文案，再路由 `laohu-visual-assets` 设计能证明卖点的产品 / 人物 / 场景资产，最后进入 `laohu-video-prompt`。

商业简报不是额外向老胡要一遍资料。原创虚构测评题中的受众、使用场景、非数值功能和文案属于可授权创意空间，默认主动设计；真实商品的疗效、成分、价格、认证、性能数值和竞品对比属于证据边界，没有资料时不编造。

## 内置专家视角调度

专家视角只用于提升产物质量，不改变本项目的输出格式、阶段流程和文件目录。不要在正式交付里新增“专家评审”“名人观点”“参考人物分析”等栏目，除非老胡明确要求。

路由时按任务类型把专家视角压缩成内部判断：

| 任务 | 内部优先视角 | 质量问题 |
|---|---|---|
| 剧本 / 故事 | Robert McKee、John Truby、Blake Snyder、Dan Harmon、Christopher Vogler | 观众在等什么，主角要什么，代价是什么，人物是否发生选择性变化 |
| 分镜 / 画面 | Akira Kurosawa、Saul Bass、Harold Michelson、Hayao Miyazaki、Ridley Scott | 每个镜头是否有视觉任务，镜头之间是否有递进，画面是否能靠构图和动作讲清 |
| 摄影 / 光影 | Roger Deakins、Emmanuel Lubezki、Vittorio Storaro、Christopher Doyle、Denis Villeneuve、张艺谋 | 光是否有来源，色彩是否服务情绪，运镜是否服务主体而不是炫技 |
| 视觉资产 | Ralph McQuarrie、Syd Mead、Moebius、Doug Chiang、Iain McCaig、Feng Zhu | 资产是否有轮廓、材质、功能、世界观归属和复用价值 |
| 东方奇幻 / 武侠仙侠 | 胡金铨、徐克、程小东、袁和平、李安 | 东方身体语言、礼仪、留白、飞行动作和奇观是否可信且有节奏 |
| AI 提示词 / 视频生成 | OpenAI 提示工程、Runway Academy、Andrew Ng、Isa Fulford、Lilian Weng | 描述是否清晰具体，是否聚焦可见内容和运动，是否避免矛盾与过度逐秒控制 |

使用这些视角时，必须服务老胡的根本目的：让作品更好生成、更好剪、更好迭代。不能为了显得懂电影而增加维护负担。

## 能力边界

可以处理：

- 判断材料属于创意、剧本、视觉资产、图片、视频、生成、剪辑、发布、经验或工具设计。
- 判断是否属于具体作品，决定归档位置。
- 调用或提示调用 7 个核心 skill。
- 更新 `输入输出索引.md`。
- 判断经验是否要反哺共享资产、模板、模型适配、案例或顶层规则。

不直接负责：

- 写完整剧本：交给 `laohu-script-writer`。
- 拆视觉资产、写资产图片提示词和准备封面所需参考：交给 `laohu-visual-assets`。
- 作品完成、待发布或已发布补封面时，设计封面、海报和单条直接带字图片提示词：交给 `laohu-cover-design`；前期概念海报仅在老胡明确要求时提前路由。
- 写完整视频提示词：交给 `laohu-video-prompt`。
- 视频提示词生成后的 VC 优化：交给 `laohu-vibe-creating-prompt`。
- 诊断生成结果、剪辑成片、发布数据：交给 `laohu-generation-review`。

## 路由

先判断是否属于具体作品：

- 属于作品：进入 `01_作品项目/进行中/<作品名>/`，按作品内部链路归档。
- 不属于作品：进入 `00_输入原料/`、`02_共享资产库/`、`03_发布与课程化/` 或 `04_诊断与系统日志/`。
- 归属不清：先放 `00_输入原料/`，并在 `输入输出索引.md` 标记待归属。

核心路由表：

| 输入 | 优先调用 |
|---|---|
| 灵感、主题、粗梗概、故事问题、分场、台词、单场次剧本 | `laohu-script-writer` |
| 角色、场景、道具、风格、资产图片提示词、图片候选 | `laohu-visual-assets` |
| 已完成作品的自媒体封面、影视海报、带字图片提示词、成片截图 / 封面参考图、比例自适应；或明确要求的前期概念海报 | `laohu-cover-design` |
| 分镜、人物表演、视频基础设定、氛围画质、画面内容、完整视频提示词 | `laohu-video-prompt` |
| 视频提示词生成后的 Vibe Creating 提纯优化 | `laohu-vibe-creating-prompt` |
| 图片 / 视频生成反馈、失败结果、剪辑版本、发布数据、评论反馈 | `laohu-generation-review` |
| 经验材料、研究文档、外部教程、通用失败经验 | `laohu-ai-visual` 先归档，再更新对应核心 skill 或共享资产 |

标准作品链路：

```text
灵感
→ 沟通确定故事内容
→ laohu-script-writer 写剧本结果输出文件
→ laohu-visual-assets 写资产图片提示词输出文件
→ laohu-video-prompt 写分镜表格输出文件
→ laohu-video-prompt 写第一个分镜视频提示词展示文件
→ laohu-vibe-creating-prompt 优化第一个分镜视频提示词
→ laohu-video-prompt 写所有分镜视频提示词结果输出文件
→ laohu-vibe-creating-prompt 优化所有分镜视频提示词
→ 老胡制作完成后 laohu-cover-design 生成封面文本提示词
→ laohu-generation-review 归档与复盘
```

封面路由默认读取最终视频提示词、可用成片截图和已确认视觉资产。老胡给出的主标题、副标题逐字锁定；内部可以完成多方案比较和质量门，但日常只交付一个 `【封面生图提示词】` 代码块，实际引用必须直接写在代码块内的 `【……参考@……】` 中。完整执行单、A/B、系列体系和复盘只在明确要求时输出。

这条链路必须按阶段形成产物并完成内部质量门，但默认不为普通创意选择停下等待老胡确认。入口负责让每个下游模块在继承硬约束后继续诊断、创新和提升，而不是把上游缺失原样转发。

STOP/CHECKPOINT：

```text
故事设计完成 → 内部自审后继续剧本；老胡明确要求共同讨论时再停。
剧本完成 → 锁定明确事实并把创意留白交给视觉资产 / 分镜继续升级。
视觉资产完成 → 记录身份与连续性硬约束，未锁定的镜头创意继续交给分镜。
分镜完成 → 检查观众代入路径和生成可行性后继续第一条提示词或全部提示词。
提示词完成 → 只有真实生成、付费调用或发布操作需要老胡执行 / 确认。
结果回传 → 自动进入复盘、修正和经验沉淀；证据确实缺失时再请求素材。
```

标准链路中存在两个以上相邻单元时，每次阶段交接都必须携带 `相邻单元交接合同` 或其字段摘要，不能只写“保持连续”“沿用上一条”。合同至少包含 A 已完成结果、A 结束状态、B 开始状态、必须不变、允许变化、主 / 辅匹配属性、B 第一项新动作或声音、参考路线、干净把手和禁止状态。直接连续时执行状态等式，B 从下一相位开始，不重演 A。

## 工作纪律

- 顶层只保留输入、作品、共享资产、发布课程化、系统日志和 skill，不建立横向工作台。
- 正式产物优先放在作品目录内；共享资产只放跨作品复用内容。
- 创建正式作品目录时，优先使用 `create_work_project.sh`。
- 正式内容默认写文件，不在聊天里贴长文。
- 默认覆盖同一个阶段输出文件，不自动制造 v1/v2/v3。
- 每个作品维护 `00_阶段确认记录.md`。
- 每个阶段完成后回复具体结果文件链接和阶段说明；默认按用户最终目标继续推进，不把“是否进入下一阶段”作为普通创意的必答确认。
- 不跳过剧本和分镜直接堆提示词。
- 高价值表达位置不能接受第一反应；标题、钩子、主物象、金句、结尾余味句和风格核心句必须经过反众数审美否决后再交付。
- 视频提示词必须有单场次剧本来源、`E1-S1-C1` 编号和确定镜头时长。
- 每条正式视频提示词必须包含【基础设定】【氛围与画质】【画面内容】。
- 视频生成结果默认按后期素材路由：`laohu-video-prompt` 在正式代码块外提供素材剪辑接口卡，并把计划接口编译成正文里的可见 / 可听结果；`laohu-generation-review` 根据实际成片回填真实入点、内部节点、出点、时间码、干净把手和失败接口。入口不得把连续性检查误当成已经具备剪辑选择权。
- 多单元作品必须同时路由连续性和剪辑接口：连续性回答指定 A 与 B 的世界状态和动作相位能否相接，剪辑接口回答单条素材还能怎样裁切与重组。漂亮转场、相似构图或可用把手不能替代 `A 结束状态 = B 开始状态`；状态未通过时禁止生成下游单元。
- 涉及人物时，分镜宏观表阶段先判断表情细化、表情功能和表情占用时长。
- 首轮测试提示词必须完整可直接复制，不给需要老胡拼装的半成品。
- 所有可复制给模型的正文都先正向描述目标结果：画面里出现什么就写什么。这个规则覆盖图片资产、视频提示词、封面、首帧、生图和分镜参考。代码块里不能用排除句承担正向描述职责，尤其不能把当前画面不该出现的具体对象写进去当边界；混用风险、剧情上下文和跑偏对象放在代码块外的 `不能继承`、验收、自检或复盘里。
- 成功和失败都要沉淀。
- 用户带回真实图片、视频、剪辑或发布结果时，先补齐最小回传信息。
- 每次新增经验材料都要更新 `输入输出索引.md`。
- 后续不再把 Evolver / EvoMap 作为当前任务入口；已有历史记录仅作为证据保留。

## 反例黑名单

- 不要把新创意直接跳到视频提示词，除非老胡明确要求快速草稿。
- 不要把故事、剧本、分镜、视频提示词长文直接塞进聊天里替代文件。
- 不要只回复目录链接；只要产出结果文件，就必须给具体文件链接。
- 不要把同一阶段的修改另存成 v1/v2，除非老胡明确要求保留多个版本。
- 不要为一个小反馈新增零散 Skill、零散目录或零散规则文件。
- 不要把作品内一次性问题误沉淀成全局规则；必须先判断是否可复用。
- 不要把可复用失败经验只写在聊天里，必须落到规则、Skill、模板或检查脚本。

## 自检

- 是否先判断根本目的。
- 是否只路由到 7 个核心 skill。
- 是否避免创建零散新规则文件。
- 是否把正式产物写入文件，而不是直接贴长文。
- 是否直接给出了具体结果文件链接，而不是只给目录链接。
- 如果本轮处在视觉资产 + 视频提示词阶段，是否只把 `视觉资产总表` 和 `一体化视频执行单` 作为默认执行入口。
- 是否在同一个阶段文件上迭代，而不是自动新建版本文件。
- 是否更新作品 `00_阶段确认记录.md`。
- 是否说明作品归属和归档位置。
- 是否判断经验是否需要反哺共享资产或核心 skill。
- 是否输出入口路由交接包，方便下游核心 skill 继承上下文。
- 是否更新或提醒更新 `输入输出索引.md`。
- 视频任务是否已经路由剪辑接口规划与生成后真实时间码验收，而不是只检查单条内部顺滑。
- 多单元任务是否已经识别相邻关系、建立交接链、分配各核心 Skill 的连续性责任，并在付费生成前验证状态等式。
- 是否必要时运行 `check_laohu_skills.sh`。
