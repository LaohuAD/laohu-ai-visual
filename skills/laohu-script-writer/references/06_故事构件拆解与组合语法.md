# 故事构件拆解与组合语法

当输入只有题材和零散材料、故事动力不清、场次彼此不推动、需要比较多个结构方向，或多个高概念正在争夺主线时读取。普通台词改字、格式整理和已有成熟因果链不读取本文件。

## 一、构件不是原型菜单

故事构件是能够独立改变人物、关系、信息、道具、空间、选择或观众判断的最小迁移单元。它不是“倒计时、反转、罗生门”这类名称，也不是把外部十二种原型换成项目自己的十二种。

素材原子提供生活证据，故事构件提供状态变化方式。素材原子仍由 `laohu-story-material` 的 `source / atom / usage` 保存；故事构件由当前 Skill 负责，不改变素材库，不保存私人原话、真实身份、独特台词和受保护情节组合。

构件只有同时回答以下问题才可调用：

```text
触发前必须有什么
人物想改变谁或什么
人物为什么采用这个行动
行动怎样改变状态
观众知道、相信和等待什么发生变化
什么可见或可听证据证明变化
它会把哪一种压力推给下一节拍
什么情况下会失效或误导
```

只有抽象名称、没有人物行动理由与前后状态的内容，不是构件。

## 二、从来源拆成构件

外部 Skill、成熟作品、生活观察、短视频段子和项目结果都按同一顺序处理：

```text
保留来源与事实边界
→ 去除人物、职业、年代、地点和独特道具外壳
→ 找人物当下目标和阻力
→ 找人物采用的方法及人物行动理由
→ 找即时结果和结果制造的下一压力
→ 找观众判断变化
→ 找不会自动恢复的代价或残留
→ 找结尾兑现或重新解释的对象
→ 拆到每个单元都能独立迁移
```

拆完执行两次测试：

1. 跨题材：换掉年代、职业、地点、题材和道具，状态变化是否仍成立；
2. 跨关系：在爱情、亲情、师徒、上下级、陌生人或人与系统之间替换，人物理由是否仍可重建。

离开原作品独特组合就失效的内容留作来源案例，不升级为通用构件。外部知名度只能证明值得研究，不能证明构件已经被本项目验证。

## 三、渐进检索

构件库入口：`scripts/story_component_library.py`；权威数据：`references/07_故事构件库.jsonl`。

按当前缺口渐进加载：

```text
stats：只看规模、类别、状态和证据分布
→ search：按职责、前后状态或兼容标签看压缩候选
→ get：只读取真正入围的构件详情
→ 组合：把少量构件放进人物因果，不把全库投喂给剧本
```

优先检索“当前缺少什么变化”：人物理由、约束、加压、信息、代价、选择、回收或场景融合。题材、年代、职业和地点只是次级适配条件，不能让表面相似压过功能相似。

构件库为空、搜索没有命中或候选不如当前原创方案时，允许零采用并继续原创。不得自动网络搜索，不得为了证明构件库有用而强行采用最高分候选。

## 四、先确定承重中心

组合前先回答：

```text
观众最终要经历什么
人物最不能承认的矛盾
人物眼前最想得到什么
人物最害怕失去什么
最后哪两个重要结果不能同时保住
作品体量、媒介和生产边界
```

构件必须服务同一个承重中心。复杂度来自因果关系和人物代价，不来自构件数量。

## 五、组合语法

候选可以从人性材料、欲望、错误方法、约束、加压、信息、代价、选择与感官回收中选择，不要求全部出现，也不限制只能使用一种成型结构。

每条主链必须写成：

```text
前置条件 → 人物行动 → 状态变化 → 观众更新 → 下一压力
```

展开时检查：

```text
A 为什么使这个人物采取 B
B 产生什么即时 C
C 怎样减少退路、提高代价或改变观众判断
人物因此继续、放弃还是更换 D
D 留下什么不可逆 E
E 怎样迫使人物在 F 与 G 之间选择
```

只把五个概念、设定、反转或情绪并排写在一起，没有一项成为下一项的原因，属于并排堆叠，不是组合。

## 六、候选竞争

重要故事至少比较三个因果真正不同的候选，也就是至少三个因果真正不同的方向。替换职业、地点和道具不算因果不同；至少要改变人物采取的方法、压力增长方式、不可逆代价或阈值选择。

逐案比较：

```text
创作者命题：它是否在讨论真正想讨论的问题
人物必要性：换一个人是否仍会采取相同行动
观众等待：证据是否足以形成预测
压力持续：每轮结果是否改变下一轮条件
高潮来源：最大结果是否由人物选择长出
首尾兑现：结尾是否完成或重新解释开场承诺
感官证据：关系是否落到动作、物件、声音或空间
制作负担：当前体量、资产与生成成本能否承载
平均化风险：是否只是旧故事换一个高概念名词
```

只让胜出候选进入正式剧本；淘汰候选保留理由，不把它们的亮点全部追回胜出方案。

## 七、场景融合

场景融合不是把多个构件塞进同一个地点，而是让同一承重行动、物件、空间或声音同时完成多个有关联的职责。

成立条件：

```text
一个人物当下目标
+ 同一承重行动
+ 一个主要状态结果
+ 若干确实改变后续的从属变化
```

例如人物在公开仪式中递出一件物品，同一个动作可以同时改变物件控制权、关系位置、群体判断和下一场压力；但主要结果只能有一个，其他变化必须从属它。

融合后检查：

- 人物是否仍在执行同一个当下目标；
- 关系、信息、道具和空间变化是否由同一动作产生；
- 观众第一遍能否读出主要结果；
- 删除某项从属变化后，后续人物选择是否真的不同。

多个构件争夺主结果、要求不同情绪准备或让观众无法判断发生了什么时，拆场或淘汰，不继续加解释。

## 八、低烈度与留白

低烈度、文艺、观察和氛围作品可以不使用高概念、倒计时和连续翻面。等待、距离、误解、表演、沉默、物件位置与空间准入只要持续改变关系和观众理解，就已经构成推进。

不为连续反转强行堆叠。连续高强度会让观众失去参照；好的压力可以暂时放松，但已经形成的代价、信息和关系状态不能自动归零。

## 九、场次编译

胜出组合进入场次时，继续继承主 Skill 的 `进入 → 施压 → 选择 → 结果 → 牵引`，并内部补齐：

```text
人物当下目标
承重行动或载体
输入状态
精确触发与人物反应
输出状态
观众理解更新
留下的不可逆残留
```

这些是编剧判断，不要求全部作为栏目出现在成品正文。只有会改变下游人物、服装、场景、道具、声音、特效或连续性的事实，进入生产证据账本。

## 十、构件状态与回流

```text
seed：理论、外部样本或单次观察支持，尚无本项目使用证据
observed：多个不同来源重复出现同一状态变化
used：已经进入具体剧本，但还没有真实结果
validated：跨题材使用，且真实生成、剪辑或观众结果支持预期作用
paused：重复证据表明定义、边界或检索方式会稳定误导
```

一次写进剧本不等于验证。真实结果先由 `laohu-generation-review` 判断第一个断点，再由 `laohu-capability-evolution` 决定是否更新构件状态、边界或组合方法。

## 十一、失败门

- 构件只有名称，没有前置、人物理由与输出状态；
- 搜索按题材表面相似排序，忽略戏剧职责；
- 五个高概念轮番登场，却没有前后因果；
- 每个构件各占一场，故事像演示功能；
- 反转要求否认观众已经看见的事实；
- 人物第一次就知道方法错误，却无收益、恐惧或身份原因继续；
- 所有场次都高强度，没有呼吸和参照；
- 构件库无合适候选时自动联网或机械凑数；
- 内部构件 ID、检索分数和分析过程泄露进正式剧本正文。
