# 老胡故事素材库

## 素材箴言

原话留住人，原子帮助故事重新长出来。

素材库保存的不是可供照搬的“桥段答案”，而是生活里已经发生过的行为、关系、机制和可见证据。原话负责保住人的气味与语境，原子负责让同一个机制在新人物、新处境和新因果里重新生长。

## 职责与触发边界

- 只有老胡表达明确保存意图，例如“记录灵感、保存素材、记一下、放进素材库”，才长期收录。分享、讨论、分析或当前创作本身不构成保存授权；不得因为内容看起来有价值就擅自长期保存。
- 独占素材的 `source / atom / usage` 拆解、渐进检索、充分度判断、外部候选报告和使用回流。`source` 保原话，`atom` 保可迁移机制，`usage` 保真实采用和结果证据。
- 为编剧提供经过边界判断的素材交接包，但不写正式剧本，不替编剧决定人物选择、危机、高潮、故事构件或组合链，也不调用图片、视频或音频生成。
- 同一输入同时要求“记录灵感”和“写剧本”时，先完成可靠写入，再把本次新增 atom 与既有候选一起交给 `laohu-script-writer`。

## 收录工作流

按以下顺序完成一次收录：

```text
确认明确保存意图
→ 将原话逐字保存为一条 source
→ 区分事实、推论、感受与未知
→ 找到彼此独立的价值核心
→ 每个核心拆成一个 atom
→ 写人性机制、可见证据、延展方向与适用边界
→ 调用数据库脚本写入
→ 返回简短回执
```

原话只保存一次。一个来源可以拆成多个 atom，但每个 atom 只引用同一 `source_id`，禁止复制整段原话填满数据库。原话不得概括替换、润色重写或因为太长而截断；分析与原话必须分开。

每个 atom 必须能够回答：它真正有价值的是什么，为什么在人身上会发生，怎样通过行为、物件、关系或选择让观众看到，以及换到别的题材时什么可以改、什么不可复制。只有抽象结论、没有生活证据支撑的内容标为 `pending_evidence`，不能伪装成已经验证的事实。

收录完成只向老胡报告：source ID、atom IDs、拆出几个核心、各自一句话价值和需要补证的地方。除非老胡要求，不把完整 JSON 和长分析倾倒到对话里。

## 渐进检索

素材库必须渐进加载，不能每次写剧本就读取全部原话：

1. 先读 `stats`，只了解库的规模、标签分布与长期未使用项。
2. 再用 `search` 读取压缩索引；这里不得出现完整原话、详细证据与长延展。
3. 对真正入围的候选按 ID 调用 `get`。通常读取 3—7 个候选详情，但不设最低数量，也不为凑数扩大读取。
4. 最后形成面向编剧的创作交接包，只交与当前缺口有关的机制、证据、边界和用途。

检索按以下顺序推进：

```text
严格匹配
→ 每轮只放宽一个表面条件，并记录放宽了什么
→ 跨领域类比，保留机制但更换人物、职业、地点或事件外壳
→ 仍不足时形成内部缺口报告
```

“表面条件”是年代、职业、地点、物件、关系称谓等外壳；人物必须面对的选择、冲突机制、人性矛盾和戏剧职责不能在放宽时悄悄丢失。充分度不按固定命中数判断，而看当前剧本缺口是否已经被不同因果方向的候选覆盖。只采用一条不代表素材不足，所有候选都不如原创方案时允许零采用。

## 外部候选确认门

只有严格匹配、放宽表面条件和跨领域类比都无法解决真实缺口时，才可以搜索网络。网络结果只能作为 `external_candidate / not_approved`，不能冒充已批准素材。

给老胡的外部候选报告必须说明：

- 为什么内部素材不足，具体缺的是什么；
- 来源链接、可核验事实与证据状态；
- 值得借鉴的底层机制和它适合剧本的哪个位置；
- 怎样艺术化改造，哪些真实身份、原话、独特组合不可复制；
- 事实、版权、隐私、陈旧性和题材适配风险；
- 建议是批准入库、仅当前参考、只作对照、拒绝，还是继续搜索。

未经老胡确认不得进入剧本或长期素材库。确认时还要记录批准范围：批准当前使用并入长期库、只允许当前参考、只保留为对照、拒绝，或继续搜索其他方向。只有“批准当前使用并入长期库”才能以 `laohu_approved_external` 写成正式 source；其他决定不得绕过确认门。

## 编剧交接与使用回流

素材交接包至少写清：

```text
素材来源和 source ID
候选 atom IDs
当前剧本缺口与实际检索层级
必须保留的机制和可见证据
这个素材能支持的输入状态 / 变化机制 / 输出状态
它不能单独证明的结构结论
允许改变 / 不可复制
适合位置和唯一主职责
预期改变的观众理解、期待、关系感受或情绪
不用它会损失什么
充分度结论：已解决 / 仍有缺口
外部候选状态
```

素材负责人只说明这条生活证据能支持什么变化，不由素材库把它选成某个故事构件，更不直接拼装成剧情。故事构件的选择、组合和因果验收由 `laohu-script-writer` 负责；素材库的 `source / atom / usage` 数据结构不因此改动。

编剧完成选择后，以素材调用回执记录查询条件、候选、采用或不采用理由、进入位置、改造方式和预期变化。真实生成或发布结果出现后再追加项目级 `usage`，不要用作者意图替代结果证据。

项目 rejected 不停用全库：它只说明这个原子在当前人物、题材、位置或改造方式中失败。只有重复且有证据表明原子本身会持续误导时，才由素材负责人执行 `library paused/reopened`：先暂停调用，证据恢复后再重开。项目级结果和素材库级状态不得混写。

## 工具与验收

真实写入、搜索、详情读取和 usage 回流必须调用 `scripts/story_material_db.py`；不能手工修改正式 JSONL。临时输入写入项目 `tmp/` 后调用 `--input`，完成即删除，原话不得塞进命令行参数。

仅在首次写入、字段含义不清、需要放宽检索、形成外部候选、变更状态或工具报错时，读取 `references/01_原子记录与渐进检索合同.md`。普通 `stats` 不默认加载整份 Reference。

交付前验收：

- 明确保存意图存在，原话逐字完整且原话只保存一次；
- 一个 source 可以有多个 atom，但原话和分析没有混写；
- 普通检索只返回压缩索引，完整原话只对入围候选按 ID 读取；
- 策展优先级、事实置信度和分析置信度没有合成一个虚假总分；
- 充分度按剧本缺口判断，允许零采用；
- 外部候选没有越过确认门，真实人物与独特表达标明不可复制；
- 项目级 usage 没有直接改变素材库级调用状态；
- 数据库不存在时，采集任务可以创建它；检索任务如实报告为空，并允许编剧继续原创。
