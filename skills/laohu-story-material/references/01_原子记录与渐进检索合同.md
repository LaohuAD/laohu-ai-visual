# 原子记录与渐进检索合同

本文件只在首次写入、字段不清、放宽检索、外部候选、状态回流或工具报错时读取。普通统计和已有交接包的复用不需要加载全文。

## 一、三种记录和单真源

正式数据库只有 `source / atom / usage` 三种记录，均为一行一个 JSON 对象。

### source：原始素材

| 字段 | 类型与枚举 | 写入规则 |
|---|---|---|
| `record_type` | 固定 `source` | 由脚本生成 |
| `id` | `SRC-YYYYMMDD-NNN` | 由脚本在锁内生成 |
| `created_at` | 带时区 ISO 时间 | 由脚本生成 |
| `original` | 字符串 | 必须逐字、完整、非空；只保存一次，不摘要替代，不截断 |
| `source_type` | `life_observation / short_video / conversation / news / personal_idea / image / audio / other / unknown` | 能从输入确认才分类，否则 `unknown` |
| `source_url` | 字符串 | 有可核验来源才填，否则空字符串；不得猜链接 |
| `source_title` | 字符串 | 原来源有标题才填；个人口述可用中性识别名，不能冒充原题 |
| `fact_status` | `personal_observation / sourced / unverified / fiction / unknown` | 只描述事实地位，不评价故事价值 |
| `curation_priority` | `laohu_selected / laohu_approved_external` | 老胡主动提供用前者；外部候选经明确批准入长期库才用后者 |
| `privacy` | 固定 `private` | 任何 source 都不得改成公开 |
| `rights_note` | 字符串 | 写版权、隐私与可复制边界；无资料时写未知，而非“无风险” |
| `status` | `active / archived` | 默认 active；来源整体不再参与检索才 archived |

禁止写入 `external_candidate` 记录类型，也禁止 `ai_external_candidate` 策展优先级。未批准的网络结果只能留在当前报告里。

### atom：可迁移故事原子

| 字段 | 类型与枚举 | 写入规则 |
|---|---|---|
| `record_type` | 固定 `atom` | 由脚本生成 |
| `id` | `ATM-YYYYMMDD-NNN` | 由脚本生成 |
| `created_at` | 带时区 ISO 时间 | 由脚本生成 |
| `source_id` | 已存在 source ID | 多个 atom 可以指向一个 source，不复制原话 |
| `atom` | 字符串 | 一句话写独立可迁移价值核心；不能只是原文摘要 |
| `human_truth` | 字符串数组 | 人为什么会这样做；证据不足可为空，不得心理诊断式猜测 |
| `mechanisms` | 字符串数组 | 行为、关系、认知或制度怎样产生结果；区分事实与推论 |
| `material_types` | 字符串数组 | 如行为细节、物件、误会、关系动作、制度摩擦、场景质感 |
| `dramatic_functions` | 字符串数组 | 如人物建立、冲突升级、选择压力、反转、回收、余韵 |
| `memory_carriers` | 字符串数组 | 能承载记忆的动作、物件、台词结构、空间变化；不是固定秒数 |
| `relationships` | 字符串数组 | 使用普通关系词；不确定就空数组 |
| `emotions` | 字符串数组 | 写可观察的主要情绪方向，不堆同义词 |
| `themes` | 字符串数组 | 只写材料真正支持的主题 |
| `visible_evidence` | 字符串数组 | 观众能够看到或听到的证据；纯结论不算证据 |
| `extensions` | 字符串数组 | 保留机制后可迁移到哪些新处境 |
| `boundaries` | 字符串数组 | 不适配条件、事实风险、伦理边界与容易误用的方向 |
| `non_replaceable` | 字符串 | 真实身份、独特原话、罕见组合等不可照搬部分；没有也填空字符串 |
| `fit` | 对象 | 记录适合题材、体量、位置或受众；信息未知可为空对象 |
| `fact_confidence` | `high / medium / low / unknown` | 现实事实可信度，不能由“老胡喜欢”代替 |
| `analysis_confidence` | `high / medium / low` | 对机制解释的把握；推论多时降低 |
| `status` | `callable / pending_evidence` | 有足够可见证据才能 callable；只有抽象结论用 pending_evidence |

策展优先级回答“它是否经过老胡选择、与老胡创作经验接近”；事实置信度回答“现实信息有多可信”；分析置信度回答“我们对机制的解释有多可靠”。三者不能合并成总分，更不能让审美优先级掩盖事实风险。

### usage：调用与结果历史

| 字段 | 类型与枚举 | 写入规则 |
|---|---|---|
| `record_type` | 固定 `usage` | 由脚本生成 |
| `id` | `USE-YYYYMMDD-NNN` | 由脚本生成 |
| `created_at` | 带时区 ISO 时间 | 由脚本生成 |
| `atom_ids` | 非空 atom ID 数组 | 只能引用已存在 atom |
| `scope` | `project / library` | 当前作品结果用 project；全库调用状态才用 library |
| `event_type` | project: `shortlisted / used / validated / rejected`; library: `paused / reopened` | 跨 scope 事件非法 |
| `project` | 字符串 | 项目级写作品名或路径；库级可说明触发来源 |
| `script_position` | 字符串 | 出现位置；未采用可空 |
| `usage_role` | 字符串 | 主故事、冲突、人物行为、台词、场景质感、物件、记忆点等 |
| `transformation` | 字符串 | 怎样改变人物、处境和外壳，避免照搬 |
| `result` | 字符串 | 写观察到的结果；没有真实结果时不得伪造验证 |
| `evidence_path` | 字符串 | 真实剧本、剪辑、发布数据或复盘证据路径；没有就空 |

一次项目 `rejected` 只否定当前使用组合，不能暂停原子。只有重复证据表明原子本身或边界会稳定误导时，素材负责人才能写 library `paused`；新证据解决问题后写 `reopened`。

## 二、四层渐进加载

| 层级 | 调用 | 允许输出 | 禁止输出 | 停止条件 |
|---|---|---|---|---|
| 1. 库概况 | `stats` | 数量、可调用数、近期 ID、长期未用 ID、高频标签 | 原话、详细证据、完整分析 | 已能判断查询方向 |
| 2. 压缩候选 | `search` | atom 摘要、关键标签、三个分离判断、usage 摘要、分数 | `original / visible_evidence / extensions / boundaries / transformation` | 有足够不同因果方向的候选，或需要调整条件 |
| 3. 候选详情 | `get --id` | 仅指定 atom、关联 source、相关 usage | 未入围素材、全库原话 | 能判断适配、改造和边界；通常 3—7 条但不设最低数 |
| 4. 创作交接 | 人工编译 | 缺口、ID、保留机制、允许改变、不可复制、职责、预期变化、充分度 | 与当前剧本无关的素材堆叠 | 编剧能够直接选择或明确零采用 |

数据库不存在时分两种情况：采集任务允许脚本创建；检索任务报告素材库为空，但不得阻塞编剧原创，也不得为了“有候选”自动搜索网络。

## 三、查询合同与逐轮放宽

编剧先提供：当前缺口、素材职责、人物关系与选择压力、希望加强的机制或情绪、必须保护的事实、候选需要在哪些因果方向不同、充分标准、禁止套路。

脚本查询格式：

```json
{
  "must": {"relationships": ["父子"]},
  "prefer": {
    "mechanisms": ["用解决实际问题代替直接表达关心"],
    "dramatic_functions": ["character_setup"]
  },
  "exclude_ids": [],
  "limit": 20,
  "per_source_limit": 2
}
```

`must` 是当前不可丢失条件，`prefer` 是排序信号。脚本固定做确定性过滤与评分；“严格、放宽、类比”由素材负责人改变查询合同，不是脚本的隐藏模式。

每轮记录：轮次、保留条件、唯一放宽字段、原因、新增候选、是否解决缺口。顺序固定为：

1. 严格匹配人物关系、选择压力、机制和职责。
2. 每次只放宽一个表面条件，例如地点、职业、年代、物件或关系称谓；不得同时移除机制和职责。
3. 跨领域类比：保留选择结构、人性机制和戏剧职责，替换事件外壳。
4. 仍无适配候选时给内部缺口报告。

充分度看六件事：候选是否真正回应缺口；因果方向是否有差异；是否适配人物；是否存在可见证据；边界是否可控；原创方案是否仍明显更好。可以一条就充分，也可以二十条仍不足；允许零采用。

## 四、外部候选报告与确认

前三轮内部检索仍不足，且用户允许为当前创作查证时，才搜索网络。外部候选报告使用：

```text
【内部缺口】
缺什么 / 为什么现有原子解决不了 / 已放宽哪些条件。

【外部候选】
状态：external_candidate / not_approved
来源与链接：
已确认事实 / 推论 / 未知：
可迁移机制：
适合位置和职责：
艺术化改造：
不可复制：
事实、版权、隐私和适配风险：
建议决策：
```

老胡必须在以下五种决定中明确选择：

1. 批准当前使用并入长期库；
2. 只允许当前参考；
3. 只保留为对照；
4. 拒绝；
5. 继续搜索其他方向。

只有第一种可以写入正式库；第二种只能在当前任务使用并标注来源；第三至第五种都不能进剧本或长期库。任何决定都不能把真实人物身份、受版权保护表达或独特情节组合直接复制成作品。

## 五、脚本调用和错误处理

入口：`scripts/story_material_db.py`。

```text
add-source --input <json-file|->
add-atoms --input <json-file|->
search --input <query-json-file|->
get --id ATM-... [--id ATM-...]
log-usage --input <json-file|->
stats
validate
```

原话或素材详情不得写进命令行参数。把输入 JSON 暂存在项目 `tmp/`，调用成功后删除；不要长期保留第二份原话。脚本成功返回 UTF-8 JSON；校验失败返回码 2；文件系统错误返回码 1。遇到错误先保留原数据库，修正输入后重试，不手改 JSONL。所有写入先整库验证再原子替换，失败不应留下半条记录。
