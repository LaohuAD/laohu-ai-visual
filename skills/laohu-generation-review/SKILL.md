# 老胡生成与发布复盘

## 复盘箴言

复盘不是给失败起名字，是找到最早走错的那一步。

成片最后暴露的问题，未必发生在最后一环。复盘先看真实结果，再沿生产链向上追到第一个断点；保护已经成立的部分，只把返修送回最早负责人。

本能力仅在明确复盘或诊断路由时调用，不作为正常生产固定步骤。只有老胡明确要求复盘、比较或诊断，或总控收到真实图片、视频、剪辑、封面、发布数据与明确可见问题后把任务路由到这里，才执行本 Skill。正常生成完成后不自动要求A/B、盲测、多模型对比或复盘；没有真实结果时也不为了流程完整伪造诊断。

## 输入与证据

先登记：

```text
反馈类型：图片生成 / 视频生成 / 剪辑 / 封面 / 发布 / 用户主观反馈。
作品与阶段：
原始输入、提示词和资产位置：
模型、参数与字符实测：
真实结果位置或用户描述：
用户最不满意的可见问题：
下一步意图：继续生成 / 剪辑 / 返修 / 发布 / 规则更新。
证据完整度：完整 / 部分 / 口述初判。
```

缺什么写“缺”。没有原提示词、实际参考、结果或数据时只能给暂定诊断，不能虚构平台原因、模型限制、观看数据和用户反应。

设计意图与真实证据分开：

- 生成前计划说明作者想得到什么。
- 成片、截图、波形、时间码和平台数据说明实际发生了什么。
- 用户偏好说明是否喜欢，不自动证明客观原因。

## 首断点归因

### 第一次观看重放

评分前把成片当作第一次看，不用剧本替它补答案。按播放顺序记录：

封面真实结果先按目标平台和实际缩略图尺寸重放，不能只看大图细节。除第一落点和文字准确外，逐项登记`标题位置`、`主体是否居中`、承重内容与画布的`边界距离`、以及`摄影机视角`是否可信。日常自媒体封面若没有系列母版或内容证据支持破格，标题压底、文字或脸贴边、主体视觉重量明显偏离中轴、用超广角畸变或斜切冒充冲击力，都先判为封面设计断点；不能用“还能读”“有氛围”放行。

其中把`人物目的与动作一致性`和`省略重建`作为连续性硬检查：人物手上的选择必须有因，镜头跳过的过程必须能由已经出现的动作目标、道具状态、空间方向和后镜结果补齐；出现悬空、瞬移、无因易手或必须靠作者口头说明时，先判断裂，再追最早负责人。

```text
我此刻实际知道什么。
我暂时相信什么。
我正在等什么，是否还有继续看的理由。
我预测下一步是什么。
眼睛和耳朵第一时间落在哪里。
我与谁情绪对齐，是否感到目标、代价、空间与身体变化。
切镜后是否知道人物、道具、方向和事件仍处于什么状态。
人物的台词、目的与手上动作是否互相证明；表面矛盾是被镜头解释的两难，还是无意逻辑错误。
被省略的路程或动作能否仅凭前镜决定、跨切载体与后镜结果重建；是否藏掉了新的选择、阻力或物体状态变化。
```

找到第一个断点：预测断裂、注意力误导、情绪对齐丢失、信息过早 / 过晚、事件边界模糊、动作因果断裂、资产走样或连续性断裂。后面的缺点可能只是连锁后果，不要平均返修所有层。

### 从表象返回最早负责人

| 可见问题 | 先检查 | 最早负责人可能是 |
|---|---|---|
| 看不懂人物为什么做、高潮不重、台词假 | 目标、信息、选择、代价与场次结果 | `laohu-script-writer` |
| 剧本加入了真实细节却不适配人物、改造后丢失原机制、多个记忆点互相竞争或素材误导事实 | 先比较素材交接包、正式剧本位置与真实结果，区分素材本身、检索选择、编剧改造和下游执行 | 当前作品返编剧；只有素材选择或适用边界确为首断点时交 `laohu-story-material` 追加项目级 usage，不能直接暂停全库原子 |
| 遮住题名和身份后不像主类型，或人物、服装、场景各自成立却不属于同一视觉世界 | 题材视觉合同、视觉证据矩阵、形态色彩材料光影系统、相邻类型测试和跨部门分发 | 交接包缺失或方向错误交`laohu-art-direction`；方向正确但专业设计未兑现时交对应人物 / 服装 / 场景 Skill；设计正确而生成漂移才交`laohu-visual-assets` |
| 人物单看好看却同脸同体型、面相替代人格、姿态动作不属于角色、群像或跨媒介身份设计错误 | 人物核心事实、选角与身体化候选、第一印象合同、稳定动作语言、群像矩阵与媒介母版 | `laohu-character-design` |
| 人物设计已经正确，但脸身、产品、空间、材质或时代在生成中走样 | 资产编译、依赖、引用职责与实际绑定 | `laohu-visual-assets` |
| 局部遵从但整体僵硬：指令高度遵从，但人物像动作演示或目录照，关系、整体气质与画面呼吸下降 | 先检查上游设计是否成立；成立后检查视觉资产是否把方向引导和模型补全错误升级为必须锁定 | 回到`laohu-visual-assets`的选择性编译；不默认增加微表情、肢体和摄影细节 |
| 服装合理却平庸、资源与展示等级不符合身份场景、精美只靠形容词或堆饰、与人物身体矛盾、全员同袍换色 | 服装情境判断、财富 / 权力 / 技术来源、人物选择、叙事策略、方向确认记录、远中近景价值证据与设计交接包 | 情境等级或胜出设计错误交`laohu-costume-design`；设计已经确认而生成丢失材料、工艺、配饰或功能证据，或W/M版式绑定错误，才交`laohu-visual-assets` |
| 镜头平、动作跳、声音错、特效无来源、转场断 | 起点、触发、屏幕变化、声画事件与结束状态 | `laohu-video-prompt` |
| 人物说一套做一套却无潜台词、拿错物、物体悬空 / 瞬移 / 易手 | 人物即时目的、道具叙事职责、起点支撑、控制权、受力路径、结束支撑与剪辑省略 | 剧本因果不成立交 `laohu-script-writer`；镜头未编译交 `laohu-video-prompt`；资产缺结构或空间落点交 `laohu-visual-assets` |
| 提示词通过底线但主视觉、峰值或作品身份仍普通 | VC 是否真实执行、是否比较更强候选、视频巅峰门是否错误放行 | `laohu-vibe-creating-prompt` / `laohu-video-prompt` |
| 封面好看却不想点、标题与正片不符，或标题压底贴边、主体失去稳定中心、摄影机视角失衡 | 内容事实、点击承诺、第一落点、标题权限、标题位置、主体是否居中、边界距离、摄影机视角与承诺兑现 | `laohu-cover-design` |
| 成片可用但剪辑接口、入点、出点或声音桥不成立 | 实际时间码、状态、匹配属性与把手 | `laohu-generation-review`，必要时返回视频 Skill |
| 有点击但低完播，或有完播但低点击 | 分开检查封面入口与正片兑现 | 封面 / 编剧 / 视频对应负责人 |

只有上游输入和约束已经清楚、实际绑定正确、提示词可执行，而模型仍偏离，才归为模型执行限制。

素材回流必须分权。单次项目级 `rejected` 只证明这个原子在当前人物、题材、位置或改造方式中失败，不能直接暂停全库原子。只有相同失效机制重复出现、证据充分且确实影响素材库级可调用性时，复盘才建议 library `paused`，并把证据交给 `laohu-story-material` 执行；新证据解除风险时由素材负责人写 `reopened`。复盘负责提交证据，不直接改库级状态。

### 特殊链路

跨 VID 必须对照 A 最后有效机位、真实参考截取、B 正式提示词和 B 第一个有效画面。把计划结束状态改为 A 的真实结束状态，再检查：

```text
A 真实结束状态：
B 起点状态：
状态等式：通过 / 不通过。
B 是否从下一相位开始：
参考是否只含一个有效机位：
允许生成 B / 改截取 / 改 B / 返修 A：
```

`提示词不是唯一变量`。当正文已经明确站位、起点、触发和下一相位，而同一问题仍重复出现时，先`停止同义词重写`：不再把“保持站位”轮换成“锁定位置、空间一致、人物不变”，而是检查目标入口、实际输入、GEO切片、参考职责、首帧阻挡、状态帧 / 尾部视频、参考强度、生成模式和随机性。只有发现正文缺少可见控制时才回视频 Skill 改词。

跨 VID 的参考先过`连续性把手质量门`：

```text
接续类型是否选对：空间 / 表演 / 动作 / 艺术 / 因果声音 / 场景重置。
把手是否只含一个连续有效机位，没有硬切前后的冲突画面。
人物、服装、道具、空间与光影是否属于A的真实正确结果。
把手是否比稳定资产新增了正确的站位、破坏、运动相位或表演余韵。
B是否声明只继承哪些属性，并从第一项新变化开始。
结论：可用 / 改截取 / 改用终帧+稳定资产 / 返回A / 场景重置不引用。
```

需要继续试验时建立`单一变量实验账本`，其目的不是强制正常生产做A/B，而是在已有真实失败且原因不明时减少无效付费生成：

```text
固定基线：模型 / 入口 / 模式 / 参数 / 提示词 / 资产 / GEO / 首帧 / 把手 / 随机种子（若可用）。
本轮唯一变化：尾部视频长度 / 终帧 / 首帧阻挡 / 某一参考职责或权重 / 某一局部提示词控制 / 入口模式中的一项。
假设：为什么这一个变量可能造成当前可见失败。
通过标准：哪项人物、空间、动作、表演或声音结果必须改善；哪些已成立部分必须保持。
结果与证据：成功 / 失败 / 混合；样本与日期。
下一步：保留 / 撤回 / 再测另一变量 / 证据不足停止。
```

同一轮同时改提示词、参考、构图、参数和入口，无法证明哪个机制有效。偶然一条成功也不自动变成长期规则；先作为当前作品证据，达到能力进化门槛后再交`laohu-capability-evolution`。

真实尾帧或抽帧在进入下一VID前执行状态帧质量门：

```text
人物身份与脸部：同一人，五官、发型和阶段形体没有漂移，手脸无畸形。
服装与道具：当前W/M和关键道具结构、颜色、数量、左右与状态正确。
空间与锚点：稳定场景拓扑、主空间锚点、入口和固定构件没有漂移。
画面质量：没有错误文字、随机物、运动模糊、异常曝光、严重压缩或不可解释遮挡。
状态价值：破坏、站位、临时光影、摄影方向和结束相位确实比稳定资产提供更多有效连续信息。
结论：可作为临时状态帧 / 需改截取 / 返修A / 返回稳定资产重建。
```

通过不等于升级资产。只连接一个相邻VID时作为临时参考，并与稳定人物、服装、道具和场景资产共同形成双参考；同一状态跨多个VID或反复调用时，交回 `laohu-visual-assets` 整理成正式场景状态资产。任何明显错误不得因“保持连续”继续向下传播。

首尾帧模式按端点输入、不变量、变化量、中间状态、摄影机路径、尾帧召回与收束定位。动作 / 奇观按运动方向、速度、接触、材料响应和永久结果定位。商业内容把视听质量与转化质量分开，额外检查需求命中、核心承诺、卖点证据、文案同步、品牌与行动。

## Reference 路由

主体先定位第一个断点，再按证据读取：

| 证据 | 读取 | 解决什么 |
|---|---|---|
| 需要外部来源或专业校准 | `references/00_资料来源与专业校准.md` | 结论依据与边界 |
| 图片、视频、资产、提示词或生成失败 | `references/01_图片与视频生成诊断.md` | 问题来自上游设计、提示词还是模型执行 |
| 时间码、剪辑、跨 VID、状态或素材接口 | `references/02_剪辑连续性与素材接口验收.md` | 哪些片段可用、怎样连接、哪里返修 |
| 封面、标题、发布数据、完播与评论 | `references/03_封面与发布漏斗复盘.md` | 卡点位于点击、开头、中段、完播还是互动 |

同一任务可以沿证据链读取多份，但不把所有检查表强加给一个局部问题。

## 返修与回流

### 保护已成立部分

先写可用部分，再写失败部分。返修不允许为了修一个动作，顺手换掉已经稳定的脸、构图、台词、节奏和色彩；也不允许因为已经花钱生成，就继续用错误状态向下放大。

### 最多三个动作

返修按收益和因果排序，最多三个：

```text
立即修：不修就不能继续的最上游问题。
下版测：一个明确变量和通过标准。
沉淀资产：只有跨作品可复用且证据充分时进入长期规则。
```

每个动作写清最早负责人、修改位置、保护项、预期可见变化和验证方法。不要把“提高电影感、加强情绪、优化节奏”当作返修动作。

### 经验回流与能力进化交接

一次反馈先成为证据，不自动成为永久规则。复盘只负责证明真实结果、定位第一个作品断点并形成交接包；需要改变长期能力时，交给 `laohu-capability-evolution`：

```text
原结果与原规则：
可见问题：
证据指纹：负责人 + 阶段 + 症状 + 候选机制。
第一个断点：
最早负责人：
改动假设：
可能伤害的旧能力：
代表性行为验证：
证据完整度与不确定性：
建议更新范围：当前作品 / 待验证经验 / 长期能力。
```

当前作品能直接修复的，返回对应业务 Skill；跨作品复用、重复出现、涉及规则冲突或明确要求沉淀的，调用能力进化 Skill。复盘只交证据包，不直接写能力进化台账；由能力进化 Skill 检索旧记录、合并或重新唤醒证据，选择受影响层、找到唯一规则负责人、实施行为验证并给出 `KEEP / OBSERVE / REVERT`。复盘不能绕过这一入口直接把一次结果写成永久禁令。

## 输出合同

复盘默认更新当前作品 `09_归档复盘.md`：

```text
【证据与结论】
反馈类型 / 证据完整度 / 成功、半成功或失败 / 是否值得继续。

【第一次观看重放】
实际认知 / 等待 / 预测 / 第一注意力 / 情绪对齐 / 第一个断点及证据。

【首断点归因】
最早负责人 / 原因链 / 模型限制是否成立 / 需要保护的成功点。

【真实素材验收】
可用入点、内部节点、出点、时间码、匹配属性、干净把手和禁切区；没有素材则 N/A。

【最多三个返修动作】
负责人 / 修改位置 / 动作 / 预期变化 / 验证。

【下一版修正】
需要时给完整修正提示词；上游事实不足时说明返回条件，不猜写。

【入库与回流】
当前作品 / 共享案例 / 返回业务负责人 / 交给 laohu-capability-evolution / 不升级，以及理由；需要能力进化时附证据包、保护项和允许范围。
```

没有真实发布数据时，只评视觉、叙事、承诺和可用性，不写“点击率会更高”。

“可用”只描述底线状态，不是正向质量结论。结果没有硬伤但平、俗、像模板、没有决定性瞬间或无法让目标观众记住时，仍然属于明确的质量失败；复盘必须沿导演选择、Reference 调用、VC 比较和巅峰门追到最早放行点。

## 证据验收

- 是否保留并引用原输入、原提示词、实际资产和真实结果。
- 是否从第一次观看出发，而不是从作者意图倒推成功。
- 是否定位第一个断点，而不是罗列所有缺点。
- 是否找到最早负责人，而不是把所有问题归给模型或最后一环。
- 是否分开世界状态、屏幕投影、剪辑接口和模型执行。
- 是否逐镜复原人物目的与承重道具状态；跨切省略是否可由观众重建，而非由作者解释补洞。
- 是否保护已成立部分，返修没有扩大无关变量。
- 是否只给最多三个高收益动作，每个都有负责人和可见验收。
- 商业内容是否有卖点证据，封面是否兑现正片，发布漏斗是否按数据分段。
- 暂定诊断是否明确标注证据不足。
- 长期经验是否交给能力进化 Skill 验证，再写回唯一负责人。
- 复盘文件和下游动作是否足以让下一轮直接执行。
- 是否把“没有错误、可以使用”误判成成功；对于平庸结果，是否找到哪个巅峰门错误放行，而不是只说审美主观。
