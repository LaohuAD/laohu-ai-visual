# 老胡视觉资产

## 导演协作接口

公开作品继承`导演阐述`中的主胜负手、观看重点、视觉主次和跨部门保护项。本 Skill 可 `CONSULT` 美术、人物、服装、场景和视频节点，判断哪些对象需要稳定、怎样绑定、什么状态能被下游使用；调用不转移主责。资产只固定已经确认的视觉身份，不改写剧本事件、人物调度或导演命题；发现上游缺口时返回最早负责人。

## 资产箴言

一张图负责惊艳，一套资产负责不走样。

资产不是画面里出现过的名词，也不是一张漂亮图片的别名。它是跨生成请求仍要保持同一个身份、结构、空间、材质、关系或状态的生产基准。

文件名帮助生产，真实像素决定画面是什么。正式图片只有在观众实际看见的内容与任务一致时，才获得下游调用资格。

## 输入与责任

资产负责人可`CONSULT laohu-language-mode`区分`ASSET_SPEC`与`IMAGE_PROMPT`。前者写跨请求需要稳定的身份、结构、材质、依赖、可变边界和禁止项；后者把已经确认的对象编译成模型能生成的一张静态时刻。调用不转移主责，语言模式不替资产 Skill 判断是否资产化、怎样设计或使用哪种图片模型；内容不足、设计未定案或图片任务与真实资产冲突时返回原负责人。

资产规格和图片正文完成后读取[有效信息与冗余裁决](../laohu-language-mode/references/05_有效信息与冗余裁决.md)。必要信息保护门先保住身份锚点、依赖、变体边界、主体绑定、空间和决定性静态时刻；边际作用门再检查每个属性是否能排除一个具体错误结果、稳定跨请求身份或改变当前单帧像素。不能排错的抽象赞美合并或删除；需要时间才成立的完整过程迁移给剧本或视频；设计本身未定时返回原负责人。

本 Skill 读取已确认剧本、场次、镜头任务、`MV导演交接包`中的`MV分镜资产任务`、美术风格设计交接包、人物连续性、人物设计交接包、服装设计交接包、场景与布景设计交接包、当前资产与真实生成结果，回答五个问题：

1. 什么必须保持同一个。
2. 什么只服务当前镜头，不值得资产化。
3. 这些资产怎样先设计、再生成、再组合。
4. 下游怎样引用，才能只继承该继承的部分。
5. 如果结果只为当前这一眼成立，怎样把人物、摄影机、环境和决定性瞬间组织成真正的成品图。

对普通叙事作品，剧本拥有事件、人物调度、世界站位、画面关系、入画退出、道具控制权和镜尾结果。本 Skill 把剧本及人物、服装、场景、道具、美术等专业设计中需要跨请求稳定的部分固化成可引用视觉形态；它可以为身份、结构、材质、空间锚点和操作面补足生产证据，也可以在资产无法支持既定动作时返回上游，但不得借人物照、场景图、道具图或叙事首帧重新安排剧情与站位。

本项目默认只交付资产定义或成品图设计、图片提示词、生成顺序、验收和调用说明，不直接生成图片。老胡明确要求调用生成工具时，真实候选仍要经像素验收与人工确认，才能标为可调用资产或已完成成品图。生成工具强制产生在默认目录的项目图片，必须在当轮移动到当前作品`03_视觉资产/图片/`下的对应类别目录；移动前校验目标文件完整性，移动后确认默认目录不再保留重复副本。

若`美术风格设计交接包`已经包含胜出形式转译卡，本 Skill只消费参考职责、具体保真不变量、来源关系和形式结果，再把它们编译进正确图片外壳；不得重做候选、另选艺术命题或把外部样片表面当成新方向。没有参考分析、艺术转译或来源关系任务时，不强制读取参考图形式转译 Reference，也不伪造形式转译卡。

歌曲型作品中，MV 导演负责歌曲事实、导演命题、创作段落、声画关系、表演策略、制作时间线和每个单元为何需要图片；本 Skill 只把已经确认的`MV分镜资产任务`编译成图片提示词与参考职责。按单元选择最低充分模式：`单帧`锁定决定性起点或表演状态，`首尾帧`分别锁定承重起点与完成态，`多关键状态`只用于多个不可合并的视觉阈值。不得把固定格数、固定时长或某个平台的输入方式写成通用规则，也不得为了方便生图重切歌曲结构。

## 资产关系

### 先判断资产，后决定图片

候选对象先回答：

```text
复用范围：会出现在哪些独立镜头、场次、集数或作品。
叙事职责：它证明身份、关系、卖点、世界规则还是空间方向。
失真代价：走样后观众会不会认错、出戏、误解或无法剪接。
正文替代：只靠当前视频提示词能否稳定说清。
下游调用：哪一个具体环节会怎样引用它。
```

只有“它出现过”，没有失真代价和下游调用，就不建资产。删掉它仍不影响身份、空间、剧情锚点和连续性，就降级为镜头画面元素、单张成品图或临时参考图。

最低可行资产优先于资产齐全。资产越多，生成成本、引用冲突和维护成本越高；少一个会失控才保留，不为目录整齐建立成套图片。

一次性整段文生视频设有直接文生视频轻链路。若人物、服装、场景和物件只服务同一次生成请求，当前视频提示词已经能给出充分的身份与状态正文，用户现阶段要验证的是故事、节奏或效果而非跨请求连续性，则跳过F / B / W / M / S / A图片资产，直接把必要设计正文和操作合同交给`laohu-video-prompt`。不能因为主角会出现在多个内部切镜里，就自动把同一次生成误判为跨请求复用；只有后续确有系列复用、独立生成单元拼接、图生视频绑定，或真实结果已经暴露高代价身份漂移时，才重新进入资产判定。已经生成但随后被轻链路替代的候选图标记为弃用试验记录，不再阻塞下游，也不冒充已验收资产。

“最低可行”只限制资产数量，不降低单项设计质量。少做一张，是为了把预算集中到真正承重的资产；留下来的每一项仍要经过设计竞争、人物 / 产品 / 世界关系校准和下游压力测试。数量精简不能成为轮廓普通、材质敷衍、人物平均、构图模板化的理由。

### 三类结果

| 结果 | 用途 | 必要内容 |
|---|---|---|
| 稳定资产 | 跨请求保持身份、结构、空间、材质或关系 | 编号、固定项、可变项、依赖、提示词、验收、下游调用 |
| 成品图 | 当前观看、发布或人工定调，如人物主视觉、封面主体、首帧、海报、氛围图 | 当次观看结果、决定性瞬间和提示词；可被人工选为后续源图，但不因此变成稳定资产 |
| 临时参考图 | 只为一个镜头、构图、测试或下一项正式资产的生成服务 | 清楚标记唯一消费者和失效时点；不得继续向消费者的下游传播 |

资产图片可以很美，但它首先要换角度仍是同一个对象；成品图可以只为这一眼成立。两者的验收不能混用。

#### 请求类型路由

图片提示词不是同一个“主体 + 风格 + 画质”模板。先问这张图下一步要控制什么，再选择外壳；同一作品可同时需要多种路由，但每张图只能有一个主要任务：

| 路由 | 主要用途 | 必须证明 | 不能越权 |
|---|---|---|---|
| 身份母版 | 跨请求稳定人物、群像或生物身份 | 脸身拓扑、比例、稳定辨识和允许阶段变化的边界 | 不自动决定剧情站位、摄影构图和瞬时表演 |
| 地点拓扑 | 稳定场景结构与行动关系 | 入口、固定锚点、方向距离、路径、遮挡、功能区和可变状态 | 不把一次性人物站位或临时光影冻结成空间本体 |
| 道具结构 | 稳定关键物件、产品、武器或可操作部件 | 轮廓比例、材料、连接、活动件、操作面、握持 / 使用方向 | 不用漂亮产品照代替真实操作与受力证据 |
| 局部受控编辑 | 在已确认图片上只改变一个明确区域或属性 | 变化区的新结果、保护区的不变证据、输入图 / 遮罩职责 | 不借局部修改重做整张图或顺手美化其他区域 |
| 叙事首帧 | 为视频建立一个正在发生的起点 | 人物关系、世界与屏幕站位、动作预备态、首个异常、阻挡和下一变化 | 不退化成中性资产板，也不把尚未发生的结果提前画完 |

#### 正式图片像素验收门

STY、VMB、KF 或其他真实图片不能凭文件名、提示词、生成任务名称或项目状态自动通过。登记为正式资产、正式成品图或正式视频参考前，必须打开实际文件完成`正式图片像素验收单`：

```text
资产编号与绝对路径：
验证状态：正式候选 / 草图 / 未验收。
目标语义：这张图按上游任务应当让观众看见和理解什么。
真实像素语义：不看文件名，只根据实际画面复述主体、关系、流程和结论。
目标语言与实际文字：目标受众语言；画面实际出现的标题、标签、英文、乱码或占位。
第一视觉重点：缩小前后首先读到什么，它是否服务目标语义。
手机可读性：按目标发布尺寸缩小后，承重标题、关系和对象是否仍能辨认。
生产编号 / 占位文字泄漏：是否出现内部编号、临时英文、样本原字、Logo或模型伪字。
文件身份一致性：文件名、资产表职责与真实像素语义是否同一段、同一对象、同一状态。
正式视频参考资格：通过 / 返修 / 仅作草图；明确唯一消费者和失效时点。
```

`目标语义`与`真实像素语义`不一致，或文件名与真实内容不一致时，直接失败并停止登记；不得通过改表述把错图解释成正确文件。KF04 与 KF05 一类内容对调必须在这里被拦截，二者都不能继续下发批次。

正式观众画面禁止出现仅供生产定位的`KFxx / STYxx / VMBxx`等内部编号。目标受众为中文时，`AIGC`、`AI`等内容本身需要的英文缩写可以保留；`SOFTWARE`、`MODEL`、模板标题等英文临时占位只有在它们本来就是确认内容时才允许。生产编号、英文临时占位、乱码、样本原字或未确认标签一旦成为第一视觉重点，正式验收失败。

草图允许保留生产编号或临时占位，但必须隔离为`草图 / 未验收`，登记唯一用途和失效时点，不能下发视频、封面或发布链。风格方向可用不等于知识终帧可用；STY只验风格职责，VMB验跨段语法，KF验当前段落知识关系，三者分别打开真实图片验收，不能互相背书。

这道门只在风格仍未确认且真实视觉选择会影响整批下游时生效。已有经人工确认的VMB、已有系列母版、用户锁定完整风格，或普通写实镜头只需继承既有作品成像合同时，直接进入稳定生产，不为流程整齐重复竞稿。若只有一张用户选中的风格图但缺少可执行母板，先编译VMB，不重复竞稿。

身份母版、地点拓扑和道具结构属于稳定资产分支；叙事首帧属于镜头状态或成品图分支；局部编辑属于已有图片的变更分支。先分流再调用人物、服装、场景、道具、摄影和注意力 Reference，避免让一个漂亮参考图同时控制身份、构图、空间和动作。

### 依赖顺序

资产不能作为人物、道具、场景、风格四张孤立清单。写提示词前建立无环依赖图：

```text
全局锚点：固定 Logo、世界材质、色彩关系、主成像基底。
独立锚点：人物身份、关键物品、空置基础场景。
组合结果：最终造型、穿戴关系、布置后场景、人物与产品 / 坐骑 / 车辆关系。
镜头状态：首帧、尾帧、故事板和具体动作状态。

群像身份图与叙事调度图分权：正面集体合照只负责成员身份、五官、发型与身高体型差；复杂多人正片另用镜头首帧、故事板或clay render负责世界位置、屏幕层次、姿势、运动路径和摄影机轴线。身份校准图不能越权成为默认叙事站位。
```

这不是固定四级目录。根据项目风险裁剪，但下游资产必须排在全部上游之后。出现循环引用时拆清职责，不能靠调整排版掩盖。

每条依赖写清：

```text
下游资产：
上游参考：
上游只负责：身份 / 结构 / 材质 / 比例 / 空间 / 色彩 / 佩戴关系中的具体项。
禁止继承：背景、临时表情、一次性动作、无关服装或构图。
生成前置：上游图片是否真实存在并已验收。
变更传播：上游变化后哪些下游必须重验。
```

#### 上游变更失效门

资产一旦被下游引用，就不能把“上游文件已经改了”误当成“下游已经自动更新”。任何会改变身份、阶段体型、疾病 / 伤势、服装、妆造、道具结构、场景拓扑、锚点、材质或色彩的上游修改，都先做反向依赖审计：列出直接消费者与传递消费者，逐项判断改动影响哪些字段、哪些图片提示词、哪些M / 首帧 / 故事板 / 批次 / 封面和哪些已生成素材。

受到影响的消费者立即标记为`待重编译 / 待重验`；旧图片、旧视频和旧抽帧只保留为历史证据，不能继续代表当前资产状态。每个消费者只能以两种方式关闭：正文和绑定职责已经同步修改并重新验收；或明确证明本次上游变化不进入该消费者的可见范围，并记录理由。只改资产表、不更新消费者，或只改一个被用户指出的批次而未枚举同资产的其他调用，均不得标记阶段完成。

反向依赖回执至少包含：`变更资产与字段 → 直接 / 传递消费者 → 每个消费者的处理动作 → 已生成结果是否失效 → 复验结果`。组合资产还要重新仲裁属性权威：同一人物的身份、阶段脸身、疾病肤色、服装、妆发和瞬时表演各自只允许一个主负责人；下游参考可以补充其他属性，不得把上游已经确定的阶段状态重新平均回健康母版或默认状态。

### 全画面闭合

图片标题写“丈夫资产”，不代表画面里只会出现丈夫。写提示词前盘点所有可能被模型画出的可识别对象：人物、关系人、服装、穿戴物、手持物、Logo、屏幕、倒影、家具和背景人物。

每个对象只选一种处理：

- 已有确认图片：显式引用并限定职责。
- 尚无图片但必须出现：从同一规范词账本复现身份、数量、位置、颜色、材质和状态。
- 本图不需要出现：通过构图、画外方向、遮挡或空场让它不进入画面。

不能写一句关系动作，让模型自由补出一个错误的人，再把错误继续传给下游。

#### 引用也要闭合

全画面引用闭合不只检查“有没有参考图”，还要检查每张参考只控制什么。凡是画面中可识别对象由参考资产承担，必须同时写清：实际绑定文件、身份 / 结构 / 材质 / 比例 / 空间 / 色彩中的职责、禁止继承的背景与瞬时状态、当前剧情时间状态，以及它是否已经真实生成并验收。上游尚未生成、只存在文字定义时，不得在下游提示词里伪装成已绑定图片。

每张参考使用同一个`参考职责合同`：

```text
绑定对象 / 主职责 / 次职责（可选） / 必须保留 / 允许改变 / 不得继承 / 失效时点 / 验证状态。
```

每张图只设一个主要职责。身份参考不自动继承构图、背景与瞬时状态；结构参考不继承占位色、编号和示意文字；风格参考与版式参考不继承原主体、品牌、原文字和精确组合；辅助插入不能反过来接管整张图。必须保留、允许改变和不得继承互相冲突时，先返回美术方向澄清，不把矛盾交给模型平均。

交给具体图片或 批次 时，不转发整个资产库，而是形成`激活参考候选`：只列当前请求真实可能绑定、能降低承重失真的少数参考，并逐项写主职责、不得继承、验证状态和与其他参考的属性仲裁。候选不是已绑定；下游根据目标入口可接收类型、参考数量、构图权重和当前镜头任务再次裁决，最终只有实际上传 / 调用的项目进入`【基础设定】`。未生成占位、与本镜无关的角色场景服装、重复控制同一属性的参考不得进入运行上下文。

组合画面需要的关系人、穿戴物、手持物、布置结果和倒影，不能因为主体资产已经存在就自动视为闭合。每一个会被模型补画的对象都要么有确认参考，要么有同一规范词账本，要么通过构图明确不出现。

### 状态不能混成身份

稳定身份、持续阶段和瞬时表演分开：

```text
稳定身份：脸、体型、永久结构、固定空间和不随剧情变化的锚点。
持续阶段：会跨多个独立片段保持的服装、伤势、污染、变身或破坏状态。
瞬时表演：眼神、呼吸、动作受力、哭笑、抬手、摔落和本镜光影。
```

持续阶段是否做图片由复用与失真代价决定；瞬时表演交给分镜和视频提示词。互斥状态不画进同一资产，让模型自己融合。

### 故事时间账本与换装判断

人物跨越多日、季节、成长、增减重、治疗、受伤恢复或身份阶段时，先按真实故事时间建立 `故事时间账本`，再按剧本和剪辑顺序调用。剧本先写学校、后插入医院回忆，不代表学校发生在初诊之前；如果不先还原真实时间，身体、服装和伤病会被错误地按文档顺序继承。

账本只登记会改变资产或镜头状态的事实：

```text
故事阶段 / 与上一阶段的时间距离：
年龄、身高与人物阶段状态：
持续身体变化、伤病或污染：
场景功能与季节天气：
当前最终造型与服装尺码：
哪些镜头属于必须连续的同一天 / 同一行动：
允许变化 / 必须不变 / 变化证据：
```

`人物阶段状态` 用于同一身份在多个独立片段中持续存在、且仅靠正文容易漂移的体型、年龄段、康复期、伤病期或形态阶段。它引用同一身份，只固定该阶段的脸部软组织、身体轮廓、比例、体态和运动限制，不固定戏服、最终发型、妆容、剧情表情和场景。它在图片职责上就是阶段素体资产：完整继承B的校准板信息结构，而不是另做一张普通身体三视图。身份资产不锁最终服装，也不把某一阶段体重冒充永久身份。

换装判断只看三项：故事时间是否跨越到合理换衣节点；地点和活动功能是否需要不同穿着；相邻镜头是否属于必须保持的直接连续。跨日、跨季节、学校到家庭或医院复检通常需要重新判断；同一天从诊室走到回家路通常保持同一套。禁止为了资产丰富每场必换，也禁止为了省资产让角色数月一直穿同一件衣服。

时间账本一旦跨季节，季节不能只留在表格里。每个W先写`适用时间戳`和`环境热条件`，明确T阶段、具体天数或直接连续关系，以及室内外、昼夜、空调、活动量与职业 / 医疗环境；再把季节证据传给W与M：层数、覆盖面积、面料克重与表面、袖裤长度、鞋袜和穿法至少有三项共同变化。身体阶段只决定版型、尺码和松量；季节阶段决定层数、覆盖和材料性能；人物身份决定设计语言；场景动作决定开合与活动余量。四类原因不得互相替代。室内空调、职业制服或医疗要求允许保留长裤与薄外层，但必须在`环境热条件`中说明其功能，不能让厚卫衣、抓绒或保暖外套无理由跨入盛夏。若同一W跨两个非连续时间点复用，必须逐一列出时间戳，并证明机构规范、恒温环境和人物状态足以让服装结构保持不变。

## 美术与提示词

### 先选设计，再锁一致

稳定只能保护设计，不能把普通设计变高级。没有参考图时，先围绕当次作品竞争 3—5 个真正不同的方向；差异落在受众承诺、轮廓比例、形状语言、材质、配色、选角、空间语法或视觉记忆点，不只是换滤镜。

选择前建立：

```text
作品类型与观看情境：
目标受众为什么愿意靠近、相信、购买或记住：
资产在故事或商业表达中的职责：
第一眼感受或欲望：
形状、比例、材质、色彩、妆造与空间怎样同向：
一个远看可认、近看可记的视觉记忆点：
同类最常见的平均答案，以及本案为什么不取：
```

这组判断是资产美术指导门。它必须在批量写提示词和锁一致性之前完成：先比较已确认人物设计、产品轮廓、形状语言、材质、配色、空间和记忆点怎样共同服务作品承诺，再选定一套方案。只得到“高级、电影感、统一风格”或若干互不冲突的形容词，说明设计尚未成立；此时不能进入资产批量生产。人物选角和身体化尚未确认时，不在本门临时补选，先返回`laohu-character-design`。

材料不靠稀奇取胜，也不靠私人专属自动深刻。选材看承载力：它能否说明人物、功能、世界规则或公共经验；换成同类平均材料后，关系和结果是否变弱。宏大环境可以有公共尺度，小物件可以有亲密证据，两者按作品用意选择，不预设大小。

### 人物、场景与物品

#### 美术方向调用门

视觉资产不负责从零决定作品题材风格。新作品、混合题材、系列首批F / W / S，或真实生成结果在`去标签测试 / 去背景测试 / 相邻替换测试`中落入其他题材时，先调用`laohu-art-direction`取得包含`风格先验与美术锚点`的`美术风格设计交接包`。视觉资产随后只做三件事：把已确认的题材视觉证据和名称锚点所承载的可迁移机制接入正确资产框架；检查模型是否兑现；把偏差按最早负责人回流。

若交接包本身缺少主辅类型、视觉证据矩阵或相邻类型边界，返回美术风格设计；若交接包正确而人物、服装或场景专业正文没有兑现，返回对应专业Skill；若两者都正确而图片仍漂移，才留在本 Skill修正引用、权重、提示词编译或模型适配。不得在资产代码块末尾临时追加“仙气、未来感、电影感、高级”等词掩盖上游缺口。

#### 人物设计调用门

B / 阶段素体 / M / G资产编译不再兼任完整原创人物设计。出现主要人物或关键配角首建、多人同脸同体型、人物只有年龄性格和发型清单、第一印象承担反转、稳定动作语言不清，或同一人物需要跨真人写实、2D、3D与AI保持身份时，先调用`laohu-character-design`，取得`人物设计交接包`后再继续。

三种入口分开：

- 完整原创：人物设计包必须含人物核心事实、脸身姿动真正不同的有效候选（开放方向通常3—5个，锁定方向按剩余差异）、第一印象—真实人格合同、自动胜出与淘汰理由、群像差异和媒介母版。
- 锁定身份：只继承用户有权使用且证据真实可见的脸身事实；不可见角度、背面身体、身高和围度不得写成零改动还原，按`推定制作信息 / 高风险缺口`分离。
- 一次性远景群众：不逐人建立人物母版或B；仍需留下年龄、体量、姿态、动作能量和密度范围的轻量群体合同，不能只写“一群弟子”。

视觉资产负责判定F用途并提供依赖要求，委托`laohu-image-creation`整合F画面与提示词；接收人工确认的F后登记共同源，再反向编译为可生成、可复用、可验收的B、W、M、阶段素体与G，并把`交给道具 / 装备资产`的人体尺度、握持穿戴、重量重心、动作语言和高风险点传给角色所属物分支。它不得重新选择骨相、身体比例、服装本体、妆造方向、第一印象、稳定动作语言、媒介锚点或人物—物件关系。只有资产编译或真实生成暴露身份不稳定、服装结构不闭合、妆造侧背面无法成立、群像同质、跨媒介回归失败或人体工学冲突时，携带证据返回对应专业负责人。

#### 服装设计调用门

W / M资产编译不再兼任完整原创服装设计。出现主要人物首套服装、世界 / 阵营衣橱、角色弧线换装，或现有服装合理但平庸、全员同袍换色、只靠腰饰区分时，先调用`laohu-costume-design`，取得`服装设计交接包`后再继续。

三种入口分开：

- 完整原创：设计包必须含世界服饰宪法、人物服装命题、同约束有效候选（开放方向通常3—5个，锁定方向按剩余差异）、自动胜出与淘汰理由、固定项和可变项。
- 已确认设计：用户明确锁定且有权使用时，不重新设计，只登记设计锁定清单、允许补全的制作信息和禁止新增项；会改变可见或运动轮廓的是`高风险缺口`，先请求补充参考或确认，不影响锁定外观的工程补全标为`推定制作信息`。
- 一次性背景群众：可以不建个人W / M；若等级或阵营承重，只接收轻量群像衣橱语法，写入群像资产或镜头正文。

视觉资产负责把胜出服装设计正文、写真母图和固定拆解框架组合成可生成、可复用、可验收的W，再把F、B、W和妆造补充正文组合成M；不得重新发明、概括或补写轮廓、比例、结构、材料关系、文化来路和妆造方向。只有资产编译暴露出无法制作、无法活动、无法引用或生成模型稳定失败时，携带证据返回对应专业负责人。

人物资产按职责建立，不把普通服装当成可以跳过的空白，也不把制作板字段当成人物设计理由：

- 专业人像模型与规格板模型能力明显分化，或主要人物需要长期跨镜复现：先建立包含完整人物、服装和妆造的F人物写真母图，人工确认后再拆同编号B / W / M；F不直接进入视频。
- 身份需要跨请求稳定：建立人物素体或身份校准资产。
- 同一身份存在可复用的体型、年龄段、康复、伤病或形态阶段：按需建立人物阶段状态资产，仍由同一身份上游控制，并使用完整阶段素体板。
- 只要角色已经进入正式人物资产或独立故事板资产链，所有最终服装先建立W；普通、朴素和一次性服装也不能绕过W直接进入M。直接文生视频轻链路不建立人物资产，已确认的一次性主角服装可以作为正文替代合同直接写进同一次视频提示词；没有被资产化的一次性背景群众同样允许在群像或镜头正文中统一描述服装。
- 每套最终造型建立M；它引用F、身份、当前阶段状态、已确认W和由妆发设计维护、可经人物入口整合交付的妆造补充正文，形成当前发型、妆容、装饰与完整穿着结果。
- 手、脚、义肢或局部只有承担身份 / 产品操作且反复出现时才补局部参考。

## 资产验收与交接

### 资产总表

多资产作品默认维护一个 `视觉资产总表`，按依赖顺序从上到下即可执行：

```text
【资产目的与最低集合】
作品承诺：
最低可行资产：
降级为画面元素 / 成品图 / 临时参考的对象与理由：

【资产依赖与生成队列】
编号 / 名称 / 职责 / 上游 / 固定项 / 可变项 / 禁止继承 / 阻塞状态。

【规范词账本】
对象 / 唯一标准描述 / 允许省略 / 不得漂移。

【可复制图片提示词】
每个资产一段独立正文，按拓扑顺序排列。

【图片生成与验收】
小批量数量 / 选择标准 / 失败类型 / 返修或降级。

【下游调用】
每个资产由哪个 批次、首帧、封面或组合结果调用，只负责什么。
```

结果保存到当前作品 `03_视觉资产/文本/` 的阶段主文件。老胡回传的实际图片登记到 `03_视觉资产/图片/`；由本 Skill 明确授权生成的实际图片，必须从工具默认输出目录移动到该项目路径的对应类别目录，不在默认目录长期留存副本。

### 验收

- 这是稳定资产、单张成品图还是临时参考，是否分类正确。
- 单张成品图是否真的按当前观看结果组织，而不是套用资产板、棚拍校准或通用“高级感”提示词。
- 每个资产是否有复用范围、叙事职责、失真代价和下游调用。
- 是否已经删到最低可行资产，未把剧本名词逐项建图。
- 依赖图是否无环，提示词是否按依赖顺序排列。
- 画面中每个可识别对象是否引用闭合、文本闭合或明确不出现。
- 稳定身份、持续阶段和瞬时表演是否没有混成一张图。
- 去掉滤镜、氛围和漂亮形容词后，设计本体是否仍成立。
- 实际图片去掉题名、身份说明和常见背景捷径后是否仍符合美术风格设计交接包；若失败，是否已返回最早负责人而非由资产层重做风格。
- 形象图是否有第一眼吸引，制作图是否能换角度保持同一个对象。
- 材料与意象是否承担作品用意和公共经验，而不是为了“专属”挑小物件。
- 代码块是否只有模型要看到的正向画面，引用是否显性且职责清楚。
- 是否能指出唯一生成任务、主注意力和主证据；人物、服装、妆造、场景、风格与摄影是否同向，专有词是否已有模型可执行的视觉翻译。
- 承重维度是否达到3级主导而不只是出现；第一眼是否被足够可辨认的证据抬高（单一机制可以成立），第二眼、第三眼与竞争元素是否明确退让。
- 正式首稿无论采用完整母稿法还是关键画面→专业补全法，是否都已闭合专业合同；压缩是否只删除低价值、重复与可补全信息，没有把承重焦点、动态力量链、声画因果或结果停点压掉。
- 实际图片是否经过身份、结构、材质、用途和下游可用性验收；未生成时是否仍标为占位。
- 正式图片是否已经打开真实文件并完成像素验收单；目标语义、真实像素语义、目标语言、第一视觉重点、手机可读性和文件身份是否一致。
- 正式观众画面是否没有生产编号、英文临时占位、乱码、样本原字或模型伪字；草图是否保持隔离且没有下发视频。
- 下游是否知道该继承什么、该重新设计什么，不需要重新猜。
- 底线是否只负责稳定、闭合和可调用；成品图或承重资产是否另行通过巅峰门，证明主视觉、人物化设计、空间记忆或产品证据已经达到本任务当前最强候选。
- 是否比较过真正不同的设计方向；胜出方案是否因作品关系和观众结果取胜，而不是因为信息更多、特效更满或规则打勾更多。
