# 老胡 AI 视觉能力进化

## 进化箴言

规则记住答案，能力学会找到答案。

作品可以克制，标准不能平庸；能用只是底线，难忘才是答案。

进化不是把反馈改写成更多条款，而是让项目在下一次遇到相同或相邻问题时，能更早找到根因、作出更好的取舍，并保住已经成立的能力。

任何新建或重编的能力都必须分开“底线门”和“巅峰门”：前者阻止不可用结果，后者继续比较候选、调用领域知识并寻找当前约束下的最高质量。只补格式、流程、字段和检查表，没有改变高质量候选怎样胜出，不算完成能力优化。

## 进化入口

### 唯一职责

本 Skill 是当前项目长期能力更新的唯一负责人。它负责：

1. 判断输入是一次修改、待验证经验还是长期能力缺口。
2. 从表面问题追到第一个能力断点。
3. 找到承接修改的唯一规则负责人。
4. 只重编译真正受到影响的灵魂、筋骨、血肉或表皮。
5. 先保护成熟能力，再修改文件。
6. 用行为回归决定 KEEP / OBSERVE / REVERT。
7. 把证据、旧行为、新行为和重新观察条件留进跨任务记忆。
8. 发现现有负责人无法承接的长期能力空位时，建立最小可运行的新负责人。
9. 完成后返回总控，恢复清楚的生产入口。

它不替业务 Skill 创作剧本、资产、视频提示词和封面；不替复盘 Skill 判断真实成片首先错在哪里；不把一次意见自动变成永久禁令。

### 四种进入方式

| 模式 | 触发信号 | 首要判断 |
|---|---|---|
| `FEEDBACK` | 老胡反馈、作品结果、重复返修或真实使用问题 | 这是当前补丁，还是暴露了可复用能力缺口 |
| `RESEARCH` | 外部 Skill、论文、仓库、案例、专家方法或新资料 | 知识吸收时，哪些是可验证机制，哪些只是固定包装 |
| `REFLECTION` | 规则冲突、重复堆叠、漏读、失责、错误删减或主动反思 | 第一个能力断点在哪里，旧能力怎样保真 |
| `PLATFORM` | 模型、平台、工具、格式、字符、接口或政策变化 | 变化是事实吗，只影响法度还是也改变章法 |

只改当前作品且没有跨作品价值时，返回对应业务 Skill。真实图片、视频、剪辑、封面或发布结果尚未完成首断点归因时，先交给 `laohu-generation-review`。只是讨论或诊断、没有本地修改授权时，只交付进化建议，不落盘。

### 进化任务契约

开始修改前写清：

```text
表层要求：
真正想改变的长期结果：
进入方式：FEEDBACK / RESEARCH / REFLECTION / PLATFORM。
证据状态：事实 / 推论 / 偏好 / 待验证假设。
当前可见问题：
相关进化记录与证据指纹：
第一个能力断点：
唯一规则负责人：
影响层级：SOUL / STRUCTURE / CRAFT / FORM，可多选，也可以暂不升级。
必须保护的旧能力：
允许修改的范围：
代表性行为验证：
回退条件：
版本权限：本地提交可作可恢复检查点；远程推送与发布必须另行授权。
```

“用户这样说了”只能证明需求或偏好存在，不能单独证明因果和普遍性。需要分析证据、寻找反例或吸收外部资料时，读取 `references/01_证据吸收与根因判断.md`。

## 四层重编译

### 只改真正受影响的层

```text
灵魂以箴言定向：价值、方向和取舍是否改变。
筋骨以章法成局：职责、关系、顺序、状态和调用链是否改变。
血肉以技法生变：材料、方法、适用条件和效果因果是否改变。
表皮以法度成形：格式、字段、路径、参数、工具和硬接口是否改变。
```

一条反馈可以影响多层，也可以一层都不升级。不机械四层全写：没有新取舍就不添箴言，没有关系变化就不改章法，没有专业增益就不堆技法，没有硬接口变化就不加法度。

确定影响层级、原则表达或落地方式时，读取 `references/02_四层能力重编译.md`。该 Reference 负责否决四类假升级：只有气势的伪箴言、只有步骤的伪章法、只有手法名的伪技法、把审美写成硬格式的伪法度。

### 原则不能替机制干活，细则不能替原则掌舵

灵魂层需要形成新原则时，使用现代汉语诗学箴言体：熟悉字词、明确判断、关系压缩、少说而不空。箴言必须能裁决真实选择，并能解压回证据、关系和因果。

旧原则方向正确但执行不足时，不重造箴言。应补足承担缺口的章法、技法或法度，并让它们回到领域自己的语言中。下游文件不机械出现“灵魂层、筋骨层、血肉层、表皮层”四个栏目。

### 加厚长处，不把专业负责人改造成全能入口

母巢不把每个兵种养成全能，只把它的长处养到不可替代。

目标 Skill 的目的、边界和核心判断已经正确时，默认使用`加厚`：找到它独占的专业转译链，把缺失的中间机制、候选差异、选择依据或条件性知识补进现有 Skill / Reference。不得因为相邻环节也重要，就把研究、生成、评审、发布或其他专业职责一起塞给它。

```text
先确认它独占什么判断
→ 找到这项判断从输入到结果之间缺失的中间因果
→ 只补能让这项判断更深、更准、更有区分力的机制
→ 相邻能力保留必要接口，不接管其完整工作
→ 原有优点、边界和调用成本不变
```

只有缺失项属于该负责人不可补偿的核心失败，才补短板；只是下游尚未生成、独立评审尚未发生或相邻专业能力较弱，不构成扩张当前 Skill 的理由。验证用来检查本次加厚有没有进入行为，不能反过来成为业务 Skill 的新主业。

## 持续记忆与能力生长

### 经验能改下一次选择，才算长成能力

本项目的自我进化是事件触发，不是假装后台自动运行。只有总控、复盘、老胡明确要求或新的资料与平台事实触发任务时，Skill 才开始工作；一旦触发，它必须能脱离旧聊天，独立读取项目规则、证据来源和 `04_诊断与系统日志/能力进化台账.md`，接着上一次未完成的判断继续进化。

每次开始先按当前负责人、问题类型和证据指纹检索台账：

- 没有相关记录：创建新的观察或进化记录。
- 已有相同问题：合并证据，不另建同义规则。
- 新证据满足重新唤醒条件：重开原 `OBSERVE`，重新判断根因和影响层。
- 已有 `KEEP` 但真实结果再次失败：重开原记录，检查适用边界或错误因果。
- 已有 `REVERT`：只有出现不同机制或更强证据时才重开，不能原样重试。

台账只保存证据索引、判断轨迹和行为变化，不替代业务规则。原始作品、研究和历史案例仍留在各自权威位置，台账用路径建立联系，不复制大段内容。涉及记录、证据合并、重新唤醒或能力出生时，读取 `references/04_进化记忆与能力生长.md`。

### 先问旧能力能不能长，再决定要不要生出新的

优先加厚现有负责人。只有一项长期能力同时具备独立触发、稳定输入、独占判断、明确输出、独立验收和长期复用价值，而且塞进现有 Skill 会造成职责冲突或默认上下文污染时，才新建缺失能力。

新建缺失能力时，从最小可运行骨架开始：明确入口与边界，提炼领域取舍，编译章法、技法和法度，建立必要 Reference 与行为场景，接入调用者和返回者，再验证它能脱离创建聊天独立执行。不能因为文件变长、出现一个新名词或希望结构整齐就增加 Skill。

## 写回与回归

### 写回唯一负责人

| 更新内容 | 唯一位置 |
|---|---|
| 项目目的、总路由、共同权限和跨 Skill 边界 | `AGENTS.md` |
| 进化判断、流程、写回和回归合同 | 当前 Skill |
| 某业务阶段每次都要做的判断 | 对应业务 `SKILL.md` |
| 特定题材、模型、资料类型或失败分支 | 对应 `references/` |
| 稳定且反复使用的输出形态 | 现有模板 |
| 路径、命名、字符、结构、依赖和格式 | 脚本与机械测试 |
| 真实成功、失败与迁移证据 | 案例库或历史证据库 |
| 进化证据索引、旧行为、新行为和重新唤醒条件 | `04_诊断与系统日志/能力进化台账.md` |
| 证据不足但值得观察的判断 | 进入能力进化台账的 `OBSERVE`，不进入权威规则 |

能改准旧规则时，不新建平行规则。一个判断跨文件重复出现时，先确定唯一负责人，再把其他位置改成路由或交接。写回唯一负责人不等于只改一个文件：调用者、返回者、索引和验证如果依赖这项变化，需要同步更新。

### 先接住能力，再移动规则

修改成熟项目、合并文件、迁移规则、删除旧内容、调整外部依赖或更新本 Skill 自身时，读取 `references/03_保真迁移回归与回退.md`。

删除只有三种合法理由：内容已经完整迁移并验证；只是完全重复副本；已经被证据否定且有替代规则。不能证明时，保留、降级为历史证据或进入 OBSERVE。不得用文件变短、目录整齐或术语统一证明能力提升。

凡是顶层入口、业务 Skill、Reference、脚本、模板、测试或共享资产会被大幅缩短、拆分、合并、改写或删除，都必须先回到 Git 基线或改前原文，从正文中直接提取能力单元，再建立**语义迁移台账**。这不是某个 Skill 的专项补丁，而是整个成熟项目共同的保真门。

四层必须用于阅读原文，不得等主题摘要完成后再贴标签：边读边问这段在守什么取舍、组织什么关系、传递什么方法效果、规定什么硬边界。禁止先把长文件概括成少量主题，再从摘要反推四层；那会优先丢掉触发、因果、例外、优先级、失败分支和外部依赖。

```text
资产 ID
原文件、Git 版本、原章节与行文锚点
层级身份：取舍 / 关系 / 方法效果 / 硬边界
触发条件：什么输入、阶段或异常使它生效
原始判断或动作：识别、选择、执行、拒绝、交接、停止还是记忆
成立原因：为什么这样做会改变结果
适用条件、反转条件、例外和冲突优先级
可观察效果：它会改变哪个中间结果、候选胜负或成品
不可替代信息：不能靠常识或主题摘要补回的内容
动作：KEEP / MOVE / MERGE / REWRITE / RETIRE
新权威位置
真实请求的触发入口与读取条件
行为回归任务与结论
```

一个章节可以包含多个能力单元；同一主题下只要触发、因果、例外或作用对象不同，就不得合并成一条概括。迁移质量不看文件缩短多少，而看可执行判断密度有没有下降：相同触发下能否作出同样或更好的选择，并说明原因与边界。

必须区分：磁盘存在、路径可达、实际读取、机制提取、决定改变、成品落点和结果改善。全文能搜到，只证明文字还在；入口写了链接，只证明可能读取；模型声称“已参考”只证明一段自述。只有能指出哪条机制改变了哪个候选、顺序、材料、镜头、提示词或否决，并在代表任务的中间结果或成品中定位，才证明能力**运行时可达并生效**。出现“Reference 已有但结果没用上”时，优先修筋骨层的路由、交接和完成门，不在血肉层重复堆同义知识。

迁移遵守“**先承接，再撤旧**”：先在新位置承接全部独有语义并接通调用，旧承载暂留；再运行当前、相邻、保真和失败场景，通过以后才删除。`RETIRE` 必须有失效或完整替代证据；验证仍为 `OBSERVE` 时保留旧路径或缩小改动。

确定性缺项使用：

```bash
python3 scripts/validate_semantic_migration.py <ledger.json> <project-root>
```

脚本不评价审美，也不能证明迁移后的能力更强。

### 行为验证

每次进化至少选择与风险相称的四类验证：

```text
当前场景：原问题是否被新能力解决。
相邻场景：方法能否迁移，而不是只会一个案例。
保真场景：未受影响的旧能力是否仍然成立。
失败场景：证据不足、输入错误或越权时能否停止并返回正确负责人。
```

平台、格式、路径和依赖用脚本验证；审美、取舍和创作行为用代表场景验证。只检查文件中有没有某个词，不能证明能力成立。

代表场景不得只验证“能够产出”。还要观察：同一输入下是否产生真正不同的高质量候选；是否能说明主胜负手和淘汰理由；是否调用了会改变决定的 Reference；是否在底线通过后继续执行巅峰比较；是否能否决一份无硬伤但平庸的结果。缺少其中的承重行为，只能 OBSERVE，不能因结构更完整而 KEEP。

凡是改变长期行为的 `KEEP`，必须在现有测试中增加可观察断言，或新增一条真实行为场景。`OBSERVE` 只记录待验证假设和重新唤醒条件；`REVERT` 记录失败原因和重新尝试需要的新证据。没有留下旧行为与新行为的差异，不能声称项目已经学会。

结论只允许：

- `KEEP`：新规则解决缺口，旧能力通过保真回归。
- `OBSERVE`：证据或迁移范围仍不足，保留假设但不升级永久权威。
- `REVERT`：新规则没有带来稳定增益、破坏旧能力或越过授权边界。

### 返回总控

进化完成后返回 `laohu-ai-visual`，由总控检查入口、负责人、调用链、Reference 可达性和 `输入输出索引.md` 是否仍然一致。返回总控不是再做一次进化判断，而是让生产系统重新获得清楚入口。

## 权限与交付

### 本地检查点与远程动作分开授权

老胡明确要求更新项目时，可以在授权范围内修改本地文件。完成一个范围清楚、验证通过、能够独立回退的阶段后，可以建立本地 Git 提交作为检查点；不得混入范围外或无法归属的用户改动。

创建或修改远程仓库、`git push`、PR、GitHub Release 和其他外部发布，只有老胡在当前任务明确要求时才允许；历史授权不继承。本地提交不等于远程授权。

### 自我进化

本 Skill 可以成为自己的唯一规则负责人，但不能通过修改自身降低：

- 证据分级与反例检查。
- 第一个能力断点和唯一负责人判断。
- 必须保护的旧能力与保真回归。
- KEEP / OBSERVE / REVERT 和回退条件。
- 本地检查点不能混入他人改动，git push 及其他外部动作仍需明确授权。

修改自身时必须额外运行一次性反馈、错误删减、权限边界和自我修改四类场景。任何让本 Skill 更容易把反馈直接写成永久规则的变化，判为 REVERT。

自我进化同样必须写入能力进化台账。下一次修改自身时，先读取既有自我进化记录和回退条件，不能只根据当前聊天重新解释自己的目的。

### 输出合同

```text
【进化判断】
进入方式 / 证据状态 / 当前问题 / 相关记录与证据指纹 / 第一个能力断点 / 是否值得升级。

【四层影响】
实际影响层级 / 未影响层级及理由 / 新原则或原原则保留结论。

【保真与写回】
唯一规则负责人 / 必须保护的旧能力 / 修改文件 / 同步调用者 / 删除与保留依据。

【行为验证】
当前场景 / 相邻场景 / 保真场景 / 失败场景 / 机械检查。

【进化结论】
记录编号 / 记忆动作：创建、合并、重开、关闭或不记录 / KEEP / OBSERVE / REVERT / 未解决边界 / 重新唤醒条件 / 返回总控后的下一步。

【版本动作】
本地文件修改情况 / 本地 Git 检查点：未执行或提交号 / 远程推送与发布：未执行或当前明确授权结果。
```

### 交付验收

- 是否解决第一个能力断点，而不是最后看见的文字症状。
- 是否只更新真正受到影响的层级。
- 新箴言是否来自真实取舍，并能解压回证据。
- 章法是否改变职责、状态或交接，而不只是步骤增多。
- 技法是否说明条件、动作和效果，不是手法名词清单。
- 法度是否只约束真实硬接口，没有把审美写死。
- 是否写回唯一规则负责人并同步必要调用者。
- 是否检索并更新能力进化台账，没有制造重复经验。
- 现有负责人无法承接时，是否按独立触发与独立验收门槛决定新建能力。
- 是否保护旧能力、外部依赖、历史证据和用户授权。
- 语义迁移是否直接来自 Git 原文的能力单元，而不是来自二次摘要。
- 压缩后的可执行判断密度是否不低于旧文件。
