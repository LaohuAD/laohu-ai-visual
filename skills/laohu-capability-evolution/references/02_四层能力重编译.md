# 四层能力重编译

只在证据包已经形成，需要确定影响层级、规则表达和领域落点时读取。四层是能力完整性的判断方式，不是四个固定标题，也不是每次更新都要填满的表格。

## 一、层级选择

| 追问 | 是时可能影响 | 不是时不要做什么 |
|---|---|---|
| 什么值得追求、舍弃或保护发生变化了吗 | 灵魂 `SOUL` | 不添箴言，不重写项目价值 |
| 负责人、关系、顺序、状态或调用链变化了吗 | 筋骨 `STRUCTURE` | 不为流程显得完整而加步骤 |
| 材料选择、专业方法、条件或效果因果变化了吗 | 血肉 `CRAFT` | 不堆手法、例句和教程 |
| 格式、字段、路径、参数、工具或硬边界变化了吗 | 表皮 `FORM` | 不把审美偏好写成机械强制 |

同一证据可以影响多层。例如外部平台更改字符上限通常只改表皮；如果新限制迫使一个提示词拆成多个 VID 并改变状态交接，才同时影响筋骨。层级由结果关系决定，不由更新显得多重要决定。

## 二、灵魂：箴言怎样成立

### 只有取舍变化，才动河床

灵魂层承载价值、方向和取舍。新增原则前必须回答：旧原则在哪类真实选择中无法裁决；新证据改变了什么取舍；新原则能统领哪些不同题材；它的边界在哪里。

原则句使用现代汉语诗学箴言体：

- 使用熟悉字词，不靠文言、生僻词和术语造势。
- 通过判断、反差、对偶、具体意象或关系压缩承载真实取舍。
- 少说而不空，含蓄而有方向，简洁而有重量。
- 可以解压回事实、人物、关系、动作和结果。
- 负责定向，不代替机制、技法和验收。

伪箴言的信号：换到任何项目仍然成立；删掉后不影响选择；需要长篇说明才知道它在说什么；只是禁令换行；词语搭配不在人类公共语感中；只有气势，没有因果。

旧箴言仍能正确裁决时，保留原句。执行失败不等于河床错误，可能只是章法没有接住、技法没有长出来或法度没有拦截。

## 三、筋骨：章法怎样成局

章法不是步骤表，而是整个能力怎样接力：

```text
可靠输入从哪里来
→ 当前负责人独占什么判断
→ 哪些状态被改变
→ 哪项结果标志阶段完成
→ 下游必须继承什么
→ 失败返回哪个最早负责人
```

以下变化才修改筋骨：新增或撤销负责人；输入权威改变；状态定义改变；调用顺序改变；业务 Skill 和外部 Skill 之间的适配改变；多个文件争夺同一判断；Reference 无法从负责人到达。

章法写进总合约或主 Skill 的任务流程。特定题材步骤不能上升为全项目章法；一个案例的操作顺序不能冒充所有作品的因果顺序。

## 四、血肉：技法怎样生变

血肉层解决“方向知道了，面对不同材料到底怎样做”。完整技法包含：

```text
触发条件
→ 材料承担的关系、情绪、信息或功能
→ 候选材料或方法的比较
→ 为什么选择这一种
→ 它如何改变可见、可听或可执行结果
→ 什么情况下保留原稿或换用其他方法
```

材料按四项选择：因果承重、典型性、媒介可见性、实现与维护代价。私人小物不因专属而天然深刻，宏大意象不因公共而天然空洞；关键是它是否承得住当前用意，又能被目标媒介表达。

对比、留白、运镜、声音桥、匹配转场、蒙太奇和光色都只是候选手段。只写“使用对比、加强节奏、增加电影感”没有传递能力。技法必须说明为什么此处必要以及怎样判断有效。

每次必做的专业判断进入 Skill；特定题材、模型、输入状态或失败分支进入 Reference；高水平与普通对照用来校准判断，不能成为必须模仿的固定答案。

## 五、表皮：法度怎样成形

法度负责让结果能被真实工具和下游使用：

- 文件路径、目录、命名和权威位置。
- 输入输出字段、结构和交接格式。
- 模型、平台、时长、字符、尺寸和参数限制。
- 脚本、依赖、外部 Skill 和失败返回。
- 哪些是硬边界，哪些只是可调整默认值。

能机械验证的事实优先进入脚本和测试。格式不合格、路径缺失、镜像漂移和字符超限应给明确错误；脚本不判断箴言深度、材料好坏和审美优劣。

法度最容易膨胀。增加一条规则前问：违反它会导致结果不可用，还是只是不符合某次偏好；能否由已有规则解释；能否通过一个更准确的字段或脚本代替一段解释。

## 六、从层级到文件

层级说明“哪种能力变化”，文件说明“谁负责变化”，二者不能混为一谈：

| 变化 | 常见负责人 |
|---|---|
| 全项目价值与跨 Skill 路由 | `AGENTS.md` |
| 某领域每次都要做的价值判断与章法 | 业务 `SKILL.md` |
| 条件性技法和具体机制 | 对应 `references/` |
| 稳定交付形态 | 模板 |
| 可确定的机械边界 | 脚本与测试 |
| 尚未验证的经验 | OBSERVE 记录或历史证据 |

不要把四层分别建成四份长期规则文件。一个业务 Skill 应用自己的领域语言承载完整能力，读者不必看见编译过程。

## 七、规则的四种表达职责

原则、机制、执行和验收不是灵魂、筋骨、血肉、表皮的同义词，也不要求每层都写一套：

- 原则句主要承载灵魂和少量高层章法，负责定向。
- 机制说明解释因果，帮助章法和技法迁移。
- 执行动作主要落在技法与法度，告诉当前负责人怎样做。
- 验收检查所有改动是否进入行为，并决定保留或回退。

原则不能替执行干活，执行不能反过来绑架原则。简单机械变化可能只需要法度和验收；价值变化才需要从原则重新向下编译。

## 八、编译完成检查

- 实际影响层级是否有证据，而不是为了完整全选。
- 新原则是否改变真实取舍，语言是否自然且可解压。
- 新章法是否改变状态和责任关系。
- 新技法是否能处理输入差异，并允许什么都不加。
- 新法度是否对应真实接口，能机械验证的是否已自动化。
- 规则是否进入领域自己的语言，而不是显露四层脚手架。
- 是否减少解释性重复，而没有删除有效判断。
