# 进化记忆与能力生长

只在进化需要跨任务积累证据、重新唤醒观察、留下行为差异，或判断是否新建 Skill、Reference、模板、脚本和测试时读取。它负责让一次更新接得上下一次更新，不替证据判断和四层重编译作决定。

## 一、母巢不是自动运行，是能从自己的经验继续生长

Skill 不会在没有任务、没有运行环境时自行醒来。这里的自我进化指：任何新任务触发后，它不依赖创建时的聊天，也不等老胡重新解释整套方法，就能从项目内的持久证据继续完成以下循环：

```text
感知新信号
→ 找回相关记忆
→ 合并或重开证据
→ 重新判断第一个能力断点
→ 编译受影响层
→ 写回唯一负责人或长出新负责人
→ 用行为回归复验
→ 留下下一次可以继续读取的记忆
→ 返回生产
```

只保存规则不是进化，只保存经历也不是进化。经历改变下一次判断、规则经真实结果重新校准，两者闭合才算生长。

## 二、能力进化台账的唯一职责

`04_诊断与系统日志/能力进化台账.md` 是跨任务进化记忆的唯一索引。它不复制作品文件、研究全文和业务规则，只回答：发生过什么，证据在哪里，原来怎样做，现在怎样做，何时需要重新打开。

每条记录使用唯一编号 `EVO-YYYYMMDD-NNN`，至少包含：

```text
状态：KEEP / OBSERVE / REVERT。
进入方式与来源：
证据指纹：
证据位置：
相关旧记录：
第一个能力断点：
唯一规则负责人：
受影响层与未影响层：
必须保护的旧能力：
旧行为：
新行为或待验证假设：
写回位置：
行为验证：当前 / 相邻 / 保真 / 失败。
重新唤醒条件：
版本动作：
```

证据指纹不是全文摘要，而是便于检索和合并的稳定组合：`负责人 + 任务阶段 + 可见症状 + 候选机制`。同一指纹出现新证据时更新原记录；机制不同但症状相同，建立新记录并互相链接，避免把不同原因硬并成一个规则。

## 三、OBSERVE 怎样跨任务继续

`OBSERVE` 不是一句“以后再看”，必须写出重新唤醒条件，例如：

- 同一负责人在相邻题材再次出现相同症状。
- 获得原提示词、真实生成结果、平台说明或发布数据。
- 高水平与相邻水平对照能够排除另一个原因。
- 新平台事实改变原假设的适用范围。
- 老胡明确把一次偏好确认成稳定长期选择。

新任务开始时不扫描所有历史正文。先按负责人、阶段、症状和机制检索台账，再读取命中记录指向的原始证据。满足条件就重新唤醒原记录；不满足时只把新证据合并，不擅自升级。

## 四、把文字变化变成行为变化

进化记录必须先写旧行为，再写期望的新行为：

```text
同一类输入到来时，旧系统会怎样路由、判断或产出。
哪一步是第一个能力断点。
修改后，同一输入应该出现什么可观察差异。
哪个相邻输入不应该被连带修改。
哪个失败输入必须停止、返回或降级。
```

修改权威文件只是实现动作。只有行为场景证明新差异出现、保真场景证明旧能力仍在，才能决定 `KEEP`。测试场景要保存输入、预期动作、禁止动作、保护项和结论，不能只搜索一句新术语。

## 五、现有能力加厚还是新建缺失能力

先尝试由现有负责人承接。以下任一情况成立时，优先加厚旧 Skill 或增加条件性 Reference：

- 入口、真实目的和主要输出与现有 Skill 相同。
- 新知识只补充一个题材、模型、失败分支或技法。
- 新规则仍由现有负责人裁决，不产生新的交接关系。
- 新能力没有脱离现有流程独立验收的意义。

只有同时满足下列条件，才允许新建 Skill：

1. 有稳定且可辨认的独立触发，不会吸走大量无关任务。
2. 有自己的可靠输入和明确输出，不只是资料集合。
3. 独占一组现有负责人不能自然承接的判断。
4. 有清楚的调用者、返回者、失败返回和完成状态。
5. 能建立独立验收场景，并能脱离创建聊天执行。
6. 长期复用价值足以抵消新入口和默认上下文成本。

满足新建门槛后，先建立最小可运行负责人：元数据、领域箴言、核心章法、必要技法、硬接口、行为场景和返回合同。只有条件性知识确实独立且会被按需读取时才建 Reference；只有机械操作需要稳定重复时才建脚本。

## 六、能力还可以怎样生长

进化不只等于“改规则”。根据第一个能力断点，可以选择：

| 生长动作 | 适用情况 | 最小结果 |
|---|---|---|
| 加厚 | 负责人正确，但判断、方法或边界不足 | 改准原 Skill 或按需 Reference，并补行为场景 |
| 重接 | 调用者、状态、顺序或返回关系错误 | 更新核心合约、调用者、返回者和保真测试 |
| 新建 | 出现满足独立门槛的长期能力空位 | 最小可运行新负责人及完整接力关系 |
| 退役 | 能力已被替代、证据否定或不再可达 | 先迁移语义与调用，再保留兼容入口或删除 |
| 观察 | 证据还不足以改变权威 | 台账记录、重新唤醒条件，不改永久规则 |

动作由能力关系决定，不由改动看起来大不大决定。一次平台字段变化可能只需加厚法度；一个很小的职责冲突也可能需要重接整条调用链。

## 七、每次返回前完成记忆闭环

进化结束前：

1. 更新原记录或创建新编号，不能让证据只留在聊天。
2. 写清这次是创建、合并、重开、关闭还是不记录。
3. `KEEP` 记录旧行为、新行为、写回位置和回归证据。
4. `OBSERVE` 记录待验证假设和重新唤醒条件。
5. `REVERT` 记录失败原因、已撤回内容和再次尝试需要的新证据。
6. 把长期权威写回业务负责人，台账不成为第二套规则。
7. 返回总控，让下一次生产从清楚入口继续。
