# 老胡群像设计

## 灵魂：专业裁决

让同一世界中的人物彼此成立，观众能读出关系而非名单。局部好看不能牺牲这个结果；已确认的故事事实与当前专业设计选择必须分开。

## 筋骨：工作次序与边界

专业次序是：**群体共同语法 → 关系分工 → 成套选角 → 逐人及整体复验**。接收当前任务已确认的对象、状态和可改范围；独立请求以必要输入直接执行，正式作品继承已有导演与美术合同，先定位本专业最早的缺口，再提出可比较方案，形成独立结果，返回实际调用者整合；独立点名时直接交付专业结果，不强制重跑所属父入口。CONSULT只交局部判断，不接管剧本或其他部门。已有锁定设计时只处理自由区；跨越身份、剧情或成本范围的选择返回所属入口。

## 血肉：怎样产生设计

先定义共同世界基线，再将年龄感、体量、头肩、脸部关系、重心、节奏、空间占用放入一张矩阵；主差异围绕关系分工建立，避免每维不同破坏世界。四人以上可比较完整群像系统，但每位未锁定主角必须在各系统里得到真正替代。

## 表皮：可交接形式

交付必须包含：群像矩阵、共同基线、每人不可重复锚点、成套候选、远中近景和同场动作测试。未观察、未测试、未生成的部分按事实/推论/设计选择与验证状态登记。正文用观众可见的结构、位置、动作和材料关系；不拿专业词表代替设计，不增加固定资产网格或假造实测状态。

## 执行方法

1. 写出本轮要改变的观看或生产结果，以及不可改项。
2. 读取[专业方法](references/专业方法.md)，按其结构关系展开，不全量调用无关部门。
3. 开放设计比较真正不同的结构或关系；局部修正只比较可改区，锁定事实不得拿来凑候选。
4. 用同一个代表动作、观看距离或状态比较方案，写出胜出收益、代价、最强反对理由与重新开启条件。
5. 输出上列专业交付，补足承接对象和最早返回负责人；只有达到本轮证据等级才能标记相应验收完成。

## 验收与返回

底线：让同一世界中的人物彼此成立，观众能读出关系而非名单所需的关键结构与因果不冲突，所有锁定事实可追溯。巅峰：删掉解释和装饰后，专业结果仍在实际观看或操作条件里可辨认；同约束更强替代已比较。缺少专业设计则继续当前节点，剧本事件矛盾返回编剧，作品整体风格矛盾返回美术，纯引用与版式错误返回资产。

## 同妆不同脸与固定身份的分流

需要明显不同的脸时，读取面部专业的[阵容差异与反模板方法](../laohu-face-design/references/结构兼容与阵容方法.md#阵容差异程序)。逐对比较整体比例、颧颌/下巴、眼、鼻、唇、自然眉六组；同组近义词只计一次，肤色、发型、衣服、妆和痣不冒充结构差异。上游“四组不同、核心组至少两组”只作为开放阵容的检查启发式，不保证成图辨识；相似亲缘、同一人物变体或大量锁定项不套此门槛。

同一套妆先交妆容专业锁色彩、质地、线条方向与相对落点，每人的完整正文复用该合同，只按五官比例调整覆盖范围；不能靠五套妆伪装五张脸。与所有已选人物逐对比较，差异不足只改自由轴；无可行差异时说明约束，不改锁定项凑数。文字组合成立与真实成图可辨分别验收。

## 当前文本的语言执行

直接接受局部请求时，也按本包[语言表达](../../../../references/语言表达.md)先判当前文本块的发声者、接收者与任务。保护原话和专业事实；只补不足的请求不得改变已确认内容。遇到混写或冗余时按该文件选择具体方法，完成后回到本专业验收。
