# 视频基础必读与专项按需调用

本页负责加载顺序，不替代专业方法。首次进入本轮视频编译时读取本页及下列基础入口；同一上下文中已读且未变的版本可复用，不逐P机械重读。每P仍须执行基础判断；“保持不动”也是明确结果，不能以“没有缺口”跳过判断。

## 每次编译的基础层

| 必读入口 | 每P必须形成的判断 |
|---|---|
| 运镜（按本包任务交接，非必需外部文件） | 机位/观看侧、固定或移动、移动主体、起点路径停点及屏幕方向；区分推轨/变焦/摇摄/拉焦 |
| 动画（按本包任务交接，非必需外部文件） | 对象起终姿、预备/接触/受力/回收、时间间距、材料不变量；刚体不强加弹性 |
| 动态图形（按本包任务交接，非必需外部文件） | 图层、对象恒常性、变量与不变量、进入/变化/停读/退出；没有图形时明确不适用 |
| 剪辑（按本包任务交接，非必需外部文件） | 切点信息、前后动作相位、方向、省略及接续余量 |
| 声画（按本包任务交接，非必需外部文件） | 谁说、何时触发、先看后听或先听后看、SFX同步、跨切声音归属；静音任务也明确 |

基础入口都加载；其长Reference只在实际问题涉及的方法上读取。表演、武打、舞蹈、VFX等完整专项继续按原缺口表调用，不把基础必读扩张成全库必读。视频参考和编译的强制验收沿用父合同。

## 知识动画专项层

关键词只提供候选，语义决定是否调用；“火柴人”不等于必然科普，“动画”不等于Vox。先判断任务目的、主解释载体、风格是否锁定与当前阶段。

| 信号与实际目的 | 调用 | 不自动触发的情形 |
|---|---|---|
| 火柴人/线条小人/stickman＋解释、教学、科普、机制演示 | [火柴人知识动画](../skills/laohu-motion-design/skills/laohu-stickman-explainer/专业方法.md) | 纯火柴人格斗只用动画/动作，不强塞旁白与知识结构 |
| Vox/编辑型讲解/档案拼贴/地图时间线/数据比较，资料组织承担理解 | [编辑型知识动画](../skills/laohu-motion-design/skills/laohu-editorial-explainer/专业方法.md) | 普通纸艺剧情不因纸纹自动加载科普模板 |
| 只说“知识讲解”，未定形式 | 先比较行动比喻、证据拼贴或直接图解哪种最清楚；美术定案后调用对应专项 | 不默认把所有知识动画锁成火柴人或纸艺 |
| 同片混合两类 | 各P明确主要载体与切换理由，分别加载所需专项，统一概念、色义和旁白 | 不把两套完整风格同权叠在每P |

知识原文尚未成立时由编剧主责，专项只给解释方法建议；分段阶段提供讲戏和需求；资产阶段提供稳定视觉要求；视频阶段实现段内C。不得跨阶段另写第二份剧本。

## 以后增加专项的登记方式

每个长期专项需给出：触发语义与关键词、排除条件、独占判断、输入/返回、父负责人、完整方法与来源、继承的基础规则、条件性模型参数、验证样例。具备独立输入输出的建为现有专业树内子Skill；只有某模型参数或单一技巧的进入Reference，不增入口。

调用回执写明基础入口的实际版本/已读状态、命中专项及理由、读到的方法改变了哪个动作/比较/切点、未采用的来源默认项；不把回执放进模型提示词。新专项失败返回自己的负责人，不能覆盖P、内容、风格或资产真源。
