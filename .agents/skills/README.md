# 老胡 Skills 目录与使用说明

当前结构已实施。六个文件夹都是真实技能内容；`.agents/skills/`是唯一技能实体目录，旧根目录`skills/`已迁入，不再使用符号链接或快捷方式。目录是递归语法：每层有自己的 `SKILL.md`、按需的 `references/`，以及确有下层能力时才建立的 `skills/`；父层给方向与约束，子层继承并深化。本文同时说明上传选择、职责边界、灵感双份保存与实际文件树，后续结构调整继续更新本文件。

## 直接上传哪一个文件夹

在本项目`.agents/skills/`下面，选择本次需要的**一个完整文件夹**上传。不要只上传SKILL.md，也不需要连同整个共享资产库上传。以下链接可以查看各包入口，文件夹名就是上传时要选择的名称。

| 文件夹 | 用途 | 典型请求 |
|---|---|---|
| [laohu-ai-visual](laohu-ai-visual/SKILL.md) | 项目总控 | 把一首歌做成MV；确定作品方向；判断已有成片哪里先出了问题 |
| [laohu-script-writer](laohu-script-writer/SKILL.md) | 故事与剧本 | 记录灵感；用故事原子开发剧情；编写完整剧本；定稿后分段讲戏 |
| [laohu-image-creation](laohu-image-creation/SKILL.md) | 图片与视觉资产 | 补全图片描述；设计人物服装场景；制作可复用资产；设计封面 |
| [laohu-video-prompt](laohu-video-prompt/SKILL.md) | 视频制作与提示词 | 段内分镜；视频提示词及提纯；音色、对白、音效、环境音、音乐 |
| [laohu-language-mode](laohu-language-mode/SKILL.md) | 语言模式 | 判断不同文本应该怎样表达；改进沟通、创作和模型指令的语言方式 |
| [laohu-inspection](laohu-inspection/SKILL.md) | 检视官 | 生成前检查剧本、图片与视频提示词是否达到条款；生成后从真实结果找第一个断点并给出返修归口 |

每包根目录都有SKILL.md，入口会指向本包内的专业方法、Reference、模板与必要脚本；共用方法全项目只维护一份正文，消费位置按相对路径读取。没有脚本运行能力时，文本创作仍可读取Markdown方法和故事原子；需要执行校验或写入工具时，如实说明当前环境能力。这里完成的是文件层面与相对链接层面的检查，未在RunningHub内实际上传或运行。

“完整文件夹”指本包职责内的方法与Reference齐全。例如视频仍需要你提供已确认内容和必要资产，这属于作品输入；它不能因为没有剧本就伪造上游确认，也不能因为只安装一个包就声称已调用另一个包。共用方法读取仓库内的唯一正文：真源不可达时如实报告依赖缺口，不用副本冒充离线自足，也不因此重新制造一套运行副本。

## 这些专业为什么这样归类

- **分段讲戏归故事与剧本。** 它确定这次演哪段原文、段落目的、估时与接续，交出P级内容执行卡；视频包才负责P内C镜头、摄影和提示词。分类依据是交付结果，不只是“是否处理文本”。
- **MV导演归项目总控。** 它负责歌曲怎样转成观众经历，保留音乐时间证据、声画关系与表演策略，不强制把歌曲改成叙事剧本。
- **音频设计归视频制作与提示词。** 音色、声音表演、环境声、动作声、音乐、剪辑和混音保留专业方法；独立音色请求可直接做，不必先设计整段分镜。
- **封面归图片与视觉资产。** 封面以真实承诺和缩略后可读性验收；稳定资产以身份、结构和复用验收，两种用途分别处理。
- **语言模式独立维护唯一正文。** 各业务包的references/语言表达.md保留领域写法，通用规则按相对路径读取语言包的同一份正文；不再各存一套完整副本，内容不足仍返回原负责人。

## 灵感在本地保存两份，分别用于溯源和应用

后续每次明确要求“记录灵感、保存素材”，都完成下面这条流程：

```text
完整原话 → 共享目录sources/保存来源
         → 提炼独立价值核心，保存共享目录atoms/故事原子
         → 自动同步到故事技能包内的应用原子目录
         → 核验同一编号、内容与可用状态，两处成功后回执
```

应用原子目录已由 `references/故事原子/` 迁至 `assets/故事原子/`（当前实际位置以本文末尾的真实文件树为准）。迁移只改变布局，编号、状态与来源关系不变；入向链接、出向链接、脚本引用、注册表引用与测试引用已同轮重算。

共享目录里的完整库负责保留原话、语境、来源、原子分析与使用证据。故事包保存同一原子的应用内容：结论、人性机制、可见证据、延展方式、适用边界、置信度与source_id。它有真实正文，不是只放一个指向共享目录的索引。原话不重复塞进应用文件；需要溯源时，本地可以按source_id找到来源。数据源与应用数据是数据关系，不是需要消除的方法副本。

本地收录工具的add-source、add-atoms、log-usage、migrate-legacy会自动同步应用内容。原子修订回到共享权威库，再同步；暂停或重新启用也会改变包内可用状态。同步失败会明确报告“来源已保存”，修复后只重试同步，避免重复新增。不能只更新共享目录，把补应用副本拖到上传前。

故事原子应用目录可以直接浏览和按需读取（当前链接：[应用原子目录](laohu-script-writer/assets/故事原子/README.md)）。包内scripts/story_atoms.py支持分页搜索、详情读取与本地同步；云端没有Python时也可按目录读原子Markdown。没有匹配素材允许零采用，原子提供创作机制，不是可以拼接或照搬的剧情答案。

截至2026-09-13本轮迁移，已有完整来源3条、应用原子12条。两处均属于本地创作内容，不进入Git；选择上传故事包时，应用原子随文件夹一起带走。云端持有上传时的内容，本地新增不会自动推送云端，后续上传更新后的同一文件夹即可。云端产生的来源或使用证据需回流本地后再同步，不能声称已自动写回本地。

## Reference、共享目录与维护方式

包内文件链接使用**相对于当前文件的路径**，在包内用`../`到达其他专业；指向其他包唯一正文的读取用仓库根相对地址，不用失效链接近似。全部内部调用都能解析到真实文件，没有绑定某台电脑的绝对路径。

原共享目录里的专业规则已经按负责人迁入对应Reference；历史工具设想和初始化记录进入系统日志。视频注意力与时间编译从图片/通用编译资料中拆出，归视频编译专业，保留完整判断条件。共享目录继续保存完整素材来源和真实创作积累，有这些材料时可更深入复用、溯源，没有时五包仍能执行通用专业方法。

跨包方法的正式正文只保留一份，由来源专业负责维护；消费位置写清负责人名与读取地址，不复制对方正文。本轮已撤除全部`内置方法/`运行副本、四个包的`references/语言模式/`语言副本与五个包内渲染脚本副本：先把消费者改指真实源，核对副本无独有信息后移除；`scripts/sync_skill_packages.py` 随之改为迁移审计/依赖检查，无参数运行只报告“副本生成模式已停用”，不再写任何方法。本文末尾的文件树按当前磁盘生成，与撤除前如实不同。

维护命令从项目根目录执行：

```bash
python3 scripts/validate_skill_packages.py
python3 scripts/sync_skill_packages.py --check    # T01 后：迁移审计与依赖检查，不再写副本
python3 -m unittest discover -s tests
python3 scripts/update_skills_readme_tree.py
```

`update_skills_readme_tree.py` 按当前磁盘刷新下面的“六包实际文件树”：保留已有说明文字，只增删真实存在的文件，不虚构未创建的方法，也不改变既有条目的先后。改动包内文件后运行它，再跑路径校验。跨包 markdown 链接在 T02 放开后，消费者才能直接改指真实源文件。

现有吸收后的专业方法、案例与条件保留在本地Reference；外部网址只作为出处信息，不代替本地方法或要求日常执行时重新读网页。外部原文保留来路与已有证据，来源未知则如实标记，不冒充项目原创。

入口优化重点是“识别任务—保护已确认内容—选择必要方法—整合结果—验收”。Reference长并不是问题；入口能选对它、用好它才是关键。仅补全图片描述时，应保留原构图、动作、光影等已确认内容，只补影响理解或执行的不足，不擅自换画面。

## 默认原创与手动资料功能

普通创作读取本次需求、已确认输入和相关专业方法，针对当前任务原创组织内容；验收前提是本次故事、画面、声音或设计是否成立，不是是否完成了素材库检索。故事素材、原子与构件管理能力用于老胡明确提出的资料任务；未查库不阻塞默认原创，也不生成假的检索回执。缺库时如实区分“未提供库／空库／检索无匹配／工具失败”，不恢复老胡未提供的数据。

“原创”不等于每次重写已确认的角色、世界设定或最终歌曲：真正锁定的事实和媒体继续继承，存在争议返回原负责人。

## 跨包交接与单包独立

包内文件链接不越出本包到失效目标；跨包需要的方法由对方专业负责，本包写清负责人名与仓库根相对读取地址，不复制对方正文。独立调用某项能力与隔离一个文件夹离线自足是两件事：任何包单独打开时，本领域方法与Reference齐全，共用方法读取仓库内的唯一正文；缺少的只能是本次作品输入，不能是本包职责内的专业方法。真源无法访问时如实报告依赖缺口，不伪造调用，也不为上传另造副本。
