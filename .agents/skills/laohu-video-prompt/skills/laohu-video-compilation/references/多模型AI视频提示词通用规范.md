# 多模型 AI 视频提示词通用规范

> 用途：在 Seedance 2、即梦、可灵、Runway、Sora、Veo 等模型之间迁移提示词时，保留共同有效的制作逻辑。

## 一、通用结构

```text
作品目标
→ 输入素材
→ 基础设定
→ 氛围与画质
→ 镜头内容
→ 声音与节奏
→ 禁止项
→ 生成后诊断
```

## 二、不同模型都需要写清的字段

| 字段 | 作用 |
|---|---|
| 作品用途 | 决定是封面、短剧、MV、广告、电影片段还是测试镜头 |
| 时长 | 决定动作密度；实际提交参数为确定值；自然演法估计可为范围，二者不得混写 |
| 画幅 | 决定构图和留白 |
| 主体 | 决定模型优先生成对象 |
| 场景 | 决定空间和光影 |
| 动作 | 决定时间轴 |
| 景别 | 决定观看距离 |
| 运镜 | 决定镜头运动 |
| 风格 | 决定画面审美 |
| 声音 | 决定音画关系 |
| 禁止项 | 降低跑偏概率 |

## 三、迁移规则

跨模型迁移在三段式内完成，只切换当前 profile 的段内引用与声音语法，不改外层三块；命中模型前的选择和段内映射读取[三段式模型标签与引用映射](三段式模型标签与引用映射.md)。

### 从文字生成视频转到图生视频

文字生成视频重点写：

```text
角色是谁、在哪里、做什么、镜头怎么拍。
```

图生视频还要补：

```text
参考图负责锁定：人物 / 服装 / 场景 / 构图 / 风格。
不要改变：参考图中必须保持的部分。
允许变化：动作、表情、镜头运动、环境细节。
```

### 从单镜头转到多镜头

单镜头重点写：

```text
一个动作从开始到结束。
```

多镜头必须增加：

```text
全局连续性设定。
每个镜头的独立任务。
镜头之间的入点、出点和后期衔接。
沿用 E01-S02-P03-C02 追踪集 / 场 / 内容段 / 摄影镜头；一P一条请求，C在P内起算。
P的生成总时长写确定值；C按已成立事件和必要的局部相对时长编排，不据此强制逐镜绝对起止时间。
```

`E01-S02-P03-C02` 是集 / 场 / 内容段 / 摄影镜头的现行引用；历史作品里的 `E1-S1-C1` 等旧写法在读取和校验时兼容，不批量重编号。

### 从无声画面转到音画同步

无声画面重点写：

```text
视觉动作和节奏。
```

音画同步必须增加：

```text
声音来源。
声音出现时间。
声音和动作的对应关系。
是否需要保留同期声或配乐。
```

## 四、提示词压缩原则

只有目标入口已经证实存在长度限制时，才按入口的实际计数口径压缩。模型名称相同，不代表网页端、移动端、API、不同模式和不同版本共享同一上限；没有官方证据或本地实测时，状态写为 `入口长度兼容性未验证`，字符统计只用于观察信息密度，不得伪造 4000、10000 等通用硬门。

需要压缩时，优先保留：

1. 主体。
2. 主要动作。
3. 场景。
4. 景别。
5. 运镜。
6. 关键风格。
7. 禁止项。

优先删掉：

- 空泛形容词。
- 重复风格词。
- 不参与画面的背景设定。
- 不能被看见或听见的心理描写。

## 五、目标入口能力合同

正式编译提示词前，先为实际使用入口建立一份最小能力合同。合同负责人记录“这个入口现在真实能接收什么”，业务 Skill 再据此决定是否压缩、怎样引用素材、哪些控制应交给界面参数；不能从模型品牌名倒推出入口能力。

```text
目标平台 / 具体入口：
模型 / 版本 / 核验日期：
模式：T2V / I2V / 首尾帧 / 多参考 / 续写 / 其他
时长 / 画幅 / 分辨率选项：
可接收输入：图片、视频、音频、文本、首帧、尾帧、参考数量
各输入职责：身份 / 服装 / 场景 / 构图 / 动作 / 声音 / 连续性把手
界面或 API 独立参数：时长、画幅、镜头控制、风格强度等
提示词语言与计数口径：字符 / token / 未公开
官方长度上限与原始来源：
本地已测最大长度与样本日期：
超限表现：拒绝提交 / 截断 / 可提交但尾部遵循度下降 / 未验证
长提示词后段遵循度：稳定 / 衰减 / 未验证
当前长度状态：已验证 / 入口长度兼容性未验证
```

合同缺项不等于入口没有能力，只表示不能把猜测升级成硬规则。未知上限时允许按镜头复杂度写足必要控制，再用生成结果验证；已知上限时，优先把能由资产、参考素材和界面参数承担的信息移出正文，而不是先删掉动作因果、人物关系或结束状态。

项目文本 profile 与实际接口字段分开；profile=H3 不证明某入口接受中文三段式，也不触发自动改六字段。字段不兼容属于入口适配问题，返回具体要求，母稿不被静默替换。

### 多版本从同一确认事实编译

只有用户或实际入口确实需要不同语言、阅读版与执行版时，才从同一份已确认P、C和当前素材绑定编译多个表面；不默认增加双语或三份提示词。各版共享人物、道具、空间、事件顺序、主要动作、台词及说话人、声音策略与结束状态，不能各自重新导演。不同入口需要不同标签或字段时，只改变表达外壳，不让格式转换暗中新增镜头、改写天气或遗漏反应。

翻译的是指令语言，不是未经授权的冻结台词。目标语言的对白改编必须先形成已确认的上游文本，不能在生成版中顺手完成。某个入口是否需要专用主体、音频或台词标签，以当前能力合同的已核验信息为准；来源项目使用的标签和六段式不能自动成为本项目通用协议。

校对时既看人能读到的版本，也看真正复制或导出的正文：纯排版差异可以存在，承重事实、原文台词、引用关系和声音决定必须一致。输入或已确认事实变化后，将受影响的各版一并标记待复验；已经显示在说明或表格中，不能代替执行正文真正包含它。多版本仍是同一事实的派生输出，不再产生多个可各自改写的真源。

## 六、模型适配测试记录

每次跨模型或入口测试后，在能力合同下追加记录：

```text
目标平台 / 具体入口：
模型 / 版本：
样本日期与证据位置：
任务类型：T2V / I2V / 多参考图 / 音频参考
原提示词：
改写提示词：
本次只改变的变量：
生成结果：
意图遵循情况：
模型优势：
模型限制：
副作用：
下次写法调整：
是否更新模板：
```

一次实验尽量只改一个变量，例如只改提示词长度、只改参考图职责、只改连续性把手。否则结果变好时无法判断究竟是哪项控制起作用。
