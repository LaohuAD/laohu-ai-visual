# 模板：整体声音描述与分任务字段

> 归属：本文件是 `laohu-audio-design` 的通用声音字段规格，与《声音提示词规范》《交接与验收》同属一个负责人。规范负责各类声音任务的写法细节，本文件只解决一件事：任何声音任务都要先有一段完整的整体描述，再按字段补易漏的具体决定。**不新建第六个包，也不另造共享教程**；八个子专业保留各自独立判断，本文件只做跨任务的字段口径统一。

## 一、宏观段：整体声音描述

先完整描述**听到什么过程**，再进入字段。整体段必须让读者闭上眼也能重建：

```text
声源之间的主次与先后；空间感与距离；随时间发生的变化；哪一层承重、哪一层让位。
```

整体段不是字段的堆砌，也不能被字段替代。反过来，字段存在不证明整体关系已经成立——两者都要写。

## 二、共用微观字段

适用于任何声音任务；启用后必须答全，不适用的写明理由，草稿阶段明确标待定。三种状态之外不留第四种。

```text
声音用途：配音、单个音效、环境底床、配乐或后期处理。用途是路由信息，决定后面哪些字段启用。
声源与身份：谁或什么发声；已定的稳定身份或材料。
内容或事件：冻结的台词与歌词，或实际声源事件；无对白不造对白。
音高音色与力度：把声音高低、质感与强弱分清，不混成一个“低沉”。
时间变化：起音、瞬态、持续、变化、衰减、尾音，以及需要的停留。
空间与听点：相对位置、远近、遮挡、直达声、反射与混响。
声像与声道：有依据的定位和宽度；不要把单声道处理改写成立体声设计。
同步与衔接：动作相位、画面或音频依据、跨切连续、循环和尾音把手。
主次与让位：前景信息、背景信息，以及谁在什么时刻退让。
交付与保护：必须保留的原文、身份、实物、修复边界与已核验的输出条件。
```

## 三、必须区分的名词

同一段声音里出现这些词时，先拆开再落决定：

```text
音高 / 音色 / 响度：频率高低／泛音与质感／听觉量级，三者不是一件事。
稳定声音身份 / 当场演法：持续辨识／这一场的表达方式；一次愤怒表演不改变声线。
混响 / 回声（延迟）：空间反射形成的持续感／可分辨的重复；延迟也可以是时间偏移或效果。
声像位置 / 宽度：左右定位／展开范围。
EQ / 压缩、限制、扩展 / 音量自动化：频谱调整／电平关系／随时间改变的控制。
整体响度 / 瞬时峰值 / 真峰值 / 动态余量：听觉量度／瞬时最大值／真实峰值／距过载的空间。
音乐速度 / 音符密度 / 配器厚度：拍号与速度／单位时间音符数／配器层数，不能互相顶替。
低沉：必须分辨是音高低、音色暗还是音量轻。
```

**空间远近不只是音量大小。** 直达声与混响的关系、反射、遮挡按场景设计，不能只靠减小音量表达距离。

具体参数和交付响度服从已核验的用途，不把某个广播值当作所有网络音频的通用标准。原混音正文的条件与反例继续有效，不被本节替代。

## 四、按任务启用的专项字段

| 音频任务 | 必须补的专项内容 | 不可越界 |
|---|---|---|
| 音色设计 | 稳定辨识、常态音区、共鸣、口音、节奏及试听条件 | 用一次愤怒表演永久改变声线 |
| 配音 | 对象和策略、冻结句、重音、意群、停顿气口、发音、句尾余势 | 改词、漏词；声线与本场语气混淆 |
| 音效 | 材料、动作／受力、瞬态、共鸣、尾音、空间、独立或与环境混合 | 只写“真实、有冲击力” |
| 环境声 | 底床、远近层、偶发声、听点、遮挡、混响、循环与跨镜连续 | 无原因切镜后换环境 |
| 配乐 | 段落功能、旋律／和声、节奏律动、配器、织体、强弱与留白、分轨需求 | 每条音效填作曲表；擅改最终歌曲 |
| 剪辑修复 | 原实物、缺陷位置、take选择、剪接余量、修复强度、保护音色与字句 | 以修爆音之名全部重新生成 |
| 混音 | 主从、掩蔽、均衡／动态／自动化的选择、空间、峰值与实际用途验证 | 把一个未经核验的响度数值强加所有平台 |

## 五、静默也要明确

静默不是“什么都不写”。四种情况分别成立，必须选一种并写明：

```text
完全静音：没有任何声音层，包括环境。
只保留环境：去掉音乐与效果，只留空间底床。
对白停顿：台词之间的气口与等待，环境仍在。
音乐退出：音乐在某个事件后停止，其他声音继续。
```

音效不是每镜必加。未涉及声音时可以有明确的静默选择，不用匿名“无”代替决定。

## 六、边界

配音逐字保护文本，规范读法与写法分开；改声音状态不改剧情和原话。真人声音复刻继续执行原有授权检查。

只清理爆音不重新生成声线，只混音不擅自重写音乐结构。音乐设计可以提出分轨需要，但不是默认给所有任务生成 MIDI、乐谱或额外文件。

数值测试和听试回执属于制作记录，不作为提示词自动保证的结果。自然语言声线不是物理参数的同义词；需要具体工具参数时由原接口适配负责。只有文本时标记文本合同通过，不报告已生成或已听试。

## 七、提交前检查

```text
整体声音描述是否先成立，而不是只填了字段。
启用字段是否都落在三种状态之一；正式稿是否还有未解决项。
音高、音色、响度是否被混写；“低沉”是否已经拆清。
空间距离是否只靠音量表达；遮挡、反射、混响是否写明。
静默是否明确选了四种之一；音效是否被无理由地每镜都加。
台词是否与冻结原文逐字一致；是否出现了“为时长删词”。
是否把未经核验的响度数值写成了通用硬规则。
```
