# 老胡火柴人知识动画

## 灵魂：让看不见的关系，通过一个小人的行动变得可见

人物推不动什么、被什么阻挡、怎样改变办法，比“知识＋一个摆手小人”更能解释机制。视觉比喻必须保住命题的成立条件，不能把漂亮变形当作事实证明。

## 筋骨：先定解释任务，再编排可见变化

输入知识原文与证据、受众、当前阶段、已定风格；视频阶段另接E-S-P、资产与声音。仅有主题时给解释结构建议并返回编剧完善内容；已有P时只深化段内实现，不重写旁白或重分P。美术与分段可CONSULT本能力取得风格约束、运动潜力和需求；本能力继承[所属专业入口](../../SKILL.md)给出的风格约束与运动潜力，视频主责仍由[视频入口](../../../../SKILL.md)整合。

执行时读取[专项方法与适配](references/专项方法与适配.md)。首次使用或需核对原法时读取[外部原始方法](references/外部原始方法.md)，随后按当前阶段读取[外部分镜模板](references/外部分镜模板.md)的提案结构或[外部OmniFlash提示词合同](references/外部OmniFlash提示词合同.md)的生产合同；[外部案例](references/外部案例.md)只在具体机制不清时读取。上游资料中的确认门、默认英文、六段十秒与模型配置不覆盖用户已定流程及下列本地适配。四份外部方法的许可保存在[上游许可](assets/upstream/LICENSE)，原仓库名、作者与MIT身份不因归位改变。

## 血肉：把命题编排成行动、阻力、改变和理解

每段选择一个承重关系：比较、累积、反馈、瓶颈、误判或因果链。指定谁代表什么、物体哪项属性代表哪个变量、什么必须不变；先展示原状态，再让一个原因触发变化，最后留下可读结果与下段接口。小人自身的预备、接触、受力和反应同样遵守基础动画判断；无脸角色用姿态与动作时间表达，不靠突然长出五官。

为关键解释比较至少两种不同载体，按准确性、直观性和前后复用选取。角色比例、空心圆头、线宽、底色极性及强调色语义持续继承；明确用户选择后可有脸、服装或别的形象，不把默认设计变成所有火柴人的定义。

## 表皮：交给当前阶段可直接使用的结果

返回命题→视觉对应、起态→触发→变化→可读终态、角色/道具/图层需求、旁白兑现位置及接续。给模型的正文采用父级三段式与P内C镜号；不附内部审计词、不声称已生成。文字/数字必须精确时交后期信息层，不用无字图标替代必要知识。配音身份继承音色资产，演法随段变化。

验收：静音能看见关系变化，打开声音后图像不引入错误因果；冻结原话、资产身份和信息次序不变，动作不为凑密度而增加。源知识不可靠返回内容负责人；风格未定返回美术；效果只在真实生成后评价。
