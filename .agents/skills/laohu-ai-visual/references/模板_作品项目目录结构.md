# 模板_作品项目目录结构

## 作品位置与最小入口

作品位于 `01_作品项目/进行中|已完成|已发布/yyyy-mm-dd_作品名/`。这是目录分类，生产状态另记在总览；新建入口始终为 IDEA，不能把收纳位置当作实际完成证据。

```text
yyyy-mm-dd_作品名/
├── 00_项目总览.md
├── 00_阶段确认记录.md
├── 00_项目总览.html          # 自动生成
├── 00_阶段确认记录.html      # 自动生成
├── 00_作品交付中心.html      # 自动生成
└── 00_原始输入/
    └── 文本/
```

创建器使用 `模板_作品项目启动包.md` 的正文，保留旧的作品名、日期、目录状态三个位置参数，新增 `--kind story|image|mv`，默认 `story`。MV 另外建立 `00_原始输入/音频/` 接收最终音频；故事和单张图不预建媒体目录。输入实际到达时才按媒介增加接收位置。

## 需要什么才建立什么

下表是存放约定，不是开工时必须创建的目录树。每个阶段默认一个当前 Markdown 主文件，自动生成同名 HTML；文本和实际媒体按职责分开，有内容再创建对应子目录。

| 触发条件 | 位置 | 内容与边界 |
|---|---|---|
| 原始输入实际到达 | `00_原始输入/文本|图片|视频|音频/` | 原话、参考和来源证据，不冒充确认事实 |
| 叙事确需独立故事设计或世界设定 | `01_世界观故事/文本/` | 故事设计主文件，不重复正式剧本 |
| 叙事进入内容母版 | `02_剧本/文本/` | 完整E-S正式剧本，E-S 的唯一内容与镜头事实来源 |
| 需要设计、图片提示词或稳定资产 | `03_视觉资产/文本/` | 专业设计与资产主文件；真实成图出现后再建 `图片/` |
| MV、强媒介知识动画、故事板图像 / 预视化或明确专业分镜需求 | `04_分镜/文本/` | SHOT 才单独使用；普通叙事不重做独立文字分镜，真实故事板出现后再建 `图片/` |
| 分段执行卡已明确 | `05_视频/文本/` | 继承E-S-P，编写段内C；VC实际调用与最终复验 |
| 视频或声音真实到达 | `05_视频/视频/`、`05_视频/音频/` | 实际生成、参考、剪辑与音频素材；不是启动占位目录 |
| 成片价值需要发布入口 | `07_封面发布/文本/` | 封面和发布方案，成图出现后再建 `图片/` |
| 有待验证的首轮小样命题 | `00_首轮验证看板.md` | 从共享看板选取适用项目，不能空建并催促付费生成 |
| 有真实生成 / 剪辑 / 发布证据需要复盘 | `09_归档复盘.md` | 证据、首断点、最早负责人和回流位置 |

单张图片走 `laohu-visual-assets` 的单张成品图分支，不强走故事、剧本或视频；MV 先让最终音频提供真实时间证据，再由 MV 导演组织结构与制作时间线。

不要为每个阶段固定创建文本、图片、视频、音频四套空目录；也不预建空故事确认稿、验证看板和归档复盘。专业确认门仍按触发条件保留，不能借“最小目录”跳过实际需要的服装方向、F、STY / VMB 人工定案。

## 归档与交付

实际生成媒体必须移动到当前作品对应媒介目录；先校验完整和一致，再清除工具默认目录副本，阶段记录使用项目真实路径。Markdown 为正文权威，运行 `scripts/render_delivery_html.py --project "当前作品路径"` 刷新同名 HTML 与交付中心。作品内容不加入 Git。
