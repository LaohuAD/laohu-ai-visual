# 老胡剧本检视

## 触发时机与本次范围

剧本或场次文本成立后、交 `laohu-video-segmentation` 分段之前进入。此时产物还是文本，条款可以直接对照；检视判断的是这份文本在当前格式与因果上是否成立，不是成片效果。

先写清本次范围：检视的是哪一版剧本、覆盖哪些场次、哪些条款本次真正承重。已由上游确认的故事事实、人物关系、冻结台词和已定导演命题属于保护项，本次检视只核对它们有没有被写坏，不重新裁决。分段之后的段落范围、讲戏、时长与接续，以及视频阶段的 C 摄影与生成，由父入口路由表上的对应能力负责。

## 判据来源

检视条款不另立标准，逐条从已经存在的正式规则里取。每条判据先解析到具体文件与章节，再对照产物。

| 判据类别 | 权威文件与章节 |
|---|---|
| E-S场次结构、场次标注、符号含义、输出合同 | [镜头化剧本与连续性](../../../laohu-script-writer/skills/laohu-format-adaptation/references/镜头化剧本与连续性.md)「正式剧本：集与场」「输出合同」 |
| △的画面单元粒度与一镜一△ | 同上「△的画面单元粒度」 |

| 相邻单元的状态交接 | 同上「相邻单元」；[剧本语言诊断与反向审稿](../../../laohu-script-writer/references/05_剧本语言诊断与反向审稿.md)「整稿交接复验」 |
| 回忆、梦境与时空子场的标记和返回 | 同上「回忆、梦境与时空子场」 |

## 逐条检查项

### 一、格式

```text
场次标注      集标题写“第X集”，每场另写 `X-X`；第二行写“内 / 外  具体地点  日 / 夜 / 晨 / 傍晚 / 雨”。
              换场、时间跳跃、长闪回或新空间开始时，空行并重新标注场次。
场次槽位      【剧本说明】【作品信息】【故事说明】、人物列表、开场状态、本场表演基线、△、台词、括注、【场次结果】
              按“正式剧本：集与场”列出的槽位齐全，正文保持偏小说性的可见结果语言。
人物列表      使用全名或稳定称呼并按全文统一，群众写“亲戚若干”“村民若干”。
△的归属      △ 归属当前场次，分为环境与场景描写、行为与动作描写两类，通过内容清楚区分。
出场人物进程状态
              人物表括号写身份、别名、当场年龄外观、衣物和伤势等状态；跨场继承，只在该场发生变化时重写。
              回忆或梦境中的年轻外貌、完好道具、伤势和地理状态留在该层，返回现实后现实层的伤势、破损和丢失物件仍然成立。
台词与括注    对白前括号写说话者的微表情、小幅动作、语气及必要声源标识，只管这一句或这一段。
              跑出房间、拔刀交锋、摔倒这类主行为另起 △；从对白括号移回 △ 时，台词位置、触发条件和行动顺序不变。
              人物表括号与对白括号不混为一项。
声源标识      O.S. 是同场画外声，V.O. 是旁白、回忆旧话重放、跨时空声音或内心声，需要区分内心时写 `内心V.O.`。
              声源标识只说明声音从哪里来；表演状态在括注或本场表演基线里单独写。
成对标记      【闪回】/【闪回结束】、【梦境】/【梦境结束】成对出现，并且能回到现实；回到父场时写明现实状态。
子场编号      父场内部的局部时空子场显示为 `1-1A`、`1-1B`，并交代该区域的地点、时间和出场人物状态。
输出边界      唯一源稿按 E-S 完整场次组织，正文不写 P、C、机位方头或生成秒数。
引用路径      产物中引用的资产、场次与文件路径真实可解析。
```

### 二、镜头粒度

```text
一镜一△       一个△必须是一个镜头描述。视频阶段可以因连续摄影、真实节奏或可执行性拆合，
              但必须保留原文对应并说明映射和必要原因；编剧不预写焦距、机位或最终 C 号。
画面单元       一行尽量一个能够连续看清的画面单元：换观看对象、明显改变动作相位、需要独立交代的细节分别写。
              同一连续动作内部的连续小动作保持在一行，不按每个动词或逗号机械换行。
              环境整体、角落物件、人物进门、人物停下后的局部反应可以分别成行。
叙述方式       “必要的整体概括＋具体名词、动词、局部状态”：概括由光源、木门、布料、手指、步伐等具体证据承载。
整场粒度       场次从人物、开场状态与表演基线进入 △ 与台词，再到【场次结果】；整场画面不被压成一个长段。
```

### 三、连续性

```text
相邻状态      A 已完成结果、A 结束状态、B 开始状态、必须不变 / 允许变化、B 第一项新动作或声音、下一相位、
              下一场压力逐对写清；直接连续时 `A 结束状态 = B 开始状态`。
道具          会被递、抢、放回、点燃、修复、丢弃或结尾回收的物件，写清出现前状态、触发动作、出现后状态与后续必须保持项。
空间          写明操作者、位置、朝向、视线、遮挡、路径、控制权和行动结果；
              每镜让“世界位置 → 摄影机观看侧 / 视轴 → 画面左中右与前中后景”同时成立。
时间          时间跳跃、长闪回或新空间开始时重新标注场次；短闪回成对标记并可返回。
人物指代      每个新动作段第一次出现人物时先写具体名称；叙述主体切换、段落重开或第三人加入时重新写具体名称。
声音          同期声、画外声、主观声、剧情内音乐按职责区分，写清声源、发生方式和对行动的影响。
动作因果      超常追击、闪现、撞墙、穿楼、机甲变形和大规模特效写出取得结果的中间因果：
              世界能力基线、起始条件、战术目的、发力来源、能力触发、运动路径、环境交互、接触点、受力结果、动作结束。
情绪因果      情绪阶段、关系目的、精确触发、可见泄露、台词策略、句后行动和禁止提前反应写清；
              证据写在同一场相邻动作的 △ 与声音中，括注只保留短的状态索引。
子场返回      子场结束标签之后写明现实状态；现实层的伤势、破损和丢失物件在返回后仍然成立。
```

### 四、信息量

```text
下游不可补猜   观众何时知道、哪些内容暂不可见；人物、空间、动作、声画来源和镜尾状态。
视听证据       跨镜头人物与场景资产信号、关键道具与状态变化、特写信号、声音触发信号、动作因果链、
              可转场物件、结尾画面职责与封面候选画面按需写清，下游据此继续展开。
场次承重       每场改变关系、信息、道具、空间、身体或下一步可能性；
              用可替换性检查：抽掉一场后人物选择、观众期待或下一条件不变时，先查它是否重复。
有效信息密度   每句台词至少改变关系、行动、压力、误会、笑点、必要理解或节奏之一；
              动作分句推进触发、路径、交互、结果或承接。
承重主轴       一个短片优先只有一个最高叙事主轴，其他信息服从这个主轴；
              主角选择、核心物件、结尾画面、台词出口和封面候选指向同一个情绪核心。
体裁边界       按[综合验收与体裁边界](references/综合验收与体裁边界.md)逐项验收：
              不需要冲突的体裁有清楚的观看推进即可成立；长片比例不线性套用到短片；
              结尾回收、黑暗时刻、递增阻力和可截图停点都是候选，只有在题材、观众经历与主情绪都要求时才成为验收项。
巅峰门         主胜负手明确，尚未锁定的关键冲突、阈值选择、高潮或结尾比较过有效对手，
              开头许下的等待由后续更强的选择、代价和结果偿还，下游得到足以继续升级的关系。
```

## 每个问题的三项结论

每个问题都必须给出下面三项，缺一项就不算完成检视：

```text
① 未满足什么        具体条款原文，以及这条条款写在哪个文件的哪一节
② 属于哪一类        输出问题（产物本身没写对）／规则问题（规则没覆盖或表述不清）
③ 归哪个顶层负责人   输出问题 → 对应生产包的专业；规则问题 → 该条款的唯一负责人
```

只写“这里不好”“建议优化”不算检视结论：它没有指出未满足的条款，也没有指出该谁改。分类依据与完整责任链见父入口[责任划分与路由](../../references/责任划分与路由.md)。

输出问题的归口按下列落点确定，落到唯一负责人而不是“相关专业”：

```text
剧本格式、E-S场次、△粒度、出场人物状态、括注与声源标记   → 编剧，格式与改编能力
人物欲望、错误信念、防御动作与可表演性                   → 人物与冲突能力
冲突、结构、高潮、结尾与尺度容量                         → 故事结构能力
场面目标、行动回应、道具、空间与停点                     → 场景能力
台词、潜台词、人物声口与声音形状                         → 对白能力
选题角度、价值方向与传播包装                             → 前提与主题能力
分段范围、讲戏、时长与接续                               → 分段负责人
语言表达、接收者与冗余                                   → 语言模式包
```

规则问题的归口按“当前 Skill → 对应 Reference → 顶层合约”的权威顺序落在最省的那一层，由该条款的唯一负责人补条款；检视只登记缺口，不自行写入生产包。

## 输出格式

```text
【检视范围】产物的版本与位置、覆盖的场次、本次承重的条款
【问题清单】逐条写：编号｜位于哪一场哪一处｜未满足的条款＋条款出处｜分类｜归口负责人
【路由结论】按负责人分组，写明该负责人要做的具体动作
【条款缺口登记】本次发现、本该被拦住但现有判据里找不到的问题
```

条款缺口登记使用父入口[检视判据](../../references/检视判据.md)的固定字段：未拦住的问题、本该拦住的阶段、现有判据为什么没拦住、建议补在哪一层。

问题清单为空时，写明检视了哪些条款、依据哪一版产物，不把“没发现问题”写成“剧本已通过全部验收”。检视范围只到本轮真正核对的条款，未覆盖的条款在缺口登记里写明。

面向老胡的检视结论按本包[语言表达](../../references/语言表达.md)写成结论、依据、分类、归口、下一步的固定写法。

## 父入口与补充方法

- [老胡检视官](../../SKILL.md)：本能力的父入口，包级路由、三种路由结果与最终交付要求在这里。
- [综合验收与体裁边界](references/综合验收与体裁边界.md)：需要判断剧本的骨架与开放位置是否成立、或需要按体裁边界作反向逐项检查时读取。
- [检视判据](../../references/检视判据.md)：需要展开格式、内容、信息量与密度的通用判据、正反例或常见误判时读取相应章节。
- [责任划分与路由](../../references/责任划分与路由.md)：需要判断问题属于输出问题还是规则问题、或需要确定归口负责人时读取相应章节。
- [语言表达](../../references/语言表达.md)：本次需要写面向老胡的检视结论正文时读取。

每条读取先写清当前未决问题、要读的精确相对文件与章节、应形成的决定；读完要能指出它确认或改变了哪一个具体判断，只记录“已读取”不算激活。检视不替生产端重写产物：未满足项、条款出处、分类和归口写清之后，返修方案由对应负责人决定。
