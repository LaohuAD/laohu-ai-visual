# 老胡图片提示词检视

## 触发时机与本次范围

图片提示词写完、尚未投喂生成时进入。此时判断的是这份文本的可执行性与合规性，不是真实图像质量；生成之后的身份、结构、参考转译、注意力与像素质量由[图片评审](../../skills/laohu-generation-review/skills/laohu-image-review/SKILL.md)负责。

先写清本次范围：检视的是哪一版提示词、对应哪张图、图属于哪一种用途与结果身份、哪些字段与保护项本次真正承重。已经人工选定的定调图、已确认的身份与结构、已锁定的文字与设计属于保护项，本次检视只核对它们有没有被写坏或写漏，不重新裁决。上游故事、场次与镜头内容是否成立，归剧本与视频包的检视，不在本条重复判断。

## 逐条检查项

### 一、字段完整性

```text
三种状态      每个启用后的字段只落在具体决定、不适用并给出理由、草稿阶段的待确定之一。
              正式可生成稿留有未解决的关键项，或把未知写成“不适用”时，都按缺项处理。
              “保持固定”“无新增特效”“可见范围内没有配饰”都是决定，可以照写。
共用覆盖项    画面用途、视觉风格、画面气质、主体与状态、场景与交互、构图、色彩、光影、材质。
              画面用途是路由信息，放在可复制正文之外。
摄影模块      本张图确实由摄影机成像时启用：观察方位、俯仰与倾斜、机位高度、取景锚点、
              景别与取景范围、对焦对象、景深、焦外表现、曝光与成像。
质量与保护    身份、结构、文字、已定设计与材质保护要求，并包含「减少假纹理假细节」。
提示词必写项  图片用途、服务场次 / 镜头、必须锁定、允许变化、不能继承、可复制图片提示词、是否可作为视频参考图。
```

### 二、结构

```text
结果身份      先判断本图是结果图写真、制作资产还是叙事成品图，三者使用各自的外壳。
三段职责      结果图写真内部完成【基础设定】→【氛围与画质】→【画面内容与构图】；
              标题可以显式或融合进连续画面叙述，验收看职责是否齐全且共同指向一个结果。
              【基础设定】写图片类型、用途、表现媒介、原创对象、身份 / 功能、必须继承的参考；
              【氛围与画质】写主名称锚点及其召回职责、按需一个机制锚点、色彩光线材料空气与成像介质；
              【画面内容与构图】写对象完整具体设计、姿态 / 状态、环境、摄影机高度与方向、焦段与透视、
              主体占比、第一落点、前中远景、留白和裁切安全。
制作资产      保留自己的专业框架：W 仍是平铺 / 人台 / 细节拆解板，S 仍是多机位与鸟瞰结构板，
              B 仍是固定三列校准板；身份、结构、材料或拓扑证据不退让。
一级结构      微观字段在既有三段内部补齐，同一整段不换标题重复多遍，正文不出现第二套一级结构。
二维知识图    完全没有模拟空间摄影时改用二维知识图的图文专业字段，构图、色彩和图形层级继续成立。
```

### 三、专项触发

```text
触发判断      先判断本图命中哪些触发条件，启用后使用固定标题回答；未启用的模块不进入正文。
人物类        有人物或类人角色时启用人物外观、服饰、配饰、妆发、姿态表情。
产品道具类    主体是产品、道具或设备时启用形体结构、功能部位、比例尺度、操作关系、表面标识。
建筑场景类    建筑、室内或景观时启用空间层次、尺度参照、路径出入口、结构和陈设、环境状态；
              实体空间布局与图上构图分别写。
封面知识图    封面、海报或知识图时启用准确文字、信息层级、图文版式、图形编码、单位与标注、阅读顺序。
图像编辑      编辑任务启用修改区域、保护区域、编辑强度、身份结构保护、边缘与光色衔接。
一致性资产    一致性资产启用身份固定项、当前状态、取景资格、实际参考职责、下游使用条件，
              沿用现有资产编号与校验格式。
画幅一致性    人物类字段与实际画幅一致：取景锚点不在脸上时，对焦对象不填眼睛；
              宏观描述没有要求看脸时，妆发不为了填空强加进画幅。
              用户改成“眼睛必须清楚”后，重新协调取景、机位和清晰范围。
图形类颜色    关键区别同时使用文字、形状或标记，颜色只作辅助。
```

### 四、可执行性

```text
可见结果      每句话指向一个可生成或可拍摄的结果，结果能够从生成画面中判断。
镜头—麦克风测试
              对象、位置 / 时间、变化和结果不能验收的句子，属于解释性表述，需翻译成可见证据。
属性绑定      按“对象 → 本对象属性 → 本对象动作 / 位置 → 与其他对象关系”组织，
              颜色、材料、衣物、动作和表情就近绑定。
空间时间关系  空间用左 / 右、前景 / 后景、靠近 / 远离、朝向、遮挡、接触点和承托物；
              时间用起点、触发、变化、结果和停点。
抽象词解压    “电影感”落到观看位置、构图、光源、色彩、材质和成像介质；
              “治愈、危险、孤独”落到处境、表情、身体、空间和环境证据；
              “特写”落到裁切、主体占比、角度、焦点和可见细节；
              “高级”落到比例、接缝、材料、留白、层级与真实使用情境。
专有词翻译    世界观专有词保留名称并紧跟视觉翻译：形状、尺度、所在部位、颜色、表面、软硬、
              透光 / 反光、垂坠 / 张力、运动状态、与相邻材料的差异。
风格分权      一个主锚点决定第一眼审美世界，机制锚点最多补一项构图、色彩、光影、材料或运动机制，
              文化根系只提供形态、色域或材料来源；每个名称写出它负责的具体职责。
正向语言      正文用正向、具体、直接的结果语言；需要排除的具体对象放在模型独立负面通道、
              代码块外的人工验收或模型适配层。
代码块边界    代码块内只放可直接粘贴给模型的正文，代码块外写说明、跑偏对象和资产边界；
              图片模型代码块里不用引号做强调，画面上要出现的文字用“标签文字为：…”这类无引号写法。
参考绑定      需要手动绑定的内容用【……参考@……】显性标注，并在同一句写清职责；
              每张参考的职责单一且绑定明确。
```

### 五、信息量与密度

```text
唯一主结果    能指出这张图最终必须成立什么；一张图只有一个主要结果，最多保留一项明确从属的次要结果。
注意力合同    唯一生成任务、主注意力、主证据、支撑证据、主动退让、3—6项不可丢锚点。
强度门        承重维度达到 3 级：目标证据足以被辨认并主导观看，其他元素明确退让；
              支撑维度达到 2 级；主动退让项不被写成新的 1 级焦点。
选择性编译门  每项信息进入正文至少满足一项：缺失会改变主结果；会造成身份、题材或关系误读；
              在当前主体尺寸真实可见并承担非默认人物记忆点；为主证据提供必要摄影托举。
单帧证据尺寸  全身、脸部微表情、服装微纹理和宏大环境不同时达到最高可读级别；
              在当前主体尺寸下不可见的要求不作不可丢锚点，改为派生头肩、B / W / M 制作板。
信息密度分区  高信息区承载细节（脸、手、道具核心、服装关键结构、标题钩子、空间入口、动作起点）；
              中信息区承载关系（衣料整体、背景主体结构、环境材质、光影层次、辅助道具）；
              低信息区承载呼吸（天空、墙面、暗部、虚化背景、海面、雾气、远景和边角）。
单帧因果      含人物的结果图写出过去痕迹 / 当前关系响应 / 下一趋势；
              动态动作帧额外闭合意图 → 支撑 / 起势 → 力量来源 → 单一力量或运动路径 →
              接触 / 临界接触 → 受影响对象 → 结果与余势。
主情绪唯一性  主情绪是“主体处境＋对处境的态度”，第一情绪只有一个，复杂余味放在第二眼；
              视觉焦点与情绪重心分别判断。
参数与证据    摄影参数与想看清的证据一致：完整角色写真需要脸和服装共同清楚时，
              使用中长焦、适度浅景深和足以覆盖全身的焦平面。
用途验收      叙事成品看主情绪与第一视觉，制作资产看身份、结构、一致性和下游调用，
              教程演示看理解与行动；用途改变时同一条特征是否算“做够了”随之改变。
```

### 六、正文与说明的分工

```text
清单归检视    核对清单写给检视者，正文写给模型执行；清单项以可见标签进入代码块时，
              模型读到的是解释而不是画面。
内部元语言    代码块只保留会改变像素、运动、声音、构图、身份或连续性的内容；
              灵魂、筋骨、血肉、表皮、注意力合同、主证据、语义最小集、关系不变量、形式转译卡
              留在内部工作卡。
作者解释      为什么这样设计、人物心里明白什么、观众应该感到什么、这一镜象征什么，
              翻译成关系对象、眼线、身体、衣发、道具、环境、摄影机、光线或声音证据后才进入正文。
先验召回      题材、媒介、身份、成熟风格或摄影母型只负责当前需要的题材、身份、成像或单一风格机制；
              正文主体是镜头控制。
```

## 每个问题的三项结论

每个问题都必须给出下面三项，缺一项就不算完成检视：

```text
① 未满足什么        具体条款原文，以及这条条款写在哪个文件的哪一节
② 属于哪一类        输出问题（产物本身没写对）／规则问题（规则没覆盖或表述不清）
③ 归哪个顶层负责人   输出问题 → 对应生产包的专业；规则问题 → 该条款的唯一负责人
```

只写“这里不够具体”“建议优化”不算检视结论：它没有指出未满足的条款，也没有指出该谁改。分类依据与完整责任链见父入口[责任划分与路由](../../references/责任划分与路由.md)。

输出问题的归口按下列落点确定，落到唯一负责人而不是“相关专业”：

```text
美术风格、形态 / 色彩 / 材料 / 光影体系         → 美术风格设计
人物外形、选角、身体与群像差异                  → 人物设计
服装结构、轮廓与世界衣橱                        → 服装设计
妆面、发型、毛发与特效妆                        → 妆发设计
地点、空间关系、行动条件与陈设                  → 场景与布景设计
道具本体、功能与操作结构                        → 道具设计
资产编号、依赖、固定项与验收资格                → 视觉资产
构图、摄影、光影、信息设计                      → 对应美术方向专业
封面与海报的承诺、标题空间与缩略图              → 封面与海报
图片提示词编译本身（字段、结构、专项触发、正文语言） → 图片提示词编译
上游故事、场次与镜头内容                        → 编剧
语言表达、接收者与冗余                          → 语言模式包
```

规则问题的归口按“当前 Skill → 对应 Reference → 顶层合约”的权威顺序落在最省的那一层，由该条款的唯一负责人补条款；检视只登记缺口，不自行写入生产包。

## 输出格式

```text
【检视范围】提示词的版本与位置、对应图片的用途与结果身份、本次承重的字段与保护项
【问题清单】逐条写：编号｜位于哪一段哪一处｜未满足的条款＋条款出处｜分类｜归口负责人
【路由结论】按负责人分组，写明该负责人要做的具体动作
【条款缺口登记】本次发现、本该被拦住但现有判据里找不到的问题
```

条款缺口登记使用父入口[检视判据](../../references/检视判据.md)的固定字段：未拦住的问题、本该拦住的阶段、现有判据为什么没拦住、建议补在哪一层。

问题清单为空时，写明检视了哪些条款、依据哪一版提示词，不把“没发现问题”写成“这张图已验证通过”。文本检视只到可执行性，真实图像的身份、结构、参考转译、注意力与像素质量留给生成后的[图片评审](../../skills/laohu-generation-review/skills/laohu-image-review/SKILL.md)。

面向老胡的检视结论按本包[语言表达](../../references/语言表达.md)写成结论、依据、分类、归口、下一步的固定写法。

## 父入口与补充方法

- [老胡检视官](../../SKILL.md)：本能力的父入口，包级路由、三种路由结果与最终交付要求在这里。
- [检视判据](../../references/检视判据.md)：需要展开格式、内容、信息量与密度的通用判据、正反例或常见误判时读取相应章节。
