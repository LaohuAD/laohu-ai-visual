# 老胡视频提示词检视

## 触发时机与检视对象

视频提示词写完、还没有投喂生成时进入本能力。检视对象是这一条正式提示词本体，以及它所依据的源P、分段执行卡、冻结台词、实际绑定资产和目标入口能力合同。

本次判断的是可执行性：这段文本有没有把已经成立的镜头写成模型能执行的起点状态、触发、屏幕变化、声画结果和结束状态，有没有达到已经写明的条款。真实结果好不好看由[生成与发布复盘](../laohu-generation-review/SKILL.md)按真实媒体判断，两种证据分开记录。

生产端保留对本条提示词的修改权。检视只指出未满足的条款、分类和归口，不改写正文、不动冻结台词、不重新决定剧情与资产事实。

## 逐条检查

按下面的顺序过一遍。每一条都要能指出它在提示词里的具体位置；指不出位置的不算检视结论。本清单供检视逐条核对，模型正文保留连续导演句。

### 一、三段式与一级区块

- 正式代码块是否只有三个一级区块，顺序为 `【基础设定】→【场景状态与氛围画质】→【画面内容】`；镜头方头、补充轨与内嵌台词都属于第三块内部，没有出现第四个区块；段内模型标签（`<Subject N>`、`<d>`、`{台词}`、`[Character A: …]`）是否被误判成结构标题之外的作者说明、额外轨或新增一级段。
- `【基础设定】` 是否只写总时长、生成方式、本镜实际绑定资产的职责和一句全条声音策略。
- `【场景状态与氛围画质】` 是否只写开拍前已经成立、且跨本条全部镜头有效的空间边界、人物与道具初始位置、主成像基底、宏观光色与空气关系。
- 开拍后才发生的入场、落泪、破坏、天气突变和局部光色变化是否留在对应镜头块。
- 代码块外是否保留分段ID与原文来源映射、段内C镜头任务、实际绑定资产、相邻批次交接、素材剪辑接口卡、字符实测与生成风险回传字段。
- 代码块内是否只有模型需要的内容；作者意图、验收说明、后期备注与前后镜头关系是否留在代码块外。
- 结构标题、C方头和补充轨本身不等于画内字幕：只有明确写为画面文字／字幕／屏幕内容的才进入可见文字任务；已批准的精确文字不被通用“无字幕”禁令删除，也不因提示词里出现方括号、尖括号或标签字样被当成水印或随机文字拦掉，逐字准确但不适合模型绘制的内容是否有明确的后期承接位置。

### 二、C方头与连续编号

- `【画面内容】` 内每个镜头是否以 `【C01｜景别｜机位 / 视角｜运镜 / 转场】` 独立分块，编号连续、无重复、无跳号。
- 方头四槽位是否与本镜正文一致：景别与信息尺度、观察方位与俯仰机位高度、摄影机路径或固定、转场机制，正文是否逐项兑现。
- 世界位置与屏幕投影是否分开核对：人物站位、眼线和轴线在世界坐标里是否连续，屏幕左右与观看侧变化是否有可追认的移动或重建证据；有意重建观看侧不强判为错。
- 运镜是否服务本镜观看任务：固定机位、静止观察和有意变焦都可以成立，不因缺少物理位移或出现变焦判缺陷；摄影机路径、焦点迁移与停点是否与正文写出的屏幕变化一致。
- 方头是否只标顺序；正式正文是否没有 `0—2秒 / 2—5秒` 这类绝对起止区间。
- 同一镜头的一镜到底是否只保留一个头部并写完整连续路径；实际剪切、时空不连续或观察位置不连续时是否新开编号，并在路径栏明确硬切、遮挡转场、甩镜或匹配剪辑。
- 分镜表、预演板和正式正文的镜头编号是否能够互相对齐。

### 三、镜头正文顺序

每一镜按下面的顺序写成连续导演句，顺序体现在句子的先后：

```text
画面里有什么
→ 机位（观察方位、俯仰与机位高度、景别与取景范围，从哪一侧、多高、多远、拍什么）
→ 主体与主体的变化（写明变化由什么引起、发生在哪个通道）
→ 机位的变化（起→经→停、速度，主动选择还是响应主体）
→ 光影变化及其来源 → 环境变化 → 构图变化 → 声音与特效
→ 结束画面与镜间衔接 → 可选的一句极小术语收束
```

- 第一句是否直接写画面里看见的对象和动作。
- 正文是否只写屏幕可观察结果：每个实义句能在成片里被直接看见、听见，或通过景别、构图、屏幕方向、焦点、透视、地平线、遮挡和镜头运动直接感到。
- 术语是否只作收束，可见结果写在术语之前；术语没有单独承担执行。

### 四、一镜一事

- 每镜是否只有一个主画面内容、一项主变化、一条连续摄影机路径和一个主观看任务。
- 两镜以上共同完成同一人物选择、道具操作或连续动作时，`【画面内容】` 开头是否先用一至三句画内事实写连续动作主线，并与全部逐镜正文逐项一致。
- 多主体运动是否逐一锁定世界坐标、屏幕坐标、朝向、速度与加减速、景深层、路径、相对顺序、终点和出画顺序。
- 真实切镜是否已经新开编号；连续拉焦、揭示和可达机位变化是否保留同一镜头身份。
- 镜头数量是否由目标体验决定，每增加一个镜头都带来新的信息、情绪、空间关系、动作阶段、视觉证据或节奏压力。

### 五、补充轨

- 补充轨是否按需紧跟本镜描述，使用 `【VFX】【环境音】【动作音】【音乐 / 节拍】`，并与正文同名事件绑定。
- 每个补充轨是否都有正文触发点：正文先一笔带过写出已经发生的事件，补充轨再对同一事件细化。
- 环境音是否写当前空间持续声场，动作音是否写当前接触或运动的同步声音，音乐是否写正文同步事件的拍前蓄势、重拍、完成点与拍后余波。
- 声音与特效是否逐镜分别写；没有内容时直接省略，不写匿名「无」，也不只在全段末尾列一张无法对齐镜头的声音清单。
- 补充轨是否只细化正文已经发生的事件：没有新增事件、没有改变主体状态、没有孤儿标签。

### 六、台词嵌入

- 冻结台词是否直接嵌入说话者所在镜头正文，与开口前动作、说话对象、本次表演、听者反应和摄影机变化连续书写；是否没有另列 `【台词】/【对白】` 轨。
- 台词是否与剧本原文逐字一致：没有为凑字符删词、改句、加句。
- 情绪承重台词是否同时写清重音 / 气口 / 口型、说话中的身体变化、眼神与面部、听者准确反应和句后停点。
- 会出声的人物是否保持同一音色锚点；本镜的病弱、哭腔、压低、隔门闷声或电话失真是否作为当前镜头状态写进画面内容。
- 段内标签是否只包冻结载荷本身：`<d>[……]…</d>`、`{台词}`、`[Character A: …]` 只包冻结台词，说话者、演法、声源和语言标记在容器之外；台词里出现的括号、尖括号、代码词或标题字样是否逐字保留，没有被二次解释成控制语法、删改或拆成另一条对白轨。

### 七、字符与结构机械检查

- 结构检查是否通过：三段齐全、镜头方头齐全、没有绝对时间轴污染。
- 字符检查是否在最终一次正文修改之后运行，只统计单个正式 `text` 代码块。
- 字符上限是否来自当次已核验的目标入口能力合同；项目配置与平台公开上限是否分开记录，未核验时只报告实测长度。
- 正文是否通过最低充分控制密度：复杂单元仍有承重人物、空间坐标、触发、表演、摄影机、声光环境、结束状态需要模型猜测时继续补足，既不为接近上限同义反复，也没有把「不凑上限」当成提前停止的理由。
- 字符统计是否按原始选中提示词计数：标签、紧邻文字的冻结载荷与标点空格一并计入，不按剥离标签后的长度、JSON 或 HTML 转义后的长度报告；结构标题、段内模型标签与普通导演正文是否分开识别，`<Audio 1>` 一类模型标签不被当成 Seedance 音效括号，Seedance 的括号音效不被当成 HTML，引用清单、实际文件与演员是否真在发声不由词法通过证明。

### 八、底线门与巅峰门

底线门与巅峰门逐条判据见[生成前验收判据](references/生成前验收判据.md)；镜头特征部分见[镜头特征质量验收](references/镜头特征质量验收.md)；本镜声音承重时，音频侧判据见[音频设计验收判据](references/音频设计验收判据.md)。

底线门未通过时，问题留在视频包修复，不进 VC、不进付费生成；底线门通过只说明可以进入下一轮比较与 VC 提纯。

### 九、参考绑定与调用回执

- Reference 调用回执是否指出机制改变了哪一个具体决定、落在哪一处成品；只写「已阅读」或摘抄摘要不算调用。
- 实际绑定资产是否真实存在，本镜未出镜、未出声、未参与空间的资产是否已经删除。
- 图生视频、首尾帧和多参考任务是否打开过真实图片，参考图调用合同的路径、入口模式、可见对象、固定与可动边界、禁止新生对象、首个变化与最终结果是否齐全。
- 参考图是否通过语义一致性门：文件名与真实像素一致，草图已验收，没有内部编号或临时占位泄漏。
- 段内标签是否与当前模型 profile 一致，定义、实际输入、角色／属性、发声事件和冻结载荷能否相互回指；一个输入提供多个 Subject、多个输入共同定义一个 Subject、参考视频音轨单独启用是否按关系类型核对，没有被当成额外资产或漏项。
- 未核验的标签效果与平台参数是否没有被标成实际通过：语法通过、引用通过、语义检视通过和实际生成通过是否分别记录，没有用文字验收替代实物验收。

## 三项路由结论

每个问题都必须给出下面三项，缺一项不算完成检视：

```text
① 未满足什么        具体条款，以及这条条款写在哪个文件
② 属于哪一类        输出问题（产物本身没写对）／规则问题（规则没覆盖或表述不清）
③ 归哪个顶层负责人   输出问题 → 对应生产包的专业；规则问题 → 该规则的唯一负责人
```

三种路由结果：

```text
规则没覆盖这条                         → 规则问题 → 归该规则负责人 → 补规则
规则覆盖了、检视查出来了、产物照旧错   → 输出问题 → 归生产端专业 → 改产物或补该专业表述
产物错、检视没查出来                   → 检视问题 → 归检视官 → 补检视判据
```

视频提示词的条款负责人按权威顺序确定：三段式、时序因果、状态账本、资产绑定与交付验收归 `laohu-video-prompt`；逐镜方头与镜内必答项归 `laohu-video-compilation`；音频文本设计与验收归 `laohu-audio-design`。分类与归口的完整判断见[责任划分与路由](../../references/责任划分与路由.md)。

## 输出格式

每次检视先写本次依据的一版产物与条款范围，再逐条列问题，最后列缺口登记。

```text
检视范围    依据哪一版提示词、对照了哪些条款
问题清单    每条写明：未满足什么（条款与所在文件）｜出现在提示词哪一处｜属于哪一类｜归哪个顶层负责人
路由结论    规则问题补在哪一层／输出问题交哪个生产端专业／检视问题补哪条判据
缺口登记    本次有没有本该拦住、而现有判据没有覆盖的问题
```

问题清单为空时，也写明检视了哪些条款、依据哪一版产物，不把「没发现问题」写成「已经通过全部验收」。检视结论属内部规则，写入 `04_诊断与系统日志/` 或使用者指定位置，不生成作品 HTML。

## 与相邻能力的分工

- 三段式、C方头、镜头正文顺序、一镜一事、补充轨、台词嵌入与字符结构由本能力逐条检视。
- 底线门与巅峰门的专业判断由视频包及其子专业作出，本能力对照条款判断是否达到，并把未满足项写回条款出处。
- 已有真实视频结果时，交[视频评审](../laohu-generation-review/skills/laohu-video-review/SKILL.md)从真实媒体往回找第一个断点。
- 需要判断问题属于输出问题还是规则问题、或确定归口负责人时，读[责任划分与路由](../../references/责任划分与路由.md)。
