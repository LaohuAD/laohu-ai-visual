# 责任划分与路由

本文件负责一件事：把检视发现的问题，判成「输出问题」还是「规则问题」，并落到唯一负责人。它不重复任何专业方法，只提供归口判断。

## 一、为什么检视必须给出归口

同一句「这段不达标」，指向三个完全不同的修改动作：

```text
产物没按已写明的条款写   → 改产物，或改生产端对这个专业的表述
条款根本没覆盖这种情况   → 补条款，归该规则的唯一负责人
条款覆盖了、检视也做了、产物照旧错 → 生产端的执行出了问题，改生产端
条款覆盖了、检视没查出来 → 补检视判据，归检视官
```

修错地方的代价是：产物照旧错、条款越来越长、检视官替生产端写第二套方法。三种原因分开之后，每一次返修都只改一个地方。

## 二、两项分类的判断方法

### 输出问题

判定信号：

```text
能指出产物哪一处违反了哪一条已写明的条款
该条款所在文件明确写了这条要求的触发条件与完成标准
条款本身表述清楚，不需要再解释才能执行
```

处理动作：归该条款的生产端专业，由它决定返修方案。检视官只指出未满足项与条款出处，不改写产物。

### 规则问题

判定信号：

```text
产物做对了，但找不到任何一条条款要求它这么做
两条条款对同一件事给出不同要求，无法同时满足
条款要求存在，但触发条件、完成标准或边界不明确，同一份产物能被读成达标也能被读成不达标
条款覆盖了一个具体媒介，换到另一个媒介后不再成立
```

处理动作：归该规则的唯一负责人补条款。规则负责人从「当前 Skill → 对应 Reference → 顶层合约」的权威顺序确定，不由检视官指定。

规则问题在检视结论里要写清三件事：缺的是哪一类判断、这类判断在哪个阶段被需要、补在哪一层最省。

## 三、责任链

真实结果不达标时，按下面顺序问：

```text
第一步  这个结果本该由谁负责？           → 该阶段的生产端专业
第二步  检视官本该查出来吗？
        本该查出来却没查出来             → 检视问题 → 补检视判据
        查出来了、生产端也收到了、产物照旧错 → 生产端问题 → 优化该专项能力的表述
第三步  生产端改完，同一份输入再走一遍，结论是否改变
```

第二步的两个分支不能同时成立。判断依据是检视记录本身：这次检视有没有针对该条款给出过结论。

第一步要落到「最早能改变根因的负责人」，而不是最后一个经手的环节：

```text
源故事、台词、空间因果不足        → 编剧
造型、视觉系统、构图与光影错误    → 对应设计专业
实际资产、绑定、参考图错误        → 资产负责人
分段范围、讲戏、时长与接续错误    → 分段负责人
P内摄影、声画、剪辑、声音实现错误 → 视频包对应专业
歌曲事实、全曲时间与MV结构错误    → MV导演
语言表达、接收者与冗余问题        → 语言模式包
```

## 四、检视官与生产端的边界

```text
检视官负责   判断是否达到已写明条款、给出条款出处、分类、归口
检视官不负责 重写产物、发明新标准、决定返修方案、替生产端解释条款
```

生产端负责在收到检视结论后决定：接受返修、提出异议、还是补齐条款。生产端提出异议时，异议本身也是一条待判定的命题：如果它指出的是一条真实存在的条款冲突，那属于规则问题，归该条款负责人。

## 五、生成前与生成后的不同归口

```text
生成前检视  产物是文本，条款可以直接对照
            不达标 → 打回重做，不让下游替它兜底
            路由结果以「补规则」和「改生产端」为主

生成后复盘  产物是真实媒体，条款无法直接对照
            先从真实结果往回找第一个断点，再看该断点是否在检视范围内
            路由结果三种都可能出现，「补检视判据」主要在这里出现
```

生成前检视不能拿「还没生成，无法判断」当作通过；它判断的是可执行性，不是真实结果。生成后复盘不能拿「提示词里已经写了」当作通过；它判断的是真实媒体里是否出现。

## 六、复盘归因的固定字段

生成后复盘每次留下同一组字段，供下一次检视复用：

```text
实际观察          看到或听到的事实，以及发生在哪个文件、哪个时点
证据尺度          画面尺寸、截图帧号、音频时点、平台窗口与分母
首断点            最早一处与预期不符的地方
保护项            本次不能改的已确认事实
返修负责人        按第三节的责任链确定
限定实验          下一次只改一个变量时的验证办法
```

只写「效果不好」「需要优化」不算复盘结论：它没有实际观察，也没有首断点。

## 七、跨阶段复盘与能力进化

生成后复盘得出的结论分两种去向：

```text
只影响当前作品        → 返回对应生产端专业返修
可能改变长期能力      → 交 laohu-capability-evolution，由它选择受影响的层
```

能力进化的判断不属于检视官的默认职责。检视官给出的是「这一次的问题归谁」，是否升级成长期规则由能力进化专业决定。

## 八、归口检查清单

```text
每个问题是否写出了具体条款与所在文件
每个问题是否写明了分类，且分类依据可复核
每个问题的归口是否落到唯一负责人，而不是「相关专业」
规则问题的补丁是否落在权威顺序里最省的那一层
复盘是否区分了「本该查出来却没查出来」和「查出来了产物照旧错」
本轮是否有条款缺口未记录
```
