# 检视判据

本文件展开检视时真正对照的东西：条款从哪里取、怎样算未满足、哪些情况容易被误判。它不新建一套标准，只把已经写在生产包里的条款整理成可逐条核对的判据。

## 一、判据的三种来源

```text
格式与结构   产物自身的版式条款：段落、编号、字段、命名、代码块边界
内容与因果   专业判断是否成立：起点、触发、变化、结果、结束状态是否闭合
信息量与密度 该写的独立信息是否写全，有效信息占比是否足够
```

三类判据的权威位置：

| 判据类别 | 权威位置 |
|---|---|
| 剧本格式、E-S结构、△与镜头粒度 | `laohu-script-writer` 及其格式能力的输出合同 |
| 图片提示词字段与结构 | `laohu-image-creation/skills/laohu-image-prompt` 及其模板 |
| 视频三段式、C方头、补充轨 | `laohu-video-prompt/SKILL.md` 与 `laohu-video-compilation` 模板 |
| 专业判断的底线门与巅峰门 | 对应专业的 `SKILL.md` |
| 跨阶段交接字段 | 对应 `交接与验收.md` |
| 字符、编号、命名等机械边界 | 对应 `scripts/` |
| 迁移与整理的信息量底线 | `~/.dsh/AGENTS.md` 第九节 |

## 二、格式判据

格式判据只判断「结构是否按已写明的版式成立」，不判断内容好坏。

### 逐条核对

```text
一级区块是否齐全，且顺序与条款一致
编号是否连续、是否有重复、是否与所引用的上游编号一致
每个编号项是否带齐条款要求的字段
代码块内外是否按条款分工，正文是否只放模型需要的内容
命名是否符合条款约定的形式
引用的相对路径是否真实可解析
```

### 常见的结构缺口

```text
区块齐全但内部为空，或只放了一句过渡语
编号连续但字段缺失，例如有编号无标题
代码块内混入了作者解释、验收说明和后期备注
同一份产物里出现两套编号体系，且没有映射
引用的文件路径在上一次迁移后没有重算
```

## 三、内容判据

内容判据判断「这一项是否真的成立」，逐项都要能指出证据在产物里的哪一句。

### 通用四问

```text
起点状态是否写清        变化从什么状态开始
触发是否写清            由什么引起，发生在哪个通道
变化是否写清            方向、幅度、路径，以及可见或可听的结果
结束状态是否写清        最后停在哪里，下一项承接什么
```

四项缺一，这一项就不算成立。只写结果不写来源、只写形容词不写可见事实，都归入缺失。

### 单一承重

```text
一个单元是否只有一个主要结果
是否最多保留一项明确从属的次要结果
并行的专业维度是否被写成了上下游关系
```

### 可执行性

```text
每句话是否指向一个可生成或可拍摄的结果
是否把核对清单当成了正文骨架
是否存在只有作者本人能懂的内部编号、临时占位或过程说明
```

## 四、信息量与密度判据

### 迁移与整理

对已有内容做搬移、合并、拆分、提取时，原文的信息量、有效信息量、信息密度都不能降低。核对方法：把源内容里的每一条独立信息列出来——一项条件、一个例子、一条反例、一处边界、一个数字、一句出处——逐条在新位置找。

```text
找不到的条目就是降低，补回
「读起来更顺」不能作为删掉一条信息的理由
编号、层级、语序可以重排，信息本身不是
提取等于拿走：整个文件被取出就删源文件，整个目录被取出就消源目录，只取某一段就只删那一段
源位置不留空壳、不留跳转文件
```

### 正文密度

```text
是否还有承重人物、空间、表演、摄影机、环境或后半段状态需要模型猜测
有效控制信息是否足够，而不是靠同义反复、作者解释和低权重装饰凑长度
是否存在机械最低字数造成的注水
是否存在为了不超上限而提前停止，导致对白表演、空间调度、动作因果、声画来源或结束接口缺失
```

## 五、常见误判

### 把核对清单当正文骨架

核对清单是写给检视者的，正文是写给模型执行的。清单项进入正文后变成可见标签时，模型读到的是解释而不是画面。

```text
错误  画面里有什么：一名女子站在窗边。这一镜只有一个主变化，是自主的：她转头。
正确  一名女子站在窗边，侧脸对着室内。她缓慢转头看向窗外，肩线随之转动。
```

落笔自问：这句话是写给模型执行的，还是写给审稿人看的。

### 把并行项写成下游

机位、运镜、构图、景别、特写是同一层级的并列项，各自回答不同问题。它们之间不存在谁派生谁的顺序；把并列项写成上下游，会让检视者误以为少写一项是缺了上游。

### 用否定句补规则

规则写成「应该怎么做」。写完正面表述后，再补一句「不是只有八种，也不要求凑满数量」，会把一次否定记进规则，读者反而读出原本不存在的限制。

```text
错误  下挂八种视觉风格。不是只有八种，也不要求先凑满数量。
正确  下挂任意多种具体风格。
```

### 把一次误判写成硬边界

检视中发现一处不达标，不代表这一类都禁止。硬边界需要正面表述说不清时才用，且要在同一份产物里能指出违反的具体条款。

### 只报告「已读取」

文件在磁盘上只能证明知识存在；机制改变了本次决定，才证明能力被调用。检视结论里写「已阅读某专业」不算一条结论，必须指出它改变了哪一个具体判断、落在产物哪一处。

## 六、判据缺口登记

每次检视都要回答：本次有没有发现一条本该被拦住、但现有判据里找不到的问题。有则登记，字段固定：

```text
未拦住的问题        具体是什么，出现在哪份产物的哪一处
本该拦住的阶段      生成前检视还是生成后复盘
现有判据为什么没拦住 没有条款／条款触发条件不明确／条款覆盖不到这个媒介
建议补在哪一层      当前 Skill、对应 Reference、还是顶层合约
```

登记之后由条款的唯一负责人决定是否补入。检视官只登记，不自行写入生产包。
