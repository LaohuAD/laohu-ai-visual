# 老胡检视官

## 包级任务路由与独立执行

先判断检视发生在产物哪一侧。产物还没有变成真实媒体时，检查它是否达到已写明的条款，不达标就打回重做；产物已经是真实媒体时，从真实结果往回找第一个断点，把能力更新送回唯一负责人。

```text
生成前  剧本 / 图片提示词 / 视频提示词   → 合规检视 → 不达标打回重做
生成后  图片 / 视频 / 音频 / 成片 / 发布数据 → 复盘归因 → 能力更新
```

先读[独立使用与交接](references/独立使用与交接.md)，明确本次输入、结果和跨阶段边界。含自然语言沟通或检视结论正文时先读本包[语言表达](references/语言表达.md)取得领域写法；完整通用规则按 `.agents/skills/laohu-language-mode/references/01_模式判定与块级切换.md` 等唯一正文读取，本包不再另存一套副本。

### 意图理解与父级继承

先写清本次要判断的结果：这份产物当前处于哪个阶段，它本该证明什么，哪些条款是本次真正承重的，哪些事实已经由上游确认不可重开。助手推断与用户已确认的事实分开记录，不把候选解释写成需求。

本包继承项目顶层规则 `AGENTS.md` 的目的、路由、边界、路径与隐私要求，在本层形成自己的专业判断；不要求用户先给专业简报，也不重复整套上游工作。检视范围能由既有条款与真实产物合理确定的直接执行；只有互斥解释、事实冲突、用户明确要求共创，或会显著改变成本、权利与外部动作时，才提少量能区分方向的问题。

按本层判断选择下一层：命中哪条分支就读哪条，不遍历全部专业。用户直接点名某项深层能力时，先沿其父级链接补齐所属链，再继续当前子任务；补依赖只建立上下文继承，不重新发起同一任务。

- [老胡剧本检视](skills/laohu-script-inspection/SKILL.md)：剧本或场次文本成立后、进入分段之前需要判断格式、镜头粒度与连续性是否达标时进入。
- [老胡图片提示词检视](skills/laohu-image-prompt-inspection/SKILL.md)：图片提示词写完、尚未投喂生成时判断字段、结构与可执行性是否达标时进入。
- [老胡视频提示词检视](skills/laohu-video-prompt-inspection/SKILL.md)：视频提示词写完、尚未投喂生成时判断三段式、镜头正文与声音特效是否达标时进入。
- [老胡生成与发布复盘](skills/laohu-generation-review/SKILL.md)：已有真实图片、视频、音频、剪辑或发布数据，需要定位第一个断点时进入。

## 检视箴言

检视不是给产物挑毛病，是判断这条毛病该谁改。

同一份产物不达标，可能出在三个地方：产物没按已写明的条款写；条款根本没覆盖这种情况；条款覆盖了、检视也做了，但漏掉了。三种原因对应三个不同的负责人，修错地方等于没修。

## 检视的三项结论

每个问题都必须给出下面三项，缺一项就不算完成检视：

```text
① 未满足什么        具体条款，以及这条条款写在哪个文件
② 属于哪一类        输出问题（产物本身没写对）／规则问题（规则没覆盖或表述不清）
③ 归哪个顶层负责人   输出问题 → 对应生产包的专业；规则问题 → 该规则的唯一负责人
```

只写「这里不好」「建议优化」不算检视结论：它没有指出未满足的条款，也没有指出该谁改。

## 三种路由结果

```text
规则没覆盖这条                         → 规则问题 → 归该规则负责人 → 补规则
规则覆盖了、检视查出来了、产物照旧错   → 输出问题 → 归生产端专业 → 改产物或补该专业表述
产物错、检视没查出来                   → 检视问题 → 归检视官 → 补检视判据
```

第三项在事后复盘时才出现：结果不达标，先问检视官本该查出来吗。本该查出来却没查出来，先补检视判据；查出来了而产物照旧错，才回到生产端。

完整的责任链、归口判断和边界见[责任划分与路由](references/责任划分与路由.md)。判据的展开、正反例与常见误判见[检视判据](references/检视判据.md)。

## 判据从哪里来

检视条款不另立一套标准，它从已经存在的正式规则里取：

```text
产物自身的格式与结构条款      → 对应生产包 SKILL.md 与模板
专业判断是否成立              → 对应专业 SKILL.md 的底线门与巅峰门
跨阶段交接字段是否齐全        → 交接合同类 Reference
字符、编号、命名等机械边界    → 对应 scripts/
```

检视官引用这些条款的位置，不复制它们的正文。条款本身有歧义时，这属于规则问题，归条款的唯一负责人，检视官不自行解释成一条新标准。

## 接力与返回

CONSULT 不转移当前作品主责。检视结论只指出未满足的条款、分类和归口，不替生产端重写产物；生产端是否接受返修、以什么方案改，由对应专业决定。检视官不发布、不删除源素材、不改变素材库级状态。

真实结果的问题返回最早能改变根因的负责人：源故事、台词、空间因果不足返回编剧；造型和视觉系统错误返回对应设计；实际资产与绑定错误返回资产负责人；歌曲事实与全曲时间返回 MV 导演。需要跨专业语言判断时 CONSULT `laohu-language-mode`，不用换写法掩盖内容缺口。

复盘归因的完整输入字段、状态账本、跨节点交接、硬边界和验收门使用[复盘交接与验收合同](skills/laohu-generation-review/references/交接与验收.md)。

## 最终验收与交付

每条检视先给出问题清单，再给出路由结论，最后给出本次未覆盖的条款缺口。问题清单为空也要写明检视了哪些条款、依据哪一版产物，不把「没发现问题」写成「产物已通过全部验收」。

只报告真实进度。设计通过、待生成、已生成、已听试／已查看、已选定分别记录；文件存在不等于验收通过。检视报告属内部规则与系统日志，不生成作品 HTML。

## 机械检查

正式视频提示词的结构与字符边界由本包脚本实测：

```bash
bash .agents/skills/laohu-inspection/scripts/validate_video_prompt_structure.sh "提示词文件.md"
bash .agents/skills/laohu-inspection/scripts/count_video_prompt_chars.sh "提示词文件.md"
```

结构检查拒绝三段缺失、镜头方头缺失和绝对时间轴污染；字符脚本默认只报告实测长度，能力合同已经核验上限时才追加 `--limit N`。脚本自测：

```bash
bash .agents/skills/laohu-inspection/scripts/test_validate_video_prompt_structure.sh
bash .agents/skills/laohu-inspection/scripts/test_count_video_prompt_chars.sh
```

## 按当前缺口读取的补充方法

每条读取先写清当前未决问题、要读的精确相对文件与章节、应形成的决定；读完要能指出它确认或改变了哪一个具体判断，只记录「已读取」不算激活。

- [检视判据](references/检视判据.md)：当前任务需要展开格式、内容、信息量与密度的具体判据、正反例或常见误判时读取相应章节。
- [责任划分与路由](references/责任划分与路由.md)：当前任务需要判断问题属于输出问题还是规则问题、或需要确定归口负责人时读取相应章节。
- [视频生成质量检查清单](references/视频生成质量检查清单.md)：当前任务需要逐条核对生成前检查、生成后评分或常见失败对应修正时读取相应章节。
- [MV文本完成门](references/MV文本完成门.md)：当前任务需要判断 MV 导演文本产物的结构底线与作品巅峰时读取。
- [独立使用与交接](references/独立使用与交接.md)：本包被单独调用、或需要写清输入输出与跨阶段边界时读取。
- [语言表达](references/语言表达.md)：本包需要写面向老胡的检视结论正文时读取。
