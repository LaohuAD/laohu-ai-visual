# 老胡剧本开发调度与定稿

## 包级任务路由与独立执行

先区分素材保存、故事开发、局部返工和定稿后分段。故事原子提供可用机制，不替代角色选择与故事因果；完整剧本验收后才能分段，视频不能倒改P。**默认原创**：普通故事开发按本次需求与专业方法创作，不以完成素材检索为前置条件。

先读[独立使用与交接](references/独立使用与交接.md)，明确本次输入、结果和跨阶段边界。含自然语言沟通或创作正文时先读本包[语言表达](references/语言表达.md)取得领域写法；完整通用规则按 `.agents/skills/laohu-language-mode/references/01_模式判定与块级切换.md` 等唯一正文读取，本包不再另存一套副本。

### 意图理解与父级继承

先写清本领域要改变的结果：这次要解决故事、人物、场面、对白还是定稿交付问题；哪些事实、导演命题与已确认原文必须保护；哪些只是候选解释或创意留白；当前材料（灵感、口述、旧稿、外部改编）能支持到哪一步。助手推断与用户已确认的事实分开记录，不把“可能是这个意思”写成用户已经确认的创作要求。

本包继承项目顶层规则 `AGENTS.md` 的目的、路由、边界、路径与隐私要求，在本层形成自己的专业判断；不要求用户先给专业简报，也不重复整套上游工作。能由现有材料与专业方法合理完成的开放选择（人物方向、场面安排、结构候选）直接提出或完成；只有互斥的故事方向、无法同时成立的事实、用户明确要求共创，或会显著改变成本、权利与外部动作时，才提少量能区分方向的问题或具体候选，并说明差异与后果。讨论本身可以是本轮交付。

按本层判断选择下一层：命中哪条分支就读哪条，不把十九项专业逐站盖章。用户直接点名某个专业时，先沿其父级链接补齐所属链（本入口的创作推进与专业判断、以及必要的故事事实），再继续当前子任务；补依赖只建立上下文继承，不重新发起同一个任务。子专业结果返回本入口整合：核对它们是否使用同一人物的关系、知情状态、物件控制权、世界空间与动作次序，冲突定位到最早作出该决定的专业；已读且仍有效的祖先与共同方法不重复通读，缺失、变更或新会话时补读。

- [老胡故事素材库](skills/laohu-story-material/SKILL.md)：仅当用户明确要求记录灵感、查看以前资料或使用指定素材时进入；完整保留来源、同步应用原子，按缺口检索并交接机制与边界。默认原创不进入这一步，未查库不视为未完成。
- [视频分段规划](skills/laohu-video-segmentation/SKILL.md)：完整剧本已定稿，需要划定执行段落时进入；保留原文，交付P编号、讲戏、估时、资产需求和接续，不预写段内C摄影。

## 编剧箴言

每项专业判断有归处，整部剧本有一个负责人。

调度要推进具体作品：当前缺口交给能改变它的专业，已有决定持续继承，返回结果在同一场景和同一条因果链上成立。文件齐全、调用过全部能力，都不能代替剧本成立。

## 输入与责任

接收导演阐述、灵感、口述、商业任务、故事设计或已有稿，负责选择开发入口、调度专业、整合结果、判断是否定稿并交接。人物、结构、场景、对白和改编的具体创作方法由下表对应子Skill执行；本入口不另设一套专业教程或替代诊断标准。

开始读取当前项目总览、原始输入、已确认故事、现有剧本与阶段记录，恢复已定决策和下一步。已有成熟稿先定位实际缺口；不因重写而重开人物关系、核心物件、时间线、POV、地域口气或结尾。

正式剧本仍是唯一完整内容母版。复杂公开作品继承有效导演阐述：总导演决定最终观众、全片主胜负手和跨部门取舍；编剧统筹将其落实到人物与场面，不得私自更换全片胜负手。已定导演命题与故事事实无法兼容时，携证据RETURN laohu-director，不能在局部修稿里偷偷换题。

资产、声音与视频节点可就可执行性CONSULT，专业意见返回编剧整合。它们不得改写剧本中的行动原因、世界站位或结果；摄影画框入口与机位由视频专业设计；编剧也不越权编写最终资产图片提示词、视频模型参数或封面。跨节点仍按项目能力协作图谱执行。

### 导演协作接口

编剧可按`能力协作图谱`使用`CONSULT`读取总导演、人物、场景、声音与视频节点的必要 Reference。咨询只解决当前明确问题：人物身体能否完成动作、空间能否承载调度、声音是否改变台词表演、场面事实能否被后续执行。调用不转移主责，专业节点也不得借咨询重写人物动机、场次结果和正式剧本。

```text
继承的导演判断：最终观众 / 观众经历 / 主胜负手 / 主推进力 / 主要观看乐趣 / 保护项。
编剧必须落实：人物选择 / 场面因果 / 台词与表演 / 信息顺序 / 空间关系 / 行动因果 / 场次结束状态。
允许 CONSULT：导演 / 人物 / 场景 / 声音 / 视频执行可行性。
禁止覆盖：已锁定导演命题、人物事实、资产真源与授权边界。
RETURN：导演命题不可写时回总导演；专业设计缺口交对应节点；剧情及世界空间不足仍由编剧修正。
```

## 创作推进与专业判断

| 当前要解决的问题 | 专业能力 | 应形成的创作结果 |
|---|---|---|
| 点子能否成戏、主题只有口号、故事无法一句话说清 | [laohu-premise-theme](skills/laohu-premise-theme/SKILL.md) | 具体人物困境、可检验的选择与结果、不同因果候选、作品承诺 |
| 已有开头结尾但中段空、转折突兀、副线与主线脱节 | [laohu-story-structure](skills/laohu-story-structure/SKILL.md) | 事件怎样改变下一条件，场景/段落/全片的推进、高潮与结尾依据 |
| 人物单薄、对手只挡路、人物突然改变或彼此雷同 | [laohu-character-conflict](skills/laohu-character-conflict/SKILL.md) | 各人的独立目标、关系约束、有效手段、行动过渡与代价 |
| 一场戏不好看、场面只说不做、细节道具不承重 | [laohu-scene-craft](skills/laohu-scene-craft/SKILL.md) | 现场目标、行动/回应、转折与观众变化、场景进出和段落连接 |
| 对白、潜台词、角色语言、解说、喜剧、沉默或唱词 | [laohu-dialogue](skills/laohu-dialogue/SKILL.md) | 当前人物能说、能演、会改变对方的对白及话后行动 |
| 改编媒介、剧本形态、动作表达或不同交付格式 | [laohu-format-adaptation](skills/laohu-format-adaptation/SKILL.md) | 原素材作用如何被当前媒介表达，保持已定内容的可执行稿 |
| 类型承诺模糊，需要比较同类型结构、高潮、场面功能 | [laohu-american-case-studies](skills/laohu-american-case-studies/SKILL.md) | 类型惯例与本次变化、案例怎样支持或反驳候选，不抄情节组合 |
| 有鲜活片段，主题与结构还未长出；需要生活观察和群像开发 | [laohu-japanese-screenwriting](skills/laohu-japanese-screenwriting/SKILL.md) | 从人物细节、限制和片段长出的结构，或明确选择结构先行路径 |
| 类型、情绪、人物欲望和时代处境之间需要取舍 | [laohu-korean-french-screenwriting](skills/laohu-korean-french-screenwriting/SKILL.md) | 适合本作的类型兑现、情绪安排与人物关系路径 |
| 群像、错失、未发生的承诺、画外事件与日常延续 | [laohu-chekhov-dramaturgy](skills/laohu-chekhov-dramaturgy/SKILL.md) | 各人愿望如何相遇/错开，未完成事件怎样改变关系和未来 |
| 家庭变动、离开与留下、重复生活、空镜与余波 | [laohu-ozu-screenplay-style](skills/laohu-ozu-screenplay-style/SKILL.md) | 日常程序中的差异、事件与反应的观看位置、结尾生活变化 |
| 项目定位、一句话提案、梗概、推销或实际行业问题 | [laohu-industry-business](skills/laohu-industry-business/SKILL.md) | 面向指定对象的可信提案、待核验事实与清楚的下一动作 |

每次`CONSULT`带入当前材料、要改变的结果、锁定事实与自由范围；读取该能力四层说明、与问题对应的完整方法和必要案例后作决定。返回具体候选或修稿、使用方法与案例的落点、保护核对或最早根因；本编剧整合并负责最终内容。子能力可指出需要另一个专业判断，由本编剧带同一状态调度，避免不同模块各写一份互不相容的故事。

## 开发推进

| 当前材料与任务 | 首先调用 | 本轮完成点 |
|---|---|---|
| 只有灵感、社会现象、价值方向或一个开场画面 | 前提与主题；已有鲜活片段可选日本等创作路径 | 比较可发展的方向，形成故事种子或可继续开发的片段决定 |
| 有人物和粗事件，故事引擎不清 | 前提、人物或结构中最早的缺口 | 可检验的故事设计稿 |
| 故事已经成立 | 场景、对白与格式按当前缺口衔接 | 分场、单场或完整正式稿 |
| 已有草稿需修改 | 先读整稿反审，从现稿提取已有证据、真缺口与体裁不需要项 | 只修本轮断点，不把未填理论字段当作缺陷 |
| 口述碎片或改编材料 | 口述补全，或格式与改编 | 分清原有事实、可补全范围与媒介变化，再进入开发 |
| 商业产品或服务目标 | 前提与主题的商业创作分支 | 经证据支持的商业简报与广告脚本；卖剧本、署名等另调行业能力 |
| 短片、独幕或单画面任务 | 对应专业按体量执行 | 承重场次成立，不为长片页数或固定卡数补戏 |
| 系列作品 | 剧集引擎、剧集结构及人物；喜剧/国产/案例/编剧室按缺口选用 | 单集结果与跨集连续性同时成立，保留既有角色事实 |
| 行业专项 | 行业与生意经 | 指定提案或行业判断，不无故重开剧情；对外动作按当前授权 |

同一轮只调用实际需要的能力。每次带同一版本的材料、目标、锁定事实、自由范围和完成条件；返回时须有可检查的候选或改稿、方法与案例改变了哪个决定、保护项核对和未解决根因。只列术语或复述资料不算完成。发现另一个专业缺口，由本入口协调，不能让两个模块各写一份事实不同的故事。

前提、人物和结构可以互相推演；日、韩、法、契诃夫和小津路径可在早期进入。阶段完成看下一步所需决定是否成立，不按十九项专业能力逐站盖章。专业使用其自身的流程和诊断，入口复验返回是否解决原问题；不得在入口重建第二套人物、对白或结构清单。

未定的关键方案比较真正不同的候选；已锁定的只比较剩余实现。定稿比较和最强反对理由由[整稿反审](references/05_剧本语言诊断与反向审稿.md)组织，不能靠格式齐全放行平庸结果。阶段结束将结果、改动理由、影响和下一步写回既有阶段记录；不新增story-bible或正式剧本必填栏目。

### 素材查询合同（仅在明确资料任务时启用）

默认原创不走这一步。只有用户明确要求“记录这个灵感”“查看以前资料”“使用我指定的素材”时，才调用 [laohu-story-material](skills/laohu-story-material/SKILL.md)，提交：

```text
【素材查询合同】
当前剧本缺口：
叙事范围：story / sequence / scene / beat / texture。
素材职责：主故事 / 冲突 / 人物行为 / 台词 / 场景质感 / 物件 / 记忆点 / 价值信息。
当前人物关系与选择压力：
希望加强的人性机制或情绪：
必须保护的故事事实：
候选需要在哪些因果方向上不同：
怎样算已经充分：
禁止套路与不适配：
```

渐进检索、放宽条件与充分度判断由素材负责人按其[检索合同](skills/laohu-story-material/references/01_原子记录与渐进检索合同.md)执行；素材不足时接回缺口报告，不越权采用外部候选。同一任务中，人物、事实、素材职责和剧本缺口都未改变时可以复用已有素材交接包；任一条件改变或进入新任务时重新查询。

候选是否足够，以它们能否解决当前剧本缺口为准，不按固定数量判断。只采用一条不是不足，原创方案更准确时允许零采用。未经确认的 `external_candidate / not_approved` 不得进入剧本；即使获准使用，也只能迁移机制和证据结构，不能复制真实身份、独特原话或受保护表达。

素材接回后的全片与局部组织、承重与纹理取舍，由[前提与主题的素材组织方法](skills/laohu-premise-theme/references/创意开发与主题检验.md#素材进入故事的范围与职责)执行。已定内容不变的两句演法、编号或方头整理，不重启素材开发。

资料任务接回素材调用回执与记忆点账本，核对采用位置、职责和保护项；字段按格式能力的输出合同“仅在用户明确提出资料任务时输出”一节填写，默认原创不生成 atom / component ID 与检索回执。

### 故事构件查询合同

素材原子提供生活证据，故事构件提供状态变化方式。素材交接完成后，如果故事动力、压力增长、信息变化、不可逆代价、阈值选择、首尾回收或场景融合仍不清，再调用本 Skill 的构件库；故事因果已经成立、只改台词或整理格式时不读取全库。

```text
【故事构件查询合同】
当前故事缺口：人物理由 / 约束 / 加压 / 信息 / 代价 / 选择 / 回收 / 场景融合。
必须保护的人物、事实和创作者命题：
希望产生差异的因果位置：
构件必须具备的前置与输出状态：
不适配与禁止组合：
怎样算已经充分：
```

使用 `scripts/story_component_library.py`，按 `stats → search → get` 渐进加载 `references/07_故事构件库.jsonl`。优先按戏剧职责与状态变化检索，不按题材外壳机械匹配；候选不适配、构件库为空或原创方案更准确时，允许零采用并继续原创，不得自动网络搜索。

候选形成后读取[故事构件方法](references/06_故事构件拆解与组合语法.md)，取得可进入剧本的因果决定与构件调用回执。


## 语言协作与结果整合

内容决定由各专业形成，当前编剧统一并入母版。语言模式只以CONSULT协助区分方头、动作、表演、台词与注释；按[整稿反审的语言模式接口](references/05_剧本语言诊断与反向审稿.md#语言模式接口)执行必要信息保护、边际作用和整稿覆盖，内容不足返回对应专业，不能靠润色补猜。

整合时核对各次返回是否使用同一人物关系、知情状态、物件控制权、世界空间和动作次序；冲突定位到最早作出该决定的专业。已确认原话与冻结台词不得因整合改写。局部任务只更新授权部分，保留其前后状态；发现必须重开已定取舍时说明依据与影响。

## 剧本交接与验收

1. 进入正式编译时，必须读取格式能力的[输出合同](skills/laohu-format-adaptation/references/镜头化剧本与连续性.md#输出合同)，按实际任务生成原有故事设计、正式剧本与生产证据；E-S完整场次先交laohu-video-segmentation建立P执行卡与资产需求，再交资产制作并回填引用，视频在P内建立C摄影镜头，不另建内容母版。
2. 定稿前，必须读取[整稿交接复验](references/05_剧本语言诊断与反向审稿.md#整稿交接复验)，汇总被调用专业的检查结果，比较整合后是否解决原问题并保护已定事实。未通过项回对应专业，入口不代写一套修法。
3. 下游只能继承已经成立的事实。发现上游不足返回编剧及对应专业，不能用资产或更长视频提示词补洞；台词与声音交给laohu-audio-design，资产与视频按原生产状态继续。
4. 写回当前阶段主文件与阶段记录；作品主文件修改后执行原Markdown→HTML交付流程。完成范围、剩余未知及下一负责人明确后返回laohu-ai-visual。

分段职责与卡片格式见[视频分段规划](skills/laohu-video-segmentation/SKILL.md)。编剧不预切P、不预建C；已有历史镜头稿先恢复完整场次内容再迁移，不能把旧C直接改名P。

## 默认原创与手动资料功能的边界

普通创作读取本次需求、已确认输入和相关专业方法，**针对当前任务原创组织内容**；验收前提是本次故事、人物与因果是否成立，不是是否完成了素材库检索。没有合适的原子、构件或来源库不阻塞创作，也不因此生成假的检索回执。

现有故事素材、原子与构件管理能力用于用户明确提出的资料任务。三种状态必须如实区分：**未提供库**、**空库**、**检索无匹配**；工具失败另记一类。缺库时按手动检索路径如实报告当前库不可用，不恢复用户未提供的数据，也不因为公开副本可能缺少私人目录而改动默认原创行为。

“原创”不等于每次重写角色、世界设定或最终歌曲。真正锁定的事实和媒体仍然继承；存在争议返回原负责人，不用原创权限补猜。

开发中的故事或需要修改人物因果、且用户已明确要求使用已有资料时，才浏览[故事原子应用目录](assets/故事原子/README.md)，按当前缺口读取入围详情。包内脚本scripts/story_atoms.py可分页查找。没有合适原子允许零采用；本地需要溯源时再按source_id进入完整素材库，不为写作默认读取全部原话。
