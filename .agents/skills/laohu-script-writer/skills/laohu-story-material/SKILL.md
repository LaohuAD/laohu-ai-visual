# 老胡故事素材库

## 应用原子与完整来源分开使用

本包已内置[故事原子应用目录](../../assets/故事原子/README.md)。无论在本地项目还是单独上传，先从这里按任务选择原子，再读取相应详情；应用原子包含结论、人性机制、可见证据、延展、适用边界、置信度及source_id，不要求读取source原话。不能把分析结论冒充事实证明，也不能把原子直接拼成剧情。

完整来源库在本地可选共享区，由使用者或本地项目提供。只有需要核验语气、证据、隐私或来源时，按source_id读取原话；云端没有原话时明确说明溯源不可用，不伪造来源。故事构件库与生活素材原子不同，两者可配合但不互相替代。

包内 `../../scripts/story_atoms.py stats / search / get` 支持离线应用检索；无脚本环境直接读目录与入围Markdown。检索每页只是上下文控制，可继续翻页。旧来源库的stats/search-index/get-source等命令继续用于完整本地采集和溯源，不是独立创作的前置。

新增素材、修订原子或暂停/恢复使用时，先可靠写入完整来源库，再同步应用原子。本地默认库的add-source、add-atoms、log-usage和migrate-legacy成功写入后，脚本自动同步；回执必须确认两处均成功。直接修订权威文件后运行包内`../../scripts/story_atoms.py sync`复验，不单独手改应用副本。同步失败时来源已保存，不重复新增；修复原因后仅重试同步。实际source、atom和usage仍由下面的工具合同管理。云端新产生的来源或usage需明确记录为待回流，不能声称已写入老胡本地库。

## 素材箴言

原话留住人，原子帮助故事重新长出来。

素材库保存的不是可供照搬的“桥段答案”，而是生活里已经发生过的行为、关系、机制和可见证据。原话负责保住人的气味与语境，原子负责让同一个机制在新人物、新处境和新因果里重新生长。

## 职责与触发边界

- 只有老胡表达明确保存意图，例如“记录灵感、保存素材、记一下、放进素材库”，才长期收录。分享、讨论、分析或当前创作本身不构成保存授权；不得因为内容看起来有价值就擅自长期保存。
- 独占素材的 `source / atom / usage` 拆解、渐进检索、充分度判断、外部候选报告和使用回流。`source` 保原话，`atom` 保可迁移机制，`usage` 保真实采用和结果证据。
- 为编剧提供经过边界判断的素材交接包，但不写正式剧本，不替编剧决定人物选择、危机、高潮、故事构件或组合链，也不调用图片、视频或音频生成。
- 同一输入同时要求“记录灵感”和“写剧本”时，先完成可靠写入，再把本次新增 atom 与既有候选一起交给 `laohu-script-writer`。

## 分层权威

素材库不是一个每次整包发送给 AI 的大文件。运行时权威按职责物理隔离：`sources/` 只保存 source 原话，`atoms/` 只保存可迁移原子详情，`usage/` 只追加使用证据；`manifest.json` 只给出库规模、版本和更新时间；`index/story_material.sqlite3` 是不含 source 原话的可重建索引；`sessions/` 保存检索会话的游标、已看、淘汰、覆盖与剩余状态。

SQLite 只承担候选定位，不是内容权威。索引丢失或损坏时从 source / atom / usage 重建，不得反过来从索引恢复原话。任何一次 AI 调用只接收当前任务所需的一页索引卡、入围的 atom 详情或被明确点取的 source，不得把整个素材目录、整库 JSON 或 SQLite 文件发送给模型。

## 收录工作流

按以下顺序完成一次收录：

```text
确认明确保存意图
→ 将原话逐字保存为一条 source
→ 区分事实、推论、感受与未知
→ 找到彼此独立的价值核心
→ 每个核心拆成一个 atom
→ 写人性机制、可见证据、延展方向与适用边界
→ 调用数据库脚本写入共享来源库
→ 自动同步技能包应用原子，校验编号与可用状态
→ 两处均成功后返回简短回执
```

原话只保存一次。一个来源可以拆成多个 atom，但每个 atom 只引用同一 `source_id`，禁止复制整段原话填满数据库。原话不得概括替换、润色重写或因为太长而截断；分析与原话必须分开。

每个 atom 必须能够回答：它真正有价值的是什么，为什么在人身上会发生，怎样通过行为、物件、关系或选择让观众看到，以及换到别的题材时什么可以改、什么不可复制。只有抽象结论、没有生活证据支撑的内容标为 `pending_evidence`，不能伪装成已经验证的事实。

收录完成只向老胡报告：source ID、atom IDs、拆出几个核心、各自一句话价值和需要补证的地方。除非老胡要求，不把完整 JSON 和长分析倾倒到对话里。

## 渐进检索

以下为完整本地来源库的增强检索流程；只有应用包时使用上文story_atoms的分页检索与详情读取，仍执行下面的充分度判断和边界保护。素材库必须渐进加载，不能每次写剧本就读取全部原话：

1. 先读 `stats`，只了解库的规模和标签首屏；需要查看某个标签维度的长尾时调用 `facet-values` 逐页展开，首屏不是永久截断。
2. 用 `search-index` 建立检索会话，只返回当前页的压缩索引卡；这里不得出现完整原话、详细证据与长延展。
3. 需要更多候选时调用 `continue-search`。单页只是上下文边界，不是创作配额；检索不设固定的总候选数，由上下文预算、覆盖缺口和边际增益共同决定是否继续。
4. 对真正入围的候选按 ID 调用 `get-atom`。它只返回指定 atom 详情和使用摘要，不得默认返回 source 原话。
5. 只有判断语气、证据、权利边界或根因归属确实需要时，才按 source ID 调用 `get-source`；使用历史则单独调用 `get-usage`。
6. 最后形成面向编剧的创作交接包，只交与当前缺口有关的机制、证据、边界和用途。

每个检索会话必须声明 `story / sequence / scene / beat / texture` 之一。长篇不是一次把更多卡塞给 AI，而是先做 story 级总结构检索，再按 sequence、scene、beat 分段建会话，最后按需补 texture；不同范围各自保留游标和覆盖状态。短片也不以原子数制造“高密度”，而看每个原子是否带来新的有效状态变化。候选在编剧交接时分为 `承重 / 支撑 / 纹理`，同一原子可以跨场复用，但每一处必须有明确职责。

首轮默认做来源平衡，避免同一 source 在第一屏挤满候选；当某来源确实形成连续因果链时，可在同一会话切换为开放展开。同源数量没有永久上限，平衡只是一种浏览策略，不是创作删减规则。

检索按以下顺序推进：

```text
严格匹配
→ 每轮只放宽一个表面条件，并记录放宽了什么
→ 跨领域类比，保留机制但更换人物、职业、地点或事件外壳
→ 仍不足时形成内部缺口报告
```

“表面条件”是年代、职业、地点、物件、关系称谓等外壳；人物必须面对的选择、冲突机制、人性矛盾和戏剧职责不能在放宽时悄悄丢失。充分度不按固定命中数判断，而看当前剧本缺口是否已经被不同因果方向的候选覆盖。只采用一条不代表素材不足，所有候选都不如原创方案时允许零采用。

## 外部候选确认门

只有严格匹配、放宽表面条件和跨领域类比都无法解决真实缺口时，才可以搜索网络。网络结果只能作为 `external_candidate / not_approved`，不能冒充已批准素材。

给老胡的外部候选报告必须说明：

- 为什么内部素材不足，具体缺的是什么；
- 来源链接、可核验事实与证据状态；
- 值得借鉴的底层机制和它适合剧本的哪个位置；
- 怎样艺术化改造，哪些真实身份、原话、独特组合不可复制；
- 事实、版权、隐私、陈旧性和题材适配风险；
- 建议是批准入库、仅当前参考、只作对照、拒绝，还是继续搜索。

未经老胡确认不得进入剧本或长期素材库。确认时还要记录批准范围：批准当前使用并入长期库、只允许当前参考、只保留为对照、拒绝，或继续搜索其他方向。只有“批准当前使用并入长期库”才能以 `laohu_approved_external` 写成正式 source；其他决定不得绕过确认门。

## 编剧交接与使用回流

素材交接包至少写清：

```text
素材来源和 source ID
候选 atom IDs
当前剧本缺口与实际检索层级
必须保留的机制和可见证据
这个素材能支持的输入状态 / 变化机制 / 输出状态
它不能单独证明的结构结论
允许改变 / 不可复制
适合位置和唯一主职责
预期改变的观众理解、期待、关系感受或情绪
不用它会损失什么
充分度结论：已解决 / 仍有缺口
外部候选状态
```

素材负责人只说明这条生活证据能支持什么变化，不由素材库把它选成某个故事构件，更不直接拼装成剧情。故事构件的选择、组合和因果验收由 `laohu-script-writer` 负责；素材库的 `source / atom / usage` 数据结构不因此改动。

编剧完成选择后，以素材调用回执记录查询条件、候选、采用或不采用理由、进入位置、改造方式和预期变化。真实生成或发布结果出现后再追加项目级 `usage`，不要用作者意图替代结果证据。

项目 rejected 不停用全库：它只说明这个原子在当前人物、题材、位置或改造方式中失败。只有重复且有证据表明原子本身会持续误导时，才由素材负责人执行 `library paused/reopened`：先暂停调用，证据恢复后再重开。项目级结果和素材库级状态不得混写。

## 工具与验收

真实写入、索引检索、详情读取和 usage 回流必须调用 `scripts/story_material_db.py`；不能手工修改分层权威文件。临时输入写入项目 `tmp/` 后调用 `--input`，完成即删除，原话不得塞进命令行参数。运行时入口是 `add-source / add-atoms / search-index / continue-search / facet-values / get-atom / get-source / get-usage / log-usage / stats / validate / rebuild-index`。

仅在首次写入、字段含义不清、需要放宽检索、形成外部候选、变更状态或工具报错时，读取 `references/01_原子记录与渐进检索合同.md`。普通 `stats` 不默认加载整份 Reference。

交付前验收：

- 明确保存意图存在，原话逐字完整且原话只保存一次；
- 一个 source 可以有多个 atom，但原话和分析没有混写；
- 普通检索只返回当前页压缩索引，atom 与 source 分开按 ID 读取；
- 单页大小没有被误当成总候选数量，长篇已经按叙事范围拆成多个检索会话；
- 策展优先级、事实置信度和分析置信度没有合成一个虚假总分；
- 充分度按剧本缺口判断，允许零采用；
- 外部候选没有越过确认门，真实人物与独特表达标明不可复制；
- 项目级 usage 没有直接改变素材库级调用状态；
- 数据库不存在时，采集任务可以创建它；检索任务如实报告为空，并允许编剧继续原创。

## 调用与返回

可由明确点名直接使用，也可由[编剧](../../SKILL.md)按当前缺口调用。直接命中本专业时先沿该链接补齐已确认故事事实、冻结文字与允许变化范围，只补依赖，不重新发起父级任务。CONSULT返回局部结果，作品主责不转移；缺少上游事实时RETURN最早负责人，不自行改写剧情。需要跨专业判断时只传当前问题和保护项，不重新运行整条创作链。

## 当前文本的语言执行

直接接受局部请求时，也按本包[语言表达](../../references/语言表达.md)先判当前文本块的发声者、接收者与任务。保护原话和专业事实；只补不足的请求不得改变已确认内容。遇到混写或冗余时按该文件选择具体方法，完成后回到本专业验收。
