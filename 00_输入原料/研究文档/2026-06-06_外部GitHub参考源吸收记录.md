## 一、参考源

### Shanyin-ai/shanyin-screenwriting-master

- 地址：https://github.com/Shanyin-ai/shanyin-screenwriting-master
- 类型：编剧 Agent Skill / 剧本创作工作流
- 本项目吸收重点：
  - 按作品体量路由：1-3 分钟概念片、5-10 分钟短片、90 分钟长片、多集剧集。
  - 阶段门控：每一步完成后停下来检查，不一次性生成完整剧本。
  - 视听化写作红线：不写心理描写，不写解释性台词，不写摄影机拍不到的内容。
  - 剧本创作八步：破题、梗概、人物、前史世界观、结构、场景拆解、场景写作、剧本医生。
- 本项目不直接照搬：
  - 不复制原 skill 的完整提示词和作者声明。
  - 不把“山音超级编剧大师”作为本项目身份。
  - 只吸收适合老胡 AI 视觉系统的工作流纪律和自检维度。

### geekjourney/awesome-ai-video-prompts

- 地址：https://github.com/geekjourney/awesome-ai-video-prompts
- 类型：AI 视频提示词资料索引
- 本项目吸收重点：
  - 视频提示词知识地图：基础模板、参数控制、电影风格、镜头语言、音画同步、质量检查。
  - 多模型视角：Sora、Veo、Runway、Pika、Kling 等视频模型的通用提示词维度。
  - 将“提示词”拆成镜头、构图、运动、声音、质量控制，而不是只写画面形容词。
- 本项目不直接照搬：
  - 该仓库不少文档仍是占位内容，因此只作为分类地图，不作为最终规则来源。

### HuyLe82US/awesome-seedance-prompts

- 地址：https://github.com/HuyLe82US/awesome-seedance-prompts
- 类型：Seedance 2.0 案例提示词库
- 本项目吸收重点：
  - 按类型建立案例库：动作、商业、社媒、剧情爱情、奇幻、恐怖、科幻等。
  - 成功案例需要记录来源、类型、时长、画幅、分镜节奏、可复用结构和验证证据。
  - 高可复用案例通常具备明确时间轴、镜头编号、动作节拍、风格约束和禁止项。
- 本项目不直接照搬：
  - 不直接复制社区案例提示词作为老胡模板。
  - 只抽取案例拆解字段和分镜组织方法。

### 直接吸收

- `mechanism`：先写效果成立的因果，不先堆关键词。
- `invariants`：明确不可删除、不可换序的承重点。
- `variable slots`：允许人物、地点、物件、材质、节奏、镜头和声音原创替换。
- `failure modes / quality repairs`：把常见失败直接映射到修复动作。
- `transfer tests`：换题材、换人物、换媒介后，机制仍应成立。
- `anti-copy boundary`：禁止继承案例表面的独特表达。

### 改造后吸收

- 外部按 MiniMax / Seedance 区分的格式只吸收任务逻辑，正式输出仍使用本项目三段式。
- 外部逐镜任务卡只作为内部规划，不进入模型正文。
- 外部精确秒点只在音乐同步或模型确实需要时使用；本项目正式正文默认不用逐镜时间码。
- 外部强案例骨架只能当候选机制，必须经过剧本、资产、连续性和可剪辑门。
- 官方纸拼贴的“最终静帧作为完成构图”改造为结果帧先行：先验证知识关系，再倒推组装，不固定为图生视频或 4 秒片段。
- 官方 3D 动画的逐秒镜头表只吸收空间锚点、退场状态和交接意识；正式三段式正文仍不用逐镜时间码。
- 官方品牌 / 产品 Skill 的事实表、来源清单和真实产品动作驱动转场，分别并入商业证据与资产真实性规则，不继承 Apple 风等固定审美。
- 官方 MV 的音频连续和自然拼接并入声音桥与剪辑接口，不继承其特定音乐风格预设。

### 明确拒绝

- 不复制人物、地点、品牌、台词、镜头顺序、精确时长和标志性表面特效。
- 不因为案例有电影术语就堆满镜头参数。
- 不把“复杂”误解成镜头越多、形容词越多、粒子越多。
- 不把 74 个外部 Skill 一比一迁入本项目，避免入口爆炸和题材重复。
- 不把模型名称当成创作机制；模型适配只负责长度、输入能力和已知限制。
- 不继承官方生产流程里的固定 16:9、4 秒、15 秒、逐秒指令、默认模型、固定色彩语义和阶段选项卡；这些是产品工作流默认值，不是视频创作底层规律。

## 人物生命感摄影对标审计

本轮完整审计 `dacnay816y62-hub/fantasy-life-force-portrait-photography` 的 `README.md`、1177 行 `SKILL.md`、六张原创样片和三组普通照片升级前后对比，固定到提交 `4256e13162219adadc2749b42183baeec1b6c333`。仓库未提供根目录许可证文件，因此只进行独立机制提炼，不复制长段原文、完整模板和案例组合。

### 直接吸收

- 静态人像要保留可推断的前后帧，让身体、视线、衣料、道具或环境至少一项仍处于时间过程中。
- 人物、摄影机和环境必须形成三方关系：人物回应事件，摄影机拥有明确观看位置，环境同时受人物影响并反作用于人物。
- 裁切、遮挡、轻微失焦和透视变形属于受控不完整，前提是保住身份、表情、接触点、产品结构等决定性证据。
- 焦散、色散、旋焦和柔光必须有物理来源、局部作用区、画面交互与衰减；皮肤和发丝按干湿状态与材质分区响应。
- 普通照片升级必须锁定人物、表情、动作、服装、道具、事件和场景类型，只开放摄影、色彩层级、背景退让与局部材质。

### 改造后吸收

- 把外部项目偏人像风格的“生命力”扩展为跨儿童、老人、文戏首帧、生活方式 B-roll 和产品使用人物图都能验证的现场关系机制。
- 把“动态抓拍”改造为 `前后帧可推断性`；安静、疲惫、冷淡和主动静止同样可以有生命感，不强迫人物大笑、奔跑或伸手。
- 把视觉不完整限定为“选择性牺牲非承重信息”，防止随机裁头、挡眼、失焦和产品结构缺失被包装成实验感。
- 把皮肤真实从泛化的“细节丰富”改成干燥 / 湿润区域、反射宽度、水滴路径和局部高光的材质判断，避免全脸油膜与蜡像感。

### 明确拒绝

- 不吸收固定特写 / 中近景比例、默认高饱和高对比、固定东亚脸、老人墨镜、儿童风车、花市伸手等样片表面组合。
- 不把生命感等同于大笑、伸手、强阳光、贴脸拍摄或全图色散。
- 不固定“一主色、一对比色、一肤色”，也不机械规定批量图片必须改变若干项。
- 不把所有老人、儿童、劳动者和普通生活场景统一拍成唯美商业人像。

### 沉淀位置与验证边界

- 详细机制进入 `skills/laohu-visual-assets/references/06_人物生命感与现场摄影关系.md`，由主体按人物现场感缺口显式路由。

### 外部项目真正解决的问题

- 构图先由关系压力决定，再由摄影机位置和视线流量兑现；前景、留白、遮挡和非对称必须有信息或关系职责。
- “电影感”被拆成观众观看权限、空间语法、色彩来源、成像基底、局部光学限制和事件余韵，而不是胶片颗粒、青橙调色或宽画幅。

- 反 AI 不是统一加脏，而是控制信息密度、保留普通 / 未完成 / 遮挡的画面、限制装饰细节，并让特殊镜头有实体机位和光源理由。
- 外部的“导演 DNA”应转译为可观察的构图、空间、光影、人物调度和材质变量，不能把具体导演名当作最终提示词。
