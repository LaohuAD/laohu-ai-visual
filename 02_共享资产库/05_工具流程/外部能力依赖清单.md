# 外部能力依赖清单

本文件登记项目运行时直接调用的外部 Skill，以及它进入本地流程后的适配关系。外部资料、GitHub 案例和专业理论如果只被提炼成知识，不属于运行时依赖，由对应 Reference 记录来源与吸收边界。

## 依赖箴言

### 外来的能力要留来路，本地的判断要有归处

外部原文负责保留方法原貌，本地适配负责决定何时调用、保护什么、怎样进入当前生产链。二者不能混成一个文件，也不能只留下简称让后续模型猜测。

## 依赖类型

| 类型 | 含义 | 项目要求 |
|---|---|---|
| 外部运行时 Skill | 当前流程会直接读取并使用其原始方法 | 必须登记原始名称、原文、便携副本、本地适配层、调用者、返回负责人和失效处理 |
| 外部知识来源 | 只吸收机制、事实、案例或校准视角 | 在对应 Reference 记录仓库、提交、证据边界和反复制边界，不作为独立 Skill 调用 |
| 本地模板与脚本 | 本项目自己维护的执行资产 | 由唯一负责 Skill 路由，并通过路径或机械测试验证 |

不得把外部知识来源误写成运行时 Skill，也不得把外部运行时 Skill 悄悄改写成本项目原创能力。

便携副本存在的原因是：完整仓库可以审计外部原文，单独安装 laohu-vibe-creating-prompt 时仍必须自包含。两份原文必须保持完全一致，不能形成两个版本。

### 调用链

    laohu-video-prompt 完成可直接生成的首稿
    → laohu-vibe-creating-prompt 判断是否值得进入 VC
    → 需要提纯时读取外部原文便携副本
    → 本地适配层保护三段式、台词、资产、状态、字符和剪辑接口
    → VC 结果返回 laohu-video-prompt
    → laohu-video-prompt 复验并写入正式作品文件

调用者只调用本地适配层，不直接调用外部原文。外部原文给方法，本地适配层给权限和边界，视频 Skill 对最终可用性负责。

### 失效处理

出现下列任一情况，停止 VC，不得凭记忆模拟外部 Skill：

- 仓库内外部原文缺失。
- 便携副本缺失。
- 两份原文内容不一致。
- 本地适配层没有写清调用条件或返回负责人。
- 外部更新改变了方法，但尚未完成本项目兼容性验证。

停止 VC 后保留已经通过基线的视频提示词原稿，并返回 laohu-video-prompt；不能让外部依赖故障阻断已经成立的基础产物。

### 更新方式

外部版本确实更新时：

1. 先记录新来源、版本或提交证据。
2. 整体更新仓库内外部原文。
3. 同步生成逐字一致的便携副本。
4. 检查本地适配层是否仍能保护项目硬接口。
5. 运行外部依赖、行为场景、字符与八个 Skill 校验。
6. 验证通过后再允许 VC 进入正式生产。
