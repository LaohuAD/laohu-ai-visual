# laohu Skills 能力生长规范

> 用途：规定如何新建、修复和扩展一个真实可执行的 Skill。
> 本文件负责能力进化的方法，不替代任何领域 Skill 的专业判断。

## 一、生长箴言

### 规则记住答案，能力学会找到答案

一个 Skill 不能只保存已知结论。它还要能识别新输入、发现缺口、提炼原则、选择材料与方法、产生可用结果，并根据真实反馈修正自己。

### 先找到高下之别，再提炼取舍之因

原则发现不在平庸答案之间挑一个顺眼版本。应比较已经被真实作品、长期实践或可靠结果证明的高水平选择，与相邻水平的普通选择，找出双方在同一任务上取了什么、舍了什么，再追查为何会产生不同结果。

### 一条规则只有进入作品，才算拥有力量

目录完整、术语齐全、四层写全都不是能力成立的证据。只有陌生输入能被推进成当前阶段的可用产物，失败能返回最早负责人，反馈能经过验证进入正确位置，能力才算成立。

## 二、三种改动

### CREATE：从零建立能力

适用于目标明确，但还没有成熟 Skill、Reference、脚本和行为证据的任务。

执行顺序：

    确认真实结果与运行环境
    → 找到高水平样本和相邻水平对照
    → 比较关键取舍
    → 追查结果差异的因果
    → 提炼领域原则
    → 编译为章法、技法与法度
    → 建立最小可运行 Skill
    → 用陌生场景验证
    → 按证据补 Reference、脚本或案例

不能只从用户口述直接扩写规则。用户口述说明需求和偏好，专业能力仍需证据、对照和可验证的因果支撑。

### REBUILD：保真重构成熟项目

适用于项目已有有效 Skill、Reference、脚本、资产和真实经验，但权威冲突、调用混乱、重复堆叠或结果退化。

执行顺序：

    盘点现有能力与调用链
    → 标记事实资产、审美判断、硬接口和历史证据
    → 找出重复、冲突、漏读与失责位置
    → 为每个判断确定唯一负责人
    → 在负责人内部重新编译四层能力
    → 先迁移并验证，再删除旧副本
    → 用旧能力场景和新缺口场景共同回归

成熟项目的优化不是把文件变短。删减只有三种合法理由：内容已完整迁移；内容只是重复副本；内容已经被证据否定。不能证明时，保留、降级为历史证据，或进入待验证区。

### EVOLVE：让能力继续生长

适用于真实生产已经返回新结果、失败、平台变化或用户反馈。

执行顺序：

    保留原始证据
    → 找第一个可证明的断点
    → 定位唯一负责人
    → 区分一次补丁与可复用缺口
    → 提出最小可证伪改动
    → 修当前结果
    → 做同类与相邻场景验证
    → 决定 KEEP / OBSERVE / REVERT

用户反馈是证据来源，不是自动生效的永久禁令。

## 三、四层怎样编译成领域能力

四层不要求显式写成“灵魂、筋骨、血肉、表皮”四个标题。它们是构建时的完整性检查：

### 灵魂以箴言定向

从真实取舍和因果中提炼少量领域箴言。箴言必须：

- 使用已有公共语言，不生造术语。
- 能统领多种选择，不只修一个例句。
- 是正向审美方向，不是禁令换行。
- 可以解压回具体事实、关系和结果。
- 不能只靠对偶、比喻和气势成立。

伪箴言的典型信号：换到任何项目仍然成立；删掉以后不影响选择；需要长篇解释才能知道它在说什么；只给态度，没有真实取舍。

### 筋骨以章法成局

章法把原则变成整体秩序：

- 当前 Skill 接受什么上游事实。
- 它独占哪些判断。
- 判断按什么因果顺序发生。
- 什么状态代表阶段完成。
- 向下游交付哪些可继承字段。
- 失败时返回哪个最早负责人。

章法不能只是步骤表。每一步都要说明它改变了什么状态，以及下游为什么依赖这个结果。

### 血肉以技法生变

技法负责材料怎样被选择、组织和改变：

- 先定材料要承担的关系、情绪、信息或功能。
- 再比较材料的因果承重、典型性、媒介可见性和实现代价。
- 再选择能产生目标效果的专业手段。
- 用高水平与相邻水平案例说明差异，不能让案例替代判断。
- 允许保留原稿；“什么都不加”也是经过比较后的有效选择。

材料不是越私密越高级，也不是越宏大越有力量。技法不是越多越专业，而是每一个动作都有必要。

### 表皮以法度成形

法度把结果变成可直接使用的产物：

- 输入缺失时哪些可补、哪些必须确认。
- 文件路径、格式、字段、命名、字符和模型限制。
- 哪些约束是不可违反的硬接口，哪些只是可调整默认值。
- 输出怎样被脚本、工具、下游 Skill 或真实平台接收。
- 验收失败时给出明确错误，不用审美分数冒充机械检查。

## 四、Skill、Reference、脚本和证据怎样分工

| 载体 | 应承载什么 | 不应承载什么 |
|---|---|---|
| Skill 主体 | 每次都要做的判断、流程、硬边界、输出合同和失败返回 | 大量特定题材知识、历史案例全文 |
| Reference | 只在明确题材、模型、阶段或失败信号下需要的完整方法 | 没有触发条件的资料堆 |
| scripts | 字符、路径、命名、结构、依赖和格式等机械事实 | 审美评分、创意裁决 |
| tests | 真实行为场景、交接结果、失败返回和回归边界 | 只检查有没有写某个漂亮词 |
| 历史证据库 | 原始失败、当时结果和迁移轨迹 | 当前任务的默认命令 |

每一份 Reference 都必须由唯一负责 Skill 写明触发条件。无法从 Skill 到达的 Reference 等于不存在；需要每次读取的 Reference 说明内容放错了位置。

## 五、行为验证

最低验证不是“文件存在”，而是以下能力在代表场景中成立：

1. 粗糙输入能找到正确阶段入口。
2. 上游事实能穿过相邻交接而不被改写。
3. 普通答案与高水平答案的关键取舍可以说清。
4. 材料选择不坠入私密小物或宏大空话的固定套路。
5. 技法能说明为何此处必要，也允许保留原稿。
6. 硬接口错误能在生成前被机械检查发现。
7. 失败能回到最早负责人，不由下游打补丁。
8. 反馈先形成证据和改动假设，再决定保留、观察或回退。
9. Skill 脱离创建上下文后，陌生模型仍能独立执行。

验证至少包含：一条主流程、一条边界流程、一条失败返回、一条不该修改的保真场景。只验证熟悉案例，会把上下文记忆误认为项目能力。

## 六、完成标准

一次能力建设只有同时满足以下条件才完成：

- 每个高价值判断有唯一负责人。
- 领域箴言能影响真实取舍，并可解压回证据。
- 章法能把上游状态推进到明确完成状态。
- 技法能处理材料差异和输入变体。
- 法度能保证产物被真实工具与下游使用。
- Reference 可达且有条件，脚本只检查机械事实。
- 旧能力经过保真回归，新缺口经过代表场景验证。
- 删除项有迁移或失效证据，回退路径清楚。

整齐不是结果，能力进入真实生产才是结果。
