# laohu_skills 能力加厚规范

> 日期：2026-06-06  
> 用途：规定项目专属 `laohu-` skill 如何从研究文档、外部参考和本地经验继续长成可独立执行的能力，而不是停留在资料摘要或链接索引。

## 一、核心判断

研究文档、GitHub 参考、EvoMap 资产和共享模板只是地基，不是 skill 的能力上限。

每个 `laohu-` skill 被调用时，都要把已有知识转成可执行判断、可复制输出、可回流经验和可交给下游的结果。即使下一次调用时没有重新阅读全部研究文档，skill 也应该能完成对应阶段的作品生产任务。

任何需求都先判断根本目的，不只处理表层说法。skill 输出或执行前至少内化：

```text
老胡表面提出了什么。
老胡真正想达成什么。
本次结果如何服务最终作品质量、创作体验和后续迭代。
```

如果老胡正在真实测试，反馈本身就是经验材料，必须进入作品经验沉淀和必要的共享规则更新。

如果反馈是通用执行问题，优先进入共享资产：`助手执行失败经验与防复发规则.md`。这类经验必须反哺到具体执行文件；只保存复盘、不修改规则，视为未完成。

## 二、能力加厚的五个方向

每个 skill 至少从以下五个方向扩展能力边界：

| 方向 | 要求 |
|---|---|
| 输入变体 | 能处理完整输入、粗糙输入、口述输入、半成品、失败反馈和缺失字段。 |
| 决策规则 | 不只套模板，要判断体量、用途、风险、优先级、是否进入下游。 |
| 产物深度 | 输出要能直接进入作品目录、生成测试、人工评审或下游 skill。 |
| 失败边界 | 说明当前结果最可能失败在哪里，应该回到哪个上游修。 |
| 经验回流 | 判断哪些内容应写回模板、词典、模型适配、案例库或课程化。 |
| 根本目的 | 判断表层需求背后的作品目标、体验目标和最终结果目标。 |

### Skill 主体与 Reference 的裁决标准

本项目不为 Skill 主体设置固定行数或字数上限。篇幅只是结构诊断信号，不是质量标准，更不是自动拆分条件。

内容是否留在主体，只看它是不是当前 Skill 每次执行都必须掌握：

```text
每次都要用的触发判断、执行流程、硬约束、输出合同、质量门和通用专业细节 → 留在 SKILL.md
只在特定题材、阶段、输入状态、模型或失败信号下使用的完整方法 → 进入 Reference
可以由脚本稳定完成的机械检查 → 进入 scripts
只供最终产物复制或调用、不需要进入推理上下文的素材 → 进入 assets
```

禁止为了让主体短、通过行数检查或符合某个看起来整齐的模板，把每次都要用的内容拆出去。拆分后必须反问：一个陌生模型只读主体并按路由读取必要 Reference，能否独立完成任务并保持原有质量下限？如果不能，说明拆分位置错误，应把信息移回主体，而不是继续补一个更抽象的摘要。

验收结构时检查的是：职责是否清楚、条件路由是否准确、主体是否能够独立决策、Reference 是否真的有独立触发条件、信息是否完整、是否存在重复或漏读风险。不得用主体行数代替这些判断。

## 三、禁止退化

禁止把 skill 写成以下形态：

- 只列参考文档，不给执行协议。
- 只给模板，不判断用户输入属于哪一类。
- 只生成漂亮文字，不说明能否拍、能否生成、能否剪辑。
- 只产出正文，不产出交接包。
- 只记录成功，不记录失败和修正路径。
- 只适配一个理想输入，不处理真实生产中的缺失、混乱和返工。

## 四、每次调用时的最低动作

每个 `laohu-` skill 至少完成：

```text
判断表层需求、真实目标和根本目的
→ 判断当前应该进入哪条流程
判断输入属于本 skill 的哪种场景
→ 补齐当前阶段必需字段
→ 给出可直接使用的正文产物
→ 给出失败风险或人工评审点
→ 输出交接包
→ 指明下一步 skill 或回流位置
```

缺失信息允许标“缺”。不能为了产出完整而编造作品事实、生成结果、发布数据或模型反馈。

## 五、与外部资源的关系

外部资源只吸收结构和方法，不直接复制成老胡项目模板。

本轮已经确认的可吸收方向：

- 山音编剧参考：吸收多体量剧本、阶段门控、人物与结构诊断、视听化红线。
- AI 视频提示词参考：吸收镜头语言、音画同步、质量检查、多模型提示词维度。
- Seedance 参考：吸收三层视频提示词、分镜时间轴、参考图一致性、案例证明意识。
- EvoMap / Evolver：吸收阶段编排、经验材料资产化、交接包和本地索引更新纪律。

任何外部新资料进入项目后，都必须先经过 `经验材料吸收与本地资产更新闭环.md`，再决定是否加厚到具体 skill。

## 六、验收标准

一个 skill 只有满足以下标准，才算能力加厚完成：

- 单独调用时，不需要用户重新解释整个项目系统。
- 能把粗输入推进到当前阶段的可用产物。
- 能说明为什么选择当前流程，而不是默认直接产出某类提示词。
- 能说明自己的能力边界，不抢下游 skill 的工作。
- 能输出可继承的交接包。
- 能在真实结果回来后进入诊断、修正和资产回流。
- 能通过 `skills/laohu-ai-visual/scripts/check_laohu_skills.sh`。

## 七、后续加厚方式

每次真实作品验证后，按以下方式更新：

```text
真实结果回传
→ 判断哪个 skill 的判断失效或不足
→ 更新对应 skill 的规则、字段、失败类型或自检
→ 如果跨作品复用，同步更新共享模板或视觉语言资产
→ 更新输入输出索引
→ 重新运行合约检查
```
