# 老胡 AI 视觉能力协作图谱

本文件规定二十二个 Skill 怎样互相借力。它不替代生产状态，不复制专业方法，也不把所有节点变成同一种能力。

## 一、网络原则

### 顺序生产，网状会商，按根因返工

作品必须按真实状态向前生产；能力不必排成只能向下说话的一条队。当前负责人可以向相邻专业咨询、接受总导演复验、读取共享事实，也可以把问题返回最早根因。

### 各有主业，彼此听得懂

每个节点是 T 型能力：纵向对自己的专业结果负责，横向理解导演意图、观众经历和相邻专业接口。理解不等于接管，参考不等于复制。

## 二、五类协作边

| 类型 | 何时使用 | 主责是否转移 | 必须返回 | 禁止行为 |
|---|---|---:|---|---|
| `HANDOFF` | 阶段完成，成果与状态正式交给下一负责人 | 是 | 锁定事实、自由区、完成条件、失败边界 | 只转发摘要，不交可执行状态 |
| `CONSULT` | 当前负责人缺少相邻专业判断，但仍能整合结果 | 否 | 对一个明确问题的判断与适用边界 | 把咨询变成共同负责或覆盖对方权威 |
| `REVIEW` | 总导演在关键节点检查整片方向，或专业节点执行独立复验 | 否 | 继续 / RETURN / 请求者取舍及证据 | 审阅者直接在下游偷改上游决定 |
| `RETURN` | 当前问题的根因不在本节点 | 是 | 首断点证据、保护项、最小返工目标 | 在末端增加文字掩盖上游缺口 |
| `SHARED_SOURCE` | 多节点需要同一人物、世界、资产、平台或模型事实 | 否 | 权威路径、版本/状态、当前有效事实 | 复制第二份事实或无权修改共享真源 |

`CONSULT ≠ HANDOFF`。调用不转移主责，也不授予调用者修改被调用节点权威文件的权限。

`laohu-language-mode`只通过`CONSULT`为当前文本块返回语言合同，不接管专业内容，也不改变生产状态。各节点可以用`SHARED_SOURCE`读取它的模式 Reference；若发现内容不足，必须用`RETURN`回到原负责人，不能让语言节点补写领域答案。

## 三、调用合同与回执

调用前写清：

```text
当前主负责人：
协作边类型：HANDOFF / CONSULT / REVIEW / RETURN / SHARED_SOURCE。
触发条件：为什么当前节点不能只靠本职完成。
目标节点与必要 Reference：
只需要回答的问题：
当前保护项：
允许挑战的假设：
禁止覆盖项：
结果进入当前哪个决定：
```

调用后留下`调用回执`：

```text
实际读取或交接：
取得的判断、事实或状态：
改变或确认的决定：
未采用内容及原因：
当前主负责人：
下一步与失败返回：
```

没有改变或确认任何决定的读取不算能力激活。不默认读取所有文件；“项目复杂”不是全量加载的理由。

## 五、导演参与范围

总导演默认介入四个节点：创作前定向、剧本后复验、生成前总检、成片后验收。单一内部资产、确定性转换、编号检查、渲染归档和已锁定导演阐述下的局部机械返工不强制调用。

MV 中若 `laohu-mv-director` 已完整承担歌曲导演职责，总导演只处理歌曲之外的品牌、系列、观众和跨作品约束，不产生第二份导演终审。

## 六、返工原则

可见问题先判断发生在哪里，而不是最后在哪里被看见：

```text
目的或观众路线互相冲突 → laohu-director
内容已成立但文本块身份或接收者混写 → 当前负责人 CONSULT laohu-language-mode
人物为什么做、台词为什么说、镜头事实不成立 → laohu-script-writer
视觉世界互相打架 → laohu-art-direction 或对应专业设计
已确认对象在生成中走样 → laohu-visual-assets
既有镜头没有被正确编译 → laohu-video-prompt
真实结果与所有计划都不一致 → laohu-generation-review 先定位首断点
```

RETURN 必须携带证据和保护项。没有首断点证据时只标观察，不把所有节点同时叫来重做。


## 编剧内部专业能力

`laohu-script-writer CONSULT 内部专业能力 → laohu-script-writer复验与整合`。十二个子Skill的触发、实际入口与创作结果由编剧主Skill“创作推进与专业判断”统一路由，包括前提、结构、人物、场景、对白、格式改编、案例、日式、韩法、契诃夫、小津与行业能力。

调用传递当前材料、目标、冻结事实和创作范围，返回具体候选或改稿、方法落点与保护核对；主编剧负责最终内容，跨能力根因仍返回主编剧协调。风格方法可以在开发早期进入，行业只按专项触发；不新增顶层负责人、作品状态或第二正式剧本。总导演、语言、资产、音频和视频的内容边界保持现有合约。来源、完整性与失效处理统一见外部能力依赖清单EXT-SKILL-002。


## 专业树的协作边

所有22入口及88专业的名称/路径/所属关系见[能力注册表](能力注册表.json)。所属关系只指定维护负责人；当前任务按以下边接力：

| 发起 | 关系 | 接收 | 返回结果 |
|---|---|---|---|
| 各当前负责人 | CONSULT | laohu-creative-development | 开放变量内的候选与选择 |
| 人物、服装、图片、资产 | CONSULT / HANDOFF | laohu-makeup-design | 妆造补充正文和阶段状态 |
| 场景、人物、资产 | CONSULT / HANDOFF | laohu-prop-design | 道具本体与可操作结构 |
| 总控、资产、封面、MV | HANDOFF / CONSULT | laohu-image-creation | 对应用途的单张画面与编译结果 |
| 图片、视频、封面、各设计专业 | CONSULT | 美术树中实际缺失的共享专业 | 静态专业决定或时间变化条件 |
| 各专业父入口 | CONSULT | 其注册子Skill | 局部结果，返回父入口整合 |

图片与资产互相调用时先区分身份：图片可请求资产提供稳定参考，资产可请求图片制作F；F的候选图返回资产依赖登记，不能再以同一缺口请求重做F。只有事实改变或验收失败才重开任务。妆发与道具已确认时直接进入M/A编译，不重复设计。


## 剧本—分段—视频交接

| 发起方 | 关系 | 接收方 | 输入与返回 |
|---|---|---|---|
| 总控/基础资产 | HANDOFF | laohu-video-segmentation | 完整E-S剧本、资产/音色目录与制作约束；返回P执行卡 |
| 分段 | CONSULT | 表演/动作/剪辑/声画/视频参考专业 | 只解决具体边界、时间或接续问题，返回本卡决定 |
| 分段 | RETURN | 编剧/基础设计 | 缺失剧情或基础结构；普通状态差异不触发设计返工 |
| 分段 | HANDOFF | 视频提示词 | P原文、讲戏、引用、状态及后续需求；视频建C和实际绑定 |
| 视频 | RETURN | 分段 | 入口时长或负荷不适配，先修P及映射，不自行重分段 |
| 视频/复盘 | SHARED_SOURCE | 资产与后续P | 经确认的真实帧、片段或预制图；计划目标与实况分开 |

常规接续以文字状态为先；视频提示词上方按需提醒生成后取帧或生成前预制。公开发布与生成权限不因交接自动扩大。
