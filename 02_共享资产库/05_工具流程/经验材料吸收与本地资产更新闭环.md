# 经验材料吸收与本地资产更新闭环

> 本文件只负责材料入口、原始归档和进化交接。长期能力更新的唯一负责人是 [`laohu-capability-evolution`](../../skills/laohu-capability-evolution/SKILL.md)。

## 一、材料不是规则，是等待验证的来信

研究文档、提示词、生成结果、成功失败案例和发布反馈进入项目，只能证明“有一份新证据”。它们不能绕过证据判断、四层重编译和行为验证，直接固化成项目规则。

```text
保存原始材料
→ 判断属于当前作品还是通用证据
→ 当前作品问题先交业务 Skill 或生成复盘
→ 可能改变长期能力时交 laohu-capability-evolution
→ 在能力进化台账创建、合并或重开记录
→ 验证后才写回唯一负责人
```

不直接固化规则，不把一次成功写成模板，不把一次失败写成永久禁令。

## 二、材料入口与原始归档

| 材料类型 | 原始或作品内位置 | 首个接收者 |
|---|---|---|
| 研究文档、论文、外部教程 | `00_输入原料/研究文档/` | 能力进化的 `RESEARCH` |
| 外部案例 | `00_输入原料/外部案例/` | 能力进化的 `RESEARCH` |
| 剧本、图片和视频提示词经验 | 对应作品阶段主文件 | 对应业务 Skill；有真实结果时进入生成复盘 |
| 生成图片、视频和剪辑结果 | `01_作品项目/<作品名>/` 对应阶段 | `laohu-generation-review` |
| 作品内成功或失败 | `01_作品项目/<作品名>/09_归档复盘.md` | `laohu-generation-review` |
| 发布数据和用户反馈 | 当前作品复盘 | `laohu-generation-review` |
| 平台、模型、格式和接口变化 | 原始来源或模型适配资产 | 能力进化的 `PLATFORM` |

原始材料不改写；来源、时间、平台、模型、作品和实际结果缺什么写“缺”。共享案例、模板、模型适配和视觉语言资产只能在验证后更新。

## 三、交给能力进化的最小证据包

```text
材料名称与来源：
原始位置：
所属作品与阶段：
事实：
推论：
老胡偏好或判断：
可见结果与预期结果：
候选的第一个能力断点：
可能影响的负责人：
必须保护的旧能力：
证据完整度：完整 / 部分 / 仅作观察。
```

没有真实结果的外部案例只能作为研究证据，不能登记为本项目成功案例。没有原输入和生成结果的失败只能暂定归因，不能直接更新负面提示词和模型适配。

## 四、材料怎样变成长期资产

由能力进化 Skill 先判断它应当：

- 返回当前作品修正。
- 进入 `04_诊断与系统日志/能力进化台账.md` 的 `OBSERVE`。
- 合并或重新唤醒既有进化记录。
- 加厚现有 Skill 或按需 Reference。
- 更新模板、模型适配、视觉语言资产或机械脚本。
- 满足独立能力门槛后，新建缺失能力。
- 因证据不足、重复或无增益而不吸收。

只有结论为 `KEEP`，且真实行为验证已经通过，长期资产才成为以后默认使用的权威内容。`输入输出索引.md` 只在公开入口、长期资产或调用关系真实变化时更新，不为每份原始材料增加一条记录。

## 五、验收边界

- 原始材料是否仍可追溯，没有被摘要替代。
- 当前作品修正是否先完成，没有被系统建设耽误。
- 是否区分事实、推论、偏好和待验证假设。
- 是否检索能力进化台账，避免重复规则。
- 是否由唯一负责人承接长期更新。
- 是否留下旧行为、新行为、保护项和重新唤醒条件。
- 是否没有把外部包装冒充本地原创。
