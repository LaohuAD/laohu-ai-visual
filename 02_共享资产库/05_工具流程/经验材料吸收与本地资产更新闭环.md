# 经验材料吸收与本地资产更新闭环

> 用途：当项目新增研究文档、实战提示词、生成结果、成功案例、失败案例、发布反馈或外部教程时，按本文件把经验吸收到本地项目资产里。

## 一、为什么要有这个闭环

老胡 AI 视觉项目不是资料仓库。

如果只是把研究文档、提示词、截图和生成结果放进目录，项目不会变强。

真正有价值的动作是：

```text
输入一份材料
→ 提取一个判断
→ 固化一条规则
→ 生成一个模板
→ 更新一个资产
→ 让下一次作品更稳
```

所以每次新增材料，都要问：

```text
这份东西能不能让下一次剧本更清楚、图片更稳定、视频更可控、成片更像作品？
```

## 二、可吸收材料类型

| 材料类型 | 归档位置 | 主要更新位置 |
|---|---|---|
| 研究文档 | `00_输入原料/研究文档/` | `02_共享资产库/01_模板库/`、`02_共享资产库/02_视觉语言资产/`、`02_共享资产库/03_模型适配/`、`02_共享资产库/05_工具流程/` |
| 剧本方法 | `00_输入原料/研究文档/` 或 `01_作品项目/<作品名>/02_剧本/文本/` | `02_共享资产库/01_模板库/剧本模板/`、`01_作品项目/<作品名>/02_剧本/文本/` |
| 图片提示词经验 | `00_输入原料/研究文档/` 或 `01_作品项目/<作品名>/03_视觉资产/文本/` | `02_共享资产库/01_模板库/图片模板/`、`02_共享资产库/02_视觉语言资产/画面风格库/` |
| 视频提示词经验 | `01_作品项目/<作品名>/05_视频/文本/` | `02_共享资产库/01_模板库/视频模板/`、`02_共享资产库/02_视觉语言资产/镜头语言库/`、`02_共享资产库/03_模型适配/` |
| 成功案例 | 先进入 `01_作品项目/<作品名>/09_归档复盘.md`，可跨作品复用后再进入 `02_共享资产库/04_案例经验库/成功案例/` | 对应模板和模型适配规则 |
| 失败案例 | 先进入 `01_作品项目/<作品名>/09_归档复盘.md`，可跨作品复用后再进入 `02_共享资产库/04_案例经验库/失败案例/` | 失败避免规则、负面提示词、模型适配规则 |
| 发布复盘 | `01_作品项目/<作品名>/09_归档复盘.md` | 封面、选题、剧本、分镜、提示词规则 |

## 三、标准处理流程

```text
1. 保存原始材料。
2. 先判断是否属于某个具体作品。
3. 属于作品的材料，先进入作品目录对应位置。
4. 不属于作品的通用材料，进入 `00_输入原料/` 或 `02_共享资产库/`。
5. 提取核心判断。
6. 判断能沉淀到哪些共享资产目录。
7. 新增或更新模板、规则、词典、检查清单。
8. 更新输入输出索引。
9. 必要时更新 AGENTS.md、README.md 或工具流程文件。
```

## 四、提取时必须回答的问题

- 这份材料属于哪条链路：剧本、人物、分镜、图片、视频、剪辑、发布，还是工具？
- 这份材料属于某个作品，还是通用经验？
- 如果属于作品，它在作品目录里的准确位置是什么？
- 它提供了什么新判断？
- 它能不能变成可复用模板？
- 它能不能变成检查清单？
- 它能不能补充词典、字段说明或模型适配规则？
- 它有没有推翻旧规则？
- 它有没有失败经验值得记录？
- 它有没有内容可以回流到老胡文稿项目，变成文章、口播或课程？

## 五、输出格式

每次吸收经验后，在 `输入输出索引.md` 里新增一条记录：

```text
### 材料标题

- 原始来源：
- 项目归档：
- 类型：
- 核心判断：
- 已沉淀：
  - 模板：
  - 视觉语言资产：
  - 模型适配：
  - 工具设计：
- 待验证：
- 状态：已归档 / 已加工 / 已模板化 / 已资产化 / 已验证 / 已复盘
```

## 六、执行边界

- 不把研究文档原样堆到资产目录后就算完成。
- 不为了整齐把失败案例删掉。
- 不把一次成功误判成稳定规律。
- 不把外部教程直接当成老胡规则，必须结合老胡项目目标重写。
- 不新增过碎的文件。如果一条经验只能作为一句补充，优先追加到已有资产文件。
