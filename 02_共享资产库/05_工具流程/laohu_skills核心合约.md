# laohu Skills 核心合约

本文件只规定十四个 Skill 怎样接力、怎样返回和怎样验收。专业方法由各 Skill 负责；作品事实由当前作品负责；平台机械限制由脚本和模型适配负责。

## 一、总合约

### 各守一段，才能同走一程

上游交付事实、状态和创意空间，下游在自己的专业范围内主动升级。下游不能改写已确认事实，也不能因上游普通就继续产出普通；发现根因不在本阶段时，返回最早负责人。

### 交接不是复述，是状态移交

每次交接至少说明：从什么可靠输入开始、本阶段改变了什么、什么已经锁定、什么仍可设计、怎样判断本阶段完成、下一站从哪里继续。

### 一处失效，回到最早断点

剧本因果不成立，不靠资产美术补；资产失真，不靠视频长文补；镜头编译错误，不靠 VC 润色补；正片承诺不足，不靠封面夸大补。

### 底线只管能不能继续，巅峰才决定能不能交付

每个 Skill 都有两道完成门：底线门检查事实、状态、接口、连续性、格式和可执行性；巅峰门比较真正不同的候选，确认主胜负手已经得到最强支持，并用领域顶尖样本、成熟从业者判断维度、目标观众结果或真实生成反馈校准。通过底线只能交给下一轮创作或 VC，不能直接宣布正式完成。

极致不等于堆满。一个维度全力承重时，其他维度可以克制、留白或静止；作品没有明确主次，所有专业同时争抢注意力，即使每项单看都强，也按平庸处理。

## 三、VC 身份与调用链

VC 的底层方法不是本项目原创，而是外部 Skill `vibe-creating-prompt` 的项目简称。当前生产链不得直接读取外部原文执行，而要经过本地适配入口 `laohu-vibe-creating-prompt`：

```text
laohu-video-prompt 完成可直接生成的首稿
→ laohu-vibe-creating-prompt 必须读取外部原文的便携副本并执行 VC
→ 判断轻度提纯、直接改写、零改动放行或退回上游
→ 本地适配层保护台词、资产、状态、三段式、字符和剪辑接口
→ 结果返回 laohu-video-prompt
→ 视频 Skill 完成最终复验与写入
```

外部原文位于 `02_共享资产库/05_工具流程/外部优化Skill/vibe-creating-prompt/SKILL.md`，便携副本位于 `skills/laohu-vibe-creating-prompt/references/01_外部Vibe_Creating原文.md`，两者必须逐字一致。身份、来源状态、更新和失效处理以 `外部能力依赖清单.md` 为准。

任一原文缺失、镜像漂移或适配关系不完整时，保留已经通过视频首稿门的基线作为排障与恢复材料，返回 `laohu-video-prompt` 并标记“VC 链路失败”。不得凭简称猜测能力；没有实际完成 VC 的稿件不得标记为正式提示词或进入付费生成。

```text
上游已确认事实：

```

事实、素材和数据缺失写“缺”；当前阶段可以专业补全的创意不能只写“缺”，要提出并选择方案。会改变核心故事、真实声称、成本、版权、安全和公开发布的内容才需要确认。

## 五、生产状态

```text
IDEA → STORY → ASSET → SHOT → PROMPT → GENERATED → EDITED → PUBLISHED → LEARNED
```

状态只在完成条件真实满足后推进：

| 状态 | 完成条件 |
|---|---|
| IDEA | 目标与原始材料已归档 |
| STORY | 叙事作品的观众等待、人物选择、因果、场次结果与下游事实成立；歌曲型作品的歌曲—视觉结构、导演命题、情绪运动和视觉引擎成立 |
| ASSET | 最低可行资产已定义；需要实际图片时已标明待生成或已验收 |
| SHOT | 镜头任务、VID 边界、相邻状态与剪辑意图明确 |
| PROMPT | 三段式、资产引用、时空因果、字符与格式通过生成前验收 |
| GENERATED | 有真实生成文件或可靠回传，不是只有提示词 |
| EDITED | 有可观看的剪辑结果与真实时间码 |
| PUBLISHED | 有真实发布记录；数据尚未回收可标待回收 |
| LEARNED | 经验已写回唯一负责人，行为验证通过，能力进化台账已留下旧行为、新行为和复验依据 |

状态表记录生产事实，不代表审美目标已经完成。正式阶段交付还需额外回答：本阶段主胜负手是什么；比较过哪些真正不同的候选；胜出方案为何优于其余方案；哪一项顶尖校准或真实结果支持它；是否仍存在一个已知且未处理的明显升级方向。最后一项为是时，不得以状态已推进为由收工。

快速草稿可以跨过部分正式文件，但不能伪造状态。只有提示词时不能写 GENERATED，只有发布计划时不能写 PUBLISHED。

## 六、相邻单元交接合同

两个节拍、场次、镜头、VID 或上下集只要共享人物、道具、空间、时间、动作、声音、情绪余势或永久结果，就逐对维护：

```text
单元 A / 单元 B：
关系：直接连续 / 同场重建 / 关系重置。
A 已完成结果：
A 结束状态：人物 / 服装伤势 / 道具 / 空间时间 / 永久结果 / 动作表演 / 声场。
B 起点状态（即开始状态）：
必须不变 / 允许变化：
主匹配属性 / 辅助匹配属性：
B 第一项新动作或声音：
下一相位：
参考路线：稳定资产 / 终帧 / 视频尾部 / 干净构图 / 无。
干净把手 / 禁止状态：
状态等式：通过 / 不通过。
不通过时返回的最早负责人：
```

直接连续执行 `A 结束状态 = B 起点状态`，但 B 不复演 A。计划状态只供设计；A 实际生成后由复盘 Skill 用真实结果二次绑定。

## 七、阶段交接

### 素材 → 编剧

```text
素材来源和 source ID：
候选 atom IDs：
当前剧本缺口与检索层级：
检索会话 ID、叙事范围与游标：story / sequence / scene / beat / texture。
动态分页状态：本页预算、是否还有候选、已覆盖 / 仍缺缺口、继续或停止理由。
保留机制和可见证据：
可支持的输入状态 / 变化机制 / 输出状态：
不能单独证明的结构结论：
允许改变 / 不可复制：
适合位置和主职责：
充分度结论：已解决 / 仍缺口。
外部候选状态：无 / external_candidate / not_approved / 已批准范围。
```

素材负责人先给压缩索引页，再按 ID 读取原子详情；不得把整库交给编剧或 AI。原始 source 只在语气、证据、权利或归因需要时显式读取，且与 atom 详情分开调用。素材负责人只交机制、证据、边界和用途，不替编剧决定人物选择，也不选择故事构件或拼装剧情。内部候选不适配时允许零采用；外部候选未经老胡确认不得进入剧本或长期素材库。

素材库与故事构件库分属两个负责人：

```text
素材原子（laohu-story-material）：保人类原话、生活证据、人性机制与不可复制边界。
故事构件（laohu-script-writer）：保可独立调用的输入状态、人物行动、状态变化、观众更新与下一压力。
```

编剧只在真实剧情缺口存在时，使用 `skills/laohu-script-writer/scripts/story_component_library.py` 对 `references/07_故事构件库.jsonl` 执行 `stats → search → get`。构件只提供变化方式，不可以编号或类别代替人物因果；候选不适配、库为空或原创方案更准确时允许零采用。

### 歌曲 / 歌词 / 背景 → MV 导演

```text
最终音频文件与真实总时长：
锁定歌词与版本：
人工 LRC / SRT / DAW 标记（如有）：
ASR 对齐候选及置信度（如有）：
歌曲创作背景、叙述者与不可改事实：
音乐创作风格提示词（只作创作背景，不冒充成品音频证据）：
目标观众、平台、画幅与成片目的：
已确认人物、世界、品牌与视觉资产：
目标模型能力合同（如已知）：
```

最终音频是时长、段落边界、能量变化与同步事件的时间权威；锁定歌词是文字权威；ASR 只做对齐候选。缺少最终音频时，MV 导演可以完成概念与候选结构，但所有精确时间码都必须标记`待音频校准`，不能用平均字数、音乐提示词或想象节奏伪造。

### MV 导演 → 编剧 / 美术 / 视觉资产 / 视频

```text
歌曲事实卡与证据等级：
一句话导演命题与观众结果：
主视觉引擎 / 辅助引擎及淘汰理由：
歌曲创作段落、情绪运动与声画关系：
叙事需求：无需连续剧情 / 需要编剧补足的最小因果链：
表演模式与对口型窗口：
制作时间线与每个生产单元边界：
每单元的资产任务：单帧 / 首尾帧 / 多关键状态 / 无需新图：
每单元的视频导演卡：起点、音频触发、屏幕变化、结束状态、剪辑接口：
固定事实 / 可设计项 / 禁止新增：
待音频校准与待模型能力校准项：
```

歌曲创作段落用于决定意义、情绪和重复回收，生产单元用于适配生成与剪辑；两者不得冒充彼此。视觉资产只编译已经确认的图片任务，视频 Skill 只编译已经确认的时间因果和三段式提示词。任何具体模型时长、输入图数量和能力边界，都来自当次目标模型能力合同，不得固化成全项目通则。

### 剧本 → 人物设计 / 服装设计 / 场景设计 / 资产 / 视频

```text
观众预期契约：可见证据 / 暂时判断 / 可预见压力 / 未揭变量 / 部分兑现。
观众等待与主情绪：
人物目标、阻力、选择和代价：
写作声音：优先感知 / 证据解释 / 语言目的 / 回避内容 / 冻结台词 / 话后行动；不声明演员生理音色。
胜出因果链：前置条件 → 人物行动 → 状态变化 → 观众更新 → 下一压力。
观众发现顺序：
场次结果与下一场压力：
正式剧本正文：场次、内外、具体地点、时间、人物、开场状态、可见可听行动、台词 / OS / VO、承重声音、屏幕文字、必要特效和场次结果。
生产证据账本：声音的声源 / 触发 / 作用，必要特效的原因 / 变化 / 结果，屏幕文字的逐字内容和出现条件。
空间拥有 / 控制 / 排除关系，人物进入、离开与必须动作：
第一次看见、后来重解和不得提前泄露的空间信息：
已确认人物、道具、空间和时间事实：
暂时无法解决的具体状态：
相邻单元：
需要稳定的对象：
允许下游设计的观看方式：
```

普通正式剧本不强制焦段、景别、机位或逐镜编号；这些由分镜与 `laohu-video-prompt` 在已成立的场次事实上决定。

### 人物设计 → 服装设计 / 场景设计 / 视觉资产

```text
调用判断与人物设计授权状态：
人物核心事实与身体化命题：
第一印象—真实人格合同：
候选A—E的选角、脸身姿动差异：
胜出人物母版、主胜负手与淘汰理由：
假设置信度、待验证条件与重新开启候选条件：
稳定动作语言与群像差异矩阵：
可听声音身份：稳定音区 / 音色 / 共鸣 / 咬字 / 常态语速 / 呼吸支撑 / 证据与假设状态；不含本场演法。
条件化行为签名：触发条件 / 人物解释 / 稳定策略 / 可变动作槽 / 升级阈值 / 弧光后新基线。
媒介无关身份母版及等效适配：
固定身份 / 阶段可变 / 瞬时表演 / 禁止新增 / 高风险缺口：
服装必须继承与不可遮蔽：
道具 / 装备必须继承的人体工学与人物—物件关系：
视觉资产建议是否需要F人物写真中间参考，以及B / 阶段素体 / M / G职责：
```

人物设计只决定人物本身及其稳定身体语言，不替服装决定轮廓材料，也不替视觉资产制作板和图片提示词。锁定真人参考只交付证据范围内的事实；不可见角度和身体数据不得伪装成零改动还原。

### 服装设计 → 场景设计 / 视觉资产

```text
调用判断：完整调用 / 轻量调用 / 无需调用。

人物服装命题与剧本证据：
定案等级：必须人工定案 / 条件人工定案 / AI自动定案 / 零设计改动。
```

## 八、Reference 合约

Reference 只承接特定题材、对象、模型、证据或失败分支。Skill 主体必须写清触发信号、读取文件和停止条件。

Reference 是否生效，看它有没有改变选择，不看文件有没有被打开。正式任务至少在内部保留一条最短生效链：

```text
触发问题
→ 实际读取的 Reference
→ 提取的机制
→ 改变的中间决定
→ 进入成品的可观察位置
```

只能复述文件名、摘要或“已阅读”，却找不到被改变的决定，视为运行时不可达。先修唯一负责人、触发条件、中间结果和完成门，不能重复增写同类知识来掩盖断链。

```text
完全适配：一个 Reference 覆盖主导机制。
组合适配：一个主要 Reference，最多一个辅助 Reference。
能力缺口：建立当前作品机制卡；有复用证据后再增加长期能力。
```

只改变颜色、年代、人物和表面风格，不自动构成新能力。新 Reference 以稳定观众任务和主导机制命名，不以单个案例、软件、人物、颜色和特效命名。

## 九、失败返回

| 发现问题的阶段 | 返回条件 |
|---|---|
| 素材 | 原话不完整、原子混写或事实边界不清 → 素材负责人；素材适配但人物与因果改造失败 → 编剧；未批准外部候选越过确认门 → 立即停止并返回素材负责人 |
| 资产 | 人物动机、故事结果或信息顺序不成立 → 编剧 |
| 视频 | 镜头尚未发明 → 分镜 / 编剧；身份或空间无稳定基准 → 资产 |
| VC | 三段、字符、连续性和动作基线不合格 → 视频；故事与资产缺口返回对应负责人 |
| 封面 | 正片没有可兑现承诺 → 编剧 / 视频；缺干净身份参考 → 资产 |
| 复盘 | 依据第一个断点返回最早负责人，不默认归因模型 |
| 能力进化 | 证据不足 → OBSERVE；旧能力受损、调用链断裂或验证失败 → REVERT；完成后返回总控 |

返回必须带证据、保护项和完成条件，不能只写“上游有问题”。

## 十、共同验收

### 生成控制语言公共合同

图片、视频、封面和其他模型生成正文里的承重控制句，内部都要能还原为：`控制对象 → 本次真实基准 / 起点 → 允许变化的维度 → 方向、幅度或路径 → 可见 / 可听终态`。正式正文不必显示五个标签，但不能缺失决定结果的环节。

比较词、最高级和继续变化词只有在本次实际绑定的参考或当前镜头起点明确时才成立；即使存在相邻参考，也要给当前请求一个独立可执行的绝对目标。身份、结构或场景的不可变项必须与本次可变项分开，不能一边锁住同一几何关系，一边要求它改变。`自然、明显、轻微、高级、流畅、进一步、最`只能作总结，不能替代轮廓、位置、距离、速度、受力、亮度、声音、持续时间或结束状态。

具体排除对象优先改写为正向唯一结果，例如把`不生成BGM和字幕`改成`声音轨仅由对白、动作声和环境声组成；画面保持纯影像，文字由后期加入`。人物尚未落泪、手仍未伸出、门没有打开等真实时间状态可以保留，它们在描述当前世界，不是作者对模型下黑名单。高成本生成前必须逐句过此合同；机械脚本只拦截明确作者解释、绝对时间轴和直接负向生成指令，弱词是否承重由人工语义审稿裁决。

- 当前是否只有一个主负责人。
- 阶段入口、完成条件和下游是否清楚。
- 已确认事实是否被保护，新增创意是否在授权范围。
- 相邻单元是否状态相等并从下一相位开始。
- Reference 是否按机制触发，不是按题材名全读。
- 结果是否能直接进入下一阶段，不依赖作者口头补充。
- 底线门与巅峰门是否分开；是否把“格式通过、能生成、能使用”误写成最终完成。
- 重要产物是否比较真正不同的候选，并说明主胜负手、胜出原因、顶尖校准和仍未处理的升级方向。
- 路径、字符、格式、命名和平台边界是否经过机械验证。
- 长期反馈是否经过能力进化，回到唯一规则负责人，并通过当前、相邻、保真与失败场景验证。
- 本地 Git 检查点是否只包含本轮可归属改动；未经老胡在当前任务明确授权，是否避免了 `git push`、PR、Release 和远程发布。

## 十一、作品HTML交付合同

十四个 Skill 中，会写作品阶段文件的业务 Skill 仍把当前阶段结果写入 Markdown 主文件；Markdown 是唯一权威内容源。面向老胡的阅读、编号识别和提示词复制由统一 HTML 编译器承担，不允许各 Skill 手写不同风格、不同字段或内容滞后的 HTML。`laohu-story-material` 的私有素材数据库不渲染 HTML，也不得在作品交付中心暴露原话。

```text
阶段Markdown主文件完成并通过本阶段检查
→ 运行 scripts/render_delivery_html.py --project <当前作品目录>
→ 每个Markdown旁生成同名HTML
→ 作品根目录刷新00_作品交付中心.html
→ 核对编号、标题、依赖关系、复制按钮和源文保真
→ 最终回复优先给HTML结果链接，并保留Markdown源文件链接
```

卡片按F / B / P或作品阶段编号 / W / M / G / S / A识别；视频卡按VID识别。F是组合人物、服装与妆造胜出设计后形成的角色主视觉图，经人工选定后供同编号B / W / M反向拆解。F是成图源而非稳定资产；它不直接进入视频，也不在B验收后自动退役。HTML不得照搬Markdown的出现顺序散排，而要按下游使用职责固定分组：`人物主视觉图（F）→ 素体与阶段素体资产（B / LZ / P）→ 服装资产（W）→ 妆造设计资产（M）→ 道具资产（A）→ 场景资产（S）→ 群像资产（G）`，组内按编号排序；VID进入独立的视频提示词分组。分组只改变交付界面的查找顺序，不反写或重排Markdown唯一源。

每个领域卡片必须有唯一编号和明确标题，代码块独立复制。领域卡采用复制优先的紧凑模式：桌面端自动多列排列，卡片默认隐藏提示词正文和制作说明，只显示编号、标题以及`复制标题 / 复制提示词 / 查看详情`三个操作。复制标题取得卡片当前显示的完整标题，包括资产编号和资产名称；复制提示词取得Markdown代码块的完整原文；查看详情进入独立大尺寸阅读层，并可再次复制完整原文。普通无领域编号代码块不显示无意义的“复制标题”。搜索必须同时检索标题、编号和默认隐藏的提示词，筛选后不得破坏原卡定位，没有可见卡片的分组同步隐藏。

HTML固定为纯文本交付，不嵌入图片、不扫描图片、不预留图片槽，也不制作示例图；“提示词对应哪一个结果”只由资产编号和明确标题表达。普通剧本、分镜、封面和复盘即使没有领域编号，也要保留可读目录、表格和代码块复制能力；当代码块是主要可执行结果时，同样默认折叠正文。重复领域编号、代码块正文丢失、HTML提示词与Markdown不一致、复制按钮没有取得完整原文或项目入口链接失效时，交付不成立。
