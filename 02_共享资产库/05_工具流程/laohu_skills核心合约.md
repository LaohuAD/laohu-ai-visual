# laohu Skills 核心合约

本文件只规定八个 Skill 怎样接力、怎样返回和怎样验收。专业方法由各 Skill 负责；作品事实由当前作品负责；平台机械限制由脚本和模型适配负责。

## 一、总合约

### 各守一段，才能同走一程

上游交付事实、状态和创意空间，下游在自己的专业范围内主动升级。下游不能改写已确认事实，也不能因上游普通就继续产出普通；发现根因不在本阶段时，返回最早负责人。

### 交接不是复述，是状态移交

每次交接至少说明：从什么可靠输入开始、本阶段改变了什么、什么已经锁定、什么仍可设计、怎样判断本阶段完成、下一站从哪里继续。

### 一处失效，回到最早断点

剧本因果不成立，不靠资产美术补；资产失真，不靠视频长文补；镜头编译错误，不靠 VC 润色补；正片承诺不足，不靠封面夸大补。

## 三、VC 身份与调用链

VC 的底层方法不是本项目原创，而是外部 Skill `vibe-creating-prompt` 的项目简称。当前生产链不得直接读取外部原文执行，而要经过本地适配入口 `laohu-vibe-creating-prompt`：

```text
laohu-video-prompt 完成可直接生成的首稿
→ laohu-vibe-creating-prompt 判断是否调用外部 VC
→ 按需读取外部原文的便携副本
→ 本地适配层保护台词、资产、状态、三段式、字符和剪辑接口
→ 结果返回 laohu-video-prompt
→ 视频 Skill 完成最终复验与写入
```

外部原文位于 `02_共享资产库/05_工具流程/外部优化Skill/vibe-creating-prompt/SKILL.md`，便携副本位于 `skills/laohu-vibe-creating-prompt/references/01_外部Vibe_Creating原文.md`，两者必须逐字一致。身份、来源状态、更新和失效处理以 `外部能力依赖清单.md` 为准。

任一原文缺失、镜像漂移或适配关系不完整时，保留已经通过视频首稿门的基线，跳过 VC 并返回 `laohu-video-prompt`；不得凭简称猜测能力，也不得让外部增强环节破坏基础产物。

## 五、生产状态

```text
IDEA → STORY → ASSET → SHOT → PROMPT → GENERATED → EDITED → PUBLISHED → LEARNED
```

状态只在完成条件真实满足后推进：

| 状态 | 完成条件 |
|---|---|
| IDEA | 目标与原始材料已归档 |
| STORY | 观众等待、人物选择、因果、场次结果与下游事实成立 |
| ASSET | 最低可行资产已定义；需要实际图片时已标明待生成或已验收 |
| SHOT | 镜头任务、VID 边界、相邻状态与剪辑意图明确 |
| PROMPT | 三段式、资产引用、时空因果、字符与格式通过生成前验收 |
| GENERATED | 有真实生成文件或可靠回传，不是只有提示词 |
| EDITED | 有可观看的剪辑结果与真实时间码 |
| PUBLISHED | 有真实发布记录；数据尚未回收可标待回收 |
| LEARNED | 经验已写回唯一负责人，行为验证通过，能力进化台账已留下旧行为、新行为和复验依据 |

快速草稿可以跨过部分正式文件，但不能伪造状态。只有提示词时不能写 GENERATED，只有发布计划时不能写 PUBLISHED。

## 六、相邻单元交接合同

两个节拍、场次、镜头、VID 或上下集只要共享人物、道具、空间、时间、动作、声音、情绪余势或永久结果，就逐对维护：

```text
单元 A / 单元 B：
关系：直接连续 / 同场重建 / 关系重置。
A 已完成结果：
A 结束状态：人物 / 服装伤势 / 道具 / 空间时间 / 永久结果 / 动作表演 / 声场。
B 起点状态（即开始状态）：
必须不变 / 允许变化：
主匹配属性 / 辅助匹配属性：
B 第一项新动作或声音：
下一相位：
参考路线：稳定资产 / 终帧 / 视频尾部 / 干净构图 / 无。
干净把手 / 禁止状态：
状态等式：通过 / 不通过。
不通过时返回的最早负责人：
```

直接连续执行 `A 结束状态 = B 起点状态`，但 B 不复演 A。计划状态只供设计；A 实际生成后由复盘 Skill 用真实结果二次绑定。

## 八、Reference 合约

Reference 只承接特定题材、对象、模型、证据或失败分支。Skill 主体必须写清触发信号、读取文件和停止条件。

```text
完全适配：一个 Reference 覆盖主导机制。
组合适配：一个主要 Reference，最多一个辅助 Reference。
能力缺口：建立当前作品机制卡；有复用证据后再增加长期能力。
```

只改变颜色、年代、人物和表面风格，不自动构成新能力。新 Reference 以稳定观众任务和主导机制命名，不以单个案例、软件、人物、颜色和特效命名。

## 九、失败返回

| 发现问题的阶段 | 返回条件 |
|---|---|
| 资产 | 人物动机、故事结果或信息顺序不成立 → 编剧 |
| 视频 | 镜头尚未发明 → 分镜 / 编剧；身份或空间无稳定基准 → 资产 |
| VC | 三段、字符、连续性和动作基线不合格 → 视频；故事与资产缺口返回对应负责人 |
| 封面 | 正片没有可兑现承诺 → 编剧 / 视频；缺干净身份参考 → 资产 |
| 复盘 | 依据第一个断点返回最早负责人，不默认归因模型 |
| 能力进化 | 证据不足 → OBSERVE；旧能力受损、调用链断裂或验证失败 → REVERT；完成后返回总控 |

返回必须带证据、保护项和完成条件，不能只写“上游有问题”。

## 十、共同验收

### 生成控制语言公共合同

图片、视频、封面和其他模型生成正文里的承重控制句，内部都要能还原为：`控制对象 → 本次真实基准 / 起点 → 允许变化的维度 → 方向、幅度或路径 → 可见 / 可听终态`。正式正文不必显示五个标签，但不能缺失决定结果的环节。

比较词、最高级和继续变化词只有在本次实际绑定的参考或当前镜头起点明确时才成立；即使存在相邻参考，也要给当前请求一个独立可执行的绝对目标。身份、结构或场景的不可变项必须与本次可变项分开，不能一边锁住同一几何关系，一边要求它改变。`自然、明显、轻微、高级、流畅、进一步、最`只能作总结，不能替代轮廓、位置、距离、速度、受力、亮度、声音、持续时间或结束状态。

具体排除对象优先改写为正向唯一结果，例如把`不生成BGM和字幕`改成`声音轨仅由对白、动作声和环境声组成；画面保持纯影像，文字由后期加入`。人物尚未落泪、手仍未伸出、门没有打开等真实时间状态可以保留，它们在描述当前世界，不是作者对模型下黑名单。高成本生成前必须逐句过此合同；机械脚本只拦截明确作者解释、绝对时间轴和直接负向生成指令，弱词是否承重由人工语义审稿裁决。

- 当前是否只有一个主负责人。
- 阶段入口、完成条件和下游是否清楚。
- 已确认事实是否被保护，新增创意是否在授权范围。
- 相邻单元是否状态相等并从下一相位开始。
- Reference 是否按机制触发，不是按题材名全读。
- 结果是否能直接进入下一阶段，不依赖作者口头补充。
- 路径、字符、格式、命名和平台边界是否经过机械验证。
- 长期反馈是否经过能力进化，回到唯一规则负责人，并通过当前、相邻、保真与失败场景验证。
- 本地 Git 检查点是否只包含本轮可归属改动；未经老胡在当前任务明确授权，是否避免了 `git push`、PR、Release 和远程发布。

## 十一、作品HTML交付合同

八个Skill仍把当前阶段结果写入Markdown主文件；Markdown是唯一权威内容源。面向老胡的阅读、编号识别和提示词复制由统一HTML编译器承担，不允许各Skill手写不同风格、不同字段或内容滞后的HTML。

```text
阶段Markdown主文件完成并通过本阶段检查
→ 运行 scripts/render_delivery_html.py --project <当前作品目录>
→ 每个Markdown旁生成同名HTML
→ 作品根目录刷新00_作品交付中心.html
→ 核对编号、标题、依赖关系、复制按钮和源文保真
→ 最终回复优先给HTML结果链接，并保留Markdown源文件链接
```

资产卡按B / P或作品阶段编号 / W / M / G / S / A识别；视频卡按VID识别。HTML不得照搬Markdown的出现顺序散排资产，而要按下游使用职责固定分组：`素体与阶段素体资产（B / LZ / P）→ 服装资产（W）→ 妆造设计资产（M）→ 道具资产（A）→ 场景资产（S）→ 群像资产（G）`，组内按编号排序；VID进入独立的视频提示词分组。分组只改变交付界面的查找顺序，不反写或重排Markdown唯一源。

每个领域卡片必须有唯一编号和明确标题，代码块独立复制。领域卡采用复制优先的紧凑模式：桌面端自动多列排列，卡片默认隐藏提示词正文和制作说明，只显示编号、标题以及`复制标题 / 复制提示词 / 查看详情`三个操作。复制标题取得卡片当前显示的完整标题，包括资产编号和资产名称；复制提示词取得Markdown代码块的完整原文；查看详情进入独立大尺寸阅读层，并可再次复制完整原文。普通无领域编号代码块不显示无意义的“复制标题”。搜索必须同时检索标题、编号和默认隐藏的提示词，筛选后不得破坏原卡定位，没有可见卡片的分组同步隐藏。

HTML固定为纯文本交付，不嵌入图片、不扫描图片、不预留图片槽，也不制作示例图；“提示词对应哪一个结果”只由资产编号和明确标题表达。普通剧本、分镜、封面和复盘即使没有领域编号，也要保留可读目录、表格和代码块复制能力；当代码块是主要可执行结果时，同样默认折叠正文。重复领域编号、代码块正文丢失、HTML提示词与Markdown不一致、复制按钮没有取得完整原文或项目入口链接失效时，交付不成立。
