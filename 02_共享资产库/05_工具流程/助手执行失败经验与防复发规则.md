# 助手执行失败经验与防复发规则

> 日期：2026-06-06  
> 用途：沉淀老胡在真实测试过程中指出的通用执行问题。此文件不属于单个作品，而是所有后续作品、skill 调用、提示词生成和复盘都必须遵守的执行规则。

## 一、总原则

凡是能跨作品复用的失败经验，不只放在单个作品的 `09_归档复盘.md` 里作为孤立记录，而要进入共享资产，并同步修改具体执行文件。

经验沉淀不是写一份复盘就结束。每条通用失败经验至少要完成两件事：

```text
1. 写入共享规则、模板、skill 或检查脚本。
2. 更新输入输出索引，说明它已经反哺到哪里。
```

如果没有修改执行文件、模板、skill 或检查脚本，就不能宣称“已沉淀”。

## 二、当前已确认的通用失败经验

### 1. 首轮测试交付不应让用户拼装

#### 表层问题

老胡在《请登仙界》真实测试中指出：

- 我没有先判断真实流程入口：是写剧本、先做图片资产、固定人物场景，还是直接视频提示词。
- 首轮测试提示词不应该让用户从前文的基础设定、氛围与画质、画面内容里自己复制替换。
- 如果只是给全片大纲，就不要输出一堆半成品分镜；如果给执行用，就必须给完整可替换提示词。
- 用户正在做实际测试，每条反馈都需要沉淀到对应经验和执行文件中。

#### 根本目的

降低真实测试成本，提高生成测试效率和最终作品质量。助手要服务老胡的创作流程，而不是制造更多阅读和拼装负担。

#### 防复发规则

1. 处理任何真实测试反馈时，先判断：
   - 表层需求是什么。
   - 真实目标是什么。
   - 根本目的是什么。
   - 当前应进入哪条流程。
2. 如果当前目标是首轮视频测试，必须输出一个可直接复制的完整三层提示词：
   - 基础设定。
   - 氛围与画质。
   - 画面内容。
   - 负面约束。
   - 回传字段。
3. 不把大量半成品分镜骨架塞给用户：
   - 如果只是方向，输出总览。
   - 如果是执行，输出完整分镜提示词或直用版测试提示词。
4. 用户反馈如果能跨作品复用，不要只写入作品内失败经验，必须进入共享规则或 skill。
5. 通用经验必须修改执行文件，否则视为未完成。

### 2. 视频提示词不能跳过剧本来源、编号和确定时长

#### 表层问题

老胡指出：

- 视频提示词的镜头总时长不能写 `10-12 秒`、`8-10 秒` 这种范围，必须给确定值。
- 正确的视频提示词生成应该根据剧本描述生成。即使老胡没有直接说“生成剧本”，也不能丢掉单场次剧本这个流程。
- 首轮测试可以判断不需要固定人物 / 场景资产，直接文生视频，但不能因此改变必要规范流程。
- 分镜编号要使用 `E1-S1-C1`，后续插入用 `E1-S1-C5A`、`E1-S1-C5B` 这类字母后缀，不打乱已有编号。
- 如果只是给全局剧情，给简要概览表即可；如果给执行文件，就必须给完整可复制的分镜提示词。

#### 真实目标

让视频提示词从“画面描述”变成“基于剧本场次的可执行拍摄说明”，保证后续修改、插入、测试、复盘都有稳定编号和确定时间，不让老胡再自己猜、拼、改。

#### 根本目的

降低真实生成测试的沟通成本和返工成本，让每个镜头都能追溯到剧本场次、明确生成时长、明确镜头任务，并能在反馈后按编号局部修改。

#### 防复发规则

1. 任何视频提示词任务，必须先判断并补齐：
   - 单场次剧本。
   - 是否需要视觉资产。
   - 基础设定。
   - 氛围与画质。
   - 画面内容。
2. 首轮测试可以跳过固定资产，但不能跳过单场次剧本、分镜编号和完整三层提示词。
3. 镜头总时长必须写确定值，例如 `12 秒`，不写范围。
4. 镜头内部动作时间轴可以写起止段，但边界必须确定，并且总和等于镜头总时长。
5. 分镜编号统一使用 `E1-S1-C1`；插入镜头用字母后缀，不重排后续编号。
6. 概览稿和执行稿必须分开：
   - 概览稿：只给简要表格。
   - 执行稿：给完整可复制提示词，不给示例半成品。

### 3. 人物表情必须在分镜阶段前置判断

#### 表层问题

老胡指出：

- 每条视频提示词都需要由基础设定、氛围与画质、画面内容三部分组成。
- 前两部分通常是通用的，但不是绝对的，可能要随分镜内容局部变化。
- 画面内容设计出来后，涉及人物时需要经过人物表情优化 skill。
- 人物表情展示本身会占用镜头时间，所以不能等最终提示词阶段临时补。
- 在“剧本场次 → 分镜设计”的宏观表里，就应该判断这个分镜是否需要细化人物表情。
- 如果需要，应以人物表情 skill 的表演设计为主，再套入画面内容 skill，保证剧情、时长一致。

#### 真实目标

让人物表情不再是视频提示词里的装饰词，而是分镜设计的一部分。镜头需要用脸、眼神、呼吸、手部和身体表达剧情时，必须提前分配时间和镜头距离。

#### 根本目的

避免“镜头动作和奇观写满，人物表情没有时间展示”的失败，让剧情、表演、时长、运镜和生成提示词保持一致。

#### 防复发规则

1. 分镜宏观表必须增加：
   - 表情细化：是 / 否。
   - 表情功能：核心任务 / 辅助状态 / 不需要。
   - 表情占用时长。
   - 表演来源：`laohu_video_prompt` / 画面内容短句 / 无。
2. 只要有人物台词、沉默、反应、眼神、微表情或情绪转折，就必须判断是否需要人物表情细化。
3. 表情是核心任务时，先在 `laohu_video_prompt` 内完成表演设计，再写画面内容。
4. `laohu_video_prompt` 输出最终稿前必须检查三层结构完整，并检查人物表演来源。
5. 基础设定和氛围画质可复用，但分镜内容改变角色状态、场景、光线、声音或镜头任务时，必须局部调整。

### 4. 独立生成提示词不能依赖“沿用全片”

#### 表层问题

老胡在《请登仙界》真实测试中指出：

- 每个视频提示词都是单独提交给 AI 视频平台执行的，平台不会知道上一条提示词、全片设定或项目上下文。
- 正式视频提示词里写“基础设定是否沿用全片”“氛围与画质是否沿用全片”没有意义，甚至会导致平台拿不到必要信息。
- C1、C2 如果都出现同一个年轻迎客仙人，但没有图片资产固定，就会生成成两个不一致的人。
- 同场连续动作在 15 秒以内时，可以合并成一条提示词，用内部时间段描述完整动作。
- 当前提示词把大量内容放在基础设定和氛围画质，真正的画面内容过短，达不到可直接投喂生成平台的详细程度。

#### 真实目标

让每条视频提示词都成为独立可复制、独立可生成、独立可诊断的执行稿，同时通过资产或合并规则控制跨镜头一致性。

#### 根本目的

降低生成平台的不确定性，避免人物变脸、场景断裂、前后提示词互相依赖和画面内容过空造成的返工。

#### 防复发规则

1. 正式视频提示词默认按单条独立请求处理，不写“沿用全片”“参考上文”替代实际内容。
2. 每条正式提示词都必须完整写出基础设定、氛围与画质、画面内容。
3. 同一个具体人物跨多个独立提示词出现且需要一致时，必须有图片资产；文本资产只能固定类型气质，不能固定同一张脸。
4. 没有图片资产时，不要让同一具体人物反复出现在多个独立提示词中。
5. 同一场景、同一未资产化人物、连续动作不超过 15 秒时，优先合并成一个分镜 / 一条视频提示词。
6. 合并镜头内部可以用确定起止段，例如 `第0秒-第2秒`；镜头总时长仍必须是确定值。
7. `【画面内容】` 必须详细到可执行，包含时间轴、景别、构图、运镜、主体动作、环境运动、人物表演、材质光影、声音和后期衔接。

### 5. 正式视频提示词不能混入场外说明

#### 表层问题

老胡在《请登仙界》真实测试中指出：

- 正式提示词里不应该出现给作者、助手或剪辑师看的内容，例如前置判断、后期备注、前一个画面是什么、下一个画面怎么承接。
- 视频生成平台只需要看到画面本身，不需要看到“接下一镜”“复制本条”“本条独立完整”这类说明。
- 镜头之间确实需要考虑衔接，但应通过画面内可见的转场实现，例如遮挡转场、运镜转场、明暗转场、高亮转场、动作转场、匹配转场等。
- 转场方式不能机械重复，不能每个镜头都黑一下或亮一下。

#### 真实目标

把“给作者看的创作判断”和“给视频模型看的正式提示词”彻底分开，让正式提示词只包含模型可以生成的片内画面、声音、动作、镜头和质感。

#### 根本目的

减少模型误读，降低生成失败和画面跑偏；同时让每个分镜在后期拼接时有自然衔接点，而不是靠场外说明补救。

#### 防复发规则

1. 正式视频提示词代码块只保留：
   - `【基础设定】`
   - `【氛围与画质】`
   - `【画面内容】`
2. 前置判断、资产判断、表情判断、生成方式、作者说明、剪辑说明、自检和回传字段只能放在提示词外。
3. 正式提示词里不写“前一个镜头”“下一个镜头”“接 E1-S1-C2”“后期备注”“复制本条”“本条是否独立完整”。
4. 需要衔接时，写成画面内可生成的转场行为：
   - 袖口、云雾、仙旗、巨门、飞檐遮挡镜头。
   - 金白强光铺满画面或云影压暗画面。
   - 镜头穿过裂隙、云层、门槛或法器。
   - 圆形裂隙、仙印、龙眼、浮灯等形状 / 光源匹配。
   - 拂袖横扫、仙旗掠过、巨门开启等大动作覆盖画面。
5. 不要所有镜头都使用同一种黑场或白场，转场必须服务镜头内容。

### 6. 资产体系必须区分提示词资产、图片子资产和组合资产

#### 表层问题

老胡指出：

- 资产不只是图片资产；基础设定、氛围与画质、妆造、环境规则等都可以是提示词资产，并能跨镜头复用。
- 图片资产也不能笼统写成人物 / 场景 / 道具。人物资产要区分素体、定装、服装 / 妆造和组合形象。
- 场景资产不应只是一张单视角漂亮图，而应是同一空间三宫格 / 四宫格 / 多角度。
- 物品资产应展示同一物品多角度和材质，背景尽量简单。
- 人物长期复用且会换装时，应记录类似 `A1 人物素体`、`A2 服装`、`A3 = A1 + A2 组合形象` 的资产关系。

#### 真实目标

让资产阶段能服务真实生成流程：既能通过提示词资产稳定风格和规则，又能通过图片资产固定具体形象，还能通过编号和组合关系支持后续多轮调用。

#### 根本目的

避免资产表只是列名词，导致后续图片、视频和分镜仍然不稳定。资产必须能被调用、组合、追踪和复盘。

#### 防复发规则

1. 资产判定必须区分提示词资产和图片资产。
2. 提示词资产可以跨镜头复用，但进入正式视频提示词时必须展开具体内容。
3. 图片资产必须标注子类型：人物素体、人物定装、服装 / 妆造、组合形象、场景多角度、物品多角度、第一帧。
4. 人物长期复用且会换装时，先做人物素体，再做服装 / 妆造，再登记组合形象资产。
5. 人物资产图推荐 16:9 横幅：左侧脸部特写 / 表情，右侧全身三视图或多角度，背景简洁灰 / 白。
6. 场景图片资产优先三宫格 / 四宫格 / 多角度，锁定同一空间结构和光源。
7. 物品图片资产优先多角度和材质细节，背景简洁。
8. 资产编号必须稳定，同一作品内不能一号多义。

## 四、结束前检查

- 这是不是单作品经验，还是跨作品通用经验？
- 如果是通用经验，是否已经进入本文件？
- 是否已经修改 `AGENTS.md`、相关 `laohu_` skill、模板或检查脚本？
- 是否更新 `输入输出索引.md`？
- 是否需要新增合约脚本检查，防止下次被删掉？
