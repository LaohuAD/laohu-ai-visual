# 老胡 AI 视觉能力地图

> 本文件是共享原则与路由地图，不承担专业执行规则。
> 任务的具体方法以对应 Skill 和被它明确调用的 Reference 为准。历史版本由 Git 保留，不在当前文件里维护第二套规则。

## 一、一条主线

### 先让人入戏，再让机器入场

AI 视觉不从提示词开始。观众在等什么、人物为什么行动、哪个选择会改变结果，先决定作品是否成立；资产、分镜、提示词和生成，只把已经成立的东西变成画面。

### 故事决定去处，镜头决定脚步，资产守住同一个世界

每一阶段只接收上游已经确认的事实，并向下游交付可继承的状态。后一阶段不能为了方便生成，暗中重写人物、因果和作品意图。

歌曲型作品由最终音频决定真实时间，由 MV 导演决定画面如何与声音同步、平行、对位、留白或跨段连接。歌词提供语义证据，但不天然等于逐句插画脚本；叙事、表演、概念与氛围都是候选引擎，要由歌曲本身的主胜负手裁决。

### 没有证据的漂亮，只是一次运气

一张图能看不等于能复用，一段视频会动不等于镜头成立。所有判断都要落到可见结果：人物有没有走样，动作有没有因果，镜头能不能相接，观众能不能读出原来的意图。

### 作品可以克制，标准不能平庸；能用只是底线，难忘才是答案

硬规格、连续性和可生成性只负责底线，不负责证明作品已经最好。每个专业阶段都要在通过底线后继续比较候选，找到本作品唯一主胜负手，并让材料、镜头、声音、表演、构图和技术共同把它推到当前证据与约束下的最高位置。极致不是所有维度同时最大，而是所有维度都为最重要的结果让路。

## 二、四层不是栏目，是能力编译器

    灵魂以箴言定向
    → 筋骨以章法成局
    → 血肉以技法生变
    → 表皮以法度成形

四层用来检查一项能力是否完整，不要机械写成下游文件的四个通用标题。

- 箴言给出价值、方向和取舍，承担河床，不代替方法。
- 章法说清整体、关系、顺序和交接，让多个部件往同一个结果用力。
- 技法负责选材、变化和效果。材料不论大小，只问能不能承重；技法不论绚丽，只问为什么此处非它不可。
- 法度管输入输出、字段、命名、字符、工具限制和可用性。硬边界越明确，创作空间越不容易被误伤。

每个 Skill 用自己的专业语言承载四层：编剧讲观众等待、人物选择和下一场压力；人物设计讲核心事实、选角、身体化与第一印象；服装讲世界衣橱、人物命题与穿着选择；布景讲空间命题、人物—空间关系与地点语法；资产讲失真代价、依赖关系和下游调用；镜头讲起点、变化和结束状态。名称服务对象，原理保持一致。

## 三、能力地图与唯一负责人

| 真实缺口 | 唯一负责人 | 负责至何时 | 不负责什么 |
|---|---|---|---|
| 不知道从哪一阶段开始 | laohu-ai-visual | 真实目的、当前状态、阶段入口和下游已确定 | 不代写各专业产物 |
| 日常灵感没有长期保存，或正式剧本缺少可调用的真实生活材料 | laohu-story-material | 原话完整、原子可检索、候选经过充分度与边界判断并能交给编剧 | 不写正式剧本，不把未批准网络候选写入作品或正式库 |
| 故事、人物、剧本或台词不成立 | laohu-script-writer | 观众等待、人物选择和下一场压力已形成 | 不写模型级视频提示词 |
| 歌曲、歌词、时间轴与创作背景尚未成为可制作的 MV 导演方案 | laohu-mv-director | 时间证据、导演命题、情绪运动、声画关系、表演策略、生产时间线和动态分镜任务已形成 | 不生成媒体，不替资产和视频 Skill 编译最终模型提示词，不强迫所有 MV 讲连续故事 |
| 人物好看但没有身体逻辑、同脸同体型、第一印象或跨媒介身份不成立 | laohu-character-design | 人物核心事实、候选竞争、脸身姿动、胜出母版和人物设计交接包已验证 | 不用面相替剧本证明人格，不制作B/M/G板 |
| 人物服装缺少原创判断、世界衣橱或群像差异 | laohu-costume-design | 人物命题、候选竞争、胜出与淘汰、服装设计交接包已验证 | 不用同袍换色和外部标志性外形代替设计 |
| 场景漂亮但通用、人物与空间关系不成立、布景只是物件清单或制作策略不清 | laohu-set-design | 空间命题、候选竞争、胜出场景母版、布景陈设和场景与布景设计交接包已验证 | 不制作S/A板，不用四机位完整冒充原创设计 |
| 人物、场景、道具或风格会走样 | laohu-visual-assets | 最低可行资产、依赖顺序、生成与下游调用已验证 | 不把漂亮终稿冒充资产，不重新发明已确认人物、服装或场景设计 |
| 剧本尚未成为可生成的时空过程 | laohu-video-prompt | 单元的起点、可见变化、结束状态与三段式基线成立，并在 VC 返回后完成复验 | 不越过剧本和资产缺口 |
| 视频提示词基线已经成立 | laohu-vibe-creating-prompt（外部 `vibe-creating-prompt` 的本地适配入口） | VC 已实际执行；可感知增益成立则采用改稿，无增益则零改动返回原稿 | 不替未成立的基础稿补漏洞，也不能被跳过 |
| 成片的点击入口不成立 | laohu-cover-design | 封面承诺可由正片兑现，缩略图第一落点清楚 | 不用封面重写正片价值 |
| 生成、剪辑、发布后不知哪里先错 | laohu-generation-review | 证据、第一个断点、最早负责人和最小返修组已确定 | 不把所有失败都归给模型 |
| 反馈、研究、反思或平台变化需要进入长期能力 | laohu-capability-evolution | 第一个能力断点、受影响层、唯一负责人、保真回归和保留结论已确定 | 不替业务 Skill 生产作品，不把一次反馈直接写成永久禁令 |

一个问题可以经过多个 Skill，但一个判断只有一个唯一负责人。下游发现上游缺口时，退回负责人修复，不在自己的文件里再造一条平行规则。

## 四、相邻单元的共同章法

### 前一镜留下什么，后一镜就从什么开始

剧本、资产、分镜、视频提示词和剪辑共用同一条状态链。交接至少包含：

    已确认事实
    当前起点状态
    本单元的可见变化
    真实结束状态
    下一单元接手的压力或相位
    使用的资产与证据
    未解决边界

后一单元如果为了表演完整而重演上一单元已经发生的动作，不是补充，而是时间倒退。

## 五、材料与技法的共同判断

### 材料不论大小，只问能不能承重

一把钥匙不因属于某个人就天然动人，一座城也不因宏大就天然空洞。选材检查四件事：

1. 它与人物、关系或价值有没有真实因果。
2. 它能不能被当前媒介看见、听见或感到。
3. 它既有个体来历，又能照见更多人的经验吗。
4. 它的生成、维护和连续性代价是否值得。

### 技法是力的方向，不是手法的清单

对比、留白、运镜、光色、节奏、声音桥和匹配转场都只是候选手段。使用前先说明它要改变观众的什么感受、强化什么关系、帮下游解决什么限制。无法回答时，不因为它专业或常见就加上去。

## 六、参考资料怎样进入任务

Reference 只在它能解决当前缺口时读取。主 Skill 必须写清触发条件，不能把一串文件名当成能力。

- 每次必须做的判断留在 Skill 主体。
- 只在特定题材、输入状态、模型或失败信号下需要的完整方法进入 Reference。
- 字符计数、路径、命名和结构完整性由脚本检查。
- 生成结果、作品反馈和发布数据是证据，不是先验规则。

导演级影视创作总控流程.md 只在复杂多部门作品出现跨专业取舍时，作为导演级综合校准读取；它不是新任务的默认入口，不替代十四个唯一负责人。

## 七、经验回到负责人，才算长成能力

### 一次反馈照见问题，多次验证才立成尺度

真实结果回来后，复盘先形成证据，能力进化再决定长期更新：

    保留原始证据
    → 找第一个可证明的断点
    → 定位最早负责人
    → 提出最小可证伪改动
    → 修正当前产物
    → 需要长期更新时交给 laohu-capability-evolution
    → 检索能力进化台账，合并或重新唤醒旧证据
    → 只重编真正受影响的层
    → 用当前、相邻、保真和失败场景验证
    → 只把稳定经验写回唯一负责人

失败记录保留当时证据，不直接对下一次任务下命令。新规则必须写清触发条件、底层原因、执行动作、适用边界和行为验证。只把用户原话改写成禁令，或把四层标题贴到旧内容上，都不算能力进化。经验没有留下旧行为、新行为和重新唤醒条件，也不能跨任务继续生长。

## 八、共同验收

- 当前解决的是最早能力缺口，还是最后看见的症状？
- 主任务和唯一负责人是否明确？
- 原来确认的事实、关系、状态和作品意图是否被保真？
- 材料为何承得起当前任务，技法为何在此处必要？
- 下游能否只凭交付产物继续，不必猜测上游意图？
- 有没有把公共规则、当前任务补丁和作品私有事实混在一起？
- 结果是否经过候选、反例、边界和真实证据的检查？

写完只是交卷，真实结果才给答案。
