# 案例拆解与入库规则

> 用途：把成功案例和失败案例变成可复用经验，而不是只保存链接或提示词。

## 一、案例类型

| 类型 | 入库位置 | 重点拆解 |
|---|---|---|
| 作品内成功案例 | `01_作品项目/<作品名>/09_归档复盘.md` | 这次为什么成功，是否只适合本作品 |
| 作品内失败案例 | `01_作品项目/<作品名>/09_归档复盘.md` | 这次为什么失败，下次如何避免 |
| 跨作品成功案例 | `02_共享资产库/04_案例经验库/成功案例/` | 已验证可复用的成功结构 |
| 跨作品失败案例 | `02_共享资产库/04_案例经验库/失败案例/` | 已验证可复用的失败规避规则 |
| 外部参考案例 | `00_输入原料/外部案例/` | 哪些方法值得吸收，哪些不能直接用 |
| 发布案例 | `01_作品项目/<作品名>/09_归档复盘.md` | 数据反馈、封面标题、观众反应、迭代方向 |

## 四、外部案例吸收原则

- 先登记来源，再拆结构。
- 不直接把外部案例当成本项目成功案例。
- 如果没有生成证据，只能标记为“参考案例”，不能标记为“已验证”。
- 外部案例的价值不在原提示词，而在结构：时间轴、镜头任务、声音、风格约束、失败风险。

## 五、案例反向更新规则

每个作品内案例拆完后，先判断能否跨作品复用。只有满足以下至少一条，才成为能力进化候选：

- 同一类问题可能在多个作品里重复出现。
- 这个提示词结构、镜头结构或失败规避规则能迁移到其他作品。
- 这个案例能更新模板、模型适配、视觉语言资产或工具流程。

候选先交给 `laohu-capability-evolution`，在能力进化台账创建、合并或重新唤醒记录。只有经过当前、相邻、保真和失败场景验证并得到 `KEEP`，才写回下面的长期资产：

- 是否更新图片提示词模板。
- 是否更新视频提示词模板。
- 是否更新镜头语言库。
- 是否更新人物表演库。
- 是否更新声音规范。
- 是否更新模型适配规则。
- 是否能回流到 `老胡文稿`，变成文章、口播、课程案例。

案例本身保留证据，不能直接承担“下次必须怎么做”的权威。一次成功默认只证明本次组合可用，一次失败默认只证明本次结果有问题；未经进化验证，不把它们升级成通用模板、负面词或永久禁令。
