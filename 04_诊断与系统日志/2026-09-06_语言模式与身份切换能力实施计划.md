# 语言模式与身份切换能力实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立一个由各专业角色按文本块调用的语言模式共享能力，让沟通、剧本动作、表演括号、人物台词、资产规格和各类模型提示词各用自己的表达合同，同时保护既有内容权与专业规则。

**Architecture:** 新建 `laohu-language-mode` 作为共享语言路由，不新增生产阶段，也不拥有剧情、资产或模型语法。它根据角色、阶段、文本块、发声者、接收者和任务判定唯一主模式，再把专业执行语言桥接回原 Skill；专门的场景 JSON 与架构测试验证模式切换、内容权保护和跨题材保真。

**Tech Stack:** Markdown Skill/Reference、YAML Agent 元数据、JSON 行为场景、Python `unittest`、现有 Shell 架构检查。

- [ ] **Step 1: 创建最小 Skill 入口**

`SKILL.md` 的核心工作流必须完整出现：

```text
领域负责人先确定内容事实与保护项
→ 判定角色、阶段、文本块、发声者、接收者和任务
→ 选定唯一主语言模式
→ 只读取该模式所需 Reference 与专业桥接
→ 领域负责人完成该文本块
→ 文本块改变时重新判定
→ 内容缺失或冲突时返回内容负责人
```

入口中明确：该 Skill 不拥有内容权、不新增生产阶段、不用统一文风覆盖整份文档、不因顺口改动锁定台词。

- [ ] **Step 2: 写模式判定 Reference**

实现设计规格中的运行时字段，并提供以下拆块规则：

```text
一个文本块只认一个主要接收者和一个主要任务。
若括号同时承担动作、心理、声音与剧情解释，先拆成 SCRIPT_ACTION、PERFORMANCE_CUE 和 SCRIPT_NOTE。
若模式无法确定，停止套用通用风格，补齐 receiver / purpose / block_type。
若内容事实不足，返回 domain_authority，不自行续写。
```

- [ ] **Step 3: 写沟通与制作说明 Reference**

从老胡音乐 V4 只迁移普通中文、说话位置、材料门槛、自然推进、事实身份与修改汇报；去掉歌词、曲式、音乐人设和音乐准入门。

- [ ] **Step 4: 写剧本文本块 Reference**

明确五类块：`SCRIPT_HEADER / SCRIPT_ACTION / PERFORMANCE_CUE / CHARACTER_DIALOGUE / SCRIPT_NOTE`。其中每句有声台词必须附可表演提示；提示至少交代情绪阶段、压制或释放、可听语气和关系态度，不能只写“声音放低”。

- [ ] **Step 5: 写模型提示词桥接 Reference**

资产、图片、视频与声音的模式只规定接收者和信息边界，使用明确路由：

```text
ASSET_SPEC / IMAGE_PROMPT → laohu-visual-assets
VIDEO_PROMPT → laohu-video-prompt
AUDIO_PROMPT → laohu-audio-design
```

视频三段式、图片注意力编译和声音生成合同不得复制到本 Skill。
