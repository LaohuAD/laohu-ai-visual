## 第二阶段：跨题材情境适配与分级人工定案

### 已确认目标

本阶段不把“高端华丽”写成所有作品、所有人物的默认服装答案，也不只修正当前仙侠案例。目标是让系统先判断人物在当前世界与剧情里**为什么应该穿到这个等级**，再完成与之匹配的原创设计：它既能设计仙侠核心弟子的精美功能法衣、都市豪门的高级定制，也能设计凡人百姓、逃亡者、卧底或故意扮猪吃虎者的有意识朴素。

主要人物的审美定位不再由 AI 一键替老胡拍板。AI 负责调查输入、诊断服装等级、提出有画面感且真正不同的候选并给出专业建议；老胡负责确认整体方向；AI 在确认后才把方向展开成完整服装正文、色卡、功能、工艺、首饰与资产交接包。

### 设计原则

#### 1. 先判断“应该穿什么”，再判断“怎样设计得好看”

每套服装先建立`服装情境判断合同`，至少读取并区分：

```text
世界服装现实：时代、技术 / 法术水平、材料经济、制作与维护制度、衣服是否兼任法宝 / 护甲 / 身份凭证。
人物位置：身份、阵营、财富来源、权力、修为 / 能力、职业、礼制权限和资源可得性。
人物选择：性格、自我形象、希望别人怎样看见自己、身体与行动方式、是否主动展示或隐藏身份。
当前场景：日常、工作、战斗、典礼、社交、旅行、闭关、逃亡、伪装、受伤或阶段转变。
叙事策略：顺从身份、夸大身份、压低身份、反抗制度、诱导误判、扮猪吃虎或临时应变。
观众结果：第一眼先读到什么；远中近景分别用什么证据证明身份、价值、功能和人物关系。
```

不得从“仙侠、豪门、穷人、战士”直接兑换成“飘逸白衣、名牌西装、补丁、重甲”。同一身份在不同场景和叙事策略下可以得到不同答案；不同身份也可能因为伪装、制度或人物选择暂时共享相似外观。

#### 2. 价值等级必须有可见证据，不靠形容词

系统根据情境判断服装的`资源与展示等级`，不把等级误写成固定装饰数量：

```text
生存 / 隐匿：资源有限或主动降低存在感，但合体、材料、修补、穿法和功能仍与人物处境一致。
体面 / 职业：满足制度、工作和社交身份，体现可靠性、秩序与可持续使用。
精英 / 定制：轮廓、合体、材料层级、工艺焦点、配饰体系和维护状态共同证明资源与审美判断。
权威 / 礼制：通过尺度、权限纹样、仪式结构、稀有材料或法器系统证明阶层、权力和公共身份。
伪装 / 反差：表面等级与真实身份有意错位，剧本必须提供动机、风险和可被后续识别的细小证据。
```

“昂贵、精致、高端、华丽”不能单独通过巅峰门。远景看轮廓与比例，中景看层次、合体和材料行为，近景看工艺、扣合、首饰、表面与功能细节；至少两个观看距离同时成立。仙侠功能法衣还要说明功能如何改变结构、材料、穿法或动作结果，不能只写一个法宝名称。

#### 3. 分级人工定案，而不是全自动或事事询问

```text
必须人工定案：主要人物、关键配角、首次建立的阵营 / 阶层衣橱、承担身份反转或人物弧线的重要换装、将进入F人物主视觉图的首次造型。
条件人工定案：两个候选承重价值接近、上游事实不足以唯一裁决、设计会改变人物核心定位、用户已有明确审美偏好但尚未锁定具体造型。
AI自动定案：已经确认世界衣橱下的普通配角、远景群像、同一服装的场次适配和不会改变身份判断的制作补全。
零设计改动：用户已经锁定足以还原的完整设计，并明确不得修改。
```

人工定案只停在会改变角色整体审美与叙事身份的高杠杆节点，不把领口宽度、扣子数量等普通专业细节逐项抛给老胡。系统必须先给推荐意见和理由，不能只问“你喜欢哪一种”。

#### 4. 候选先让人看见，再进入技术展开

必须人工定案的角色先交付三种真正不同的`方向提案卡`。每种先用短篇画面描述呈现人物穿上后如何进入场景、如何行动、材料怎样受光和运动、观众为何一眼读到这个人；随后用简明字段说明：

```text
身份与叙事押注 / 资源与展示等级 / 轮廓与身体关系 / 材料层级 / 工艺与功能焦点 / 配饰和首饰体系 / 色彩关系 / 远中近景昂贵或朴素证据 / 场景适配 / 风险。
```

三个候选至少改变两项承重关系，其中至少一项来自身份表达、叙事策略、轮廓、身体关系、材料系统或功能系统。只换颜色、花纹和饰品不是新方向。AI 标出推荐候选，但在老胡确认前状态保持`待服装方向确认`，不得生成最终服装正文、F、W或M。

#### 5. 确认后才编译完整设计与资产

确认结果进入`服装方向确认记录`：候选编号、保留原因、明确删去项、允许AI补全范围、需要重开候选的条件。随后服装 Skill 完成：母型—变体、全套层次、身体修饰、材料与工艺、功能、色卡、首饰、鞋履、背面与内里、动作响应和交接包。

`laohu-visual-assets`只消费已确认的服装设计结果：先与人物、妆造和美术方向共同编译F人物主视觉图；F人工选定后再反向拆解B / W / M。资产 Skill 不得把未确认候选自行合并，也不得用图片模型的随机结果替代服装方向确认。

### 状态流

```text
服装输入未齐
→ 服装情境已诊断
→ 方向候选已提案
→ 待服装方向确认
→ 服装方向已确认
→ 完整服装设计已锁定
→ F人物主视觉图待生成 / 待人工选定
→ B / W / M待拆解与验收
```

未经过人工定案的主要人物不能伪装成`服装方向已确认`。老胡要求快速草稿时可以生成标明`候选试验`的图片，但试验图不能自动升级为稳定服装设计或视频资产。
