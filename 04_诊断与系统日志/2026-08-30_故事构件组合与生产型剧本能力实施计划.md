# 故事构件组合与生产型剧本能力实施计划

> **执行要求：** 使用 `executing-plans` 在当前主分支按任务顺序实施。修改 Skill 与脚本时必须遵守 `test-driven-development`、`writing-skills`、`skill-creator` 和 `verification-before-completion`。每个任务先观察预期失败，再写最小实现并复验。

**目标：** 在不新增平行编剧 Skill、不把外部十二原型固化成菜单的前提下，为 `laohu-script-writer` 建立可增长的故事构件库、渐进检索、因果组合、期待契约、场景融合、生产型剧本格式和真实结果回流。

**架构：** 私有 `laohu-story-material` 继续保存 `source / atom / usage` 生活证据；`laohu-script-writer` 新增只读的去标识故事构件 JSONL 与检索脚本，把素材机制和故事构件通过人物意图、前置条件和状态变化连接。主 Skill 只保留入口、流程和完成门，详细拆解、组合、格式和失败分支进入按需 Reference。

**技术栈：** Markdown Skill / Reference、UTF-8 JSONL、Python 3 标准库、`unittest`、现有能力场景 JSON 与架构验证脚本。

- [ ] **Step 2：实现验证器最小功能**

实现：

```python
def load_records(path: Path) -> list[dict]: ...
def validate_records(records: list[dict]) -> None: ...
def stats(records: list[dict]) -> dict: ...
def search(records: list[dict], query: dict) -> list[dict]: ...
def get_records(records: list[dict], ids: list[str]) -> list[dict]: ...
```

验证器必须拒绝：

- 重复或不符合 `CMP-\d{3,}` 的 ID；
- 未知类别、状态或证据状态；
- 空的 `name / operation / character_intention`；
- 缺少 `before / after` 的状态变化；
- 缺少 `knows / believes / waits_for` 的观众变化；
- `original / source_id / source_url / private` 等私人素材字段；
- 列表中出现空字符串或非字符串；
- 不是 `component` 的记录类型。

- [ ] **Step 3：实现渐进披露**

CLI：

```text
story_component_library.py [--db PATH] validate
story_component_library.py [--db PATH] stats
story_component_library.py [--db PATH] search --input QUERY.json
story_component_library.py [--db PATH] get --id CMP-001 [--id CMP-002]
```

`search` 只返回：

```python
COMPACT_FIELDS = (
    "id", "name", "category", "dramatic_functions", "operation",
    "state_change", "compatible_tags", "conflict_tags", "evidence_status", "status",
)
```

不得返回 `visible_evidence / failure_modes / boundaries / source_refs / audience_shift` 全量详情。默认排除 `paused`，只有查询显式允许时才返回。

查询合同：

```json
{
  "must": {"category": ["信息"]},
  "prefer": {
    "dramatic_functions": ["反转", "回收"],
    "compatible_tags": ["双重解释"]
  },
  "exclude_ids": [],
  "include_paused": false,
  "limit": 12
}
```

`must` 做确定性过滤；`prefer` 只排序。评分权重固定为：戏剧职责 5、类别 4、兼容标签 3、前后状态文本 2、名称 1。相同分数按 ID 排序，保证重复调用稳定。

- [ ] **Step 2：写拆解合同**

Reference 必须明确：

```text
保留来源与事实边界
→ 去除题材外壳
→ 找人物目标和阻力
→ 找人物采用的方法及理由
→ 找即时结果和下一压力
→ 找观众判断变化
→ 找不可逆残留与回收对象
→ 拆到可以独立跨题材和跨关系迁移
```

同时写出停止条件：只能依赖原作独特角色、台词或组合才成立的内容留作案例，不升级为构件。

- [ ] **Step 3：写组合语法和候选竞争**

明确主链：

```text
前置条件 → 人物行动 → 状态变化 → 观众更新 → 下一压力
```

重要故事至少比较三个因果不同的候选。比较创作者命题、人物意图、观众等待、压力持续、阈值选择、首尾兑现、感官证据、制作负担与平均化风险。替换职业、地点和道具不算因果不同。

- [ ] **Step 4：写场景融合与失败边界**

场景融合使用：

```text
一个人物当下目标
+ 同一承重行动 / 物件 / 空间 / 声音
+ 一个主要状态结果
+ 若干会真实影响后续的从属变化
```

明确拒绝：同场出现多个无关设定、每个构件各占一段、没有人物理由的反转串、多个主结果争夺注意力。低烈度作品允许零构件堆叠，以等待、距离、误解、表演和物件状态推进。

- [ ] **Step 5：写构件检索合同和零采用门**

说明何时先 `stats`、何时 `search`、何时按 ID `get`；只按当前缺口读取。构件候选不适配时必须写“允许零采用并继续原创”，不得自动联网或强行使用高分候选。
