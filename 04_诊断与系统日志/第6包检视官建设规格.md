## 一、「提取」的准确含义

**提取＝拿走，原位消失。**

```text
整个文件被取出   → 源文件删除
整个目录被取出   → 源目录消失
只是某个段落被取 → 只删那一段，其余留在原位
```

取出的内容**整合后重新梳理表述**，不是原样堆到一起；同时把散落的**检查要点**归并成检视判据。
提取之后源位置不留空壳、不留跳转文件。

### 提取时的保真底线

**原文的信息量、有效信息量、信息密度都不能降低。增加可以，降低不行。**

```text
整合重排时，原文的每一条有效信息都要在新位置可查
合并同类项时，条件、例外、反例、例子、适用边界一并带走，不因「合并」压掉
表述可以重写，重写后承载的信息只多不少
完成一项提取后逐条核对：源里有的，新位置是否都有；缺一条就补回
```

判断方法：把源内容里的每一条独立信息（一项条件、一个例子、一条反例、一处边界、一个数字、
一句出处）列出来，逐条在新位置找。找不到就是降低，必须补回。
「读起来更顺」不能作为删掉一条信息的理由。

## 三、第 6 包结构

```text
.agents/skills/laohu-inspection/                 第六个顶层入口
├── SKILL.md                                     检视总入口：检视什么、怎么判、怎么路由
├── references/
│   ├── 检视判据.md                              格式/内容/信息量与密度的判据
│   └── 责任划分与路由.md                        输出问题 vs 规则问题，归哪个顶层负责人
└── skills/
    ├── laohu-script-inspection/                 剧本检视
    │   └── SKILL.md                             检视规则直接写在本体
    ├── laohu-image-prompt-inspection/           图片提示词检视
    │   └── SKILL.md                             检视规则直接写在本体
    ├── laohu-video-prompt-inspection/           视频提示词检视
    │   └── SKILL.md                             检视规则直接写在本体
    ├── laohu-image-review/                      生成后：图片
    ├── laohu-video-review/                      生成后：视频
    ├── laohu-audio-review/                      生成后：音频
    ├── laohu-edit-review/                       生成后：成片
    └── laohu-release-review/                    生成后：发布
```

**生成前与生成后都在这一个入口下**，但触发时机与产出不同，各用各的判据：

```text
生成前  剧本 / 图片提示词 / 视频提示词  → 合规检视 → 不达标打回重做
生成后  图片 / 视频 / 音频 / 成片 / 发布数据 → 复盘归因 → 能力更新
```

检视规则写在 SKILL.md 本体；需要展开的判据、正反例、案例建 reference。

## 四、检视官必须给出的路由结论

检视官不只找问题，还要给出**这问题该谁改**：

```text
每个问题附三项：
  ① 未满足什么        具体条款、在哪个文件里写着
  ② 属于哪一类        输出问题（产物本身没写对）／规则问题（规则没覆盖或表述不清）
  ③ 归哪个顶层负责人   输出问题 → 对应生产包的专业；规则问题 → 该规则的唯一负责人
```

三种路由结果：

```text
规则没覆盖这条                       → 规则问题 → 归该规则负责人 → 补规则
规则覆盖了、检视官查出来了、产物照旧错 → 输出问题 → 归生产端专业 → 改产物或补该专业表述
产物错、检视官没查出来               → 检视问题 → 归检视官 → 补检视判据
```

## 五、责任链

```text
结果不达标
  ↓
先查检视官：这条它本该查出来吗？
    本该查出来却没查出来 → 完善检视官的判据
    查出来了但产物还是错 → 生产端的问题
         ↓
      优化对应专项能力的表述或规则
```
