# 有效信息合同能力加厚设计

日期：2026-09-06

## 一、问题不是字多，而是作用已经停止

当前 `laohu-language-mode` 已经能够判断一段文字属于用户沟通、剧本动作、人物台词、资产规格还是模型提示词，却还没有继续判断：这段文字在当前位置为什么值得存在。

因此一段文字可以同时满足“身份正确、事实正确、人物口气大致正确”，却仍然啰嗦。当前 Luna 剧本中的典型表现是：人物已经说清光型名称、可见特征和核心效果，后半句仍继续列举用途；知识没有错，但人物此刻的攻防、动作和观众期待没有继续变化。问题不等于机械字数过长，而是新增分句的边际作用已经归零。

这类缺口会同构地出现在其他模式：动作正文重复方头或解释心理；表演括号重复动作；资产规格堆放不能排除错误结果的形容词；图片提示词混入时间过程；视频提示词用同义词重复同一种视觉要求；声音提示词重复情绪，却没有改变重音、气口、距离或声场。

## 二、方案比较

### 方案 A：在语言模式 Skill 内建立共享有效信息合同

所有正式文本块先由原专业负责人保证内容成立，再由语言模式按当前接收者和任务判断“什么变化才算有效”，逐分句执行 `KEEP / MERGE / MOVE / DELETE / RETURN`。十一种语言模式共享判断骨架，但各自拥有不同的有效性定义。

优点是只增加一个共享判断源，不新增生产状态，不改变专业主责，也能处理跨载体迁移。风险是如果写成机械删字器，会伤害节奏、留白、必要重复和模型控制完整性，因此必须设置“必要信息保护门”和保真场景。

### 方案 B：由编剧、资产、视频和声音 Skill 各写一套有效信息规则

优点是贴近专业，缺点是同一种边际作用判断会重复出现，久而久之形成多套互相矛盾的“简洁”标准；用户沟通、剧本块与模型文本之间仍没有统一迁移语言。

### 方案 C：新建独立的有效信息审稿 Skill

优点是表面职责清楚，缺点是它会变成所有产物之后的新生产站，也容易越权改内容。每次交付多一次审稿并不能保证上游写作时真正使用该能力。

### 结论

采用方案 A。`laohu-language-mode` 本来就独占“文本块写给谁、用什么形式交付”的判断，有效信息是这个判断向下的一层深度，不构成新角色。

## 三、原则与边界

保留现有箴言，不新增同义箴言：

> 话有对象，文有身份。身份一换，写法就得换。

本轮不改变灵魂层方向，真正缺的是筋骨、血肉和表皮：

- 筋骨缺少从模式识别到有效性裁决的必经门。
- 血肉缺少边际作用判断、跨载体分配和必要重复辨别。
- 表皮缺少统一裁决动作、行为场景和完成门字段。

语言模式仍然不拥有内容权。它可以判断一条信息应留在台词、字幕、动作、说明还是模型正文，却不能自行发明缺失知识、剧情、资产或模型事实。压缩可能损害内容时必须 `RETURN` 原负责人。

## 四、有效信息的共同模型

有效不是信息固有的属性，而是信息在特定接收者、特定位置和特定任务中的作用关系：

```text
当前接收者状态
→ 当前文本块要造成的目标变化
→ 该分句实际增加的作用
→ 删除或迁移后是否损害承重结果
→ KEEP / MERGE / MOVE / DELETE / RETURN
```

每个分句至少回答：

```text
receiver_before：接收者在看到这句话前已经知道、感到或能够执行什么。
target_delta：本块原本必须增加什么理解、关系、动作、情绪、决策或执行控制。
contribution：当前分句新增了什么；不能只写“补充信息”。
evidence_of_change：怎样观察到它确实改变了接收者或下游结果。
removal_cost：删去后哪个承重结果会受损。
best_carrier：台词、动作、字幕、说明、资产规格、图片、视频或声音正文中，谁最适合承担。
decision：KEEP / MERGE / MOVE / DELETE / RETURN。
```

“没有新事实”不等于无效。重复台词如果改变攻防位置、压力、关系或动作许可，仍然有效；停顿、结巴、沉默和回声如果改变表演与观众期待，也可以保留。反过来，信息很多但没有改变当前位置的任何结果，仍然无效。

## 五、双门：先防欠缺，再防堆积

有效性检查不能等同于删短，必须依次通过两道门。

### 必要信息保护门

先确认当前专业结果已经包含不可缺的因果、身份、空间、表演、执行和接口信息。若下游仍需猜测，先补专业内容或返回原负责人，不能以“简洁”为理由删掉承重信息。

### 边际作用门

在必要信息已经成立后，逐分句检查新增作用。若一个分句只重复同一事实、同一关系动作、同一视觉约束或同一情绪结论，则合并、迁移或删除；若它在新位置产生了新的戏剧功能、节奏效果、模型消歧或连续性保护，则保留。

两道门共同防止两个相反错误：写得短却信息不足，写得全却没有有效作用。

## 六、十一种模式分别怎样定义有效

| 模式 | 有效变化 | 常见无效表现 |
|---|---|---|
| `USER_COMMUNICATION` | 改变老胡对因果、取舍、风险、方案或下一步的理解与决定 | 同义解释、抽象术语堆叠、只报结论不交判断依据 |
| `PRODUCTION_NOTE` | 改变责任、状态、保护项、执行动作、完成条件或返回位置 | 工作过程倾倒、形容“已优化”、重复上游全文 |
| `SCRIPT_HEADER` | 改变镜头定位、观看侧、构图、景别、运镜或时长判断 | 提前讲完整动作、人物心理和主题目的 |
| `SCRIPT_ACTION` | 改变可见可听状态、因果、空间、关系、动作或镜尾 | 重复方头、解释不可见心理、同一动作换词复述 |
| `PERFORMANCE_CUE` | 改变该句实际演法：情绪阶段、收放、气口、重音、语速、关系动作 | 重复台词字面、重复动作正文、只写泛化情绪词 |
| `CHARACTER_DIALOGUE` | 人物用话改变对方、关系、行动、压力、观众期待或必要理解 | 人物替作者总结、知识清单、意思落下后继续解释 |
| `SCRIPT_NOTE` | 改变连续性、权限、资产状态、待核实事实或下游边界 | 解释观众本应从画面看懂的情绪和主题 |
| `ASSET_SPEC` | 排除错误生成、锁定稳定身份、依赖、结构或变体边界 | 不可区分的美学形容词、临场剧情污染母资产 |
| `IMAGE_PROMPT` | 改变单一静态时刻的像素、注意力、构图、姿态、光色或材质关系 | 完整时间链、创作者目的、同义视觉形容词堆积 |
| `VIDEO_PROMPT` | 改变起点、触发、时序、运动、表演、摄影机、声音、结果或接续 | 静态形容词反复、作者解释、不会改变任何帧的术语 |
| `AUDIO_PROMPT` | 改变实际发音、重音、停顿、呼吸、音色、距离、声场或时间相位 | 视觉细节堆积、情绪近义词重复、为自然擅改锁定台词 |

## 七、台词的专项有效性合同

台词不是知识容器，而是人物对另一个人实施的语言行动。每一轮台词至少建立：

```text
开口资格：眼前什么事实逼他现在说。
语言动作：他想让对方停止、相信、靠近、退让、回答、放过、误判还是行动。
新增作用：这一句相对前一句改变了哪一项关系、压力、行动或必要理解。
话后结果：对方怎样回应，或下一动作为什么因此发生。
呼吸容量：按当前奔跑、受伤、哭泣、克制或平静状态，他说得完多少。
尾部检查：最有力的意思落下以后，是否仍在解释。
```

知识型台词还要建立载体分配：名称、核心识别和当前冲突所需信息优先进入人物原话；完整用途、例外和补充可以交给受光画面、字幕、对手复述、动作结果或安全停顿。迁移不等于删知识，必须证明目标观众仍然能够学会。

## 八、跨载体调度

当一条信息有价值但当前位置无效时，优先 `MOVE`，不直接删除：

```text
人物说不完，但观众必须知道 → 字幕、另一人物复述或安全停顿。
动作已经证明，括号仍需表演索引 → 动作留正文，括号只留会改变声音的部分。
资产稳定特征与临场状态混写 → 稳定项回资产，临场项进镜头或提示词。
图片提示词出现时间过程 → 选决定性静态时刻，完整过程交视频。
视频正文出现制作理由 → 理由留导演卡，可见结果进模型正文。
声音正文出现视觉姿态 → 只有改变呼吸、力度、距离或声场时才转译。
```

## 九、运行接入

1. 在 `laohu-language-mode/SKILL.md` 的运行链中，把“选定模式”之后增加必要信息保护门与边际作用门。
2. 新增一份按需读取的 `05_有效信息与冗余裁决.md`，作为跨模式唯一详细规则。
3. `03_剧本文本块语言.md`只增加台词与五类剧本块的薄接口，不重复整套算法。
4. `04_资产图片视频与声音提示词桥接.md`只增加各模式有效性返回点。
5. 编剧、资产、视频和声音 Skill 只接入一句调用与返回规则；专业判断继续留在原负责人。
6. `laohu-language-mode` 完成门新增：每个保留分句能指出新增作用；每个迁移分句有新载体；必要信息未因压缩消失。

## 十、验证设计

### 当前场景

审计 Luna 灯光教学剧本：保留“我说正侧光”这类语义重复但戏剧功能改变的台词；把逃跑时知识清单迁移给字幕或拆到其他节拍；不改已经锁定的“正——侧着踹”“你说谁脸黑”“特效付费”。

### 相邻场景

- 温暖爱情场景中的重复问句，如果每次改变靠近、退让或确认关系，应保留。
- 用户方案说明可以比台词长，只要每段改变理解或取舍，不按台词长度裁剪。
- 资产、图片、视频与声音使用同一事实时，分别产生可区分的有效控制。

### 保真场景

- 复杂动作不能以简洁为由删掉发力、路径、接触与结果。
- 高风险视频提示词不能删除避免模型补猜的空间和连续性锚点。
- 沉默、停顿、重复和留白只要改变关系、节奏或期待，仍然有效。

### 失败场景

- 短台词没有语言动作，仍应判无效。
- 长台词每一部分都改变关系或必要理解时，不得因字数强删。
- 缺少专业事实时必须 `RETURN`，不能通过改写制造“高密度”假象。

结构验证只证明模式、裁决动作、路由和测试存在；是否真正更像人、是否更好笑、模型是否更稳定，继续标记 `OBSERVE`，等待独立朗读、异题材作品和真实生成结果。

## 十一、范围与非目标

- 不新增 Skill、生产状态、审稿站或总监角色。
- 不设置台词字数、句长、形容词数量和重复次数的全局硬阈值。
- 不把所有信息都压成高密度金句；呼吸、停顿、生活口语和留白可以承重。
- 不把 Luna 教学喜剧的节奏升级为爱情、治愈、惊悚和其他题材的默认模板。
- 不声称结构测试能够证明台词质量、观众笑点或模型生成质量。
