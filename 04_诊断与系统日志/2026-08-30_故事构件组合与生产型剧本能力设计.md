# 故事构件组合与生产型剧本能力设计

## 一、设计结论

本次不复制 `SoloEnt-AI/5min-drama-contest` 的十二种结构原型，不把它们重新命名为本项目的十二种原型，也不新建第二个编剧 Skill。

外部项目真正值得吸收的是一种研究方法：从大量具体故事中移除人物、职业、年代、地点和道具外壳，识别行动在叙事中承担的功能，再把功能拆成能够跨题材迁移的构件。外部十二种原型只作为反向拆解样本和回归样本，用于验证本项目能否：

1. 把成型原型继续拆成更小的状态变化构件；
2. 用相同构件重新组合出原有结构；
3. 组合出外部样本没有列出的新故事；
4. 在低烈度、非反转型和非五分钟作品中仍能正确停止套用。

本次能力建设仍由 `laohu-script-writer` 承接，形成一条完整创作链：

```text
现实素材与创作命题
→ 素材原子提供人性、关系与生活证据
→ 故事构件提供状态变化方式
→ 组合语法建立人物意图与事件因果
→ 场景融合把多个职责压进同一承重行动
→ 期待契约管理观众的预测、兑现与翻义
→ 正式剧本记录可见可听事实
→ 生产证据账本向人物、服装、场景、资产和视频负责人交接
→ 真实结果回流，决定构件或组合继续观察、保留还是撤回
```

## 二、真正要解决的问题

当前 `laohu-script-writer` 已经具备人物目标、错误信念、选择代价、观众等待、场次压力、动作与物件因果、素材检索、相邻状态和下游分权。缺口不在于再增加三幕式、英雄之旅或十二种原型，而在于这些能力之间缺少可重复的中间编译层：

- 素材原子能够提供真实细节，但缺少把多个素材组织成新故事的组合语法；
- “观众正在等什么”已有，但缺少从可见证据到暂时判断、可预见压力、未揭变量和后续兑现的期待契约；
- 场次压力已有，但缺少把触发、人物策略、状态变化、观众更新和下一压力拆成可检索构件的方法；
- 结构理论已有，但主要用来诊断，尚不能快速产生因果真正不同的候选组合；
- 短剧格式已有，但正式剧本的声音、屏幕文字、必要特效、道具状态和生产连续性没有形成稳定交接；
- Reference 中已有的正确知识没有全部进入主 Skill 的调用门与完成门，存在“磁盘有规则、运行时不生效”的风险。

## 三、证据与边界

### 3.1 可吸收的证据

- 外部项目证明了把多个成型故事压缩成推进机制，可以降低结构选择成本；其十二种原型提供反向拆解样本，但不是本项目的固定答案。
- 用户提供的口述稿提出“钩子是未尽之事”：观众看见冲突苗头，能够预测压力，却尚未获得完整结果。这可转译为期待契约，而不能转译为故意藏信息。
- 普罗普的故事形态研究说明，可以从角色和题材外壳转向行动功能；它的研究对象和功能顺序有明确题材边界，本项目只吸收功能拆解方法。
- Rumelhart 的故事语法说明，故事意义来自高于相邻句子的结构整体；本项目据此要求构件通过因果和状态变化连接，不能并排堆叠。
- Riedl 与 Young 的叙事规划研究把因果推进与人物意图视为可理解故事的关键条件；本项目据此要求每个构件同时记录前置条件、人物理由和结果状态。
- BBC、Academy Nicholl 与 Final Draft 的格式资料支持母场景剧本以场景头、可见可听行动、角色和对白为主；镜头焦段、景别和机位不应成为普通正式剧本的默认字段。

### 3.2 不升级为通用规则的内容

- 固定五分钟、前三十秒、3/10/30 秒、固定四幕和固定假高潮；
- 固定十二种结构、单一主原型或最多借用一个局部技巧；
- AI 真人短剧优先、固定帧数、固定对白画面比例和固定字符量；
- “观众理解能力低”的表述；本项目改为控制注意力负担，不低估观众；
- “高潮不停”等同于持续最大声量；本项目要求状态持续变化、强度形成波形；
- 在正式文学剧本里提前写满景别、焦段、机位和模型提示词。

### 3.3 版权与来源边界

外部仓库当前未发现许可证文件。本项目只记录来源并独立重写方法，不复制其大段原文、完整模板、专有示例和独特情节组合。外部十二种原型不作为可照搬作品资产。

## 四、双层原子模型

### 4.1 素材原子

现有 `laohu-story-material` 继续独占 `source / atom / usage`，保存老胡选择的原话、生活证据、人性机制和真实使用结果。它回答：

> 故事里有哪些真实、有趣、有情感质感的材料？

素材原子继续保留 `human_truth / mechanisms / dramatic_functions / memory_carriers / visible_evidence / extensions / boundaries`，不改变现有私有数据库三种记录的单真源合同。

### 4.2 故事构件

新增的是由 `laohu-script-writer` 负责的抽象故事构件。它回答：

> 一项材料怎样改变人物、关系、信息、道具、空间、选择或观众判断？

故事构件不保存私人原话，不复制具体作品，不替代素材库。它只保存已经去除人物名、作品名、职业、地点和独特表达的可迁移机制。

构件类别开放扩展，不预设总数：

| 类别 | 主要职责 |
|---|---|
| 人性与关系 | 说明人物为什么会坚持、回避、控制、讨好、隐瞒、保护或伤害 |
| 欲望与目标 | 说明人物当下试图改变谁或什么 |
| 错误方法 | 说明人物惯用策略为何短期有效、长期制造反噬 |
| 触发 | 打破原有生活或关系平衡 |
| 约束 | 说明人物为什么不能离开、等待、坦白或换一种方法 |
| 加压 | 减少选项、增加代价、转移控制、公开秘密或让行为不可逆 |
| 信息 | 改变人物和观众分别知道、相信与误解什么 |
| 代价与残留 | 说明什么不会随场景结束、循环重置或表面胜利自动恢复 |
| 选择 | 把两个都重要或都痛苦的结果变成不能同时保住的阈值选择 |
| 回收 | 让前文动作、物件、台词、声音或空间获得第二层意义 |
| 感官载体 | 把抽象关系翻译成可见、可听和可表演证据 |
| 场景条件 | 让公开空间、封闭空间、仪式、倒计时或群体围观改变行动 |
| 传播 | 形成可记忆、可复述、可讨论或可模仿的具体关系与结果 |

类别只用于检索，不是新的固定原型目录。新构件必须证明独立迁移价值，不能仅因名称新鲜就进入长期资产。

## 五、故事构件记录合同

每个构件是一个最小状态变化单元，而不是“倒计时、身份反转、误会”一类名词标签。记录至少包含：

```text
构件 ID 与名称
类别与戏剧职责
触发前条件
人物目标与行动理由
变化操作
输出状态
观众知道 / 相信 / 等待的变化
可见可听证据
适合体量与位置
兼容标签与冲突标签
常见失败和适用边界
来源类别与证据状态
能力状态：seed / observed / used / validated / paused
```

其中：

- `seed`：来自理论、外部样本或单次观察，能解释机制但没有本项目使用证据；
- `observed`：在多个不同来源中观察到相同状态变化；
- `used`：已经进入具体剧本或场景，但还没有真实生成、剪辑或观众结果；
- `validated`：已经跨题材使用，并有真实生成、剪辑或观众结果支持其预期作用；
- `paused`：重复证据表明该构件定义、边界或检索方式会稳定误导，暂停调用。

证据状态不与审美价值合成总分。外部知名作品、理论名气或作者声称不能替代本项目真实结果。

## 六、构件拆解方法

任何外部 Skill、优秀剧本、短视频段子、生活观察或项目成片，都使用同一拆解流程：

```text
保留来源与事实边界
→ 去掉人物、职业、年代、地点和独特道具外壳
→ 找到人物当下要改变的对象
→ 找到阻止他的力量
→ 找到他采用的方法及其人物理由
→ 找到即时结果
→ 找到结果制造的下一压力
→ 找到观众判断发生变化的位置
→ 找到不会自动恢复的代价或残留
→ 找到结尾重新解释或最终兑现的对象
→ 拆到每个单元都能独立迁移
```

拆解后执行两种测试：

1. 跨题材：替换时代、职业、地点、题材和道具后，机制是否仍成立；
2. 跨关系：替换爱情、亲情、师徒、上下级、陌生人或人与系统后，机制是否仍成立。

只能在原作品独特组合中成立的内容，保留为来源案例，不升级为通用构件。只有抽象结论、没有可见证据或人物理由的内容保持 `seed`，不得伪装成成熟规律。

## 七、组合语法

### 7.1 先定承重中心

组合前先确定：

```text
观众最终要经历什么
人物最不能承认的矛盾
人物眼前最想得到什么
人物最害怕失去什么
最后哪两个重要结果不能同时保住
作品体量、媒介和生产边界
```

构件服务承重中心，不用构件数量证明丰富。

### 7.2 组合不是随机相加

候选组合可以从以下职责中选择，不要求全部出现：

```text
一条人性或关系素材
+ 一个当下欲望
+ 一种人物错误方法
+ 一个外部约束
+ 一种加压方式
+ 一种信息变化
+ 一个不可逆代价
+ 一次阈值选择
+ 一个可以首尾回收的感官载体
```

构件必须通过因果边连接：

```text
A 使人物采取 B
B 产生 C
C 减少退路或提高代价
人物因此继续、放弃或更换 D
D 造成不可逆的 E
E 迫使人物在 F 与 G 之间选择
```

并排出现多个概念、反转或设定，但彼此不改变下一状态，判为堆叠失败。

### 7.3 候选竞争

重要故事先产生至少三个因果真正不同的候选，不以替换职业和道具冒充差异。比较：

- 创作者命题和观众体验是否一致；
- 人物行动是否具有可信意图；
- 观众问题是否清楚且值得等待；
- 压力是否能持续改变可选道路；
- 高潮是否由人物选择长出；
- 结尾能否兑现或重新解释开头；
- 是否有可见、可听、可记忆的载体；
- 是否适配当前体量、资产和生成成本；
- 是否只是旧故事换了高概念名词。

胜出候选进入完整因果推演，其他候选记录淘汰理由，不把全部候选塞进同一剧本。

## 八、场景融合

构件组合完成后，不让每个构件各占一场。优先寻找同一个动作、物件、空间或声音能否同时改变关系、信息、权力、道具和下一压力。

场景融合的条件：

1. 人物仍在执行同一个当下目标；
2. 多项职责能落在同一承重行动或载体上；
3. 融合后观众仍能读出唯一主要变化；
4. 每项从属变化都对后续选择或状态有真实影响。

同一地点出现多个无关设定不叫融合。若多个构件争夺主结果、要求不同情绪准备或让观众无法判断发生了什么，应拆场或淘汰从属构件。

每场继续执行现有 `进入 → 施压 → 选择 → 结果 → 牵引`，并补充：

```text
人物当下目标
承重行动或载体
输入状态
触发与反应
输出状态
观众理解更新
留下的不可逆残留
```

## 九、期待契约与首尾回收

钩子不是少给信息，而是让观众凭足够证据开始预测一个尚未完成的结果。关键节拍记录：

```text
观众看见的证据
观众据此暂时相信的解释
如果状态不改变，观众能预见的后果
仍未揭开的决定性变量
人物正在采取的行动
本节拍必须部分兑现的内容
后续是完成、扩大、推翻还是重新解释
```

开场先选择一个主要注意入口：人物、规则概念或眼前危机。其他信息从属，不在开头同时争夺注意力。

建立承诺—兑现账本：开场动作、物件、台词、声音或空间提出什么问题；中段怎样改变其意义；结尾是否完成、拒绝、反转或重新解释。不是每部作品都必须机械首尾闭环，但凡使用反转、伏笔或强钩子，就必须能够指出前文证据和兑现路径。

“冲突不断”不解释为持续最大声量，而解释为：人物每次行动都有结果，结果改变人物的选择空间或观众判断，并成为下一次行动的原因。允许呼吸、等待和低烈度场景，只要状态仍在变化。

## 十、渐进检索和数据流

### 10.1 两库接力

```text
编剧提交素材查询合同
→ laohu-story-material 渐进检索私有素材原子
→ 返回人性机制、可见证据、边界和用途
→ 编剧判断当前缺少哪种状态变化
→ 渐进检索故事构件库
→ 读取少量入围构件详情
→ 形成多个组合候选
→ 选择并写入剧本
```

素材库不决定结构，构件库不冒充生活证据，编剧不修改两个库的历史事实。

### 10.2 构件库渐进加载

故事构件库采用单个 JSONL 和确定性脚本：

1. `stats`：只读取规模、类别、状态和高频标签；
2. `search`：按当前缺口返回压缩索引，不返回全部说明；
3. `get`：按 ID 读取入围构件详情；
4. 编剧形成组合交接，只保留当前故事使用的构件、作用位置和边界。

优先按戏剧职责、输入状态、输出状态和观众变化检索，题材、年代、职业和地点只做次级适配条件。构件库为空或没有合适候选时，编剧继续原创，不自动网络搜索、不为凑数强行采用。

### 10.3 不修改素材库三记录合同

故事构件不增加到私有素材 JSONL，不把现有 `source / atom / usage` 改成四种记录。两库分别维护生活证据和抽象创作语法，避免一个负责人同时拥有原话、理论规则和正式剧本。

## 十一、正式剧本与生产交接

### 11.1 双层交付

正式交付分为剧本正文和生产证据账本。

剧本正文保持可读、可演：

```text
第1集 1-1
内 / 外  具体地点  日 / 夜 / 晨 / 连续
人物：……
开场状态：人物位置、正在进行的行动和上一场余势

△ 可见或可听的行动。
角色名（必要的表演状态）：台词。
角色名（OS）：内心声。
角色名 VO：画外声。
【声音：声源、发生方式及其对行动的影响】
【屏幕文字：观众实际看见的内容】
【特效：剧情必须发生的可见结果，不写实现方法】

【场次结果】
人物 / 关系 / 信息 / 道具 / 空间 / 身体发生的变化：
留下的未解决状态：
```

普通动作正文不强制编号成镜头，不写焦段、景别和机位；分镜与视频提示词继续由下游负责。

生产证据账本只记录影响下游的承重事实：

```text
证据编号
首次出现与使用位置
承重对象：人物 / 服装 / 场景 / 道具 / 声音 / 特效 / 屏幕文字
叙事职责
出现前状态
触发动作
出现后状态
后续必须保持
允许下游发挥
连续性风险
下游负责人
```

### 11.2 声音职责

- 同期声：现场真实发生并参与行动因果；
- 画外声：声源暂不在画面，但会改变人物行动或观众信息；
- 主观声：人物认知、记忆或身体状态的一部分；
- 音乐：剧情内有声源时写声源和影响；非剧情内音乐只写结构职责，不替剪辑锁死曲目；
- “悲伤 BGM、紧张音效”没有声源、触发或作用时，不算生产证据。

## 十二、运行时输出

根据任务体量按需交付，不机械展示全部内部过程。完整故事开发可使用：

```text
【创作命题与观众结果】
【素材调用回执】
【当前故事缺口】
【入围故事构件】
【组合候选与淘汰理由】
【胜出因果链】
【期待与兑现账本】
【人物与场次链】
【正式剧本】
【生产证据账本】
【相邻单元与下游交接】
```

快速单场、台词修改和格式整理只读取需要的部分，不为显示系统完整而倾倒所有候选、构件和账本。

## 十三、能力进化

本系统不通过不断命名新原型证明成长。构件和组合按证据演进：

```text
外部理论或单次观察 → seed
多个不同来源重复出现 → observed
跨题材写入剧本并保住人物因果 → used
真实生成、剪辑或观众结果支持 → validated
重复误导或边界失效 → paused
```

一个成功故事不会自动生成永久原型。只有多个构件在不同人物、题材和体量下保持相同因果作用，才允许总结为可复用组合；组合仍记录适用条件、反转条件和失败表现，不成为必选菜单。

每次真实结果由 `laohu-generation-review` 先定位第一个断点：素材选择、构件选择、组合因果、场景融合、正式剧本、资产还是视频执行。只有证据可能改变长期能力时，才由 `laohu-capability-evolution` 更新构件、Reference 或规则。

## 十五、行为验证

### 当前场景

1. 把外部十二种成型原型拆成更小构件，不把十二个名称写入固定菜单；
2. 用拆出的构件生成至少一个外部样本未列出的合理组合；
3. 把用户口述稿的“未尽之事”落实成可见证据、暂时判断、可预见压力、未知变量和后续兑现；
4. 正式剧本能够交接声音、屏幕文字、必要特效、道具和状态变化。

### 相邻场景

1. 同一生活素材生成至少三个因果真正不同的故事候选；
2. 同一构件跨家庭、职场和高概念题材后仍保留状态变化功能；
3. 一个承重场景同时完成关系、信息、物件和下一压力，但只有一个主要结果；
4. 系列短剧能够区分季级持续机制与单集局部构件。

### 保真场景

1. 人物选择、代价、场次压力和素材必查零采用继续成立；
2. 文艺、观察和低烈度作品不被强迫连续反转；
3. 正式剧本不越权写满镜头焦段、景别和机位；
4. 未经确认的外部素材候选仍不得进入剧本和长期素材库。

### 失败场景

1. 随机抽取多个构件但没有因果边时必须拒绝；
2. 构件只有抽象名称、没有人物理由与状态变化时不得升级；
3. 构件库为空或候选不适配时允许原创和零采用；
4. 多个构件让场景主结果不清时拆场或淘汰，而不是继续堆叠；
5. 只有格式齐全、没有观众期待与人物选择时不能通过巅峰门。

## 十六、完成标准

本次能力优化只有同时满足以下条件才可判定 `KEEP`：

- 外部十二原型只作为拆解与回归样本，没有成为固定答案；
- 故事构件拥有可验证的数据合同和渐进加载工具；
- 素材原子、故事构件和正式剧本职责没有混写；
- 编剧能够产生、比较并淘汰因果不同的组合；
- 期待契约、首尾回收和场景融合进入实际完成门；
- 正式剧本与生产证据账本能被下游直接继承；
- 当前、相邻、保真和失败场景通过；
- 机械测试只证明格式和数据不变量，不冒充审美质量；
- 本地修改不混入工作区既有无关改动，不执行远程推送或发布。

如果只有文件、字段和脚本增加，却不能让同一素材产生更可信、更有区分力的故事候选，结论只能是 `OBSERVE`，不能宣布能力已经完成。
