# 目标目录结构（待确认）

> 本文给出**建议的最终目录排布**与每一层的作用说明。它是要改成的样子，不是现状；确认后才执行。现有文件不删内容，只做合并与归位。

---

## 一、三层结构规则

目录层级 = 调用层级。只有三层，不再更深：

```text
第 1 层  板块        .agents/skills/<板块>/SKILL.md
                    作用：路由。识别任务属于哪个板块，把请求分派下去。
                    谁能检索到它：宿主扫描时直接命中的入口。

第 2 层  专业        <板块>/skills/<专业>/SKILL.md
                    作用：一个可以被独立调用、独立验收的能力。
                    判定标准：它会不会被本板块以外的请求调用？
                              会 → 值得做第 2 层；不会 → 并进调用它的专业。

第 3 层  方法        <专业>/references/<方法>.md
                    作用：该专业的方法正文、案例、条件、反例。
                    判定标准：这个主题会不会被两个以上专业读？
                              会 → 单独成文件；不会 → 并进读它的那个专业。
```

**只在一种情况下再加一层 `skills/`**：这个专业下面确实有**两个以上各自可独立调用、且互不依赖**的子能力（例如音频设计下的配音／音效／环境／配乐／混音）。递归到此为止。

## 二、拆分判据（复用性优先）

```text
值得单独成一个文件/专业：
  ① 会被本专业以外的请求调用
  ② 有独立的判断、输入输出和验收
  ③ 换掉它，其他部分仍然成立

不值得拆，应当合并：
  ④ A 和 B 天然同时出现、总是一起被读 → 合成一个模块
  ⑤ 只服务一个专业、且篇幅不足约 500 字 → 并进该专业
  ⑥ 只有"主题名不同"，调用方和时机完全相同 → 合成一个模块
```

本轮的教训：我按"主题不同"切，没按"复用性"切，结果把 322 字的《正反打与轴线》、375 字的《镜头语言常见错误》也单独成文件——它们既不会被别的板块单独调用，本身又不足以独立成篇。

## 五、每个文件承担什么（判读口诀）

```text
看到 <板块>/SKILL.md          → 这是路由，别在里面找方法
看到 <板块>/skills/<专业>/     → 这是一个能被独立调用的能力
看到 <专业>/references/        → 这是该专业的方法正文，按缺口读，不整份加载
看到 references/内置方法/       → 这是别的板块的方法，随包携带，来源专业维护
看到 references/语言模式/       → 这是语言方法的随包副本，来源语言板块
看到 reference.md（19 个编剧专业）→ 这是上游快照正文，位置和文件名保留外部身份
```
