# 图像视频能力分类与创意机制研究

状态：新架构已落盘，结构与保真回归已通过。实际媒介效果继续观察。完整节点以[能力注册表](../02_共享资产库/05_工具流程/能力注册表.json)为准，原文去向见[迁移清单](视觉能力重构迁移清单.json)。

## 本轮纠偏

专业分类不能直接照抄已有目录，也不能把影视岗位一一变成AI能力。对每个候选，分别核对专业对象、决定范围、独立结果、父级归属、跨媒介消费者和验收。

- 光影设计比灯光设计更适合作为本项目入口：覆盖自然与人工光、明暗组织、投影、反射、体积氛围和风格化阴影。灯光设计并非行业错误用语，只是此处命名不足以明确跨绘画与非写实媒介的范围。
- 色彩与成像应拆清：作品色彩系统属于美术统筹；镜头色调继承该系统；透视、景深、曝光和光学成像属于摄影实现；材质外观需单独说明受光响应与一致性，不能全塞进色彩。
- VFX不等于所有动效。角色动画、动态图形、现象特效和合成分别回答行为、图形时间组织、效果发生、不同元素能否属于同一画面。
- 原方案偏摄影与人物，需要补插画与图形语言、信息可视化、非人角色与机械对象、非写实运动、合成及媒介转译的适用分支。
- 生动的角色不能普遍要求摄影写实；生命感应由意图、反应与行为连贯性解释，皮肤和光学真实只是部分媒介的方法。

## 建议的分类原则

把作品统筹、任务路线、专业能力、媒介方法和模型编译区分开。摄影、插画、拼贴、定格与3D不是题材换皮；它们有不同的形态、空间、运动与材质表达。题材与任务按需组合能力，不为每个题材复制完整体系。

早期研究的分类维度（具体目录以下文为准）：创意与概念开发；美术与视觉语言；对象与世界设计；构图与摄影；表演与运动；时间与声画；制作编译与验收。家族是组织分类，不默认各建一个转发路由。可调用专业仍需明确输入、判断、结果、返回与保护项。

不能承诺一份有限列表覆盖未来任何图像视频。应以典型与边界任务验证覆盖，并设置明确的能力缺口登记；不得把不适配任务强塞进相似名称。

## 创意能力的可执行定义

创意需同时考虑相对什么既有方案发生变化，以及这种变化对当前目标是否有价值。熟悉、准确、可信有时比新奇更重要；用户已锁定身份或局部修复时，不重开概念。

建议先建立一个跨媒介“创意与概念开发”能力，Reference包含组合、探索、规则变换、类比与视觉隐喻、候选比较及陈套诊断。先不把每一种思考动作拆成子Skill。

输入：目标观众、希望改变的理解或感受、已定事实、当前常见方案、可改变范围。过程：识别惯例→选择需要变化的关系/观看方式/规则→生成机制不同的候选→检查可理解性和目标适配→交还作品或专业负责人定案。返回：核心想法、相对惯例改变了什么、为何服务目标、可见或可听的实现依据、保护项、所需专业。

“去掉风格词后机制是否仍不同”用于诊断表面替换，但不能否认形式创新；若风格变化改变了阅读、动作、感受或意义，应按实际作用评估。AI可帮助生成、比较和查证，不能把自身判断冒充观众反馈或全世界原创性证明。

## 外部依据与适用限度

- [Boden：Creativity and artificial intelligence](https://www.sciencedirect.com/science/article/pii/S0004370298000551)：组合、探索与变换三种路径；本文用于设计候选生成方法，不证明任何具体生成结果具有原创性。
- [Amabile：Componential Theory of Creativity](https://www.hbs.edu/ris/download.aspx?name=12-096.pdf)：新颖与适合目标共同构成创造性判断，不能只以稀奇评分。
- [Pixar：Stylization at Pixar](https://renderman.pixar.com/stories/stylization-at-pixar)：风格化阴影、明暗交界与体积形态说明光影不等于写实布灯。
- [ScreenSkills：Look development artist](https://www.screenskills.com/job-profiles/roles/look-development-artist/)：外观开发涉及纹理、光照与渲染条件下的一致性，不等于色板。
- [ScreenSkills：Compositor](https://www.screenskills.com/job-profiles/roles/compositor-animation/)：合成承担多来源元素的光影、色彩与整体连续性。
- [Adobe：Layout basics](https://www.adobe.com/learn/illustrator/web/layout-basics)：图文组织有层级、关系与阅读顺序，不能全部归入摄影构图。

以上资料支持专业边界分析，具体Skill划分是针对本项目的设计推论，不宣称行业只有这一种标准架构。

### 每个专业交回什么

同一份内容不重复放在父Skill、子Skill和Reference。下表明确结果归属；条目越多不代表每次调用越多。

#### 总控（`laohu-ai-visual`）

辨认文本、图片、视频、音频及混合任务，确定当前负责人。

#### 总导演（`laohu-director`）

锁定观众经历、全片取舍与跨部门保护项。

#### MV导演（`laohu-mv-director`）

整合最终歌曲事实、声画结构、表演与时间线。

#### 故事素材（`laohu-story-material`）

保留原话并交付适配缺口的素材证据。

#### 编剧（`laohu-script-writer`）

调度现有十二专业并整合唯一镜头化剧本。

#### 创意开发（`laohu-creative-development`）

在保护事实下提出机制不同的概念，交当前负责人定案。

#### 美术指导（`laohu-art-direction`）

确定风格、视觉系统与专业之间的视觉取舍。

| 专业 | 独立返回结果 |
|---|---|
| 色彩设计 | 色彩方案及跨画面色彩规则 |
| 构图 | 静态或动态画面的主体、层次与关系方案 |
| 摄影 | 可继承的景别、机位、镜头和曝光选择 |
| 光影设计 | 光源与明暗、投影、受光的完整方案 |
| 材质设计 | 跨条件可辨识的材质外观 |
| 插画设计 | 符合主题与媒介的造型和笔触方案 |
| 版式设计 | 图文阅读顺序及画幅布局 |
| 字体与文字设计 | 字体选择、文字形态和排印方案 |
| 信息设计 | 准确、可理解的信息图与图解方案 |
| 合成 | 多来源素材的统一画面方案 |

### 本轮补齐与重新定位

1. **角色**：补选角、面部、人体体态、生物、群像。五官比例、鼻眼细节保留R；面部与身体需要单独候选时才分别调用，角色父入口统一同一个人。
2. **服装**：补考据、造型、结构、面料、纹样装饰、配饰、戏服连续性。上一轮“戏服设计”与父入口过于同义，收窄为“戏服连续性”；世界衣橱与整体定案仍属父入口。
3. **妆发**：补妆容、发型、毛发、特效化妆。妆容不改变基础五官；发饰本体归配饰，发型负责佩戴固定；毛发专业只处理需要单独解决的毛发形态，不重做整体发型。
4. **场景**：补考据、建筑、室内、景观、空间布局、布景陈设。状态变化在父入口R维护并供各专业继承，暂不建只有状态表的“场景状态设计”Skill。
5. **道具**：补手持道具、产品、载具、机械。外观对象型与机构型任务可以会商，不让产品与机械各定义一套结构。
6. **美术**：字体和版式具有不同结果，拆为平级专业；取消夹在中间只转发的“平面设计”父层。构图、光影、色彩、材质、摄影、合成保留共享权威。
7. **图片**：补静物摄影，不让产品食物任务默认按人物生命感执行；写真与F定调源仍是图片结果。
8. **资产**：改成素体、服装、妆造、场景、道具、群像、风格参考七类；不再把服装妆造包进角色资产。F依然作为B/W/M共同源，不直接进入视频；B/LZ/P、W、M、S、A、G等编号保持既有合同，具体适用不得按本图发明新编号。
9. **封面**：补策划、标题、版式与缩略图适配；日式排版方法归共享版式R，封面只保存其发布场景应用。
10. **视频**：补舞蹈编排，覆盖MV已存在的舞蹈需求；动画、动作、表演、动态图形、VFX分清对象与结果。舞蹈本体组织动作句，表演负责人物意图，动画负责媒介运动实现。
11. **音频**：补音频剪辑与混音的区别；配乐只承接现有音乐任务简报，不扩张为歌曲创作平台。
12. **复盘**：图片、视频、音频、成片、发布均有不同真实证据，候选分为五个评审专业，父入口统一首断点。生成前专业自检仍由创作专业完成，不冒充真实结果评审。

### 不强拆的能力与理由

| 当前能力 | 结论 | 原因 |
|---|---|---|
| 总控 | 保留一入口＋R | 路由、状态与交接是同一编排结果，拆四个媒介转发器只会增加绕路 |
| 总导演 | 保留一负责人＋R | 观众经历、主胜负手、部门取舍共同构成唯一导演阐述 |
| MV导演 | 保留一负责人＋R | 歌曲事实与声画结构必须统一；舞蹈、配音、剪辑调用专业，不复制 |
| 创意开发 | 保留一专业＋完整R | 组合、类比、变换是形成候选的方法，不先变成三个互相转发的角色 |
| 故事素材 | 保留一专业＋R及脚本 | 查询保存回流共享source/atom/usage协议，暂无必要拆独立内容负责人 |
| 编剧 | 保留已验证十二专业 | 不为其他领域变多再改写完整外部章节 |
| VC | 保留已有适配入口 | 不另建第二个提纯入口重复执行；视频保持调用前后两次验收 |
| 语言模式 | 保留一共享专业＋R | 分模式不等于分内容权，避免多个表达入口争夺正文 |
| 能力进化 | 保留统一责任＋R及校验脚本 | 证据、重编、回归属于同一可追溯变更闭环，不为对称拆目录 |

### 共享归属与接口冲突裁决

目录位置表示维护归属，不表示每次调用必须沿所有父级转发。构图与摄影放美术指导下是本项目的跨媒介方法管理方案，不宣称行业摄影部门隶属美术。图片和视频可直接CONSULT共享子Skill，原任务负责人整合结果；锁定的世界风格需要变化才返回美术父入口。

| 交界 | 唯一决定与消费者 |
|---|---|
| 色彩／光影／摄影／合成 | 色彩定配色规则；光影定受光与阴影；摄影定景别机位曝光焦点等；合成匹配多来源。不因同一结果失真就由四处同时改全片色调 |
| 材质／面料 | 材质负责通用外观与受光原理；面料选具体织物与垂坠；服装调用材质R，不复制物理定义 |
| 构图／运镜 | 构图定关系原理；运镜补时间路径和变化实现，继承构图，不建第二套中心三角教程 |
| 人物设计／表演／配音 | 角色定身体与身份；表演落实已定情境的行为节拍；配音落实声音表现，冻结台词不变 |
| 动作／动画／VFX | 动作确定力量与操作过程；动画确定运动媒介语法；VFX完成现象。上游没决定的剧情由编剧裁决 |
| 设计／摄影／资产 | 设计定对象；摄影定当次呈现；资产固化必要复用信息。漂亮写真不等于多角度身份已验收 |
| 封面版式／共享版式与字体 | 封面按承诺取舍；共享专业提供排版与字体方案，日式案例只有一份方法真源 |
| 剪辑／视频编译 | 剪辑定镜头关系节奏；编译按模型组织批次，不为了批次长度重写已定故事 |
| 音频／声画 | 音频设计决定声音内容与表现；声画关系决定与画面的时序联系，最终音频事实仍优先 |
| 分镜／剧本 | 分镜只在现行允许场景做可视化，普通叙事母版仍是镜头化正式剧本 |

### 代表任务覆盖检查（设计推演，非已执行测试）

| 任务 | 最小调用组合 | 应避免的错误 |
|---|---|---|
| 改一张照片光线 | 图片→光影＋编辑 | 不重新选角换衣服 |

| 角色战损戏服 | 服装→结构＋戏服连续性，必要时妆发 | 不把破损衣服登记为永久身体身份 |

### 落地条件与保真要求

1. 上述子Skill是候选建设边界，不以目录数量作为质量指标。完整方法不足的候选先研究、补案例与验证，不创建空入口；暂无独立调用价值的分支保留完整R。
2. 每个旧章节都登记方法、因果、例外、案例、硬合同和当前调用者；新负责人完整承接并可实际到达后再清退旧文。先选新标题再摘要覆盖旧文不合格。
3. 新Reference名称是承接范围，不表示旧资料已经迁移完。外部编剧原正文、Reference及既有四层适配保持保真。
4. 同一场景比较单项调用和组合调用：选对专业、保住事实、回执改变实际结果、失败回到最早负责人。文字哈希、链接检查和生成效果分别验收。
5. 编号、现有作品、Markdown→HTML、三段式视频、F→B/W/M、音频冻结文本与VC合同先保持；必要变更单列影响，不被目录整理暗改。
6. 新命名按当前设计文件中的唯一ID实施；顶层AGENTS、核心合约、协作图谱、输入输出索引和发现配置同步变更，不能只搬目录。
7. 文件可达与Codex/其他Agent原生发现分别验证。嵌套不自动注册，当前没有安装或移动任何能力。
8. 本次目标是提示词与设计交付。服装结构不是工业纸样、建筑不是施工图、机械不是工程验算、混音方案不是已经处理好的音频，不扩张实际工具操作。
9. 保留已知未知：当前专业列表不声称穷尽所有未来媒介；遇到新任务先登记真实缺口，判断应补R、扩展专业还是新建独立负责人。
